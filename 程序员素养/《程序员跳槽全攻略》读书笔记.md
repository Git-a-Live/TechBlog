## 全书逻辑主线

全书围绕一条因果链展开：

> 人才是商品（价值论）→ 供需与信息不对称决定价格 → 跳槽是「自我实现」与「市场需求」的再匹配 → 因此需要系统地准备（自我认知 → 能力建设 → 材料与渠道）。

全书的核心主张是：求职不是经验论，而是可以逻辑化的学科。

---

## 一、核心框架：价值论

作者把人才当作商品，用三条经济规律解释薪资差异。

### 1. 使用价值

- 公司购买人才是为了「使用」，看中的是使用价值，即人才如何直接或间接地为公司挣钱。
- 使用价值相对于使用者存在：同一份机器学习/编译原理能力，在建站公司一文不值，在数据公司就是核心竞争力。
- 核心结论：**「你的价值，和你牛不牛无关，只和你能为你的雇主提供多少价值有关。」**（多数情况下能力越强越能提供价值，但根本规则是前者。）

### 2. 供需

- 使用价值是基础，但交换价值（价格）更容易受供需影响：职位供不应求时人才涨价，反之降价。
- 破局之道是切入细分市场：同是「管服务器」，普通运维与云计算运维的薪资差异巨大，而补足差距所需的知识并不多。

### 3. 信息透明度

- 市场很大，但只有你接触到的机会才对你有意义。北京 100 家招 PHP 的公司，若只知 3 家，就只能被动接受低薪。
- 招聘网站为招聘方设计，靠信息不对称收费，优先展示付费公司而非最好的公司。
- 破局之道：在短时间内获取大量机会，才能「做选择题」而不是「做判断题」。

## 二、跳槽的认知：不是什么 & 到底为什么

### 跳槽不是什么

1. **不是追求价值最大化**——纯按薪资选雇主有两个反例：
   - 工作是生活的三分之一（每天 8 小时），高薪换不开心不划算；
   - 职业具有不可逆性：换方向、甚至换语言，前期积累都可能前功尽弃，方向错了跑得越猛输得越狠。
2. **不是找工作，是换工作**——换工作有成本（放弃期权、重熟业务、重搞关系），不应裸辞。
3. **不是加薪的砝码**——以跳槽威胁谈薪会摧毁主管信任；同理，主管用加薪挽留的跳槽也宜拒绝。

### 如何正确地谈加薪（三步法）

1. 先讲自己最近的成长，确认主管是否认同；
2. 从能力提升角度，争取更大的发展空间与业务挑战；
3. 最后问：能力达到新水平后，薪资能否同步提升。

要点在于：只谈未来不谈现在，既表明对当下满意（降低主管戒备），又不给对方立即涨薪的压力，且随时可以体面收场。

### 跳槽到底为什么

- **求职的本质**：挣钱有四种形式——帮别人挣钱（打工 E）、为自己挣钱（SOHO/S）、雇别人挣钱（企业主 B）、让钱挣钱（投资 I）。选打工是因为门槛与风险最低，本质是「用劳动能力换资源的阶段性行为」。
- **跳槽的意义**：打工形态下的一种自我调节，寻找「市场需求」与「自我实现」的最佳匹配，从而在金钱与成长上双丰收。
- **跳槽的原则**：**「永远不要因为『现在很差』而跳槽，要因为『未来更好』而跳槽。」** 只有这样才能保证一直往上走。
- **节奏与路线图**：衡量是否该跳的指标是能力而非时间。从目标（如 CTO）倒推节点：应届生 → 初级 → 小组主管 → 部门经理 → 总监 → CTO。总是先在风险最小的路径（当前公司）寻求成长，失败后再考虑换公司。

## 三、准备篇：自我认知与职业规划

### 自我认识

- 去什么公司、做什么、拿多少钱，都取决于一个问题：想成为什么样的人。想不明白之前没人能帮忙。
- 两条建议：① 给自己定义一年期目标（意义是自我赋予的）；② 暂时没找到意义，就先多挣点钱，将来用得上。

### 程序员职业四大象限（源自《穷爸爸富爸爸》现金流象限）

| 象限 | 挣钱方式 | 对应路线 | 关键提示 |
|------|---------|---------|---------|
| E | 帮别人挣钱（雇员） | 专家线 / 管理线 | 最安全；2~3 年后才有资本选路线 |
| S | 为自己挣钱（SOHO/小老板） | 小老板线 | 有风险，需有「卖得出去的东西」 |
| B | 让雇员挣钱（创业） | 创业/CTO | 规模化优先；去创业公司当 CTO 是低风险捷径 |
| I | 让钱挣钱（投资） | 投资 | 技术背景做投资有规避产品技术风险的优势 |

- **E 象限两条线**：专家线主要和机器打交道，管理线主要和人打交道。
- **B 象限的低风险捷径**：去创业公司做 CTO——公司成了是上市公司 CTO，公司挂了换一家接着当。CEO 承担失败责任，CTO 不必。
- **A 轮前后 CTO 差异巨大**：A 轮前重敏捷开发，A 轮后重高可用、团队与资源管理。

### 市场需求分析

- **定量分析**：抓取 50 份以上目标职位 JD，分词按词频排序，即可看清雇主对某职位的真实要求（可加薪资下限过滤，看出「会哪些技能更值钱」）。
- **定性分析**：约目标公司的工程师交流，即可了解基本情况。
- **观察技术潮流**：从根源看「人们如何使用技术」判断技术兴衰（书以 PHP 崛起/ASP 衰落、OC/Swift 变迁为案例）。
- **投资新兴市场与细分市场**：新兴市场所有人同一起跑线、适合后进者；成熟市场则做细分定位（如「安全方向的 PHP 专家」：比你懂安全的没你懂 PHP，比你懂 PHP 的没你懂安全）。
- 结论：**「站在风口不一定能飞起来，但站在冰山上必然会沉下去。」**

### JobDeer 职业画布（个人求职规划工具）

以「价值主张」为中心（我能给雇主带来哪些价值），左侧是「如何构架价值」（我是谁/竞争优势/谁帮我），右侧是「如何传递价值」（雇主需要什么人/怎样被知道/怎样证明自己），底部是「预估收益」（成本/收益/失败可重用性）。可作为每次跳槽前的一页纸规划工具。

## 四、准备篇：个人品牌与能力建设

### 构建个人品牌

- **公司品牌 ≠ 个人品牌**：大公司带来的资源与影响力只是公司品牌的折射，离职即归零。
- **个人品牌是「一身相随」的资产**，可从上一家带到下一家。
- 技术人必备四件套：**Github 账号、技术博客、微博（业内交流）、技术社区账号（如 StackOverflow）**——关键在持续产出优质内容。
- 结论：**「中国最不缺的就是人，品牌就是雇主在芸芸众生中不选别人、唯独选你的理由。」**

### 学会沟通和写作

- **条理性**：技术写作是应用文，只需「讲清楚」。用列表列提纲，汇报时先给概要、再给细节。
- **逻辑性**：前后句应有明确关系（后续/论据/总结/并列），避免跳跃性思维。

### 开源项目

- **「开源项目是技术求职的大规模杀伤性武器」**：若目标公司在用本人写的代码，加分巨大；即便不知名，也能清晰展示编码风格与架构能力。
- **开源是转型的利器**：想从 A 语言转 B 语言，直接开源一个 B 语言项目，向雇主证明真实兴趣与动手能力，避免被贴上「光说不练」标签。
- **开源并不遥远**：iScroll 只是「处理滚动条的小 Tip」却大规模流行，作者甚至被苹果、微软雇过兼职。做好开源的秘诀是「来自真实需求」+「持续更新的毅力」，而非高超技术。

### 提升架构能力

- **DRY（Don't Repeat Yourself）**：把常用功能抽象成库、重复代码重构为可复用模块。
- **正交性**：功能之间尽量互不干扰，依赖尽可能少、规则要明确；API 是强化正交性的利器（通过接口隐藏实现、去除依赖）。
- 补充理念：不必二元思维，半自动化（机器做常规、人做判断）同样大幅提效。

## 五、操作篇：简历、渠道、面试、离职

### 简历

- **简历的唯一目的：约到面试**。它既不是人生履历，也不是技能大放送。
- **STAR 法则（组织经历的主框架）**：Situation（背景）→ Task（任务）→ Action（行动）→ Result（结果），按「背景—任务—行动—结果」描述每段经历，结果尽量量化。
- **给论据别给论题**：把结论留给读简历的人自己得出；论据要具体、量化、印象深刻。
  - 弱论据：「参与了 WAPCMS 开发」；
  - 强论据：「Web 前端从 10QPS 提到 200QPS，服务器从 10 台减到 3 台」。
- **FAB 视角（价值补充）**：Feature（是什么）→ Advantage（好在哪）→ Benefit（给雇主什么好处）。其核心是 Benefit——结果不仅量化，更要落到「为雇主带来的价值」上。
- **对比体现成长**：没有显赫成绩就讲成长（遇到什么问题 → 旧方案 → 新方案好在哪 → 如何找到 → 效果如何）。
- **铁律：简历不要造假**，技术圈极反感，一旦被发现后果严重。
- 工具与格式：用 Markdown 维护简历、投递转 PDF；每个里程碑更新一次简历，倒逼自己多做「值得写进履历」的事。

### 求职渠道（优先级从高到低）

1. **人脉：最优途径**——信任可简化筛选流程；优先找「了解自己」的朋友，而非不认识的人（后者无背书）。
2. **竞拍/批量推荐**：遍历潜在机会，把「不知道的机会」也推到眼前（应届/冷门职位不适用）。
3. **猎头**：服务好但乱象多，注意隐私保护（求职专用小号、来电拦截）。
4. **直投**：绕过不懂技术的 HR，直接联系技术主管。
5. **常规渠道**：企业官网 > 技术社区招聘版 > 招聘网站。

### 面试

- 小技巧：提到对方公司用「咱们 XXX」而非「你们 XXX」，提升亲切感。
- 常见四问的应对逻辑：
  - **为什么离职**：不说上家坏话、只说下家好话，呼应「因为未来更好」原则；
  - **最大挑战**：挑有代表性的情景，突出压力下冷静分析、解决问题的能力（可用「讲个最近发生的」降级）；
  - **三年后成为什么人**：强调成长性与稳定性，与招聘方能提供的空间匹配；
  - **你还有什么要问的**：问一个带「兴趣指标」的问题，表明对产品的真实好奇（不当场挑产品细节的刺）。
- **知己知彼**：面试前读对方的博客/微博，既为面试，也判断主管风格是否合拍。

### 离职

- 按劳动法提前一个月书面通知即可，无需雇主同意；但应做好平滑交接，圈子不大、冤家路窄。
- **离职访谈**：可吐槽具体规定，避免评价同事（尤其上级人品）；话术仍是「新机遇更好、原同事很好、建议挑无关痛痒的说」。
- **记得开离职证明**，新公司报到要用。

## 六、金句摘录

1. 你的价值，和你牛不牛无关，只和你能为你的雇主提供多少价值有关。
2. 永远不要因为「现在很差」而跳槽，要因为「未来更好」而跳槽。
3. 站在风口不一定能飞起来，但站在冰山上必然会沉下去。
4. 简历的存在只有一个目的——帮你约到面试。
5. 开源项目是技术求职的大规模杀伤性武器。
6. 公司品牌不是个人品牌；个人品牌是「一身相随」的资产。
7. 中国最不缺的就是人，品牌就是雇主在芸芸众生中不选别人、唯独选你的理由。
8. 简历里给论据、别给论题；论据要具体、量化、印象深刻。
9. 你以为她是你的 HR，其实她只是公司的 HR——所以职业生涯规划要自己做。

## 七、落地建议

1. **用价值论自检**：列出当前雇主的业务，判断「自己提供的价值是否直接/间接帮公司挣钱」，据此定位稀缺性。
2. **跳槽决策只用一个标准**：不是因为「现在很差」而走，而是确认「下一个机会的未来更好」。
3. **简历改造成 STAR 结构**：每个项目按「背景（S）→ 任务（T）→ 行动（A）→ 结果（R）」组织，结果量化并落到雇主收益（FAB 的 Benefit 视角），例如「QPS 10→200，服务器 10→3 台」。
4. **做一次定量市场调研**：抓 50 份目标岗位 JD，词频统计，反向补足高频技能的短板。
5. **建个人品牌四件套**：Github + 技术博客 + 技术社区 + 社交/内容账号，持续产出而非一次性。
6. **准备一个开源项目**：优先选「工作中真实遇到的费事小细节」，长期维护而非追求高难度。
7. **面试前读面试官公开内容**，并把「反问」当作展示兴趣指标的机会。
8. **离职时留好离职证明、做好交接**，不与前东家交恶。
