`print` 能输出信息，但缺少级别、时间戳、来源与去向控制。网络失败时，开发者需要知道哪个命令、哪个参数、哪个状态码出错；生产环境又不能让调试信息淹没真正的错误。日志系统要解决的是“按严重程度过滤、按来源归类、按目的地输出”。

Dart 的 `package:logging` 提供命名 logger、级别阈值与记录流。日志实例通过构造函数传入命令，而不是在命令内部自行创建，这种依赖注入让日志配置集中在应用入口，也便于测试替换。

## print 的局限

| 维度 | `print` | 日志系统 |
|------|---------|----------|
| 级别 | 无 | `INFO`、`WARNING`、`SEVERE` 等 |
| 过滤 | 只能删代码 | 运行时按阈值过滤 |
| 来源 | 无法区分 | logger 名称标识模块 |
| 目的地 | 标准输出 | 文件、控制台、网络、多路复用 |
| 结构化字段 | 只有字符串 | 时间、级别、错误、堆栈、序列号 |
| 生产控制 | 无 | 可配置级别与输出策略 |

命令行工具在开发期需要详细日志，在发布后只需要警告与错误。日志级别让同一份代码在两种环境下使用不同阈值，而不必修改调用点。

## 核心类型

| 类型 | 职责 |
|------|------|
| `Logger` | 具名日志入口，提供 `info`、`warning`、`severe` 等方法 |
| `Level` | 严重程度常量，从 `ALL` 到 `OFF` |
| `LogRecord` | 一条日志记录，包含时间、级别、消息、错误、堆栈等 |
| `Logger.root` | 根 logger，默认级别为 `INFO` |

```dart
import 'package:logging/logging.dart';

final logger = Logger('wikipedia');
logger.info('fetching summary');
logger.warning('status code 404');
logger.severe('unexpected response shape');
```

`package:logging` 默认不输出任何内容：必须设置级别并监听 `onRecord`，记录才会到达目的地。这种“默认静默”的设计避免库代码擅自打印，把输出策略留给应用。

## 级别

级别按严重程度递增：

| 级别 | 用途 |
|------|------|
| `ALL` | 最低阈值，记录全部 |
| `FINEST` / `FINER` / `FINE` | 细粒度调试信息 |
| `CONFIG` | 配置与环境信息 |
| `INFO` | 正常流程的关键节点 |
| `WARNING` | 可恢复的异常或降级 |
| `SEVERE` | 功能失败，需要关注 |
| `SHOUT` | 最高严重程度 |
| `OFF` | 关闭所有记录 |

`logger.level` 是阈值：严重程度大于等于该级别的记录才会被发出。设置 `Level.WARNING` 后，`info` 与 `fine` 被丢弃，`warning` 与 `severe` 通过。

未显式设置级别时，logger 继承最近的祖先级别；没有祖先配置时使用 `Logger.root.level`，默认 `INFO`。`Logger.root.level = Level.ALL` 是开发期打开全部日志的常用做法。

级别是过滤手段，不是分类标签。`severe` 表示“功能不可用”，不是“错误信息比较长”；`warning` 表示“可以继续，但需要留意”。级别语义混乱会让过滤失去意义。

## 层级与监听

logger 名称用点号分隔形成层级，例如 `api.wikipedia` 的父级是 `api`，再往上是根。默认情况下，所有 logger 共用根配置；启用层级后，每个 logger 可以独立配置级别与监听器：

```dart
hierarchicalLoggingEnabled = true;

Logger.root.level = Level.WARNING;
Logger.root.onRecord.listen((record) {
  print('[ROOT] ${record.level.name}: ${record.message}');
});

final apiLogger = Logger('api');
apiLogger.level = Level.ALL;
apiLogger.onRecord.listen((record) {
  print('[API] ${record.level.name}: ${record.message}');
});
```

启用层级后，一条记录会送达该 logger 的监听器，也会向上送达祖先的监听器，因此根监听器可以统一收集，子 logger 监听器可以单独处理。未设置级别的子 logger 继承父级阈值；根级别不会反过来过滤子 logger 已发出的记录。

`hierarchicalLoggingEnabled` 是全局开关，应在配置级别与监听器之前设置。关闭时，所有层级的日志合并到根 logger：非根 logger 的有效级别取自根，对非根 logger 设置 `level` 会抛 `UnsupportedError`。需要独立配置时先开启层级。

`LogRecord` 的常用字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `level` | `Level` | 严重程度 |
| `message` | `String` | 日志正文，非字符串会被转为字符串 |
| `time` | `DateTime` | 记录创建时间 |
| `sequenceNumber` | `int` | 进程内递增序号，用于排序 |
| `loggerName` | `String?` | logger 名称 |
| `error` | `Object?` | 关联错误对象 |
| `stackTrace` | `StackTrace?` | 关联堆栈 |

## 文件日志

```dart
import 'dart:io';
import 'package:logging/logging.dart';

Logger initFileLogger(String name) {
  hierarchicalLoggingEnabled = true;

  final logger = Logger(name);
  final now = DateTime.now();

  final scriptFile = File(Platform.script.toFilePath());
  final projectDir = scriptFile.parent.parent.path;

  final dir = Directory('$projectDir/logs');
  if (!dir.existsSync()) dir.createSync();

  final logFile = File(
    '${dir.path}/${now.year}_${now.month}_${now.day}_$name.txt',
  );

  logger.level = Level.ALL;

  logger.onRecord.listen((record) {
    final msg =
        '[${record.time} - ${record.loggerName}] '
        '${record.level.name}: ${record.message}';
    logFile.writeAsStringSync('$msg \n', mode: FileMode.append);
  });

  return logger;
}
```

逐段说明：

- `hierarchicalLoggingEnabled = true`：允许具名 logger 使用自己的级别与监听器。
- `Logger(name)`：创建具名 logger，名称会出现在每条记录的 `loggerName` 字段中。
- `Platform.script`：当前运行的脚本 URI；`toFilePath()` 转为本地路径。
- `scriptFile.parent.parent.path`：从 `bin/cli.dart` 上溯两级得到包目录，日志写入 `<package>/logs/`。
- `Directory.createSync()`：目录不存在时创建；父目录必须存在，否则抛 `FileSystemException`。
- 文件名包含年月日与 logger 名，同一天多次运行追加到同一文件。
- `logger.level = Level.ALL`：开发期记录全部级别。
- `onRecord.listen`：订阅记录流，格式化后同步追加写入文件。

路径推导的边界：该逻辑假设通过 `dart run bin/cli.dart` 启动，`Platform.script` 指向 `bin/cli.dart`。AOT 编译后的可执行文件中，`Platform.script` 指向可执行文件本身，`parent.parent` 不再是项目根目录；部署环境应通过环境变量或命令行参数显式指定日志目录，而不是依赖脚本路径。

同步写入会阻塞事件循环。命令行工具日志量小，影响可以忽略；高频日志应改用 `IOSink` 异步写入，或批量缓冲后刷盘。

## 级别配置

```dart
logger.level = Level.ALL;        // 开发：全部记录
logger.level = Level.INFO;       // 常规运行：信息及以上
logger.level = Level.WARNING;    // 生产：只记录异常
logger.level = Level.OFF;        // 关闭
```

生产环境不建议使用 `ALL`：`fine` 级别的调试信息会迅速膨胀日志文件，也会拖慢高频路径。`INFO` 适合记录命令开始、结束与关键参数；`WARNING` 适合只关心失败场景的部署。

日志级别可以在运行时通过环境变量覆盖：

```dart
final levelName = Platform.environment['LOG_LEVEL'] ?? 'INFO';
logger.level = Level.LEVELS.firstWhere(
  (level) => level.name == levelName,
  orElse: () => Level.INFO,
);
```

`Level.LEVELS` 包含全部预定义级别，按严重程度升序排列。

## 命令中的日志

命令通过构造函数接收 logger：

```dart
class SearchCommand extends Command {
  SearchCommand({required this.logger}) {
    addFlag(
      'im-feeling-lucky',
      help: 'If true, prints the summary of the top article.',
    );
  }

  final Logger logger;

  @override
  String get name => 'search';

  @override
  String get description => 'Search for Wikipedia articles.';

  @override
  bool get requiresArgument => true;

  @override
  String get valueHelp => 'STRING';

  @override
  String get help =>
      'Prints a list of links to Wikipedia articles that match the given term.';

  @override
  FutureOr<String> run(ArgResults args) async {
    if (requiresArgument &&
        (args.commandArg == null || args.commandArg!.isEmpty)) {
      throw ArgumentException('Please include a search term', name);
    }

    final buffer = StringBuffer('Search results:\n');
    try {
      final SearchResults results = await search(args.commandArg!);

      if (args.flag('im-feeling-lucky')) {
        final title = results.results.first.title;
        final Summary article = await getArticleSummaryByTitle(title);
        buffer.writeln('Lucky you!');
        buffer.writeln(article.titles.normalized.titleText);
        if (article.description != null) {
          buffer.writeln(article.description);
        }
        buffer.writeln(article.extract);
        buffer.writeln();
        buffer.writeln('All results:');
      }

      for (var result in results.results) {
        buffer.writeln('${result.title} - ${result.url}');
      }
      return buffer.toString();
    } on HttpException catch (e) {
      logger
        ..warning(e.message)
        ..warning(e.uri)
        ..info(usage);
      return e.message;
    } on FormatException catch (e) {
      logger
        ..warning(e.message)
        ..warning(e.source)
        ..info(usage);
      return e.message;
    }
  }
}
```

日志与用户提示分工明确：

| 通道 | 内容 | 受众 |
|------|------|------|
| 返回值 | 用户可读的错误摘要 | 终端用户 |
| `logger.warning` | 状态码、URI、解析源 | 开发者与运维 |
| `logger.info(usage)` | 出错命令的用法 | 排查输入错误 |

`..` 级联让同一个 logger 连续记录多条，不必重复写变量名。`e.uri` 是 `HttpException` 的字段，`e.source` 是 `FormatException` 的字段，二者都能提供上下文。

`GetArticleCommand` 采用同样的结构：

```dart
class GetArticleCommand extends Command {
  GetArticleCommand({required this.logger});

  final Logger logger;

  @override
  String get name => 'article';

  @override
  String get description => 'Read an article from Wikipedia';

  @override
  String get help => 'Gets an article by exact canonical wikipedia title.';

  @override
  String get defaultValue => 'cat';

  @override
  String? get valueHelp => 'STRING';

  @override
  FutureOr<String> run(ArgResults args) async {
    try {
      var title = args.commandArg ?? defaultValue;
      final List<Article> articles = await getArticleByTitle(title);
      final article = articles.first;
      final buffer = StringBuffer('\n=== ${article.title.titleText} ===\n\n');
      buffer.write(article.extract.split(' ').take(500).join(' '));
      return buffer.toString();
    } on HttpException catch (e) {
      logger
        ..warning(e.message)
        ..warning(e.uri)
        ..info(usage);
      return e.message;
    } on FormatException catch (e) {
      logger
        ..warning(e.message)
        ..warning(e.source)
        ..info(usage);
      return e.message;
    }
  }
}
```

`args.commandArg ?? defaultValue` 在未提供标题时回退到 `'cat'`；`defaultValue` 在父类中声明为 `String?`，这里重写为 `String` 是合法的协变返回。

## 依赖注入

命令不自行创建 logger，而是由外部传入：

```dart
SearchCommand(logger: errorLogger)
```

这是构造函数注入，属于依赖注入的一种。收益：

1. **配置集中**：日志级别、文件路径、格式只在 `initFileLogger` 中决定一次。
2. **可测试**：测试传入 `Logger('test')` 并监听 `onRecord`，即可断言命令记录了哪些级别与消息，不需要访问文件系统。
3. **可替换**：生产使用文件 logger，开发可以换成控制台 logger，命令代码不变。
4. **依赖显式**：构造函数签名直接表明命令需要日志能力，而不是隐藏在全局单例中。

替代方案是全局单例 `Logger.root`，实现更短，但测试之间会共享监听器与级别，容易相互污染；多实例场景也无法隔离。构造函数注入的代价是每个命令都要多一个字段，规模增大时可以用一个依赖容器统一创建，但本质仍是显式传递。

## 应用接线

```dart
import 'package:cli/cli.dart';
import 'package:command_runner/command_runner.dart';

void main(List<String> arguments) async {
  final errorLogger = initFileLogger('errors');

  final app = CommandRunner(
    onOutput: (String output) async {
      await write(output);
    },
    onError: (Object error) {
      if (error is Error) {
        errorLogger.severe(
          '[Error] ${error.toString()}\n${error.stackTrace}',
        );
        throw error;
      }
      if (error is Exception) {
        errorLogger.warning(error);
        print(error);
      }
    },
  )
    ..addCommand(HelpCommand())
    ..addCommand(SearchCommand(logger: errorLogger))
    ..addCommand(GetArticleCommand(logger: errorLogger));

  await app.run(arguments);
}
```

接线逻辑：

1. 创建名为 `errors` 的文件 logger。
2. 构造 `CommandRunner`，注入输出与错误回调。
3. 注册帮助、搜索、全文三个命令，共享同一个 logger。
4. `await app.run`，确保进程等待全部异步工作结束。

`onError` 的策略与 [[7. 错误与异常处理|异常处理]] 一致：`Error` 记录 `severe` 并附带堆栈，然后重新抛出；`Exception` 记录 `warning` 并打印给用户。`error.stackTrace` 在 `Error` 上可用，但更通用的做法是使用 `catch` 捕获的 `StackTrace`，或在 `onError` 签名中同时接收错误与堆栈。

`cli/lib/cli.dart` 作为公开入口导出：

```dart
export 'src/commands/get_article.dart';
export 'src/commands/search.dart';
export 'src/logger.dart';
```

## 日志内容设计

一条可用的日志至少包含“何时、何地、何事”：

```text
[2026-11-21 14:21:44.123 - errors] WARNING: statusCode=404, body=...
```

建议：

- 时间使用带时区的 ISO 8601 格式，便于跨机器排序；`DateTime.now()` 是本地时间，跨时区部署应使用 `toUtc()`。
- 消息包含操作与关键参数，但不要拼接整个响应体；大对象应截断。
- 错误对象与堆栈分开记录，不要把 `stackTrace.toString()` 混进消息导致无法结构化解析。
- 不记录令牌、Cookie、用户隐私字段；日志文件的访问权限应受限。
- 同一失败只记录一次。命令层记录上下文，顶层记录未捕获异常，避免重复刷屏。

## 日志轮转与保留

`package:logging` 只负责产生记录，不负责文件管理。当前实现按“日期 + logger 名”命名，同一天追加，长期运行会持续增长。生产环境需要补充：

| 问题 | 方案 |
|------|------|
| 单文件过大 | 按大小或日期切分 |
| 旧日志占满磁盘 | 保留最近 N 天，定期清理 |
| 多进程写入 | 每进程独立文件，或使用集中式日志服务 |
| 崩溃丢失缓冲 | 关键日志同步写入，普通日志异步批量 |

命令行工具通常生命周期短、日志量小，按日期单文件足够；常驻服务应接入成熟的日志库或平台日志系统。

## 边界

- 日志不是异常处理。捕获异常后只写日志而不修正控制流，会让调用方误以为操作成功。
- 日志不是用户界面。面向用户的提示走返回值或标准输出，日志面向开发者。
- 级别不是越多越好。项目内统一使用 `fine`/`info`/`warning`/`severe` 四档，足以覆盖大多数场景。
- 依赖注入不必引入框架。一个构造函数参数就是最小的注入形式。

从第一个 `Hello, Dart!` 到带日志、测试、API 客户端与命令框架的 CLI，Dart 的核心机制已经串联起来：类型与空安全保证数据形状，类与继承组织行为，`Future` 处理等待，包与库划分边界，异常区分失败类型，模式匹配校验外部数据。后续的 Flutter 开发建立在这些机制之上，差异主要在于 UI 组合与响应式状态管理，语言层的能力仍然通用。
