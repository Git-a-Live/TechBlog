网络请求、文件读写、定时器都属于“发起后需要等待结果”的操作。如果程序在等待期间被阻塞，界面会掉帧，命令行会失去响应，CPU 也处于空转状态。Dart 的解法不是为每个请求开线程，而是在单线程内用事件循环调度：耗时的 I/O 交给运行时，当前函数暂停，事件循环继续处理其他任务，结果就绪后再恢复该函数。

这套机制的语言级抽象是 `Future<T>`：它表示一个“现在还没有、将来会有的 `T` 类型值”。`async` 与 `await` 则把基于回调的异步代码改写成接近同步代码的线性结构。

## 事件循环

每个 isolate 拥有一个事件循环与两条队列：

```text
                    ┌──────────────────────┐
同步代码执行 ──────► │  microtask queue     │  清空后才处理事件
                    └──────────┬───────────┘
                               ▼
                    ┌──────────────────────┐
                    │  event queue         │  I/O、Timer、端口消息
                    └──────────────────────┘
```

事件循环的规则是：先执行同步代码直到调用栈清空；然后反复清空微任务队列；再从事件队列取出一个事件执行，执行完再次清空微任务。`Future` 的完成回调、`await` 之后的续体都以微任务形式排队，因此优先级高于定时器与 I/O 事件。

单线程意味着 CPU 密集计算会阻塞事件循环。排序大数组、解析超大 JSON 这类任务应放入 `Isolate`，而不是用 `await` 包装。异步只解决“等待”，不解决“计算占满线程”。

## Future 的状态

`Future<T>` 只有三种状态：

| 状态 | 含义 | 迁移 |
|------|------|------|
| 未完成 | 尚无结果 | 完成后进入成功或失败 |
| 成功完成 | 持有 `T` 类型值 | 终态 |
| 失败完成 | 持有错误与堆栈 | 终态 |

`Future<void>` 表示完成后没有值，只关心“是否结束”。`Future<int>`、`Future<String>` 分别表示将来得到整数、字符串。

在 `async`/`await` 普及之前，结果通过回调注册：

```dart
Future<int> fetchCount() => Future.value(42);

void main() {
  fetchCount().then((value) {
    print('count = $value');
  }).catchError((Object error) {
    print('failed: $error');
  });
}
```

`then` 注册成功回调，`catchError` 注册失败回调，`whenComplete` 无论成败都会执行。这种写法在多个异步步骤串联时会形成嵌套，错误传播也不直观。

## async 与 await

`async` 标记函数为异步函数，函数体可以出现 `await`；调用这样的函数会立即返回一个 `Future`，函数体同步执行到第一个 `await` 为止。

```dart
Future<void> main() async {
  print('start');
  final value = await Future.delayed(
    const Duration(seconds: 1),
    () => 42,
  );
  print('value = $value');
  print('end');
}
```

输出顺序为 `start` → 等待约一秒 → `value = 42` → `end`。`await` 暂停的是当前函数的后续执行，不是整个程序；暂停期间事件循环可以处理其他任务。

关键语义：

- `await` 只能出现在 `async` 函数内（`async*` 生成器除外）。
- `await` 的表达式必须是 `Future<T>` 或 `T`；后者会被自动包装为已完成 `Future`。
- `await` 成功时“拆包”得到 `T`，失败时在 `await` 位置重新抛出错误，因此可以直接用 `try`/`catch` 捕获。
- `async` 函数的返回值会被自动包装：`return x;` 等价于完成一个值为 `x` 的 `Future`；抛出异常等价于失败完成。
- 声明为 `void` 的 `async` 函数实际返回 `Future<void>`，调用方可以等待，也可以忽略；忽略时错误可能变成未处理异常。

一个把回调改写成 `await` 的例子：

```dart
// 回调风格
Future<String> loadTitle() {
  return fetchArticle().then((article) => article.title);
}

// async/await 风格
Future<String> loadTitle() async {
  final article = await fetchArticle();
  return article.title;
}
```

两种写法编译后的调度行为一致，后者的控制流与错误处理更接近同步代码。

## 添加 http 依赖

Dart 的网络请求由 `package:http` 提供，需要先在 `pubspec.yaml` 的 `dependencies` 中声明：

```yaml
dependencies:
  http: ^1.4.0
```

`^1.4.0` 是 caret 约束，等价于 `>=1.4.0 <2.0.0`：允许同一主版本内的补丁与次版本升级，主版本变化意味着不兼容修改，需要显式调整。

```bash
dart pub get
```

该命令解析依赖图、下载包、写入 `.dart_tool/package_config.json`，并更新 `pubspec.lock`。随后在代码中导入：

```dart
import 'dart:io';
import 'package:http/http.dart' as http;
```

`as http` 是社区惯例，调用时写作 `http.get`、`http.Response`，避免与其他库的同名符号冲突。

## 发起请求

```dart
Future<String> getWikipediaArticle(String articleTitle) async {
  final url = Uri.https(
    'en.wikipedia.org',
    '/api/rest_v1/page/summary/$articleTitle',
  );

  final response = await http.get(url);

  if (response.statusCode == 200) {
    return response.body;
  }

  return 'Error: Failed to fetch article "$articleTitle". '
      'Status code: ${response.statusCode}';
}
```

`Uri.https(authority, path)` 构造 HTTPS URI，路径中的空格、非 ASCII 字符会被百分号编码。更复杂的查询参数写法见 [[12. 网络请求与 API 客户端|API 客户端]]。

`http.get` 返回 `Future<http.Response>`，`await` 之后得到响应对象。`Response` 的常用成员：

| 成员 | 类型 | 说明 |
|------|------|------|
| `statusCode` | `int` | HTTP 状态码，200 表示成功 |
| `body` | `String` | 按响应头字符集解码后的文本 |
| `bodyBytes` | `Uint8List` | 原始字节，需要自行解码时使用 |
| `headers` | `Map<String, String>` | 响应头，键为小写 |
| `request` | `BaseRequest?` | 关联的请求对象 |

HTTP 协议层面，404、500 也是“成功收到响应”，不会让 `http.get` 抛出异常。因此必须显式检查状态码，不能只依赖 `try`/`catch`。当前实现把错误信息作为字符串返回，调用方无法区分“文章内容”与“错误提示”；更合理的做法是抛出异常，见 [[7. 错误与异常处理|异常处理]]。

## 串联异步步骤

搜索流程包含“解析标题 → 请求摘要 → 输出”三个阶段，用 `await` 顺序表达：

```dart
void searchWikipedia(List<String>? arguments) async {
  final String articleTitle;

  if (arguments == null || arguments.isEmpty) {
    print('Please provide an article title.');
    final inputFromStdin = stdin.readLineSync();
    if (inputFromStdin == null || inputFromStdin.isEmpty) {
      print('No article title provided. Exiting.');
      return;
    }
    articleTitle = inputFromStdin;
  } else {
    articleTitle = arguments.join(' ');
  }

  print('Looking up articles about "$articleTitle". Please wait.');

  final articleContent = await getWikipediaArticle(articleTitle);
  print(articleContent);
}
```

这里有两处容易忽略的细节：

1. `searchWikipedia` 被标记为 `async`，但返回类型仍是 `void`。调用方 `main` 不等待它，程序依靠事件循环中未完成的 I/O 事件保持存活，直到请求结束。若 `main` 需要感知完成或错误，应改为 `Future<void> main() async` 并 `await searchWikipedia(...)`。
2. 标题为空时提前 `return`，避免向 API 发送空路径。`return` 在 `async` 函数中等价于完成一个值为 `null` 的 `Future<void>`。

多个互不依赖的请求可以并发等待，而不是逐个串行：

```dart
final results = await Future.wait([
  getWikipediaArticle('Dart'),
  getWikipediaArticle('Flutter'),
]);
```

`Future.wait` 返回 `Future<List<T>>`，默认只要有一个失败就整体失败；需要收集全部结果时传入 `eagerError: false` 并自行处理错误。串行 `await` 的总耗时是各请求之和，并发等待接近最慢的那个请求，这是异步编程最直接的收益。

## 错误传播

`await` 会把失败 Future 的错误在当前函数内重新抛出，因此 `try`/`catch` 的位置决定了谁来处理：

```dart
Future<String> load(String title) async {
  try {
    return await getWikipediaArticle(title);
  } on FormatException {
    return 'Invalid response';
  }
}
```

未被捕获的错误会沿 `Future` 链向上传播，最终交给当前 Zone 的未处理错误处理器；在命令行程序中通常表现为打印堆栈并终止。忽略一个会失败的 Future（不 `await`、不注册 `catchError`）不会让错误消失，只会让它脱离调用栈上下文。

## 异步设计要点

- 只在真正需要等待的地方使用 `async`；纯计算函数保持同步，便于测试与复用。
- 避免在循环中逐个 `await` 独立请求，优先 `Future.wait` 并发。
- 不要用 `Future.delayed` 模拟同步等待来“修复”竞态，延迟不构成同步保证。
- 对外暴露的异步 API 应明确失败语义：返回错误值还是抛出异常，二者不可混用。
- 命令行程序的 `main` 若需要等待全部工作完成，声明为 `Future<void> main() async`，让运行时以返回的 Future 作为退出依据。

`Future` 把“稍后得到的结果”变成一等值，`async`/`await` 把这种值还原成线性控制流。理解事件循环的调度顺序，才能判断一段代码是并发还是串行，也才能解释为什么 `await` 不会阻塞整个程序。下一节把命令解析逻辑抽成独立包，开始处理多包工程的组织问题，见 [[4. 包与库的组织|包与库的组织]]。
