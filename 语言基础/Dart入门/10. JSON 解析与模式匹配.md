Web API 的响应体是 JSON 文本。直接按下标取值（`json['pageid'] as int`）能跑通，但字段名拼错只会在运行时暴露，类型错误也要到取值那一刻才发现。更稳妥的做法分两步：先用 `jsonDecode` 把文本解码为通用集合，再用模式匹配校验结构并构造强类型模型。

Dart 3 的模式匹配把“检查形状、提取字段、类型转换”合并到一个表达式中。map 模式对应 JSON 对象，list 模式对应 JSON 数组，变量模式负责绑定并收窄类型，通配符丢弃不需要的字段。

## JSON 与 Dart 类型映射

`jsonDecode` 的结果只使用以下几种 Dart 类型：

| JSON | Dart | 说明 |
|------|------|------|
| object | `Map<String, dynamic>` | 键固定为字符串 |
| array | `List<dynamic>` | 元素类型不固定 |
| string | `String` | |
| number（无小数点） | `int` | 超出 64 位范围时可能为 `double` |
| number（有小数点/指数） | `double` | |
| `true` / `false` | `bool` | |
| `null` | `Null` | |

解码结果是动态类型，字段访问与类型转换的责任在调用方。JSON 本身不表达类型约束，同一个字段在不同响应中可能是字符串或 `null`，模式匹配正是用来在运行时确认实际形状。

## 解码与编码

```dart
import 'dart:convert';

const String jsonString = '{"title": "Dart", "pageid": 12345}';

final Map<String, Object?> jsonMap =
    jsonDecode(jsonString) as Map<String, Object?>;
```

`jsonDecode` 的静态返回类型是 `dynamic`，需要显式转型。`Map<String, dynamic>` 与 `Map<String, Object?>` 在运行时是兼容的：`dynamic` 与 `Object?` 都是顶层类型，泛型参数按子类型规则匹配。

反向序列化使用 `jsonEncode`：

```dart
final String text = jsonEncode(<String, Object?>{
  'title': 'Dart',
  'pageid': 37194605,
});
```

`jsonEncode` 接受可序列化的对象：`num`、`String`、`bool`、`null`、`List`、`Map`（键必须是 `String`）。其他对象需要先转换为这些类型，或实现 `toJson()` 并由调用方传入 `toEncodable`。

## 类型化模型

把 API 响应映射为类，可以获得编译期字段检查与编辑器补全：

```dart
class ArticleSummary {
  final String title;
  final int pageid;

  ArticleSummary({required this.title, required this.pageid});

  factory ArticleSummary.fromJson(Map<String, Object?> json) {
    return ArticleSummary(
      title: json['title'] as String,
      pageid: json['pageid'] as int,
    );
  }
}
```

`factory` 构造函数与普通构造函数的区别：

| 维度 | 普通构造函数 | 工厂构造函数 |
|------|--------------|--------------|
| 是否创建新实例 | 总是创建 | 可以返回已有实例、缓存对象或子类型 |
| 能否访问 `this` | 能 | 不能 |
| 返回要求 | 隐式返回新对象 | 必须显式 `return` 一个实例 |
| 典型用途 | 初始化字段 | 反序列化、缓存、选择子类 |

`fromJson` 是社区惯例命名，表示“从解码后的 map 构造实例”。构造函数不能返回 `List`，因此批量解析使用静态方法，见后文。

## 模式匹配

### switch 表达式

Wikipedia 摘要响应中 `description` 是可选字段，其余字段固定。用两个分支分别处理：

```dart
factory Summary.fromJson(Map<String, Object?> json) {
  return switch (json) {
    {
      'titles': final Map<String, Object?> titles,
      'pageid': final int pageid,
      'extract': final String extract,
      'extract_html': final String extractHtml,
      'lang': final String lang,
      'dir': final String dir,
      'content_urls': {
        'desktop': {'page': final String url},
        'mobile': {'page': String _},
      },
      'description': final String description,
    } =>
      Summary(
        titles: TitlesSet.fromJson(titles),
        pageid: pageid,
        extract: extract,
        extractHtml: extractHtml,
        lang: lang,
        dir: dir,
        url: url,
        description: description,
      ),
    {
      'titles': final Map<String, Object?> titles,
      'pageid': final int pageid,
      'extract': final String extract,
      'extract_html': final String extractHtml,
      'lang': final String lang,
      'dir': final String dir,
      'content_urls': {
        'desktop': {'page': final String url},
        'mobile': {'page': String _},
      },
    } =>
      Summary(
        titles: TitlesSet.fromJson(titles),
        pageid: pageid,
        extract: extract,
        extractHtml: extractHtml,
        lang: lang,
        dir: dir,
        url: url,
      ),
    _ => throw FormatException('Could not deserialize Summary, json=$json'),
  };
}
```

语法拆解：

| 片段 | 作用 |
|------|------|
| `switch (json) { ... }` | 对值做多分支匹配，整体作为表达式返回值 |
| `{ 'key': pattern }` | map 模式，要求包含指定键并匹配对应值 |
| `final int pageid` | 变量模式，声明变量并把值收窄为 `int` |
| `String _` | 通配符模式，校验类型但丢弃值 |
| `=>` | 分支体，单个表达式 |
| `_` | 兜底通配符，匹配任何值 |

map 模式是“开放”的：只要求列出的键存在，额外的键不影响匹配。因此第一个分支在 `description` 存在时命中，第二个分支在没有该字段时命中；顺序不能颠倒，否则带 `description` 的响应会先被宽松分支接走，字段被丢弃。

嵌套模式可以一次校验多层结构。`'content_urls': {'desktop': {'page': final String url}}` 同时要求外层有 `content_urls`、内层有 `desktop`、最内层有字符串 `page`。任何一层缺失或类型不符，整个模式失败。

### if-case

结构固定、只需一次校验时，`if case` 比 `switch` 简洁：

```dart
factory TitlesSet.fromJson(Map<String, Object?> json) {
  if (json case {
    'canonical': final String canonical,
    'normalized': final String normalized,
    'display': final String display,
  }) {
    return TitlesSet(
      canonical: canonical,
      normalized: normalized,
      display: display,
    );
  }
  throw FormatException('Could not deserialize TitleSet, json=$json');
}
```

`if case` 只匹配一个模式，匹配成功时在 `if` 块内绑定变量；失败时执行后续代码。它不要求穷尽，也不产生值，适合“校验后立即返回”的守卫式写法。

### 列表模式

Wikipedia 的 opensearch 接口返回顶层数组：

```json
[
  "dart",
  ["Dart (programming language)", "Dart"],
  ["", ""],
  [
    "https://en.wikipedia.org/wiki/Dart_(programming_language)",
    "https://en.wikipedia.org/wiki/Dart"
  ]
]
```

对应的解析：

```dart
factory SearchResults.fromJson(List<Object?> json) {
  final List<SearchResult> results = <SearchResult>[];
  if (json case [
    String searchTerm,
    Iterable articleTitles,
    Iterable _,
    Iterable urls,
  ]) {
    final List titlesList = articleTitles.toList();
    final List urlList = urls.toList();
    for (int i = 0; i < articleTitles.length; i++) {
      results.add(SearchResult(title: titlesList[i], url: urlList[i]));
    }
    return SearchResults(results, searchTerm: searchTerm);
  }
  throw FormatException('Could not deserialize SearchResults, json=$json');
}
```

列表模式按位置匹配，默认要求元素个数完全一致；四个元素对应四个子模式。`Iterable _` 匹配第三个数组（描述文本）并丢弃。需要匹配不定长列表时使用 rest 模式：`[first, ...rest]`。

`titlesList[i]` 的静态类型是 `dynamic`，传给 `SearchResult` 的 `String` 参数时发生隐式向下转换；实际元素不是字符串会在运行时抛 `TypeError`。更严格的写法是在循环内再次使用模式：

```dart
for (int i = 0; i < titlesList.length; i++) {
  if ((titlesList[i], urlList[i]) case (String title, String url)) {
    results.add(SearchResult(title: title, url: url));
  }
}
```

### 对象模式

搜索结果放在 `query.pages` 的 map 中，键是页面 ID，值是页面对象。遍历时可以直接解构 `MapEntry`：

```dart
static List<Article> listFromJson(Map<String, Object?> json) {
  final List<Article> articles = <Article>[];
  if (json case {'query': {'pages': final Map<String, Object?> pages}}) {
    for (final MapEntry<String, Object?>(:Object? value) in pages.entries) {
      if (value case {
        'title': final String title,
        'extract': final String extract,
      }) {
        articles.add(Article(title: title, extract: extract));
      }
    }
    return articles;
  }
  throw FormatException('Could not deserialize Article, json=$json');
}
```

`MapEntry<String, Object?>(:Object? value)` 是对象模式：要求对象是 `MapEntry<String, Object?>`，并按 getter 名 `value` 提取字段。`(:Object? value)` 同时声明类型与变量名。页面对象缺少 `extract`（例如页面不存在）时，内层模式失败，该条目被跳过，而不是让整个解析失败。

## 静态方法返回集合

构造函数只能返回单个实例，批量解析用静态方法：

```dart
class Article {
  Article({required this.title, required this.extract});

  final String title;
  final String extract;

  static List<Article> listFromJson(Map<String, Object?> json) { ... }

  Map<String, Object?> toJson() => <String, Object?>{
    'title': title,
    'extract': extract,
  };
}
```

`toJson` 返回 `Map<String, Object?>`，可直接传给 `jsonEncode`。序列化与反序列化成对出现，保证模型可以往返转换。

## 多包工作区

三个包需要共享依赖解析结果，使用 Dart workspace：

```yaml
# dartpedia/pubspec.yaml
name: _
publish_to: none

environment:
  sdk: ^3.8.1

workspace:
  - cli
  - command_runner
  - wikipedia
```

每个子包声明加入工作区：

```yaml
# cli/pubspec.yaml
name: cli
resolution: workspace
```

```yaml
# command_runner/pubspec.yaml
name: command_runner
resolution: workspace
```

```yaml
# wikipedia/pubspec.yaml
name: wikipedia
resolution: workspace
```

在根目录执行一次 `dart pub get`，所有包共享同一个 `.dart_tool/package_config.json` 与锁文件，依赖版本不会在包之间漂移。子包单独执行 `dart pub get` 会提示应到工作区根目录解析。

`wikipedia` 只作为库使用，不需要 `bin/`。用 `dart create wikipedia` 生成后删除 `bin/`，或直接使用 `dart create -t package wikipedia`。

## 解析失败的语义

模式不匹配时统一抛出 `FormatException`，并在消息中附带原始 JSON：

```dart
throw FormatException('Could not deserialize Summary, json=$json');
```

这属于“响应形状与预期不符”，是调用方可处理的异常，不是程序缺陷。附带原文便于定位是字段改名、接口变更还是测试数据过期；生产环境应注意 JSON 可能包含敏感信息，日志中不宜完整输出。

失败策略有两种：

| 策略 | 适用场景 | 行为 |
|------|----------|------|
| 整体失败 | 关键字段缺失，后续逻辑无法继续 | 抛 `FormatException` |
| 跳过无效项 | 列表中的单项损坏，其余仍可用 | 内层模式失败时跳过 |

`Summary` 与 `TitlesSet` 采用整体失败，`Article.listFromJson` 对单个页面采用跳过策略。选择依据是“缺失这一项是否影响整体语义”，而不是“尽量不报错”。

## 模式匹配与记录的边界

记录是数据结构，模式是解构手段，两者经常一起出现但概念不同：

- 记录用 `(name: value)` 创建，有固定字段与值语义；
- 模式用 `(name: pattern)` 匹配，可作用于记录、map、list、对象；
- `var (:option, :input) = record;` 是记录模式解构；
- `switch (json) { {'key': final int x} => ... }` 是 map 模式匹配。

JSON 解析主要使用 map 与 list 模式，记录更多用于函数返回值与局部多值传递。

## 工作流总结

```text
HTTP 响应体（String）
   │ jsonDecode
   ▼
Map<String, dynamic> / List<dynamic>
   │ 模式匹配校验 + 提取
   ▼
Summary / TitlesSet / Article / SearchResults
   │ toJson
   ▼
Map<String, Object?> → jsonEncode → String
```

`jsonDecode` 负责语法层解析，模式匹配负责结构层校验，模型类负责类型层表达。三层职责分开后，接口字段变化只会让对应的 `fromJson` 失败，并在异常信息中给出具体 JSON，而不是在业务逻辑深处出现难以追踪的 `null` 或类型错误。
