帮助信息由多段文本拼成：全局用法、每个命令的说明、命令下的每个选项、默认值与参数类型。拼接过程中还要插入缩进、换行与颜色转义。如果每一步都用 `+` 生成新字符串，循环内的累计复制会带来平方级开销。

输出环节还有另一个问题：库包不应该假定调用方一定要把结果打印到控制台。测试需要捕获输出，应用可能需要写入文件或加前缀。把“生成文本”和“呈现文本”分开，库只返回字符串，由调用方通过回调决定如何输出。

## 字符串不可变

Dart 的 `String` 是不可变对象。拼接、截取、替换都返回新实例，原字符串不变：

```dart
const base = 'Dart';
final result = base + 'pedia'; // 新字符串 'Dartpedia'
```

在循环中反复拼接时，每一步都要复制之前累积的内容：

```dart
var text = '';
for (var i = 0; i < 1000; i++) {
  text += 'line $i\n'; // 第 i 步复制 i 个字符
}
```

总复制量约为 `n²/2` 个字符。文本较短时差异不可见，行数上千后耗时明显上升。`StringBuffer` 用一个可增长的缓冲区累积片段，追加操作摊还 O(1)，最后一次性生成字符串。

## StringBuffer

```dart
final buffer = StringBuffer();
buffer.write('Usage: ');
buffer.writeln('dart bin/cli.dart <command>');
buffer.writeAll(['help', 'version', 'search'], ', ');
final text = buffer.toString();
```

常用成员：

| 成员 | 作用 |
|------|------|
| `write(Object?)` | 追加对象的 `toString()`，不加换行 |
| `writeln([Object?])` | 追加内容并补 `\n` |
| `writeAll(Iterable, [separator])` | 追加多个对象，可指定分隔符 |
| `clear()` | 清空缓冲区，可继续复用 |
| `length` / `isEmpty` | 当前字符数 / 是否为空 |
| `toString()` | 生成最终字符串 |

`StringBuffer` 不是 `String`，不能调用字符串方法；需要文本处理时先 `toString()`。`toString()` 可以在任意时刻调用，之后仍可继续 `write`。

`StringBuffer` 与 `List<String>.join()` 都能避免平方级复制。前者适合边计算边追加、混用 `writeln` 的场景；后者适合先收集所有片段、最后统一拼接的场景。

## 渲染帮助信息

`HelpCommand` 支持三种输出：默认的简略列表、`--verbose` 的完整说明、`--command=<name>` 的单命令详情。

```dart
@override
FutureOr<String> run(ArgResults args) async {
  final buffer = StringBuffer();
  buffer.writeln(runner.usage.titleText);

  if (args.flag('verbose')) {
    for (var cmd in runner.commands) {
      buffer.write(_renderCommandVerbose(cmd));
    }
    return buffer.toString();
  }

  if (args.hasOption('command')) {
    var (:option, :input) = args.getOption('command');

    var cmd = runner.commands.firstWhere(
      (command) => command.name == input,
      orElse: () {
        throw ArgumentException(
          'Input $input is not a known command.',
          name,
        );
      },
    );

    return _renderCommandVerbose(cmd);
  }

  for (var command in runner.commands) {
    buffer.writeln(command.usage);
  }

  return buffer.toString();
}
```

分支顺序决定了优先级：`--verbose` 先于 `--command`，同时出现时输出全部命令的详情。`args.flag('verbose')` 在选项缺失时返回 `false`，无需先判断存在性。

单命令详情由私有方法渲染：

```dart
String _renderCommandVerbose(Command cmd) {
  final indent = ' ' * 10;
  final buffer = StringBuffer();
  buffer.writeln(cmd.usage.instructionText);
  buffer.writeln('$indent ${cmd.help}');
  if (cmd.valueHelp != null) {
    buffer.writeln(
      '$indent [Argument] Required? ${cmd.requiresArgument}, '
      'Type: ${cmd.valueHelp}, Default: ${cmd.defaultValue ?? 'none'}',
    );
  }
  buffer.writeln('$indent Options:');
  for (var option in cmd.options) {
    buffer.writeln('$indent ${option.usage}');
  }
  return buffer.toString();
}
```

`' ' * 10` 依赖 `String` 的 `operator *(int)`，生成十个空格。缩进值只在此处使用，声明为局部常量即可。

`cmd.help` 是可空字段，直接插入字符串时 `null` 会显示为字面量 `"null"`。若希望省略空帮助，应显式判断：

```dart
if (cmd.help != null) {
  buffer.writeln('$indent ${cmd.help}');
}
```

`cmd.defaultValue ?? 'none'` 展示了空值合并的典型用法：有默认值时显示值，没有时显示占位文本。

## 记录解构

`getOption` 返回具名记录：

```dart
({Option option, Object? input}) getOption(String name)
```

调用处可以直接解构：

```dart
var (:option, :input) = args.getOption('command');
```

`(:option, :input)` 是记录模式，`:` 前缀是 `option: option` 的简写，表示按同名字段绑定变量。解构后 `option` 的类型是 `Option`，`input` 的类型是 `Object?`，无需通过 `result.option`、`result.input` 逐项访问。

模式匹配的完整语法与更多形态见 [[10. JSON 解析与模式匹配|JSON 与模式匹配]]。

## 输出回调

`CommandRunner` 不再直接 `print`，而是把输出交给可选回调：

```dart
class CommandRunner {
  CommandRunner({this.onOutput, this.onError});

  /// If not null, this method is used to handle output.
  FutureOr<void> Function(String)? onOutput;

  FutureOr<void> Function(Object)? onError;

  Future<void> run(List<String> input) async {
    try {
      final ArgResults results = parse(input);
      if (results.command != null) {
        Object? output = await results.command!.run(results);
        if (onOutput != null) {
          await onOutput!(output.toString());
        } else {
          print(output.toString());
        }
      }
    } on Exception catch (exception) {
      if (onError != null) {
        onError!(exception);
      } else {
        rethrow;
      }
    }
  }
}
```

回调类型 `FutureOr<void> Function(String)?` 的含义：

| 片段 | 含义 |
|------|------|
| `Function(String)` | 接受一个字符串参数 |
| `FutureOr<void>` | 返回 `void` 或 `Future<void>` |
| `?` | 回调本身可以为 `null` |

调用处 `await onOutput!(...)` 同时支持同步与异步实现：同步实现直接返回，异步实现返回 Future，`await` 统一等待完成。若回调耗时较长，`run` 会等到输出结束才返回。

回调为空时回退到 `print`，保证库在没有配置输出方式时仍可独立运行。这种“可选注入 + 默认实现”的模式比强制传入回调更易用。

## 逐行输出

应用层可以实现带延迟的逐行打印：

```dart
Future<void> write(String text, {int duration = 50}) async {
  final List<String> lines = text.split('\n');
  for (final String line in lines) {
    await _delayedPrint('$line \n', duration: duration);
  }
}

Future<void> _delayedPrint(String text, {int duration = 0}) {
  return Future<void>.delayed(
    Duration(milliseconds: duration),
    () => stdout.write(text),
  );
}
```

`Future.delayed` 在指定时长后执行回调，返回在该时刻完成的 Future。循环中 `await` 每一次输出，保证行序与数组顺序一致；若去掉 `await`，所有定时器同时启动，输出顺序取决于延迟与调度，文本会交错。

`stdout.write` 不追加换行，因此字符串里显式写了 `' \n'`。行尾多出的空格在终端中不可见，但会进入重定向后的文件，若用于管道输出应去掉。

`duration` 是每行之间的间隔，总耗时约为 `行数 × duration`。行数较多时 50ms 的默认值会显著拖慢输出，实际使用应按场景调整或设为 0。

## 计算与呈现分离

回调机制带来三个直接收益：

1. **可测试性**：测试传入收集字符串的回调，断言输出内容，无需拦截进程的标准输出。
2. **可替换性**：同一个运行器可以输出到控制台、日志文件或网络，库代码不变。
3. **职责清晰**：命令只负责计算结果，运行器只负责调度，应用决定呈现方式。

代价是调用链多了一层间接：排查输出问题时需要确认回调是否为空、是否异步、是否抛异常。回调内的异常会传播回 `run`，可能被 `onError` 捕获，形成“输出失败被当作命令失败”的耦合；对输出可靠性要求高的场景，应在回调内部自行处理 I/O 异常。

## 性能边界

- `StringBuffer` 适合大量小片段追加；一次性已知全部内容时，`List.join` 更直接。
- 不要在循环中反复调用 `buffer.toString()`，每次都会复制当前全部内容。
- `writeln` 统一使用 `\n`，在 Windows 上不会自动转换为 `\r\n`；需要平台换行时使用 `Platform.lineTerminator`。
- 颜色转义序列会增加字符串长度，但不影响显示宽度；按宽度换行时不能把转义序列计入字符数。
