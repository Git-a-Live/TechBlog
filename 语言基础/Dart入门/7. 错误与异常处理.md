命令行工具的输入不可控：用户可能敲错命令、漏掉选项值、一次传两个命令，网络也可能超时或返回 500。这些情况属于“可预期的失败”，程序应当给出可读提示并继续或干净退出，而不是打印一屏堆栈。

与之相对，数组越界、对 `null` 调用方法、类型转换失败属于程序缺陷。它们应当在开发阶段被修复，而不是在生产环境被捕获后静默吞掉。

Dart 用 `Exception` 与 `Error` 两条继承线区分这两类失败，用 `try`/`on`/`catch`/`finally` 控制处理范围，用 `throw` 与 `rethrow` 控制传播方式。

## 两类失败

| 维度 | `Exception` | `Error` |
|------|-------------|---------|
| 含义 | 可预期的运行时失败 | 代码中的缺陷或违反契约 |
| 能否恢复 | 通常可以 | 不应恢复，应修复代码 |
| 典型子类 | `FormatException`、`HttpException`、`SocketException`、`TimeoutException` | `RangeError`、`TypeError`、`StateError`、`ArgumentError` |
| 典型原因 | 用户输入非法、网络中断、文件缺失 | 索引越界、空值调用、类型不匹配 |
| 处理策略 | 捕获、提示、降级或退出 | 任其传播，保留堆栈以便定位 |

`Exception` 与 `Error` 都直接继承 `Object`，二者没有继承关系。`Exception` 是一个抽象接口，本身不携带字段；具体异常类自行定义 `message`、`source` 等成员。

```dart
try {
  final value = int.parse('abc');
} on FormatException catch (e) {
  print('输入不是整数: ${e.message}');
}
```

`int.parse` 在无法解析时抛 `FormatException`，属于用户输入问题，可以被捕获后转换为友好提示。

```dart
final list = <int>[];
// list[3]; // RangeError: 索引越界，属于程序缺陷
```

`RangeError` 表示调用方违反了“索引必须有效”的前提。捕获它只会掩盖真正的逻辑错误。

## throw

`throw` 接受任意非空对象，惯用法是抛出 `Exception` 或 `Error` 的子类：

```dart
throw ArgumentException(
  'The first word of input must be a command.',
  null,
  input.first,
);
```

抛出时运行时记录当前堆栈，异常沿调用栈向上传播，直到遇到匹配的 `catch` 或到达顶层。抛出字符串（`throw 'error'`）在语法上合法，但调用方无法用 `on` 按类型捕获，也拿不到结构化字段，不应使用。

## try / on / catch / finally

```dart
try {
  final results = parse(input);
  await results.command!.run(results);
} on ArgumentException catch (e) {
  print('参数错误: ${e.message}');
} on FormatException catch (e, stackTrace) {
  print('格式错误: ${e.message}');
  print(stackTrace);
} on Exception catch (e) {
  print('其他异常: $e');
} finally {
  print('done');
}
```

各子句的语义：

| 子句 | 作用 |
|------|------|
| `on Type` | 只捕获该类型及其子类型，不绑定变量 |
| `on Type catch (e)` | 捕获并绑定异常对象 |
| `on Type catch (e, st)` | 同时绑定堆栈跟踪 |
| `catch (e)` | 捕获所有被抛出的对象，包括 `Error` |
| `finally` | 无论成功、失败还是提前 `return` 都执行 |

`on` 子句按书写顺序匹配，范围窄的类型放在前面。`on Exception` 只捕获 `Exception` 子类型，`Error` 会继续向上传播，这是库代码通常希望的行为：

```dart
try {
  throw StateError('bug');
} on Exception {
  print('不会执行');
}
```

裸 `catch` 会连 `Error` 一起吞掉，使程序在状态不一致的情况下继续运行，通常只在顶层日志记录处使用，并且记录后应重新抛出。

`finally` 适合释放资源（关闭文件、取消订阅）。若 `finally` 中执行 `return`，它会覆盖 `try` 中的返回值与异常，这种写法应避免。

## rethrow

`catch` 块中重新抛出时，`rethrow` 保留原始堆栈，`throw e` 会把堆栈重置到当前行：

```dart
try {
  await command.run(results);
} on Exception catch (e) {
  logger.warning(e);
  rethrow; // 堆栈仍指向最初抛出处
}
```

```dart
} on Exception catch (e) {
  throw e; // 堆栈从这一行开始，原始位置丢失
}
```

需要在上报或记录后继续传播时使用 `rethrow`；需要改变异常类型时，才用 `throw` 构造新异常，并通过 `Error.throwWithStackTrace` 保留原堆栈（高级用法）。

## 自定义异常

`ArgumentException` 表示命令行参数不合法，继承 `FormatException`：

```dart
class ArgumentException extends FormatException {
  /// The command that was parsed before discovering the error.
  ///
  /// This will be empty if the error was on the root parser.
  final String? command;

  /// The name of the argument that was being parsed when the error was
  /// discovered.
  final String? argumentName;

  ArgumentException(
    super.message, [
    this.command,
    this.argumentName,
    super.source,
    super.offset,
  ]);

  @override
  String toString() {
    return 'ArgumentException: $message';
  }
}
```

这里的 `super.message`、`super.source`、`super.offset` 是超参数（super parameter）：把构造参数直接转发给父类构造函数，省去初始化列表。父类 `FormatException` 的签名为：

```dart
const FormatException([this.message = "", this.source, this.offset]);
```

`message` 是描述，`source` 是导致错误的原始输入，`offset` 是出错位置。子类把 `command` 与 `argumentName` 作为可选位置参数追加，既保留父类能力，又携带解析上下文。

自定义异常的价值：

- 调用方可以用 `on ArgumentException` 精确捕获，不会误伤其他 `FormatException`。
- 异常对象携带结构化字段，日志与提示可以引用具体命令与参数名。
- `toString` 统一输出格式，顶层打印时无需额外拼接。

异常类应保持不可变，字段声明为 `final`；不要在异常中执行 I/O 或复杂计算，构造函数应尽可能简单。

## 解析器中的校验

参数解析需要在多个位置拒绝非法输入：

```dart
ArgResults parse(List<String> input) {
  ArgResults results = ArgResults();
  if (input.isEmpty) return results;

  if (_commands.containsKey(input.first)) {
    results.command = _commands[input.first];
    input = input.sublist(1);
  } else {
    throw ArgumentException(
      'The first word of input must be a command.',
      null,
      input.first,
    );
  }

  if (results.command != null &&
      input.isNotEmpty &&
      _commands.containsKey(input.first)) {
    throw ArgumentException(
      'Input can only contain one command. '
      'Got ${input.first} and ${results.command!.name}',
      null,
      input.first,
    );
  }
  // ...
}
```

选项解析部分同样逐项校验：

```dart
var option = results.command!.options.firstWhere(
  (option) => option.name == base || option.abbr == base,
  orElse: () {
    throw ArgumentException(
      'Unknown option ${input[i]}',
      results.command!.name,
      input[i],
    );
  },
);
```

`firstWhere` 在没有匹配项且未提供 `orElse` 时抛 `StateError`，那是“调用方假设一定存在”的缺陷信号；这里提供 `orElse` 并抛出 `ArgumentException`，把“用户输入未知选项”转换为可恢复的异常。

需要覆盖的非法情况：

| 情况 | 判定 | 异常信息 |
|------|------|----------|
| 未知命令 | 首参数不在命令表中 | 首词必须是命令 |
| 多个命令 | 命令之后又出现命令名 | 只能包含一个命令 |
| 未知选项 | `-`/`--` 前缀但不在选项表中 | 未知选项 |
| 选项缺值 | 选项后无参数，或紧跟另一个选项 | 选项需要参数 |
| 位置参数过多 | 已有 `commandArg` 又出现非选项参数 | 最多一个位置参数 |

选项值出现在末尾或紧跟另一个 `-` 开头参数时，无法区分“值是负数”与“缺少值”。当前实现选择把后者视为缺值，这是命令行解析的常见取舍；需要支持负数时，应使用 `--` 分隔符或 `--option=-1` 形式。

## 应用层的错误策略

库负责抛出带类型的异常，应用负责决定如何呈现。`CommandRunner` 接受一个可选回调：

```dart
class CommandRunner {
  CommandRunner({this.onError});

  FutureOr<void> Function(Object)? onError;

  Future<void> run(List<String> input) async {
    try {
      final ArgResults results = parse(input);
      if (results.command != null) {
        Object? output = await results.command!.run(results);
        print(output.toString());
      }
    } on Exception catch (exception) {
      if (onError != null) {
        onError!(exception);
      } else {
        rethrow;
      }
    }
  }
}
```

`FutureOr<void> Function(Object)?` 表示“接受一个 `Object`、返回 `void` 或 `Future<void>` 的可空函数”。回调为空时重新抛出，把处理权交还给调用方。

应用入口区分两类失败：

```dart
void main(List<String> arguments) {
  var commandRunner = CommandRunner(
    onError: (Object error) {
      if (error is Error) {
        throw error;
      }
      if (error is Exception) {
        print(error);
      }
    },
  )..addCommand(HelpCommand());

  commandRunner.run(arguments);
}
```

`Error` 被重新抛出，保留堆栈并让进程以非零状态退出；`Exception` 打印后继续。这个策略把“程序 bug”和“用户输入错误”明确分开，避免用同一套提示掩盖问题。

## 堆栈跟踪

异常对象的 `toString()` 只包含消息，堆栈需要显式获取：

```dart
try {
  await run();
} catch (e, st) {
  print(e);
  print(st);
}
```

`StackTrace` 的文本格式依赖运行模式：JIT 下包含源码文件与行号，AOT 下为编译后的符号。日志系统应同时记录异常与堆栈，见 [[13. 日志与依赖注入|日志]]。

## 设计原则

- 库代码只抛 `Exception` 子类，不抛裸字符串；`Error` 留给类型系统与断言。
- 捕获范围尽量窄，`on Exception` 优于裸 `catch`；捕获后要么处理，要么 `rethrow`。
- 异常类型承载语义，消息承载上下文：类型给机器判断，消息给人阅读。
- 不在 `finally` 中 `return`，不在 `catch` 中吞掉异常后继续执行依赖该结果的逻辑。
- 顶层统一处理未捕获异常，记录日志并返回非零退出码。

异常机制把“正常路径”与“失败路径”分开，使调用方必须显式面对失败。下一节转向另一种扩展方式：增强枚举为枚举成员附加数据与行为，扩展方法在不修改原类型的前提下增加能力，见 [[8. 增强枚举与扩展方法|增强枚举与扩展方法]]。
