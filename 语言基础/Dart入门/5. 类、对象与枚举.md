命令行参数在内存中需要一种结构化表示：一个选项有名称、类型、缩写、帮助文本与默认值；一次解析结果有命令名、位置参数与若干选项值。用零散的字符串和 `Map` 传递这些数据，编译器无法检查拼写错误，编辑器也无法补全字段。

类把状态（字段）与行为（方法、getter）绑定在同一个类型下，枚举把取值范围收敛到固定的几个成员，记录则为“临时组合几个值”提供轻量结构。三者配合，可以把命令行的语法结构直接映射为类型。

## 类与对象

类是对象的蓝图，对象是类的实例。Dart 中创建实例可以省略 `new`：

```dart
final verbose = Option('verbose', type: OptionType.flag);
```

`Option` 的职责是描述一个命令行选项。最简形态只包含名称与类型：

```dart
class Option {
  Option(this.name, {required this.type});

  final String name;
  final OptionType type;
}
```

字段声明在类体内，构造函数负责初始化。`final` 字段只能赋值一次，赋值位置限于声明处、初始化列表或构造函数的初始化形参。

## 构造函数

Dart 的构造函数有多种形式，常用的是初始化形参（initializing formal）与命名参数。

```dart
class Option {
  Option(
    this.name, {
    required this.type,
    this.help,
    this.abbr,
    this.defaultValue,
    this.valueHelp,
  });

  final String name;
  final OptionType type;
  final String? help;
  final String? abbr;
  final Object? defaultValue;
  final String? valueHelp;
}
```

`this.name` 是初始化形参：它把传入的实参直接赋给同名字段，省去 `name = name` 的样板代码。初始化形参在构造函数体执行之前完成赋值，因此即使字段是 `final` 也能使用。

参数列表的三种形式：

| 语法 | 形式 | 是否必填 |
|------|------|----------|
| `String name` | 位置参数 | 必填 |
| `[String? abbr]` | 可选位置参数 | 可选，必须位于末尾 |
| `{required String name}` | 命名参数 | 必填 |
| `{String? help}` | 命名参数 | 可选，默认 `null` |

命名参数用花括号包裹，调用时必须写出参数名，顺序无关：

```dart
final option = Option(
  'verbose',
  type: OptionType.flag,
  abbr: 'v',
  help: 'Display extra logging information.',
);
```

可空字段（`String?`、`Object?`）在调用方省略时默认为 `null`。`Object?` 在这里用于容纳两种不同的默认值：标志位的默认值是 `bool`，普通选项的默认值是 `String`，统一用 `Object?` 表达。

类没有声明任何构造函数时，编译器提供无参默认构造函数；一旦声明了构造函数，默认构造函数不再生成。构造函数不会被继承，子类需要自行声明并调用 `super`，见 [[6. 继承、抽象类与封装|继承与抽象类]]。

## 字段与 Getter

字段保存状态，getter 在访问时计算值。`usage` 不需要存储，每次读取时根据 `abbr` 是否存在拼接：

```dart
String get usage {
  if (abbr != null) {
    return '-$abbr,--$name: $help';
  }

  return '--$name: $help';
}
```

调用方把它当作属性使用，不写括号：

```dart
print(verboseOption.usage);
```

getter 与字段的区别：

| 维度 | 字段 | getter |
|------|------|--------|
| 存储 | 占用对象空间 | 不存储，按需计算 |
| 一致性 | 值可能过期 | 始终反映当前字段状态 |
| 可写性 | 取决于是否 `final` | 只读，除非同时定义 setter |
| 代价 | 读取为字段访问 | 每次访问执行方法体 |

只读计算属性适合用 getter；需要缓存或计算代价很高时，才考虑在构造时算好存入 `final` 字段。getter 内不应有副作用，否则调用方无法从语法上分辨它与普通字段读取。

## 枚举

选项只有两种类型：不带值的标志位，和需要接收值的普通选项。用枚举把取值范围固定下来：

```dart
enum OptionType { flag, option }
```

枚举成员是编译期常量，类型系统只接受这两个值：

```dart
final type = OptionType.flag;
// final invalid = OptionType.positional; // 编译错误
```

枚举的常用成员：

| 成员 | 说明 |
|------|------|
| `values` | 所有成员的常量列表，顺序与声明一致 |
| `name` | 成员名称字符串，如 `'flag'` |
| `index` | 声明顺序的零基索引 |
| `byName(String)` | 按名称查找，找不到抛 `ArgumentError` |

在 `switch` 上使用枚举时，编译器会检查是否覆盖全部成员；缺少分支且没有 `default` 会报错，这就是穷尽性检查。相比用 `int` 或 `String` 表示类型，枚举把非法值排除在类型之外。

基础枚举只能表示“有哪几个值”。需要给每个成员附带数据或行为时，使用增强枚举，见 [[8. 增强枚举与扩展方法|增强枚举与扩展]]。

## 记录

解析结果需要同时返回“命中的选项”和“用户输入的值”。为此单独定义一个类显得笨重，记录（record）提供了匿名的结构化组合：

```dart
({Option option, Object? input}) getOption(String name) {
  final mapEntry = options.entries.firstWhere(
    (entry) => entry.key.name == name || entry.key.abbr == name,
  );

  return (option: mapEntry.key, input: mapEntry.value);
}
```

`({Option option, Object? input})` 是具名记录类型：两个字段分别叫 `option` 与 `input`，类型为 `Option` 与 `Object?`。记录字面量用括号加字段名构造，访问时使用属性语法：

```dart
final result = results.getOption('command');
print(result.option.name);
print(result.input);
```

记录的特征：

- 结构类型：字段名称与类型构成类型本身，不需要预先声明类。
- 不可变：字段隐式为 `final`，创建后不能修改。
- 值语义：两个记录的所有字段相等时，`==` 为真，`hashCode` 也一致。
- 不能定义方法、getter 或构造函数，只承载数据。

记录适合函数内部或短生命周期的多值返回；需要行为、校验或对外 API 时，仍应定义类。记录也支持解构，`final (:option, :input) = result;` 会按字段名提取变量，详见 [[10. JSON 解析与模式匹配|模式匹配]]。

## 用集合建模解析结果

`ArgResults` 保存一次解析的完整结果：

```dart
class ArgResults {
  String? command;
  String? commandArg;
  Map<Option, Object?> options = {};

  bool flag(String name) {
    for (var option in options.keys.where(
      (option) => option.type == OptionType.flag,
    )) {
      if (option.name == name) {
        return options[option] as bool;
      }
    }
    return false;
  }

  bool hasOption(String name) {
    return options.keys.any((option) => option.name == name);
  }

  ({Option option, Object? input}) getOption(String name) {
    final mapEntry = options.entries.firstWhere(
      (entry) => entry.key.name == name || entry.key.abbr == name,
    );

    return (option: mapEntry.key, input: mapEntry.value);
  }
}
```

`Map<Option, Object?>` 以 `Option` 实例为键，避免用名称字符串做键时的拼写错误与重名冲突。Dart 的 `Map` 字面量默认是插入有序的 `LinkedHashMap`，遍历顺序与插入顺序一致。

集合查询的语义：

| 调用 | 返回 | 无匹配时 |
|------|------|----------|
| `keys.where(predicate)` | 惰性 `Iterable` | 空 `Iterable` |
| `keys.any(predicate)` | `bool` | `false` |
| `entries.firstWhere(predicate)` | 首个匹配项 | 抛 `StateError` |
| `entries.firstWhere(predicate, orElse: ...)` | 首个匹配项或兜底值 | 由 `orElse` 决定 |

`flag()` 先用 `where` 过滤出标志位，再按名称匹配，最后用 `as bool` 转型。`as` 是运行时检查：值不是 `bool` 时抛 `TypeError`。这里的前提是标志位在写入时已保证为 `bool`，转型只是把 `Object?` 收窄回具体类型。

`getOption()` 没有提供 `orElse`，名称不存在时抛 `StateError`。这类“调用方保证存在”的契约适合内部使用；对外的帮助命令应先判断 `hasOption`，或在 `orElse` 中抛出带上下文的异常。

## 模型的职责边界

`Option` 描述“选项是什么”，`ArgResults` 描述“这次解析得到了什么”，两者都不负责解析本身。解析算法放在 `CommandRunner` 中，输出格式化放在命令的 `run` 方法中。这种划分让数据模型可以独立测试，也避免模型随解析策略变化而频繁修改。

模型字段的可变性与职责对应：

- `Option` 的字段全部 `final`：选项定义在构造后不再变化。
- `ArgResults` 的 `command`、`commandArg`、`options` 可变：解析过程逐项填充。
- 计算属性（`usage`）用 getter，派生数据不重复存储。

类、构造函数、getter、枚举与记录共同构成了类型化的命令行模型。下一节引入抽象类与继承，把这些模型组织成可扩展的层次，并用封装限制外部对内部集合的修改，见 [[6. 继承、抽象类与封装|继承、抽象类与封装]]。
