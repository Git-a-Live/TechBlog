选项（`--verbose`）与命令（`help`）共享一组特征：都有名称、帮助文本、默认值与用法说明；区别在于命令还能执行逻辑，并且可以拥有自己的选项。如果为两者各自重复声明这些字段，修改一处就要同步修改多处，类型系统也无法用统一的方式处理它们。

继承把共同部分上移到父类，抽象类把“必须由子类提供的能力”写成契约，封装则限制外部直接修改内部集合。三者共同构成一个可扩展的命令框架：新增命令只需继承 `Command`，运行器通过父类接口统一调度。

## 类层次

```text
        ┌──────────────────────┐
        │  CliElement          │  抽象：所有 CLI 元素的共同契约
        │  name / help / usage │
        └──────────┬───────────┘
                   │ extends
        ┌──────────┴───────────┐
        ▼                      ▼
┌───────────────┐     ┌──────────────────────┐
│  Option       │     │  Command             │  抽象：可执行命令
│  type / abbr  │     │  description / run   │
└───────────────┘     └──────────┬───────────┘
                                 │ extends
                                 ▼
                      ┌──────────────────────┐
                      │  HelpCommand         │  可实例化
                      └──────────────────────┘
```

`Option` 与 `Command` 都继承 `CliElement`，因此都可以被当作 `CliElement` 处理；`HelpCommand` 继承 `Command`，必须实现 `run`。

## 抽象类

抽象类用 `abstract` 修饰，不能直接实例化：

```dart
abstract class CliElement {
  String get name;
  String? get help;
  Object? get defaultValue;
  String? get valueHelp;

  String get usage;
}
```

`CliElement()` 是编译错误。抽象类的作用是定义子类必须满足的接口：没有方法体的 getter 是抽象成员，子类必须提供实现。抽象类也可以包含已实现的成员、字段与构造函数，供子类复用。

抽象类与接口的差别：

| 方式 | 关键字 | 继承实现 | 可声明状态 | 多继承 |
|------|--------|----------|------------|--------|
| 继承 | `extends` | 是 | 是 | 否，单继承 |
| 实现接口 | `implements` | 否，必须全部重写 | 否 | 可多实现 |
| 混入 | `with` | 是，可复用方法 | 通常无 | 可多个 |

Dart 中每个类都隐式定义了一个接口，`implements` 只要求签名一致，不继承任何实现。`extends` 则同时继承接口与实现。

## 继承与重写

`Option` 继承 `CliElement`，用 `@override` 标注实现：

```dart
class Option extends CliElement {
  Option(
    this.name, {
    required this.type,
    this.help,
    this.abbr,
    this.defaultValue,
    this.valueHelp,
  });

  @override
  final String name;

  final OptionType type;

  @override
  final String? help;

  final String? abbr;

  @override
  final Object? defaultValue;

  @override
  final String? valueHelp;

  @override
  String get usage {
    if (abbr != null) {
      return '-$abbr,--$name: $help';
    }

    return '--$name: $help';
  }
}
```

Dart 的字段隐式生成同名 getter，因此 `final String name;` 自动满足父类的 `String get name;`，不需要额外写方法。`@override` 本身不改变语义，但能让分析器检查“确实存在被重写的成员”，拼错名称时给出警告。

`Command` 同样继承 `CliElement`，并新增命令特有的契约：

```dart
abstract class Command extends CliElement {
  @override
  String get name;

  String get description;

  bool get requiresArgument => false;

  late CommandRunner runner;

  @override
  String? help;

  @override
  String? defaultValue;

  @override
  String? valueHelp;

  FutureOr<Object?> run(ArgResults args);

  @override
  String get usage => '$name:  $description';
}
```

`requiresArgument` 提供了默认实现 `false`，子类只在需要时重写；`run` 没有默认实现，所有具体命令都必须实现。`help`、`defaultValue`、`valueHelp` 声明为可写字段，既满足父类 getter，又允许子类在构造后赋值。

子类构造时默认调用父类的无参构造函数；父类没有无参构造函数时，必须显式调用：

```dart
class VerboseOption extends Option {
  VerboseOption() : super('verbose', type: OptionType.flag);
}
```

## 多态

运行器只依赖 `Command`，不关心具体是哪个命令：

```dart
class CommandRunner {
  final Map<String, Command> _commands = <String, Command>{};

  void addCommand(Command command) {
    _commands[command.name] = command;
    command.runner = this;
  }

  Future<void> run(List<String> input) async {
    final ArgResults results = parse(input);
    if (results.command != null) {
      Object? output = await results.command!.run(results);
      print(output.toString());
    }
  }
}
```

`_commands` 的值类型是 `Command`，可以存放 `HelpCommand`、后续的 `SearchCommand`、`GetArticleCommand`。调用 `run` 时由运行时类型决定执行哪个实现，这就是动态分派。新增命令不需要修改 `CommandRunner`，只需注册。

`HelpCommand` 的实现：

```dart
class HelpCommand extends Command {
  HelpCommand() {
    addFlag(
      'verbose',
      abbr: 'v',
      help: 'When true, prints each command and its options.',
    );
    addOption(
      'command',
      abbr: 'c',
      help: 'Prints verbose usage for the specified command.',
    );
  }

  @override
  String get name => 'help';

  @override
  String get description => 'Prints usage information to the command line.';

  @override
  String? get help => 'Prints this usage information';

  @override
  FutureOr<Object?> run(ArgResults args) async {
    var usage = runner.usage;
    for (var command in runner.commands) {
      usage += '\n ${command.usage}';
    }
    return usage;
  }
}
```

构造函数调用继承自 `Command` 的 `addFlag` 与 `addOption`，把选项注册到内部列表。`run` 通过 `runner` 访问运行器的命令集合，这与 [[4. 包与库的组织|包]] 中的依赖方向一致：命令依赖运行器的抽象能力，运行器不依赖具体命令。

## 封装

`Command` 把选项存放在私有列表中，只暴露只读视图：

```dart
final List<Option> _options = [];

UnmodifiableSetView<Option> get options =>
    UnmodifiableSetView(_options.toSet());
```

下划线前缀使 `_options` 仅在声明它的库内可见。外部代码即使拿到 `Command` 实例，也无法调用 `_options.add(...)`，只能通过 `addFlag`、`addOption` 注册，或读取 `options`。

`UnmodifiableSetView` 来自 `dart:collection`，包装一个集合并禁止修改操作；`add`、`remove`、`clear` 会抛 `UnsupportedError`。这里先调用 `toSet()` 生成快照，因此视图反映的是读取时刻的内容，后续再注册的选项不会出现在旧视图中。若需要实时视图，应包装底层集合本身，而不是副本。

同样的手法用于运行器的命令表：

```dart
final Map<String, Command> _commands = <String, Command>{};

UnmodifiableSetView<Command> get commands =>
    UnmodifiableSetView<Command>(<Command>{..._commands.values});
```

`...` 是展开运算符，把 `_commands.values` 的每个元素放入新的集合字面量。复制一份再包装，可以防止调用方通过视图修改内部 `Map`；代价是每次访问都创建新集合。

封装的收益不只是“防止误改”，还包括保留修改入口：所有选项都必须经过 `addFlag`/`addOption`，这两个方法可以统一设置 `type`、`defaultValue`，未来加入校验或去重时也只需改一处。

Dart 的私有性是库级而非类级：同一库中的其他类可以访问 `_options`，不同库即使同包也不能。把需要隐藏的状态与操作它的方法放在同一个库中，是封装能够成立的前提。

## late 字段

`Command` 需要引用执行它的运行器，但命令在构造时尚未注册：

```dart
late CommandRunner runner;
```

`late` 表示“非空，但赋值推迟到首次读取之前”。注册时由运行器写入：

```dart
void addCommand(Command command) {
  _commands[command.name] = command;
  command.runner = this;
}
```

在赋值之前读取 `runner` 会抛 `LateInitializationError`，因此 `late` 不是“绕过空安全”，而是把初始化责任交给调用方，并在违反契约时给出明确错误。相比声明为 `CommandRunner?` 再到处写 `!`，`late` 让类型保持非空，使用处无需重复断言。

`late` 还有另一种用法：带初始化表达式的 `late final` 字段在首次读取时求值，适合昂贵且可能不被使用的对象。

## 空断言与级联

`run` 中先判断命令是否存在，再调用：

```dart
if (results.command != null) {
  Object? output = await results.command!.run(results);
  print(output.toString());
}
```

流分析无法跨语句跟踪字段的可空性（字段可能被其他方法修改），因此需要 `!` 明确断言。若省略判断直接使用 `!`，未知命令会在运行时抛错；第 7 节会把这里改为抛出带上下文的 `ArgumentException`。

应用入口使用级联运算符连续调用：

```dart
void main(List<String> arguments) {
  var commandRunner = CommandRunner()..addCommand(HelpCommand());
  commandRunner.run(arguments);
}
```

`..` 在同一个对象上连续调用方法，并返回对象本身，省去重复写变量名。它与 `.` 的区别是：`..` 的表达式值是接收者，`.` 的表达式值是方法返回值。

## FutureOr

`Command.run` 的返回类型是 `FutureOr<Object?>`：

```dart
FutureOr<Object?> run(ArgResults args);
```

`FutureOr<T>` 表示“要么是 `T`，要么是 `Future<T>`”。同步命令可以直接返回字符串，异步命令可以返回 `Future<String>`，运行器统一 `await`：

```dart
Object? output = await results.command!.run(results);
```

`await` 对非 Future 值直接返回该值，因此两种实现可以共用同一段调度代码。这比强制所有命令都声明 `Future` 更灵活，也避免了为纯计算命令引入不必要的异步开销。

## 框架的运行流程

```text
main
 └─► CommandRunner.run(arguments)
      ├─► parse(arguments)          解析出 Command 与 ArgResults
      ├─► command.run(results)      多态调用具体命令
      │    └─► 访问 runner / options
      └─► print(output)
```

`parse` 目前只识别命令名，选项解析与校验留到错误处理一节；`run` 目前只打印结果，输出格式化留到 CLI 打磨一节。需要注意，`parse` 直接访问 `input.first`，空输入会抛 `StateError`，这一边界在第 7 节加入空列表判断后修复。框架已经具备扩展点：新增命令实现 `Command`，新增选项调用 `addFlag`/`addOption`，运行器代码不变。

继承解决“共享什么”，抽象类解决“必须实现什么”，封装解决“谁可以修改”。下一节处理失败路径：当输入不合法、选项缺失或命令不存在时，框架需要区分可恢复的异常与程序缺陷，并给出可读的错误信息，见 [[7. 错误与异常处理|错误与异常处理]]。
