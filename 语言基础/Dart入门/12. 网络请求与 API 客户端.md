把 `http.get` 直接写在命令的 `run` 方法里，短期可以工作，但网络细节会渗透到业务逻辑：URL 拼接、状态码判断、JSON 解码、错误提示混在一起，测试需要真实网络，复用也无从谈起。

更合理的结构是单独一层 API 客户端：它只负责“构造请求、检查响应、返回类型化模型”，命令只负责“取参数、调用客户端、格式化输出”。客户端位于 `wikipedia` 包，`cli` 通过包依赖使用它。

## 分层与依赖方向

```text
cli（命令、参数、输出）
 │  依赖
 ▼
wikipedia（API 函数 + 数据模型）
 │  依赖
 ▼
package:http（传输）
```

`cli` 不直接接触 `http`，也不关心 JSON 的字段名；`wikipedia` 不关心命令如何解析参数、如何着色输出。依赖方向单一，任何一层都可以独立替换或测试。

## 依赖声明

```yaml
# wikipedia/pubspec.yaml
dependencies:
  http: ^1.3.0
```

```bash
cd wikipedia
dart pub get
```

`http` 是纯 Dart 包，不依赖 Flutter，可在 CLI、服务端与 Flutter 中通用。它提供顶层函数 `get`、`post`，也提供可复用的 `Client` 接口。

## 构造 URI

`Uri.https` 的签名：

```dart
Uri.https(
  String authority,
  String unencodedPath, [
  Map<String, dynamic>? queryParameters,
])
```

三个参数分别对应主机、路径与查询参数：

```dart
final Uri url = Uri.https(
  'en.wikipedia.org',
  '/api/rest_v1/page/summary/$articleTitle',
);
```

`authority` 可以包含端口（`example.com:8443`），不能包含协议；`https` 已确定协议。路径中的非法字符会被百分号编码，查询参数由第三个参数统一编码。

直接拼接路径适合标题中不含 `/`、`?`、`#` 的情况。标题含斜杠时，路径分段会改变：

```dart
// 标题 "AC/DC" 会生成 /summary/AC/DC，服务端按两段解析
final url = Uri.https('en.wikipedia.org', '/summary/$title');
```

需要把标题作为单个路径段时，先编码：

```dart
final encoded = Uri.encodeComponent(title);
final url = Uri.https('en.wikipedia.org', '/summary/$encoded');
```

`Uri.encodeComponent` 把 `/` 编码为 `%2F`，但是否被服务端正确还原取决于路由实现；更稳妥的做法是把标题放进查询参数，由服务端按参数名读取。

## 查询参数

```dart
final Uri url = Uri.https(
  'en.wikipedia.org',
  '/w/api.php',
  <String, Object?>{
    'action': 'opensearch',
    'format': 'json',
    'search': searchTerm,
  },
);
```

生成的 URL 形如：

```text
https://en.wikipedia.org/w/api.php?action=opensearch&format=json&search=Dart+Programming
```

`Uri.https` 会处理：

- 键值对的 `&` 与 `=` 连接；
- 空格编码为 `+` 或 `%20`；
- 非 ASCII 字符按 UTF-8 百分号编码；
- 重复键（值为 `Iterable`）展开为多个同名参数。

查询参数的顺序通常不影响语义，但 MediaWiki 的 Action API 对某些参数有顺序要求。教程中的 `getArticleByTitle` 把 `explaintext` 放在 `prop` 之后，注释明确标注“order matters”，这是接口实现的特例，不是 HTTP 规范要求。

## 状态码与异常

`http.get` 在收到任何 HTTP 响应时都正常完成，包括 404 与 500：

```dart
final http.Response response = await http.get(url);

if (response.statusCode == 200) {
  // 处理响应体
} else {
  throw HttpException(
    '[WikipediaApiClient.getRandomArticleSummary] '
    'statusCode=${response.statusCode}, body=${response.body}',
  );
}
```

状态码分类：

| 范围 | 含义 | 客户端处理 |
|------|------|------------|
| 200–299 | 成功 | 解析响应体 |
| 300–399 | 重定向 | `http` 默认跟随，最终状态码通常为 2xx 或 4xx |
| 400–499 | 客户端错误 | 参数或路径有误，不应重试 |
| 500–599 | 服务端错误 | 可有限重试，需退避 |

`HttpException` 来自 `dart:io`，构造时可附带 `uri`：

```dart
throw HttpException(
  '[WikipediaApiClient.search] statusCode=${response.statusCode}',
  uri: url,
);
```

它属于 `IOException` 家族，调用方可以用 `on HttpException` 精确捕获，也可以用 `on IOException` 覆盖文件、套接字等 I/O 失败。

错误信息包含函数名、状态码与响应体，便于定位；生产环境应限制响应体长度，避免日志被大段 HTML 错误页淹没。

## 返回类型化模型

三个函数覆盖三种响应形状。

### 摘要

```dart
Future<Summary> getRandomArticleSummary() async {
  final Uri url = Uri.https(
    'en.wikipedia.org',
    '/api/rest_v1/page/random/summary',
  );
  final http.Response response = await http.get(url);
  if (response.statusCode == 200) {
    final Map<String, Object?> jsonData =
        jsonDecode(response.body) as Map<String, Object?>;
    return Summary.fromJson(jsonData);
  } else {
    throw HttpException(
      '[WikipediaApiClient.getRandomArticleSummary] '
      'statusCode=${response.statusCode}, body=${response.body}',
    );
  }
}

Future<Summary> getArticleSummaryByTitle(String articleTitle) async {
  final Uri url = Uri.https(
    'en.wikipedia.org',
    '/api/rest_v1/page/summary/$articleTitle',
  );
  final http.Response response = await http.get(url);
  if (response.statusCode == 200) {
    final Map<String, Object?> jsonData =
        jsonDecode(response.body) as Map<String, Object?>;
    return Summary.fromJson(jsonData);
  } else {
    throw HttpException(
      '[WikipediaApiClient.getArticleSummaryByTitle] '
      'statusCode=${response.statusCode}, body=${response.body}',
    );
  }
}
```

两个函数的差异只有端点：随机摘要不需要标题，按标题查询把标题插入路径。重复的状态码判断可以抽取为私有辅助函数，但当前规模保持显式更易读。

### 搜索

```dart
Future<SearchResults> search(String searchTerm) async {
  final Uri url = Uri.https(
    'en.wikipedia.org',
    '/w/api.php',
    <String, Object?>{
      'action': 'opensearch',
      'format': 'json',
      'search': searchTerm,
    },
  );
  final http.Response response = await http.get(url);
  if (response.statusCode == 200) {
    final List<Object?> jsonData =
        jsonDecode(response.body) as List<Object?>;
    return SearchResults.fromJson(jsonData);
  } else {
    throw HttpException(
      '[WikipediaApiClient.search] '
      'statusCode=${response.statusCode}, '
      'body=${response.body}',
    );
  }
}
```

opensearch 的顶层是数组，因此转型为 `List<Object?>`。若误按 `Map` 解析，会在 `as` 处抛 `TypeError`，属于解析假设错误，而不是网络错误。

### 全文

```dart
Future<List<Article>> getArticleByTitle(String title) async {
  final Uri url = Uri.https(
    'en.wikipedia.org',
    '/w/api.php',
    <String, Object?>{
      // order matters - explaintext must come after prop
      'action': 'query',
      'format': 'json',
      'titles': title.trim(),
      'prop': 'extracts',
      'explaintext': '',
    },
  );
  final http.Response response = await http.get(url);
  if (response.statusCode == 200) {
    final Map<String, Object?> jsonData =
        jsonDecode(response.body) as Map<String, Object?>;
    return Article.listFromJson(jsonData);
  } else {
    throw HttpException(
      '[WikipediaApiClient.getArticleByTitle] '
      'statusCode=${response.statusCode}, '
      'body=${response.body}',
    );
  }
}
```

`title.trim()` 去掉首尾空白，避免用户从剪贴板粘贴标题时带入空格。`explaintext: ''` 是空值参数：MediaWiki 以“参数是否存在”判断是否返回纯文本，空字符串同样会出现在查询串中。

## 导出公开接口

`wikipedia` 包的入口只做导出：

```dart
export 'src/api/get_article.dart';
export 'src/api/search.dart';
export 'src/api/summary.dart';
export 'src/model/article.dart';
export 'src/model/search_results.dart';
export 'src/model/summary.dart';
export 'src/model/title_set.dart';
```

调用方只需一个导入：

```dart
import 'package:wikipedia/wikipedia.dart';
```

内部文件仍可自由调整目录结构，只要入口的 `export` 列表保持稳定。若某个模型只供内部使用，不加入导出即可。

## 客户端复用

顶层 `http.get` 每次调用都会创建并关闭一个 `Client`，适合一次性请求。连续多次请求时，复用 `Client` 可以保留连接、减少 TLS 握手：

```dart
class WikipediaApiClient {
  WikipediaApiClient({http.Client? client}) : _client = client ?? http.Client();

  final http.Client _client;

  Future<Summary> getArticleSummaryByTitle(String title) async {
    final url = Uri.https('en.wikipedia.org', '/api/rest_v1/page/summary/$title');
    final response = await _client.get(url);
    // ...
  }

  void close() => _client.close();
}
```

构造函数接受可选 `Client`，测试可以传入 `MockClient` 返回固定响应，无需网络。类实例需要显式 `close()`，否则连接池不会释放；命令行程序在退出前关闭即可。

改造为类会引入生命周期管理，当前教程规模使用顶层函数更简单。选择依据是“请求次数与是否需要注入替身”，而不是“类一定优于函数”。

## 响应编码

`Response.body` 按响应头 `Content-Type` 的 `charset` 解码；缺少 `charset` 时，`package:http` 按 HTTP 规范回退到 `latin1`。Wikipedia 返回 `application/json; charset=utf-8`，因此中文与特殊字符不会乱码。

若接口未声明字符集，应显式解码：

```dart
final text = utf8.decode(response.bodyBytes);
```

`bodyBytes` 是原始字节，`utf8.decode` 允许传入 `allowMalformed: true` 以容忍非法字节序列，但会替换损坏字符，是否使用取决于对数据完整性的要求。

## 验证

改动 API 层后，先运行原有模型测试：

```bash
cd wikipedia
dart test
```

模型测试不依赖网络，验证的是“给定 JSON 能得到正确对象”。API 函数本身需要集成测试或手工验证：

```bash
cd cli
dart run bin/cli.dart search Dart
```

若返回 403，检查 User-Agent 与请求频率；若返回 404，检查标题编码与端点路径；若解析抛 `FormatException`，先用 `curl` 或浏览器确认响应形状是否变化。

## 设计要点

- URL 构造集中在 API 层，命令不拼接查询串。
- 只对成功状态码解析响应体，失败统一抛 `HttpException`，不返回“错误字符串”混入正常数据。
- 函数返回类型化模型，调用方不接触 `Map` 与 `jsonDecode`。
- 查询参数交给 `Uri.https` 编码，避免手工拼接导致的转义遗漏。
- 需要复用连接或注入测试替身时，改用 `http.Client` 实例。
- 公开接口通过入口文件导出，内部实现放在 `src/`。

API 层完成后，命令只剩“调用函数、处理异常、格式化输出”。最后一节为这些路径加上日志：记录失败上下文、区分日志级别、把日志写入文件，并通过构造函数把 `Logger` 注入命令，见 [[13. 日志与依赖注入|日志与依赖注入]]。
