Dart 是 Google 设计的面向客户端优化的编程语言，也是 Flutter 的编程语言。对 Android 开发者而言，Dart 的类、接口、泛型、空安全与 Kotlin 有大量对应关系；差异主要集中在单线程事件循环、`Future` 异步模型、扩展方法与模式匹配。工具链可以完全放在 Android Studio 内：Dart 插件提供补全、分析、运行与断点调试，运行配置与 Android App 配置共用 Run/Debug 工具窗口。

本篇以已安装 Android Studio 的 Android 开发环境为前提，复用现有 JDK、Android SDK 与 Gradle，不重复配置这些组件。Dart SDK 由 Flutter SDK 或已有的 Dart SDK 提供，独立 SDK 的下载与升级不在本篇展开。

## 工具链与 Android 开发对照

Dart CLI 的工程模型比 Android 简单：没有 Manifest、没有 Gradle 构建脚本、没有 Activity 生命周期。依赖声明与 SDK 约束集中在 `pubspec.yaml`，解析与执行由 `dart` 命令完成。

| Dart | Android 开发对应 | 说明 |
|------|------------------|------|
| `dart` 命令 | Gradle/AGP 命令行 | Android Studio 的 Dart 插件调用同一个 SDK |
| `pubspec.yaml` | `build.gradle.kts` | 依赖、版本、SDK 约束 |
| `pubspec.lock` | `gradle.lockfile` | 锁定依赖解析结果 |
| `dart pub get` | Gradle Sync | 解析依赖，生成 `.dart_tool/package_config.json` |
| `dart analyze` | Android Lint | 静态检查与快速修复 |
| `dart format` | ktlint / IDE Reformat | 统一代码格式 |
| `dart test` | JUnit | 单元测试 |
| `bin/*.dart` | 应用入口 | CLI 可执行入口 |
| `lib/` | `app/src/main/java` | 库与业务代码 |
| `test/` | `src/test` | 测试代码 |

Dart CLI 没有 `buildTypes`、`productFlavors`、Manifest 合并与资源限定符。小规模 CLI 工程的目录结构接近一个纯 Kotlin/JVM 模块：源码、依赖声明、测试目录、可执行入口，四部分即可构成完整工程。

## 在 Android Studio 中启用 Dart

Android Studio 基于 IntelliJ 平台，Dart 插件由 Google 维护，官方声明支持 Android Studio。纯 Dart 命令行项目不需要 Android SDK、模拟器或 Gradle；Android Studio 在这里承担编辑器、分析器与调试器。

### 安装 Dart 插件

1. 启动 Android Studio。
2. 在 Welcome 界面选择 `Plugins`；已经打开项目时使用 `File | Settings | Plugins`。
3. 切换到 `Marketplace`，搜索 `Dart`。
4. 选择发布者为 Google 的 `Dart` 插件，点击 `Install`。
5. 重启 IDE 使插件生效。

同时开发 Flutter 时，安装 Flutter 插件会一并安装 Dart 插件；纯 Dart 项目只需 Dart 插件。插件市场按 IDE 构建版本提供兼容版本，搜索不到时先确认 Android Studio 是否为当前稳定版，再检查 `Settings → Plugins → Installed` 中插件是否被禁用。

### 关联 Dart SDK

1. 打开 `File | Settings`（`Ctrl+Alt+S`）。
2. 进入 `Languages & Frameworks | Dart`。
3. 勾选 `Enable Dart support for the project <project name>`。
4. 在 `Dart SDK Path` 中选择 SDK 根目录：
   - 已安装 Flutter：指向 `<flutter>\bin\cache\dart-sdk`。
   - 已有独立 Dart SDK：指向同时包含 `bin` 与 `lib` 的 SDK 根目录。
5. 路径有效时，`Version` 只读字段会显示 SDK 修订号。
6. 在 `Enable Dart support for the following modules` 中勾选需要 Dart 支持的模块。

Dart 插件只负责使用指定路径，不负责安装 SDK。Android Studio 本身不随附 Dart SDK；没有 Flutter SDK 时，需要本机已有 Dart SDK。独立 SDK 的获取属于通用 Dart 环境问题，与 Android 开发环境的工程管理无关，本篇不展开。

SDK 路径必须指向根目录，而不是 `bin` 目录：

```text
<flutter>\bin\cache\dart-sdk
├── bin\
│   └── dart.exe
└── lib\
```

Android Studio 的 `Project SDK`（JDK）用于 Android/Gradle 工程，与 Dart SDK 无关。纯 Dart 项目不需要设置 JDK，也不应把 Dart SDK 指向 JDK 目录。Flutter 项目应使用 Flutter 自带的 Dart SDK，避免与独立 SDK 混用导致分析器与 Flutter 引擎期望的版本不一致。

### 验证配置

配置完成后，`Version` 字段应显示具体修订号；打开任意 `.dart` 文件，补全、跳转与错误提示应正常工作。若 `Version` 为空或提示路径无效，优先检查路径是否指向 SDK 根目录、SDK 目录是否包含 `bin` 与 `lib`。

## 创建第一个 Dart 工程

### Android Studio 新建

1. 在 Welcome 界面点击 `New Project`；已打开项目时使用 `File | New | Project`。
2. 在左侧项目类型中选择 `Dart`。
3. 在 `Dart SDK` 字段中确认 SDK 路径；为空时选择 SDK 根目录。
4. 需要示例代码时勾选 `Generate sample content`，选择控制台应用（Console）模板；不需要时保持不勾选，创建空工程。
5. 点击 `Next`，填写项目名与保存位置。
6. 点击 `Finish`，IDE 会创建目录结构并执行依赖解析。

不同 Android Studio 版本的新建向导存在差异。若向导中没有 `Dart` 类型，使用 Flutter SDK 自带的 `dart` 创建，再用 `File | Open` 打开：

```powershell
<flutter>\bin\dart create cli
```

`<flutter>` 替换为实际 Flutter SDK 路径。该命令直接调用 Flutter 目录下的 `dart`，不需要额外配置。

### 打开已有工程

1. 选择 `File | Open`。
2. 选中包含 `pubspec.yaml` 的目录。单包工程选 `dartpedia/cli`；多包 workspace 选包含 `workspace:` 声明的根目录。
3. 首次打开时按提示信任项目。
4. 如果 Dart 支持未自动启用，按上一节的步骤勾选 `Enable Dart support` 并确认 SDK 路径。
5. 打开 `pubspec.yaml`，点击编辑器顶部的 `pub get` 链接解析依赖。

不要只打开 `bin/` 目录，也不要打开位于包之上的空目录。IDE 通过 `pubspec.yaml` 识别 Dart 包，打开层级错误时，文件仍能显示，但补全、导航与运行配置都无法正常工作。

### 工程结构

```text
dartpedia/
├── cli/
│   ├── bin/
│   │   └── cli.dart          # 可执行入口
│   ├── lib/
│   │   └── cli.dart          # 库的公开入口
│   ├── test/
│   │   └── cli_test.dart
│   ├── analysis_options.yaml
│   └── pubspec.yaml
└── (后续章节会加入 command_runner/ 与 wikipedia/)
```

| 路径 | Dart 职责 | Android 对照 |
|------|-----------|--------------|
| `pubspec.yaml` | 工程元数据、依赖、SDK 约束 | `build.gradle.kts` |
| `pubspec.lock` | 锁定依赖版本 | `gradle.lockfile` |
| `.dart_tool/` | 依赖解析与工具缓存 | `.gradle/` |
| `analysis_options.yaml` | 静态分析规则 | Lint/Detekt 配置 |
| `bin/cli.dart` | 可执行入口 | 应用入口 |
| `lib/cli.dart` | 库的公开入口 | 模块源码 |
| `lib/src/` | 实现细节 | 模块内部实现 |
| `test/` | 单元测试 | `src/test` |

`bin/` 与 `lib/` 的分工是 Dart 工程的固定约定：`bin/` 存放可执行脚本，一个包可以有多个入口；`lib/` 存放可被导入的库代码。Flutter 应用的入口在 `lib/main.dart`，而标准 Dart CLI 工程的入口在 `bin/`，两者不可混用同一套路径习惯。

## 程序入口

模板生成的 `bin/cli.dart` 内容如下：

```dart
import 'package:cli/cli.dart' as cli;

void main(List<String> arguments) {
  print('Hello world: ${cli.calculate()}!');
}
```

`main` 是每个可执行 Dart 程序的入口，签名要求为顶层函数、返回 `void` 或 `Future<void>`，参数可以是无参、`List<String>`，或省略。`List<String> arguments` 接收终端传入的命令行参数，不包含可执行文件名本身。

`import 'package:cli/cli.dart'` 是包导入：`package:` 之后的 `cli` 是 `pubspec.yaml` 中声明的包名，路径映射到该包的 `lib/` 目录，因此 `package:cli/cli.dart` 对应 `lib/cli.dart`。`as cli` 给导入加上前缀，调用时写作 `cli.calculate()`，用于避免不同库之间的命名冲突。

`print()` 向标准输出写入一行文本，并在末尾补换行。字符串中的 `${...}` 是插值语法，花括号内可以是任意表达式。

与 Android 开发的对应关系：

| Dart | Android | 差异 |
|------|---------|------|
| `main(List<String>)` | 进程入口 | Dart CLI 没有 Activity 生命周期、Context 与主线程概念 |
| `print` | `Log.i` / `System.out` | 输出到 stdout，不进入 Logcat，也没有 tag 与优先级 |
| `arguments` | 命令行参数 | 不是 Intent extras，进程启动后不会再收到新的参数 |
| `package:` 导入 | 模块依赖 | 由 `pubspec.yaml` 解析，不经过 Gradle |

## 运行、调试与依赖管理

### 运行配置

1. 在 Project 工具窗口打开 `bin/cli.dart`。
2. 点击 `main` 左侧行号栏的绿色箭头，或右键编辑器选择 `Run 'cli.dart'`。
3. IDE 自动创建名为 `Dart Command Line App` 的运行配置，并在 Run 工具窗口显示输出。

`Dart Command Line App` 与 Android App 配置并列在 Run/Debug 配置下拉框中，操作方式一致：选择配置、点击 Run、在 Run 工具窗口查看输出。区别是前者运行在桌面 Dart VM，不需要设备或模拟器。

需要传入命令行参数时，打开 `Run | Edit Configurations`，选中该配置：

| 字段 | 填写内容 | Android 对照 |
|------|----------|--------------|
| `Dart file` | `bin/cli.dart`，文件必须包含 `main()` | 启动入口 |
| `VM options` | 可选，传给 Dart VM 的启动参数 | JVM 参数 |
| `Program arguments` | 传给 `main(List<String>)` 的参数，如 `search Dart` | 启动参数/Intent extras |
| `Working directory` | 默认为包根目录，通常留空 | 工作目录 |
| `Environment variables` | 可选，进程环境变量 | 环境变量 |

`Program arguments` 按空格分词，包含空格的单个参数需要加引号。`Working directory` 影响相对路径的解析，默认的包根目录与命令行执行的行为一致。

### 调试

1. 在需要暂停的代码行点击行号栏设置断点。
2. 右键编辑器选择 `Debug 'cli.dart'`，或点击调试按钮。
3. 在 Debug 工具窗口查看 `Frames`、`Variables` 与 `Watches`。
4. 使用 Step Over、Step Into、Step Out 控制执行，Resume 继续运行。
5. 需要计算表达式时使用 `Evaluate Expression`（`Alt+F8`）。

断点、单步、变量查看与 Android 调试一致。差异在于没有设备与进程选择，也没有 Logcat；标准输出与错误输出显示在 Run 或 Debug 工具窗口的 Console 中。断点只在 Debug 模式生效，Run 模式会直接执行到结束；断点未命中时，先确认启动的是 Debug 而不是 Run。

### 依赖解析

打开 `pubspec.yaml` 后，编辑器顶部会显示 `pub get`、`pub upgrade`、`pub outdated` 链接；也可以在项目工具窗口中右键 `pubspec.yaml` 调用 Pub 操作。

这一过程对应 Android 的 Gradle Sync：读取依赖声明、解析版本、下载包、生成 IDE 可识别的工程模型。Dart 的解析结果写入 `.dart_tool/package_config.json`，该文件由工具生成，不应手工编辑。应用包应提交 `pubspec.lock`，保证不同机器解析到相同版本；库包通常不提交锁文件。

### 静态分析与格式化

Dart 分析服务器随插件启动，问题会汇总在 IDE 的问题视图中，`Alt+Enter` 提供快速修复。这一层对应 Android Lint：在编辑期发现类型错误、空安全问题和风格违规。

```bash
dart analyze
dart format .
```

`analysis_options.yaml` 控制分析规则，作用类似 Android 工程的 Lint 配置。IDE 的 `Code | Reformat Code`（`Ctrl+Alt+L`）按 Dart 格式化规则重排代码；团队协作时以 `dart format` 的结果为准，避免不同 IDE 配置产生差异。

### 测试

`test/` 下以 `_test.dart` 结尾的文件会在行号栏显示运行图标，可以单独运行某个 `test` 或整个文件。测试结构对应 JUnit：`group` 类似测试套件，`test` 类似 `@Test` 方法，`expect` 类似断言库。

Run 工具窗口会显示通过、失败与跳过的用例数量。测试同样支持断点调试，启动方式选择 Debug 即可。

### 命令行等价操作

Android Studio 是主入口，命令行用于脚本化与快速验证。已安装 Flutter 时，直接调用 Flutter 目录下的 `dart`，不需要额外配置：

| 操作 | Android Studio | 命令行 |
|------|----------------|--------|
| 创建工程 | `New Project → Dart` | `<flutter>\bin\dart create cli` |
| 解析依赖 | `pubspec.yaml` 顶部 `pub get` | `<flutter>\bin\dart pub get` |
| 运行 | `Run 'cli.dart'` | `<flutter>\bin\dart run` |
| 测试 | 测试文件行号栏运行 | `<flutter>\bin\dart test` |
| 静态分析 | 问题视图 | `<flutter>\bin\dart analyze` |
| 格式化 | `Code → Reformat Code` | `<flutter>\bin\dart format .` |

## 常见配置问题

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| 插件市场搜不到 Dart | Android Studio 版本过旧，插件无兼容版本 | 升级 IDE；检查 `Settings → Plugins → Installed` 中是否已安装但被禁用 |
| `Dart SDK Path` 为空或无效 | 未关联 Flutter SDK，或路径指向 `bin`、JDK 目录 | 指向 `<flutter>\bin\cache\dart-sdk` 或含 `bin`/`lib` 的 SDK 根目录 |
| `New Project` 没有 Dart 类型 | 插件未启用或版本不兼容 | 启用插件并重启；仍无该类型时用 `<flutter>\bin\dart create` 创建后 `File → Open` |
| 代码无补全、无法跳转 | 未勾选 `Enable Dart support` 或 SDK 路径错误 | 在 `Languages & Frameworks → Dart` 中启用并确认 `Version` 有值 |
| `pub get` 失败 | SDK 约束与已安装版本不匹配，或依赖冲突 | 阅读首条错误；对齐 `environment.sdk`；检查 Flutter 与 Dart 版本是否匹配 |
| 断点不生效 | 以 Run 启动，或以非 Debug 配置启动 | 使用 `Debug` 启动；确认断点未被禁用 |
| 工程被当作 Android 工程 | 打开层级错误，目录未包含 `pubspec.yaml` | 重新打开包含 `pubspec.yaml` 的目录 |
| Flutter 项目提示 SDK 不一致 | 使用了独立 Dart SDK | 将 `Dart SDK Path` 指向 `<flutter>\bin\cache\dart-sdk` |
| Run 按钮灰色 | 文件没有 `main()`，或项目未启用 Dart 支持 | 确认入口文件；在 Dart 设置中启用项目支持 |

## Android 开发者视角的概念映射

后续笔记围绕语言机制展开，先建立与 Kotlin/Android 的对应关系，避免把 Dart 当作完全陌生的语言：

| Dart | Android/Kotlin | 差异 |
|------|----------------|------|
| `final` / `const` | `val` / `const val` | `final` 运行期只赋值一次，`const` 要求编译期常量 |
| `String?` | `String?` | 可空类型写法接近，Dart 用流分析做类型提升 |
| `class` / `abstract class` | `class` / `interface` | Dart 单继承，每个类隐式定义接口 |
| `extension` | 扩展函数 | Dart 扩展静态解析，不能声明实例字段 |
| `Future` / `async` / `await` | `Deferred` / `suspend` | Dart 单线程事件循环，没有协程调度器与线程切换 |
| 模式匹配 | `when` + sealed class | Dart 3 的模式可用于 `switch`、`if-case` 与解构 |
| `pubspec.yaml` | `build.gradle.kts` | Dart 没有变体、Manifest 与资源合并 |

这些对应关系只用于建立方向，具体语义仍以 Dart 为准。例如 `Future` 与 Kotlin 协程都能表达异步结果，但 Dart 的 `await` 只暂停当前函数，不涉及线程池调度；扩展方法在 Dart 中是静态分派，也不会进入运行时类型。

## 工程约定

- 包名使用小写字母与下划线，作用类似 Android 的 `applicationId`/命名空间；导入路径与目录名必须一致。
- 库的公开入口放在 `lib/<package>.dart`，实现细节放在 `lib/src/`，由入口文件 `export` 决定对外暴露的范围，详见 [[4. 包与库的组织|包与库的组织]]。
- 可执行代码只放在 `bin/`，业务逻辑放在 `lib/`，保证逻辑可被测试与其他包复用。
- 提交前运行 `dart analyze` 与 `dart format`，静态分析能发现大部分类型与空安全问题。
- `.dart_tool/` 由工具生成，不提交；应用包提交 `pubspec.lock`。
- Android Studio 的 SDK 路径保存在 IDE 配置中，可能包含本机绝对路径；团队协作时按仓库约定决定 `.idea/` 的提交范围，避免把个人路径推给其他成员。

第一个程序的规模很小，但它确定了后续所有章节的基本结构：`bin/` 负责启动，`lib/` 承载逻辑，`pubspec.yaml` 描述依赖，`main` 接收命令行参数。与 Android 工程相比，少了 Manifest、Activity 与 Gradle，保留了源码、依赖、测试与运行配置四件事。下一节在这个骨架上加入分支、变量与标准输入，使程序从固定输出变成可交互的命令行工具，见 [[2. 变量、常量与命令行交互|变量、常量与命令行交互]]。
