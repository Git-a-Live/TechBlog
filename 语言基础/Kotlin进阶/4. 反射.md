反射（reflection）是一种在运行时获取到一个对象所有信息（如类名、属性以及方法等）的功能。在 Java 当中，反射是很常见的，但也容易被滥用，从而导致对象的封装性被破坏。下面就从几个方面展开，介绍 JVM 语言的反射特性和实际用法。

Java 的反射机制是 JDK 自带的，而 Kotlin 的完整反射能力需要额外添加 `kotlin-reflect` 依赖：

```kotlin
dependencies {
    implementation(kotlin("reflect"))
}
```

使用 `kotlin("reflect")` 的好处是版本由 Kotlin Gradle 插件统一管理，不会出现反射库与编译器版本不一致的问题。如果项目没有使用 Kotlin Gradle 插件，也可以显式写 `org.jetbrains.kotlin:kotlin-reflect:<与 Kotlin 版本一致>`。

需要区分的是：`::class`、`KClass` 的基础成员（`simpleName`、`isInstance` 等）由标准库提供；而 `memberProperties`、`primaryConstructor`、`findAnnotation()` 这些 `kotlin.reflect.full` 中的扩展，以及 `call()`、`sealedSubclasses` 等需要读取 Kotlin 元数据的实现，都依赖 `kotlin-reflect`，否则运行时会抛 `KotlinReflectionNotSupportedError`。

需要注意的是，由于 Kotlin 兼容 Java，后者的反射功能在 Kotlin 当中是可以调用的。Kotlin 自己的反射功能一般通过 `SomeType::class` 来调用，而 Java 的反射功能则通过 `SomeType::class.java` 来调用：

```kotlin
// 获取 KClass<*> 对象，调用 Kotlin 反射功能
val kClass: KClass<String> = String::class
println(kClass.simpleName)

// 获取 Class<*> 对象，调用 JDK 反射功能
val javaClass: Class<String> = String::class.java
println(javaClass.name)
```

> 在 JVM 中，每一个类型（包括 `int` 这样的基本类型）都有对应的 `Class` 实例，它在类加载时由 JVM 创建，是访问该类型元信息的入口。`int.class` 的类型是 `Class<Integer>`，并不是“基本类型没有 `Class` 对象”。Kotlin 侧对应的入口是 `KClass` 实例。

## 类引用

类引用在 Kotlin 当中的含义是：通过 `SomeType::class` 语法来获得一个 `KClass<*>` 类型实例，通过 `SomeType::class.java` 语法来获得一个 `Class<*>` 类型实例。类引用是其他所有反射功能的基础，因此必须掌握。通过类引用，开发者可以获知一个对象实例的属性/字段、函数/方法、父类以及使用的注解等等信息。

获取 `KClass` 的几种方式：

```kotlin
// 编译期已知的类
val fromClass: KClass<String> = String::class

// 运行期对象的实际类型，可能比声明类型更具体
val value: Any = "text"
val fromInstance: KClass<out Any> = value::class

// 从 Java 的 Class 转回 KClass
val fromJava: KClass<*> = String::class.java.kotlin
```

基本类型在这里有一个容易踩的坑：`Int::class.java` 得到的是**基本类型** `int`，而泛型、反射创建实例等场景通常需要的是包装类型 `Integer`，此时要用 `javaObjectType`：

```kotlin
println(Int::class.java)              // int
println(Int::class.javaObjectType)    // class java.lang.Integer
println(String::class.javaPrimitiveType) // null，String 没有对应的基本类型
```

`KClass` 只描述“是哪个类”，不保留类型实参和可空性：`List<String>` 和 `List<Int>` 共享同一个 `List::class`，`String` 和 `String?` 也一样。需要保留这些信息时，用 `typeOf<T>()` 获取 `KType`：

```kotlin
val type = typeOf<List<String?>>()
println(type.classifier)                  // class kotlin.collections.List
println(type.arguments.single().type)     // kotlin.String?
```

## KClass常用API

`KClass` 提供的成员很多，可以按用途分成几组。其中 `declaredMembers`、`memberProperties`、`primaryConstructor` 等是 `kotlin.reflect.full` 中的扩展，使用前需要 import。

类的结构与成员：

| API | 用途 |
| :--- | :--- |
| `simpleName` | 简单类名，匿名类为 `null` |
| `qualifiedName` | 全限定名，局部类或匿名类为 `null` |
| `constructors` | 所有构造函数（`Collection<KFunction<T>>`） |
| `primaryConstructor` | 主构造函数，没有则返回 `null`（需 `kotlin.reflect.full`） |
| `members` | 本类及父类中所有可访问的函数和属性，不含构造函数 |
| `declaredMembers` | 仅本类声明的函数和属性 |
| `memberProperties` / `declaredMemberProperties` | 非扩展属性 / 仅本类声明的非扩展属性 |
| `memberFunctions` / `declaredMemberFunctions` | 非扩展、非静态函数 / 仅本类声明的非扩展、非静态函数 |
| `staticFunctions` / `staticProperties` | Java 类中声明的静态方法 / 静态字段 |
| `nestedClasses` | 类内部声明的所有嵌套类（含 inner 与静态嵌套类） |
| `objectInstance` | `object` 声明的唯一实例，非 object 返回 `null` |
| `supertypes` | 直接父类型列表（`KType`） |
| `typeParameters` | 类型参数列表 |
| `visibility` | 可见性，无法表示时为 `null` |
| `annotations` | 类上的注解列表 |

类型判断与转换：

| API | 用途 |
| :--- | :--- |
| `isAbstract` / `isFinal` / `isOpen` / `isSealed` | 类修饰符 |
| `isData` / `isInner` / `isCompanion` / `isValue` / `isFun` | 是否为数据类 / 内部类 / 伴生对象 / 值类 / 函数式接口 |
| `sealedSubclasses` | 密封类的直接子类列表，非密封类为空 |
| `isInstance(value)` | 判断 `value` 是否为该类的实例，等价于 Java 的 `Class.isInstance` |
| `cast(value)` | 强制转换，失败或为 `null` 时抛异常 |
| `safeCast(value)` | 安全转换，失败或为 `null` 时返回 `null` |
| `java` / `javaObjectType` / `javaPrimitiveType` | `java` 取对应的 Java 类型，`javaObjectType` 取包装类型，`javaPrimitiveType` 只在存在基本类型时返回非 `null` |

一个综合示例：

```kotlin
data class User(val name: String, val age: Int)

fun main() {
    val clazz = User::class
    println(clazz.simpleName)       // User
    println(clazz.qualifiedName)    // com.example.User

    // 通过主构造函数创建实例（需要 kotlin-reflect）
    val user = clazz.primaryConstructor!!.call("Tom", 18)
    println(user)                   // User(name=Tom, age=18)

    // 遍历属性
    clazz.memberProperties.forEach {
        println("${it.name}: ${it.returnType}")
    }
}
```

## 访问类属性/字段

### KProperty

`KClass<*>` 类型实例可以通过下表所示的方式来获取某个类的属性列表：

| 访问方式 | 用途说明 |
| :--- | :--- |
| `KClass<T>.declaredMemberProperties` | 获取该类当中所有非扩展的属性，返回的元素类型为 `KProperty1<T, *>` |
| `KClass<T>.memberProperties` | 获取该类及其父类中所有非扩展的属性，返回的元素类型为 `KProperty1<T, *>` |
| `KClass<T>.declaredMemberExtensionProperties` | 获取该类声明的所有扩展属性，返回的元素类型为 `KProperty2<T, *, *>` |
| `KClass<T>.memberExtensionProperties` | 获取该类及其父类声明的所有扩展属性，返回的元素类型为 `KProperty2<T, *, *>` |

之所以 `KProperty1` 带一个类型参数、`KProperty2` 带两个，是因为属性访问需要接收者：`KProperty1<T, V>` 表示“在 `T` 上取一个 `V`”，`KProperty2<T, R, V>` 表示“在 `T` 上、以 `R` 为扩展接收者取一个 `V`”，`KProperty0<V>` 则是不需要接收者的顶层或对象属性。

通过 `KProperty*`，开发者可以进行以下操作：

| 操作 | 使用 API |
| :--- | :--- |
| 获取属性名称 | `KProperty*.name` |
| 获取属性类型 | `KProperty*.returnType` |
| 获取属性可见性 | `KProperty*.visibility`，返回 `KVisibility?` |
| 获取属性注解列表 | `KProperty*.annotations` |
| 获取调用所需参数列表（接收者在最前） | `KProperty*.parameters` |
| 获取 getter / setter | `KProperty*.getter` / `KMutableProperty*.setter` |
| 读取属性值 | `KProperty0.get()` / `KProperty1.get(receiver)` |
| 修改属性值 | `KMutableProperty1.set(receiver, value)` |
| 获取属性的委托对象，非委托属性返回 `null` | `KProperty*.getDelegate(...)` |
| 以可变参数方式调用属性的 getter | `KProperty*.call(...)` / `callBy(...)` |
| 判断是否为 `const` 常量 | `KProperty*.isConst` |
| 判断是否为 `lateinit` 属性 | `KProperty*.isLateinit` |
| 判断是否为挂起函数（在 `KFunction` 上才有实际意义） | `KCallable*.isSuspend` |
| 判断属性是否为抽象 / final / open | `KProperty*.isAbstract` / `isFinal` / `isOpen` |

需要特别注意 `call()` 的语义：它调用的是**属性的 getter**，返回的是属性值。如果属性本身是函数类型，`call()` 拿到的仍然是那个函数对象，还要再 `invoke()` 才会执行：

```kotlin
class Holder {
    var callback: (() -> Unit)? = null
}

val holder = Holder()
val property = Holder::callback
property.set(holder) { println("called") }
property.get(holder)?.invoke()   // called
```

`KProperty` 没有公开的 `isAccessible`。需要绕过可见性时，要先拿到对应的 Java 字段：

```kotlin
val field = Holder::class.java.getDeclaredField("callback")
field.isAccessible = true
```

### Field

`Class<*>` 类型实例则通过下表所示的方式来获取某个类的特定字段或字段列表（返回的字段元素类型都是 `Field`）：

| 访问方法 | 用途说明 |
| :--- | :--- |
| `Class<T>.getField()` | 获取该类及其父类当中指定名称的 `public` 字段 |
| `Class<T>.getDeclaredField()` | 获取该类当中自己声明的指定名称字段 |
| `Class<T>.getFields()` | 获取该类及其父类所有 `public` 字段 |
| `Class<T>.getDeclaredFields()` | 获取该类当中自己声明的所有字段 |

通过 `Field` 对象，开发者可以进行以下操作：

| 操作 | 使用 API |
| :--- | :--- |
| 获取字段名称 | `Field.getName()` |
| 获取字段类型 | `Field.getType()` |
| 获取字段的泛型类型 | `Field.getGenericType()` |
| 获取字段注解列表 | `Field.getAnnotations()` |
| 获取字段修饰符 | `Field.getModifiers()` |
| 获取字段值 | `Field.get()` / `Field.getXXX()` |
| 修改字段值 | `Field.set()` / `Field.setXXX()` |
| 允许无视字段可见性直接访问 | `Field.setAccessible(true)` |
| 判断当前是否可访问 | `Field.canAccess(obj)`（Java 9+，Android SDK 未提供；`isAccessible()` 自 Java 9 起已废弃） |
| 判断该字段本身是否为枚举常量 | `Field.isEnumConstant()` |
| 判断该字段是否由编译器合成 | `Field.isSynthetic()` |

`Field.get()` 需要传入目标实例，静态字段传 `null`：

```kotlin
class Person(var name: String)

val person = Person("Tom")
val field = Person::class.java.getDeclaredField("name")
field.isAccessible = true

println(field.get(person))     // Tom
field.set(person, "Jerry")
println(person.name)           // Jerry
```

> 注意，Java 的 Synthetic 成员是一种由编译器在编译阶段生成的成员，通常用于对 `private` 字段或类（比如内部类）的访问，从而绕开语言限制。在实际生产中基本不会让开发者用到。

最为值得关注的地方就是 `Field` 提供了修改字段可访问性以及读写字段值的方法。从开发规范的角度来说，这些操作会破坏掉对象的封装特性，如果滥用可能会给项目的可维护性带来负面影响。

`setAccessible(true)` 的拦截机制也发生了变化：早期的 `SecurityManager` 可以阻止这一操作，但 `SecurityManager` 自 Java 17 起已被标记为废弃（JEP 411），Android 上则根本没有这套机制。现代 JVM 上真正的限制来自模块系统（JPMS）：如果目标类位于一个没有对当前模块开放的包中，反射访问会抛出 `InaccessibleObjectException`，需要在启动参数里加 `--add-opens`。Android 不受 JPMS 约束，反射自己的类基本总是成功；但 Android 9 起有隐藏 API 限制，反射框架的非 SDK 成员仍可能被拦截。

| `KClass<*>.functions` | 获取该类及其父类中所有非静态方法，以及该类当中声明的静态方法 |
| `KClass<*>.staticFunctions` | 获取该类当中声明的静态方法 |
| `KClass<*>.memberFunctions` | 获取该类及其父类当中声明的所有非扩展、非静态方法 |

| `KClass<*>.declaredMemberFunctions` | 获取该类当中声明的所有非扩展、非静态方法 |
| `KClass<*>.declaredMemberExtensionFunctions` | 获取该类当中声明的所有扩展函数 |
| `KClass<*>.constructors` | 获取该类所有构造函数 |
| `KClass<*>.primaryConstructor` | 获取该类的主构造函数，若没有则返回 `null` |

`Class<*>` 类型实例则通过下列方法来获取类方法：

| 访问方法 | 用途说明 |
| :--- | :--- |
| `Class<*>.getMethods()` | 获取该类及其父类中所有 `public` 方法 |

| `Class<*>.getConstructors()` | 获取该类所有的 `public` 构造方法 |
| `Class<*>.getDeclaredConstructors()` | 获取该类声明的所有构造方法 |
| `Class<*>.getConstructor()` | 获取该类某个指定的 `public` 构造方法 |
| `Class<*>.getDeclaredConstructor()` | 获取该类某个指定构造方法 |

| 使用 API | 用途说明 |

| `KFunction<*>.isInline` | 判断函数是否为内联函数 |
| `KFunction<*>.isExternal` | 判断函数是否为 `external` 声明（由 JNI 或平台侧实现） |
| `KFunction<*>.isOperator` | 判断函数是否为运算符函数 |
| `KFunction<*>.isInfix` | 判断函数是否为中缀函数 |
| `KFunction<*>.isSuspend` | 判断函数是否为挂起函数 |
| `KFunction<*>.parameters` | 参数列表（接收者在最前） |

### Method和Constructor

`Method` 代表的是非构造方法，Java 提供了以下 API：

| 使用 API | 用途说明 |
| :--- | :--- |
| `Method.getName()` | 获取该方法的名称 |
| `Method.getReturnType()` | 获取方法返回值类型 |
| `Method.getParameterTypes()` | 获取方法入参类型的数组 |
| `Method.getModifiers()` | 获取该方法使用的修饰符 |
| `Method.getDefaultValue()` | 获取注解方法声明的默认值，非注解方法返回 `null` |
| `Method.isBridge()` | 判断该方法是否为桥接方法 |
| `Method.isDefault()` | 判断该方法是否为接口当中的默认方法 |
| `Method.isVarArgs()` | 判断该方法是否能传入可变参数 |
| `Method.getExceptionTypes()` | 获取该方法抛出的异常的类型数组 |
| `Method.setAccessible(true)` | 允许无视方法可见性直接访问 |
| `Method.invoke()` | 调用该方法 |

`Method.invoke()` 是最为值得关注的，因为其高度灵活且位于底层位置，在后面介绍动态代理时会派上大用场。它的第一个参数是目标实例，静态方法传 `null`，后面是方法的参数；调用时保持多态，实际执行的是运行期类型的重写版本。

> 注意，桥接方法和前文提到的 Synthetic 一样，都是编译器生成的，通常情况下开发者不用太关注。

`Constructor<*>` 代表的是**某一个具体的构造方法**，它跟 `Method` 基本相同，只不过多了 `Constructor<*>.newInstance()` 这个 API。先用 `getDeclaredConstructor(...)` 按参数类型选出构造方法，再调用 `newInstance(args)` 传入对应的实参，就能创建对象实例：

```kotlin
class Account(val id: String)

val constructor = Account::class.java.getDeclaredConstructor(String::class.java)
val account = constructor.newInstance("A-001")
println(account.id)   // A-001
```

`Class<*>` 实例也有一个 `newInstance()` 可以用来创建对象，但它仅代表无参构造方法，而且**自 Java 9 起已被废弃**，应改用 `getDeclaredConstructor().newInstance()`。

## 动态代理

动态代理（Dynamic Proxy）是 Java 标准库提供的一种机制，其主要作用就是在运行期创建某个接口实例。动态代理的“代理”思想源自[[结构型设计模式#七、Proxy|Proxy模式]]，而“动态”是指这种机制能够灵活实现被代理对象（也就是接口）的业务逻辑。Kotlin 和 Java 在动态代理方面有各自的实现方案，前者通过 `by` 关键字来实现“委托”，而后者相对麻烦，需要通过专门方式才能实现动态代理。

### Kotlin的委托

#### 类委托

类委托的核心思想是：**将一个类的具体实现交由另一个类去完成**，即一个类中定义的方法实际是调用另一个类的对象的方法来实现的。示例如下：

```kotlin
// 接口
interface Demo {
    fun foo()
}

// 被委托类
class DemoImpl : Demo {
    override fun foo() = println("foo")
}

// 委托类
class Delegate(demo: Demo) : Demo by demo

// 调用
Delegate(DemoImpl()).foo()   // foo
```

当接口只有较少的方法需要实现时，事实上并不需要委托模式，直接通过已经实现好的被委托类实例化对象去调用相关的方法即可。委托模式的适用场景为：接口定义了大量方法，但其中的**大部分都由被委托类实现，少部分在委托类中另外实现**，并且还可能再声明一些接口以外的独有方法以供调用。

这里再提供一个典型的例子——协程作用域的继承与实现。如下面代码所示，`Demo` 类想要继承 `CoroutineScope` 的特性，但是如果直接继承 `CoroutineScope`，就会发现不知道具体要实现哪些东西，或者实现出来了可能也没有官方的完善。在这种情况下，开发者可以通过 `CoroutineScope by MainScope()` 来继承 `MainScope` 对 `CoroutineScope` 的全部实现方案，不用自己手动实现任何内容，即可调用功能完善的协程 API：

```kotlin
class Demo : CoroutineScope by MainScope() {
    fun load() {
        launch {
            // 协程体
        }
    }
}
```

需要注意，`MainScope()` 创建的 `Job` 不会自动取消，`Demo` 不再使用时应当调用 `cancel()`，否则可能泄漏。

#### 属性委托

属性委托的含义是：**将一个属性（字段）的具体实现交由另一个类去实现**，即一个类的某个属性值不是在类中直接进行定义，而是将其托付给一个代理类，从而实现对该类的属性统一管理。示例如下：

```kotlin
// 声明属性
class Demo {
    var p: Any? by Delegate()
}

// 管理属性
class Delegate {
    private var value: Any? = null

    operator fun getValue(thisRef: Any?, property: KProperty<*>): Any? = value

    operator fun setValue(thisRef: Any?, property: KProperty<*>, value: Any?) {
        this.value = value
    }
}
```

`getValue` 的第一个参数是属性所属的对象（`thisRef`），第二个参数是属性的元信息；`val` 只需要 `getValue`，`var` 还需要 `setValue`，两者都必须用 `operator` 修饰。

属性委托的意义在于：将属性的声明与读写控制相分离，这样就不必在声明属性的类中为它们一一编写具有相同业务逻辑的 `get()` 和 `set()` 方法（试想一下在一个声明了大量属性的类里面，要成对地编写 `get()` 和 `set()` 方法是何等恐怖）。

#### lazy函数

`lazy` 函数的通用名称是“懒加载函数”，使用 `lazy` 函数的目的是直到第一次访问该属性的时候，才根据需要创建对象的一部分，以减少资源的消耗，确切地说就是某些逻辑只会在第一次访问的时候执行。其基本使用方式为：

```kotlin
val config: Config by lazy {
    loadConfig()
}
```

尽管在了解委托的基本原理后可以自定义一个 `lazy` 函数，但是 Kotlin 内置的 `lazy` 函数在实现上更为严谨，因而在实际开发中更推荐使用。Kotlin 内置 `lazy` 函数还可以传入一些配置参数来改变具体的懒加载方式，如下表所示：

| 参数 | 用途说明 |
| :--- | :--- |
| `LazyThreadSafetyMode.SYNCHRONIZED` | 保证线程安全的懒加载方式，在初始化实例对象时会加锁，默认方式 |
| `LazyThreadSafetyMode.PUBLICATION` | 允许并发初始化实例，但只有最先完成初始化操作的线程所返回的实例会被使用 |
| `LazyThreadSafetyMode.NONE` | 没有线程安全保障的懒加载方式，通常不推荐使用，或是只在单线程当中使用 |

`lazy` 返回的是 `Lazy<T>` 实例，可以通过 `isInitialized()` 判断是否已经完成初始化：

```kotlin
val lazyConfig: Lazy<Config> = lazy { loadConfig() }
println(lazyConfig.isInitialized())   // false
println(lazyConfig.value)             // 首次访问，执行 loadConfig()
println(lazyConfig.isInitialized())   // true
```

注意，`by lazy` 声明的属性本身不能用 `::prop.isInitialized` 判断——那是 `lateinit` 的语法。要判断初始化状态，需要持有 `Lazy` 实例，或者把属性声明为 `Lazy<T>` 类型。

### Java动态代理

Java 的动态代理方案是基于 JDK 提供的 `Proxy.newProxyInstance()` 来实现的。虽然没有写静态的实现类，但是开发者在运行期间就可以利用 `Proxy.newProxyInstance()` 来动态创建接口实例对象。这一过程大致为：

1. 定义一个 `InvocationHandler` 类型实例，负责实现接口的方法调用；
2. 通过 `Proxy.newProxyInstance()` 创建接口实例；
3. 将返回的 `Object` 类型实例强制转换成对应的接口类型。

具体过程参考下面的示例代码：

```kotlin
import java.lang.reflect.InvocationHandler
import java.lang.reflect.Proxy

// 接口
interface Computer {
    fun turnOn()
    fun shutdown()
}

// 定义 InvocationHandler 实例
val handler = InvocationHandler { proxy, method, args ->
    when (method.name) {
        "turnOn" -> println("booting...")
        "shutdown" -> println("shutting down...")
        else -> error("unsupported method: ${method.name}")
    }
}

// 创建接口实例
val computer = Proxy.newProxyInstance(
    Computer::class.java.classLoader,   // 接口的 ClassLoader
    arrayOf(Computer::class.java),      // 需要实现的接口数组，至少包含一个接口
    handler                             // InvocationHandler 实例
) as Computer

// 调用接口实例方法
computer.turnOn()
```

由于 Kotlin 兼容 Java，上面的代码是可以执行的。JDK 动态代理只能代理**接口**，不能代理类；需要代理类时通常改用字节码生成库（如 Byte Buddy、CGLIB）。

动态代理实际上是 JVM 在运行期动态创建字节码文件并加载的过程，它并没有什么黑魔法，也不存在任何可以直接实例化接口对象的途径。JVM 生成的代理类大致如下（非字节码形式）：

```java
// 省略了 extends java.lang.reflect.Proxy，以及 equals/hashCode/toString 等方法的转发
public final class ComputerProxy implements Computer {
    private final InvocationHandler handler;

    public ComputerProxy(InvocationHandler handler) {
        this.handler = handler;
    }

    @Override
    public void turnOn() {
        try {
            handler.invoke(this, Computer.class.getMethod("turnOn"), new Object[0]);
        } catch (Throwable e) {
            throw new UndeclaredThrowableException(e);
        }
    }

    @Override
    public void shutdown() {
        try {
            handler.invoke(this, Computer.class.getMethod("shutdown"), new Object[0]);
        } catch (Throwable e) {
            throw new UndeclaredThrowableException(e);
        }
    }
}
```

## 反射的代价

反射让代码获得了运行期的灵活性，但代价也很直接：

- **性能**：反射调用要经过参数装箱、访问检查和方法查找，比直接调用慢一到两个数量级。高频路径（列表 `bindViewHolder`、序列化热路径）应避免逐次反射，改为缓存 `Method` / `Field`，或者使用编译期生成的代码。
- **包体**：`kotlin-reflect` 会明显增大方法数和包体，Android 项目如果只是偶尔取个类名，没必要引入完整反射库。
- **混淆**：反射按字符串查找成员，R8 / ProGuard 开启后可能把目标成员重命名或裁掉，需要配置 keep 规则；Kotlin 反射还依赖 `@Metadata` 注解，混淆时也要保留。
- **封装性**：`setAccessible(true)` 能绕过 `private`，但这会破坏封装，让重构变得危险。

因此，现代 Kotlin 项目在“需要元数据”的场景下，通常优先选择编译期方案：注解处理用 KSP，序列化用 kotlinx.serialization 或 Moshi 的代码生成，依赖注入用编译期生成代替运行期扫描。反射更适合框架层、调试工具和少量确实无法在编译期确定的逻辑。
