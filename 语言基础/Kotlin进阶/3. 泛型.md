早在 Java 1.5 版本时期，泛型机制就已经被引入了。所谓泛型，其实就是一种“代码模板”，即可以用一套代码套用各种类型，实现了编写一次、万能匹配，又通过编译器保证了类型安全（避免不必要的强制转型）。

## 泛型类

泛型类的基本定义方式为：

```kotlin
class Box<T>(val value: T)
```

在实例化某个泛型类时，可以采用以下方式：

```kotlin
val explicit: Box<Int> = Box<Int>(1)
val inferred = Box("text")          // 编译器推断为 Box<String>
```

类型参数可以有多个，习惯上用 `K`、`V` 表示键值，用 `E` 表示元素，用 `R` 表示返回值：

```kotlin
class Pair2<A, B>(val first: A, val second: B)
```

## 泛型函数

泛型函数的定义如下：

```kotlin
fun <T> singletonList(item: T): List<T> = listOf(item)
```

类型参数写在函数名之前。调用时通常不需要显式指定类型实参，编译器会从参数推断：

```kotlin
val numbers = singletonList(1)          // List<Int>
val strings = singletonList<String>("a") // 也可以显式指定
```

### 类型上界与 where

Kotlin 允许开发者以 `<T : BaseType>` 的形式对泛型类型**上界**进行限制，例如 `<T : Number>` 就表示仅允许传入 `Int`、`Float` 以及 `Double` 等继承于 `Number` 基类的类型：

```kotlin
fun <T : Number> addAsDouble(a: T, b: T): Double = a.toDouble() + b.toDouble()
```

在默认情况下，所有泛型的上界都是可空的 `Any?`。如果想让泛型类型不可为空，就将上界修改为不带 `?` 的类型：

```kotlin
fun <T : Any> requireNonNullValue(value: T?): T = value ?: error("null")
```

当需要**多个上界**时，尖括号里只能写一个，其余的要放到 `where` 子句中：

```kotlin
fun <T> copyWhenGreater(list: List<T>, threshold: T): List<String>
        where T : CharSequence,
              T : Comparable<T> {
    return list.filter { it > threshold }.map { it.toString() }
}
```

传入的类型必须同时满足 `where` 中的全部约束。

## 泛型擦除

Java 的泛型只在**编译期**存在：编译器用类型实参做类型检查，但生成的字节码里并不保留类型实参，这个过程称为**泛型擦除**。擦除并不是一律擦成 `Object`，而是擦到类型参数的**上界**：`<T>` 擦成 `Object`，`<T : Number>` 擦成 `Number`。

擦除带来的直接结果是：运行期只能看到“某种 `Box`”，看不到它装的到底是 `String` 还是 `Int`。因此 JVM 上的泛型有这样几条限制：

| 限制 | 具体表现 | Kotlin 的处理方式 |
| :--- | :--- | :--- |
| 泛型实参不能是基本类型 | `List<int>` 非法 | `Int` 等类型在泛型位置自动装箱为 `Integer`，源码可以写 `List<Int>`，代价是装箱开销 |
| 无法获取带类型实参的 `Class` | `List<String>::class` 非法 | 只能取 `List::class`；需要保留实参信息时用 `typeOf<List<String>>()` |
| 无法判断带类型实参的类型 | `value is List<String>` 非法 | 用星投影 `value is List<*>` |
| 不能直接实例化 `T` | `T()` 非法 | 用 `reified` 配合 `T::class` 反射创建，或 `arrayOfNulls<T>()` |
| 不能创建泛型数组 | `Array<T>(size)` 非法 | `reified` 之后可以 `arrayOfNulls<T>(size)` |

例如下面这段代码，第二个判断无法通过编译：

```kotlin
fun check(value: Any) {
    if (value is List<*>) {
        println("是任意元素类型的 List")
    }
    // if (value is List<String>) { }  // 编译错误：Cannot check for instance of erased type
}
```

`List<*>` 之所以合法，是因为它不要求知道元素的具体类型，只要求“这是个 `List`”。

## 泛型实化

擦除让泛型在运行期“失忆”，但有些场景确实需要在运行期拿到类型，例如 `startActivity<DetailActivity>()`、`Json.decodeFromString<T>()` 这类 API。Kotlin 的办法是**泛型实化**：把函数声明为内联函数，编译器在编译期把类型实参直接替换进函数体，于是 `T` 在函数体内就像一个普通类一样可用。

```kotlin
inline fun <reified T> Any.isInstanceOf(): Boolean = this is T

inline fun <reified T : Activity> Context.startActivity() {
    startActivity(Intent(this, T::class.java))
}
```

泛型实化必须同时满足两个条件：

1. 函数是 `inline` 的；
2. 类型参数用 `reified` 修饰。

实化之后，`is T`、`as T`、`T::class`、`T::class.java`、`typeOf<T>()` 都可以使用：

```kotlin
inline fun <reified T> create(): T =
    T::class.java.getDeclaredConstructor().newInstance()

inline fun <reified T> typeName(): String = typeOf<T>().toString()
```

> `reified` 只对**编译期已知**的类型实参有效。如果把一个非实化的类型参数（例如外层函数的 `T`）继续传给 `reified` 参数，编译器会报错，因为它在编译期无法确定具体类型。

实化的原理并不神秘：内联函数会把函数体复制到调用处，此时编译器已经知道 `T` 是什么，直接把 `T` 替换成具体类型即可，所以不需要运行期的类型信息。它与[[1. 函数式编程#内联函数|内联函数]]是同一套机制的两个用途。

## 协变与逆变

型变（variance）描述的是：当 `A` 是 `B` 的子类型时，`Box<A>` 与 `Box<B>` 之间是否也存在子类型关系。

- **协变**：`Box<A>` 也是 `Box<B>` 的子类型，方向与 `A → B` 一致；
- **逆变**：`Box<B>` 是 `Box<A>` 的子类型，方向与 `A → B` 相反；
- **不变**：两者没有任何子类型关系。

用“生产/消费”来理解更直观：如果 `Box<T>` 只会**产出** `T`（`T` 只出现在返回值位置），那么它天然是协变的——一个能产出 `String` 的盒子，当然也能当作“能产出 `Any` 的盒子”使用。反过来，如果 `Box<T>` 只会**消费** `T`（`T` 只出现在参数位置），它就是逆变的——一个能接收 `Any` 的盒子，当然也能接收 `String`。

### 声明处型变

Kotlin 使用 `out` 关键字修饰协变的类型参数，使用 `in` 关键字修饰逆变的类型参数，直接写在类型参数声明处：

```kotlin
interface Producer<out T> {
    fun produce(): T
}

interface Consumer<in T> {
    fun consume(value: T)
}
```

这样声明之后，子类型关系自动成立：

```kotlin
val stringProducer: Producer<String> = TODO()
val anyProducer: Producer<Any> = stringProducer       // OK，协变

val anyConsumer: Consumer<Any> = TODO()
val stringConsumer: Consumer<String> = anyConsumer    // OK，逆变
```

编译器会检查类型参数的使用位置：`out T` 不能出现在参数位置，`in T` 不能出现在返回值位置（`private` 成员不受此限制，因为它不会暴露给外部）。这正是“只读/只写”约束的编译期保障。

### 使用处型变

有些类既读又写 `T`，无法在声明处标成 `out` 或 `in`，例如 `Array<T>`（既有 `get` 又有 `set`）。这时可以在**使用处**做类型投影：

```kotlin
// from 只读，不能写入
fun copy(from: Array<out Any>, to: Array<Any>) {
    for (i in from.indices) {
        to[i] = from[i]
    }
}

// dest 只写，可以接收 Array<String>、Array<CharSequence> 或 Array<Any>
fun fill(dest: Array<in String>, value: String) {
    dest[0] = value
}
```

### 星投影

当对类型实参一无所知、但又想安全地使用时，可以用星投影 `Foo<*>`：

```kotlin
fun printAll(list: List<*>) {
    list.forEach { println(it) }   // 读出的元素按上界处理，这里是 Any?
}

fun clearAll(list: MutableList<*>) {
    list.clear()                   // 与元素类型无关的操作可以调用
    // list.add("x")               // 编译错误：不知道具体类型，无法安全写入
}
```

星投影的规则可以归纳为：

| 声明形式 | `Foo<*>` 等价于 | 能读出的类型 | 能否写入 |
| :--- | :--- | :--- | :--- |
| `Foo<out T : TUpper>` | `Foo<out TUpper>` | `TUpper` | 不能 |
| `Foo<in T>` | `Foo<in Nothing>` | 无 | 不能 |
| `Foo<T : TUpper>` | 读 `Foo<out TUpper>`、写 `Foo<in Nothing>` | `TUpper` | 不能 |

星投影看起来像 Java 的原始类型（raw type），但它是**类型安全**的：编译器不允许你往 `MutableList<*>` 里塞任何值，从而避免了 `ClassCastException`。

### Java通配符与PECS

Java 没有声明处型变，只能在每次使用时写通配符，两者一一对应：

| Kotlin | Java | 含义 |
| :--- | :--- | :--- |
| `Box<out T>` | `Box<? extends T>` | 生产者，只读 |
| `Box<in T>` | `Box<? super T>` | 消费者，只写 |

这也引申出集合框架里常用的 **PECS 原则**：Producer 用 `extends`，Consumer 用 `super`。例如 `Collections.copy(List<? super T> dest, List<? extends T> src)`，目标列表只写所以用 `super`，源列表只读所以用 `extends`。

Kotlin 编译成 Java 字节码时，会把协变类型参数在**参数位置**展开成通配符：`fun unboxBase(box: Box<Base>)` 生成的签名是 `unboxBase(Box<? extends Base>)`，而返回值位置不生成。类型实参是 `final` 类时（例如 `String`）通配符没有意义，也不会生成。需要精确控制时，用 `@JvmWildcard` 强制生成，或用 `@JvmSuppressWildcards` 抑制。

### 型变与集合

标准库的集合接口就是型变的最佳例子：

```kotlin
val strings: List<String> = listOf("a", "b")
val anys: List<Any> = strings            // OK：List<out E> 是协变的

val mutableStrings: MutableList<String> = mutableListOf("a")
// val mutableAnys: MutableList<Any> = mutableStrings  // 编译错误：MutableList<E> 是不变的
```

`List<out E>` 只提供读取，所以协变；`MutableList<E>` 既能读又能写，只能不变。这也解释了 Kotlin 为什么要把集合拆成只读的 `List` 和可变的 `MutableList` 两个接口：**可写的容器必须不变**，否则就能通过 `MutableList<Any>` 的视图，把 `Int` 塞进一个实际是 `MutableList<String>` 的列表里，直到运行时才暴露问题。

标准库中还有其他型变的例子：`Comparable<in T>` 只消费 `T`，所以是逆变；`Function1<in P1, out R>` 的参数是 `in`、返回值是 `out`，同一个类型上两种型变可以并存。

如果确实需要在 `out T` 的参数位置使用 `T`，可以用 `@UnsafeVariance` 让编译器放行：

```kotlin
interface Box<out T> {
    fun get(): T
    fun set(value: @UnsafeVariance T)
}
```

这个注解只是关掉了编译器的检查，类型安全要由开发者自己保证，绝不能滥用。

**总结：协变让 `Box<子>` 能当作 `Box<父>` 来读，逆变让 `Box<父>` 能当作 `Box<子>` 来写，不变则两个方向都不允许。**
