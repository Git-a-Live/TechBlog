函数式编程（Functional Programming）是一种抽象程度很高的编程范式，纯粹的函数式编程语言编写的函数没有变量，因此，任意一个函数，只要输入是确定的，输出就是确定的，这种纯函数称之为**没有副作用**（无状态）。而允许使用变量的程序设计语言，由于函数内部的变量状态不确定，同样的输入，可能得到不同的输出，因此，这种函数是有副作用（有状态）的。

函数式编程的一个特点就是，允许把函数本身作为参数传入另一个函数，还允许返回一个函数。

比起指令式编程，函数式编程更加强调程序执行的结果而非执行的过程，倡导**利用若干简单的执行单元让计算结果不断渐进，逐层推导复杂的运算**，而不是设计一个复杂的执行过程。

Kotlin 是一门从一开始就支持函数式编程的语言，主要包括以下特性：

1. 支持函数类型，允许函数接收其他函数作为参数，或返回其他函数；
2. 支持 Lambda 表达式，用最少的样板代码方便地传递代码块；
3. 数据类，提供了创建不可变数据对象的简明语法；
4. 标准库中提供丰富的函数式 API，可用函数式编程风格操作对象和集合。

## Lambda表达式

Lambda 表达式本质上是**可以传递给其它函数的一小段代码**。有了 Lambda，可以轻松地把通用代码结构抽取成库函数。Lambda 最常见的用途是和集合一起配合。

在 Kotlin 中，完整的 Lambda 表达式语法结构如下：

```kotlin
{ arg1: Type1, arg2: Type2, ... -> functionBody }
```

函数体内<u>最后一行代码会自动作为返回值</u>，通常不建议在函数体部分编写太多太长的代码（最好能整合成函数调用），否则可能会影响代码的可读性。

Kotlin 对于 Lambda 的使用有以下规定：

- Lambda 表达式的参数通常可以**不声明类型**，由编译器从上下文推断；
- 在调用可接收 Lambda 表达式的函数时，可以直接传入表达式；
- 若 Lambda 表达式是函数的**最后**一个参数，可将其放在函数括号之外；
- 若 Lambda 表达式是函数的**唯一**一个参数，可将函数括号去掉；
- 若 Lambda 表达式中只有一个参数，可以不声明其名称，而是用 `it` 来代替；
- 若 Lambda 有多个参数但只想使用其中一部分，可以用下划线 `_` 占位，表示该参数不使用。

最典型的例子就是在 Kotlin 开发情况下，Android 控件 Button 监听点击动作：

```kotlin
button.setOnClickListener { view ->
    // TODO
}
```

当 Lambda 的参数没有被使用时，可以进一步省略成 `{ }`，此时 `it` 依然指向那个唯一的参数。

## 函数类型

既然 Lambda 是“一段可以传递的代码”，编译器就必须为它安排一个类型。Kotlin 用下面这种形式描述函数类型：

```text
(Type1, Type2, ...) -> ReturnType
```

左边是各个传入参数的类型，右边是返回结果的类型。不返回有意义的结果时，返回类型写 `Unit`；参数列表为空时写 `() -> Unit`。函数类型本身也可以为可空，此时整体加上括号：`((Int) -> String)?`。

有了函数类型，就可以像声明普通变量一样声明一个“存放函数的变量”：

```kotlin
val printer: (String) -> Unit = { message -> println(message) }
val provider: () -> Int = { 42 }

printer("hello")
println(provider())
```

函数类型也可以作为返回值，这正是“返回一个函数”的实现方式：

```kotlin
fun counter(): () -> Int {
    var count = 0
    return { ++count }
}
```

函数类型在 JVM 上会被编译成 `FunctionN` 接口的实例，调用时执行的是 `invoke()`。例如 `(String) -> Int` 对应 `Function1<String, Int>`：

```kotlin
val length: (String) -> Int = { it.length }
println(length.invoke("kotlin")) // 6
```

> 用 `fun` 声明的具名函数是**声明**而不是表达式，不能像变量那样直接传递。要把它变成函数类型的对象，需要用 `::` 取函数引用（详见[[#高阶函数]]）；而 Lambda、匿名函数本身就是函数类型的对象。

当同一个函数类型在代码里反复出现时，可以用 `typealias` 起个别名，避免签名越写越长：

```kotlin
typealias OnResult = (Boolean, String?) -> Unit

fun request(callback: OnResult) {
    callback(true, "ok")
}
```

## 常用函数式API

### 集合

Lambda 表达式经常同集合搭配使用，这意味着集合类中有大量的函数式 API 可供调用。下面列出了一些常见的 API。

| API | 作用 | 备注 |
| :--- | :--- | :--- |
| `filter` | 选出应用给定 Lambda 后返回 `true` 的元素 | 返回新 `List` |
| `map` | 对每个元素应用给定 Lambda，收集结果 | 返回新 `List` |
| `mapNotNull` | 先 `map` 再剔除 `null` | 结果类型自动收窄为非空 |
| `flatMap` | 先映射再展平 | 常用于“一对多” |
| `reduce` | 从第一个元素开始累积 | 空集合会抛异常 |
| `fold` | 从指定初始值开始累积 | 空集合安全，且可改变结果类型 |
| `all` / `any` / `none` | 全部满足 / 存在满足 / 全部不满足 | 空集合时 `all`、`none` 为 `true` |
| `count` | 统计满足条件的元素个数 | 不传条件等价于 `size` |
| `find` | 返回第一个满足条件的元素 | 没有则返回 `null`，等价于 `firstOrNull` |
| `maxByOrNull` / `minByOrNull` | 按给定条件找极值元素 | 集合为空返回 `null` |
| `maxOf` / `minOf` | 按给定条件取极值本身 | 不需要元素对象时更直接 |
| `groupBy` | 按条件分组 | 返回 `Map<K, List<T>>` |
| `associateBy` | 按条件建立索引 | 返回 `Map<K, T>`，键重复时后者覆盖前者 |
| `partition` | 按条件一分为二 | 返回 `Pair<List<T>, List<T>>` |
| `sortedBy` / `sortedByDescending` | 按条件排序 | 返回新 `List` |
| `zip` | 把两个集合逐项配对 | 返回 `List<Pair<A, B>>`，以短的一方为准 |
| `distinct` | 去重 | 依据 `equals` / `hashCode` |
| `take` / `drop` | 取前 n 个 / 去掉前 n 个 | 越界不会抛异常 |
| `sumOf` | 按条件求和 | 结果类型由选择器决定 |

> `maxBy` / `minBy` 自 Kotlin 1.4 起废弃，1.6 起已从标准库中隐藏，应改用 `maxByOrNull` / `minByOrNull`。

这些 API 可以链式组合，例如筛出启用状态的前 10 个用户名：

```kotlin
val names = users
    .filter { it.enabled }
    .sortedBy { it.name }
    .map { it.name }
    .take(10)
```

需要留意的是，上面每一步都会创建一个中间集合。链式调用较长、数据量较大时，可以先用 `asSequence()` 转成序列，让整个链条只遍历一次：

```kotlin
val names = users.asSequence()
    .filter { it.enabled }
    .sortedBy { it.name }
    .map { it.name }
    .take(10)
    .toList()
```

序列是惰性的：没有终结操作（`toList()`、`count()`、`first()` 等）时，前面的步骤不会执行。

### Kotlin标准函数

Kotlin 标准库提供了一批常用的作用域函数（习惯上也叫标准函数），大多定义在 `kotlin/Standard.kt` 中，任何 Kotlin 代码都能自由调用。它们都接收一个 Lambda，区别只在于**接收者怎么引用**以及**返回什么**：

| 函数 | Lambda 内引用接收者 | 返回值 | 典型场景 |
| :--- | :--- | :--- | :--- |
| `let` | `it` | Lambda 最后一行 | 判空后使用、把值映射成另一种结果 |
| `run` | `this` | Lambda 最后一行 | 配置对象并计算一个结果 |
| `with` | `this` | Lambda 最后一行 | 对同一对象连续调用多个方法 |
| `apply` | `this` | 接收者本身 | 对象初始化 |
| `also` | `it` | 接收者本身 | 附加操作（日志、校验）后原样返回 |
| `takeIf` / `takeUnless` | `it` | 接收者或 `null` | 条件过滤 |

下面分别说明。

- **let**

`let` 函数经常和 `?.` 操作符搭配使用，用于辅助判空处理，避免空指针异常：

```kotlin
val value = obj?.let {
    // it 就是非空后的 obj
    it.doSomething()
}
```

上述代码的含义为先判断 `obj` 是否为空，不为空则执行 `let` 内的业务逻辑，为空就不做任何操作。在 Lambda 内部应当使用 `it` 而不是再次访问外部的 `obj`：`it` 是判空那一刻的值，即使 `obj` 是可能被其他线程修改的全局变量，也不会在判空之后又变回 `null`。

- **also**

`also` 在用法上和 `let` 基本一样，但它只返回调用的对象本身，适合插入一段不影响结果的附加操作：

```kotlin
val user = createUser().also {
    Log.d(TAG, "created: ${it.id}")
}
```

- **with**

`with` 不是扩展函数，需要把对象作为第一个参数传入，可以连续调用同一对象的多个方法，使得代码变得精简：

```kotlin
val result = with(button) {
    text = "确定"
    isEnabled = true
    performClick()
}
```

- **run**

`run` 的使用场景和 `with` 类似，但是它需要通过一个对象来调用；此外还有一个不依赖接收者的版本，相当于一个可以返回值的代码块：

```kotlin
val value = obj.run {
    // this 就是 obj
    computeResult()
}

val config = run {
    val density = resources.displayMetrics.density
    Config(density, Build.VERSION.SDK_INT)
}
```

- **apply**

`apply` 在使用上与 `run` 极其类似，但是它**无法指定返回值**，只会自动返回调用对象本身，因此特别适合对象的链式初始化：

```kotlin
val intent = Intent(context, DetailActivity::class.java).apply {
    putExtra("id", id)
    flags = Intent.FLAG_ACTIVITY_NEW_TASK
}
```

- **takeIf / takeUnless**

`takeUnless` 在逻辑上与 `takeIf` 相反，因此这里只介绍 `takeIf`。`takeIf` 通过对象来调用，传入一个条件进行判断，如果对象符合条件则返回自身，反之则返回 `null`：

```kotlin
val validName = input.takeIf { it.isNotBlank() } ?: "anonymous"
```

- **repeat**

`repeat` 不需要依赖对象调用，使用时传入执行次数和 Lambda 表达式：

```kotlin
repeat(3) { index ->
    println("第 $index 次")
}
```

- **use**

`use` 是 `Closeable` / `AutoCloseable` 的扩展函数，无论是否抛出异常都会关闭资源，等价于 Java 的 try-with-resources：

```kotlin
FileInputStream(file).use { input ->
    input.readBytes()
}
```

## 高阶函数

### 基本概念

高阶函数（Higher-order function）是一种以函数为参数或返回值的函数，因此前文所提到的各种函数式 API，本身就是高阶函数。掌握高阶函数的用法可以编写自定义函数式 API。

在 Kotlin 中，除了整型、字符型和布尔型等类型之外，还有一种“函数类型”。有了函数类型，就可以声明函数类型的变量、参数和返回值，其语法就是上一节介绍的 `(Type1, Type2, ...) -> Type`。

### 基本使用方式

高阶函数的主要作用是让作为参数或返回结果的函数类型对象来决定执行逻辑，从而输出不同的结果。就“替换执行逻辑”而言，高阶函数有点类似于设计模式中的[[行为型设计模式#九、Strategy|Strategy]]。

一个高阶函数的常见构造方式如下：

```kotlin
fun calculate(a: Int, b: Int, operation: (Int, Int) -> Int): Int {
    return operation(a, b)
}

val sum = calculate(3, 4) { x, y -> x + y }   // 7
```

调用高阶函数传入函数类型对象时，通常采用以下几种方式。

1. **Lambda 表达式**

Lambda 表达式本质上就是函数类型对象，正因如此，它才能被赋值给别的变量，或是以自身作为参数传入高阶函数使用。

```kotlin
calculate(3, 4) { x, y -> x + y }
```

2. **匿名函数**

顾名思义，匿名函数就是一种没有名称的函数，<u>其定义方式跟普通函数基本相同</u>，只不过不需要写函数名称。匿名函数和 Lambda 表达式一样，本质上也是函数类型对象。参数类型在上下文能推断时可以省略；它与 Lambda 最大的区别在于可以显式写出返回类型，而且 `return` 返回的是匿名函数自身，不是外层函数。另外，匿名函数必须写在括号内，不能像 Lambda 那样作为尾随 Lambda 放到括号外：

```kotlin
calculate(3, 4, fun(x: Int, y: Int): Int {
    return x + y
})
```

3. **函数引用**

函数引用是一种将函数转化为函数类型对象的手段，其基本做法就是在作为参数的函数的名称前加上 `::`。虽然这种手段的名字叫函数引用，但实际上是创建了一个与原来的函数具有相同功能的函数类型对象：

```kotlin
fun square(x: Int): Int = x * x

val f: (Int) -> Int = ::square
```

4. **成员引用**

成员引用和函数引用类似，但需要指明是哪个类或哪个实例的成员。以下是一段示例代码：

```kotlin
// 包含待引用函数的类定义
class Demo {
    fun foo(p1: Int, p2: String): Boolean = p1 > 0 && p2.isNotEmpty()
}

// 采取成员引用的高阶函数定义
fun func(f: KFunction3<Demo, Int, String, Boolean>) {
    println(f.name)
}

// 调用高阶函数
func(Demo::foo)
```

传入高阶函数的参数类型为 `KFunctionN<>`。其中 N 是**值参数个数**，未绑定接收者的成员引用会把接收者算作第一个参数；尖括号内依次是这 N 个参数的类型，最后再加上返回值类型，共 N+1 个类型实参。上面的 `Demo::foo` 有“接收者 + 两个参数”共 3 个值参数，返回值是 `Boolean`，所以类型是 `KFunction3<Demo, Int, String, Boolean>`。

如果引用的是某个具体实例的成员，接收者会被绑定掉，类型参数里就不再出现它：

```kotlin
val demo = Demo()
val bound: KFunction2<Int, String, Boolean> = demo::foo
```

### 内联函数

使用高阶函数是有运行时代价的：每个函数类型对象都要占用一次内存分配，并且会捕获闭包（即 Lambda 内部访问到的外部变量），调用还要经过虚方法分派。为了解决这一问题，Kotlin 采用**内联函数**的机制，即**Kotlin 会将内联函数中的代码在编译时自动替换到调用它的地方**，Lambda 的函数体也会被直接展开，不再创建对象。

内联函数的用法非常简单，就是在定义好的高阶函数前用 `inline` 关键字进行修饰：

```kotlin
inline fun measure(block: () -> Unit) {
    val start = System.nanoTime()
    block()
    println("cost: ${System.nanoTime() - start} ns")
}
```

如果只想内联一部分函数类型参数，那么就在不需要内联的函数类型参数前加上 `noinline` 进行修饰。被 `noinline` 标记的 Lambda 可以像普通对象一样保存到字段里，或继续传给其他函数：

```kotlin
inline fun foo(inlined: () -> Unit, noinline notInlined: () -> Unit) {
    val task = notInlined   // 合法：noinline 参数可以当对象使用
    inlined()
    task()
}
```

内联函数的 Lambda 支持**非局部返回**，也就是在 Lambda 里直接 `return` 退出外层函数：

```kotlin
fun hasZero(numbers: List<Int>): Boolean {
    numbers.forEach {
        if (it == 0) return true   // forEach 是内联函数，这里的 return 退出 hasZero
    }
    return false
}
```

但如果内联函数把 Lambda 放到**另一个执行上下文**中调用（例如塞进 `Runnable`、局部对象或嵌套函数），编译器就无法保证非局部返回时的调用栈，此时必须用 `crossinline` 修饰该参数，Lambda 内也不能再直接 `return`，只能使用 `return@label` 做局部返回：

```kotlin
inline fun post(crossinline action: () -> Unit) {
    val runnable = Runnable { action() }   // action 在 Runnable 里执行
    runnable.run()
}
```

`inline` 只对包含函数类型参数（或 `reified` 类型参数）的函数才有明显收益。普通函数即使内联也不会减少对象分配，反而会让字节码膨胀，编译器会对这种“没有可内联内容”的 `inline` 给出警告，可以用 `@Suppress("NOTHING_TO_INLINE")` 抑制。

还有一条限制：`public` / `protected` 的内联函数属于模块的公开 API，其函数体会被复制到其他模块，因此**不能访问 `private` 或 `internal` 声明**。确实需要访问时，给那个 `internal` 声明加上 `@PublishedApi`：

```kotlin
@PublishedApi
internal fun internalHelper(): String = "internal"

inline fun publicApi(): String = internalHelper()   // 没有 @PublishedApi 则编译失败
```

属性也可以内联，但只能内联**没有 backing field** 的访问器：

```kotlin
val currentTimeMillis: Long
    inline get() = System.currentTimeMillis()
```

需要让内联函数“看见”具体的类型实参时，还要配合 `reified`，详见[[3. 泛型#泛型实化|泛型实化]]。

## DSL

DSL（Domain Specific Language，领域特定语言）是一种**以极其高效的方式描述特定领域的对象、规则和运行方式的语言**。DSL 分为两类：

- **外部 DSL**：拥有独立的语法和解析器，例如 SQL、正则表达式、模板语言；
- **内部 DSL**：不发明新语法，而是借用宿主语言的语法糖，把 API 设计得像一门小语言。Kotlin DSL 属于这一类，不需要额外的解释器，编译器就是它的解释器。

Kotlin 支持 DSL，并且实现方式也并不固定，最主要的有 infix 函数和高阶函数。

### infix函数实现DSL

infix 函数是 Kotlin 提供的一种高级语法糖，它可以让开发者使用被称作“中缀表示法”的语法规则，亦即忽略调用的点 `.` 与圆括号 `()`，类似于自然语言，即调用 infix 函数时，`A foo B` 等同于 `A.foo(B)`。最典型的应用就是 Kotlin 自带 `mapOf()` 函数中的 `key to value` 语法。

infix 函数具有以下特点：

- 必须是成员函数或[[2. 延迟初始化、扩展函数与密封类#扩展函数|扩展函数]]；
- 必须只有一个参数；
- 其参数不得接受可变数量的参数且不能有默认值；
- 调用优先级低于算术操作符、类型转换以及 `rangeTo` 操作符，但高于布尔操作符 `&&` 与 `||`、`is` 与 `in` 检测以及其他一些操作符。

infix 函数的定义和普通函数的主要区别在于要使用 `infix` 关键字修饰：

```kotlin
// infix 修饰成员函数
class Demo {
    infix fun match(param: Int): Boolean = param > 0
}

// infix 修饰扩展函数
infix fun <K, V> K.withValue(value: V): Pair<K, V> = this to value
```

`to` 本身就是标准库里的 infix 扩展函数，返回一个 `Pair`：

```kotlin
val map = mapOf("a" to 1, "b" to 2)
```

### 高阶函数实现DSL

使用高阶函数实现自定义 DSL 的场景、形式多种多样，限于篇幅不可能一一详解，但其核心思想是不变的：**利用带接收者的高阶函数，把嵌套的对象构造写成连续的代码块**。关键在于把 Lambda 的接收者类型声明为目标类，这样在 Lambda 内部就能直接访问该类的成员：

```kotlin
class Dialog {
    var title: String = ""
    var message: String = ""
}

fun dialog(block: Dialog.() -> Unit): Dialog = Dialog().apply(block)

val confirm = dialog {
    title = "提示"
    message = "确定要删除吗？"
}
```

当 DSL 出现多层嵌套时，内层 Lambda 会“看见”外层的接收者，容易误调用外层的方法。给接收者类标上同一个 `@DslMarker` 注解，可以限制这种跨层的隐式访问：

```kotlin
@DslMarker
annotation class DialogDsl

@DialogDsl
class Dialog { /* ... */ }
```

Gradle 的 Kotlin DSL 就是这一套思路的产物，依赖声明可以写成与 Groovy 十分相似的形式：

```groovy
// Gradle Groovy DSL
dependencies {
    implementation 'com.squareup.okhttp3:okhttp:4.12.0'
}
```

```kotlin
// Gradle Kotlin DSL
dependencies {
    implementation("com.squareup.okhttp3:okhttp:4.12.0")
}
```
