## 何为注解

注解（annotation）是一种元数据标签，用来给类、函数、属性、参数等元素附加说明。它和注释的区别在于：注释会被编译器忽略，注解则按保留策略被写入字节码，甚至保留到运行期，供编译器、注解处理器或反射读取。

Kotlin 当中的注解概念跟 Java 是一样的，并且 Kotlin 能完全兼容 Java 注解，因此在讨论注解的时候，除了部分语法差异需要说明外，一般不会区分到底是 Kotlin 注解还是 Java 注解。

按照保留策略（`@Retention`），注解可以大致分为以下三类：

- **源码注解**（`SOURCE`）：只在编译期可见，编译完成后就被丢弃，不会进入字节码。`@Override`、`@Suppress` 都属于这一类。
- **字节码注解**（`BINARY` / Java 的 `CLASS`）：会被写入字节码文件，但类加载后不会保留在内存里，运行期无法通过反射读取。这类注解主要供字节码处理工具使用，开发者一般不需要自己处理。
- **运行时注解**（`RUNTIME`）：写入字节码并保留到运行期，可以通过反射读取，是自定义注解最常用的一类。

两种语言的默认值并不相同：**Kotlin 的 `@Retention` 默认是 `RUNTIME`，Java 的 `@Retention` 默认是 `CLASS`**。这意味着在 Kotlin 里写一个不带 `@Retention` 的注解，默认就能被反射读到；而从 Java 迁过来的注解如果不写 `@Retention`，运行期是读不到的。

对于开发者而言，一些由语言标准库和第三方依赖库所提供的现成注解，使用起来通常并不会有什么问题，除非完全看不懂文档和示例。因此这里先说明如何自定义注解——理解了自己写的注解如何被读取，也就理解了现成注解是如何发挥作用的；常见注解的速查表放在文末。

## 自定义注解

### 定义注解

#### 声明

在 Kotlin 语言中，声明一个自定义注解的方式如下：

```kotlin
annotation class Demo(val value: String)
```

而 Java 当中的声明方式为：

```java
public @interface Demo {
    String value();
}
```

可以发现，Kotlin 声明注解的方式跟普通的 class 基本一样，只不过多了一个 `annotation` 修饰符。而 Java 声明注解的方式更接近于声明一个接口。

注解类不能有函数体，也不能声明 `init` 块；它的参数会直接成为注解的属性。

#### 参数

注解当中可以使用参数，注解支持的参数类型有：

- 基本类型；
- 字符串；
- 类引用（Kotlin 写 `Foo::class`，编译后自动转成 Java 的 `Class`）；
- 枚举；
- 其他注解；
- 上述类型的数组。

```kotlin
enum class Method { GET, POST }

annotation class Request(
    val path: String,
    val method: Method = Method.GET,
    val headers: Array<String> = []
)
```

有两条限制需要记住：

- 参数**不能是可空类型**，因为 JVM 不支持把 `null` 存进注解属性；
- 传入的实参必须是**编译期常量**，不能是运行期计算出来的表达式。

Kotlin 还允许像调用构造函数一样直接创建注解实例，这在测试或把注解当作配置对象传递时很方便：

```kotlin
annotation class InfoMarker(val info: String)

fun processInfo(marker: InfoMarker) = println(marker.info)

processInfo(InfoMarker("default"))
```

#### 元注解

元注解（meta annotation）是一类可以用来修饰其他注解的注解，通常由语言的标准库定义和内置，开发者一般不需要自己去编写元注解，只要使用现成的即可。下表展示的是 Kotlin 和 Java 当中可以使用的元注解：

| 元注解 | 用途说明 | Kotlin | Java |
| :--- | :--- | :---: | :---: |
| `@Target` | 限定注解的适用范围，如类、字段、函数、参数等 | ✔ | ✔ |
| `@Retention` | 定义注解的生命周期：源码、字节码或运行期 | ✔ | ✔ |
| `@Repeatable` | 允许同一个注解在同一元素上重复使用 | ✔ | ✔ |
| `@MustBeDocumented` / `@Documented` | 声明该注解属于公开 API，应出现在生成的文档中 | ✔（名为 `@MustBeDocumented`） | ✔（名为 `@Documented`） |
| `@Inherited` | 允许子类继承父类上的注解，仅对类级注解有效 | ❌ | ✔ |

Java 的 `@Inherited` 只对**类**生效，对接口无效，而且只影响 `Class.getAnnotations()`（`getDeclaredAnnotations()` 不会返回父类的注解）。Kotlin 没有对应能力——Kotlin 类不会从父类继承注解。

`@Target` 的参数在两种语言里差别较大，先看 Kotlin 的 `AnnotationTarget`：

| Kotlin 目标 | 适用位置 | Java 对应 |
| :--- | :--- | :--- |
| `CLASS` | 类、接口、对象、注解类、枚举类 | `ElementType.TYPE` |
| `ANNOTATION_CLASS` | 注解类 | `ElementType.ANNOTATION_TYPE` |
| `TYPE_PARAMETER` | 泛型类型参数 | `ElementType.TYPE_PARAMETER` |
| `PROPERTY` | 属性（Java 侧不可见） | 无 |
| `FIELD` | 字段，包括属性的 backing field | `ElementType.FIELD` |
| `LOCAL_VARIABLE` | 局部变量 | `ElementType.LOCAL_VARIABLE` |
| `VALUE_PARAMETER` | 函数/构造函数的参数 | `ElementType.PARAMETER` |
| `CONSTRUCTOR` | 构造函数 | `ElementType.CONSTRUCTOR` |
| `FUNCTION` | 函数、方法 | `ElementType.METHOD` |
| `PROPERTY_GETTER` | 属性的 getter | 落到 `ElementType.METHOD` |
| `PROPERTY_SETTER` | 属性的 setter | 落到 `ElementType.METHOD` |
| `TYPE` | **类型用法**，如 `List<@Foo String>` | `ElementType.TYPE_USE` |
| `EXPRESSION` | 表达式 | 无 |
| `FILE` | 文件，需配合 `@file:` 使用 | 无 |
| `TYPEALIAS` | 类型别名 | 无 |

这里最容易混淆的是 `TYPE` 和 `CLASS`：**`CLASS` 才是“标注在类声明上”，`TYPE` 表示“标注在类型引用上”**，它映射到 Java 的 `TYPE_USE`，和类、接口、枚举的声明没有关系。

Java 的 `ElementType` 则包括：`TYPE`、`FIELD`、`METHOD`、`PARAMETER`、`CONSTRUCTOR`、`LOCAL_VARIABLE`、`ANNOTATION_TYPE`、`PACKAGE`、`TYPE_PARAMETER`、`TYPE_USE`、`MODULE`（Java 9+）、`RECORD_COMPONENT`（Java 16+）。

> Android 项目需要留意：注解一旦声明了 `AnnotationTarget.TYPE`，编译出的 Java 目标里就会包含 `TYPE_USE`，而 Android API 26 以下的运行库没有这个枚举值。确实要兼容低版本时，可以加编译参数 `-Xno-new-java-annotation-targets` 阻止生成它。

`@Retention` 的取值对应关系如下：

| 语义 | Kotlin | Java |
| :--- | :--- | :--- |
| 仅源码可见 | `AnnotationRetention.SOURCE` | `RetentionPolicy.SOURCE` |
| 写入字节码，运行期不可见 | `AnnotationRetention.BINARY` | `RetentionPolicy.CLASS` |
| 运行期可反射读取 | `AnnotationRetention.RUNTIME` | `RetentionPolicy.RUNTIME` |

写法上，Kotlin 的数组参数直接逗号分隔，Java 需要花括号：

```kotlin
@Target(AnnotationTarget.CLASS, AnnotationTarget.FUNCTION)
@Retention(AnnotationRetention.RUNTIME)
annotation class Demo
```

```java
@Target({ElementType.TYPE, ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
public @interface Demo {
}
```

`@Repeatable` 的机制也不一样。Java 必须额外声明一个“容器注解”，其 `value()` 返回被重复注解的数组：

```java
@Repeatable(Tags.class)
@interface Tag {
    String name();
}

@interface Tags {
    Tag[] value();
}
```

Kotlin 不需要手写容器，编译器会自动生成一个名为 `Tag.Container` 的容器注解：

```kotlin
@Repeatable
annotation class Tag(val name: String)
```

如果希望 Java 侧看到一个自定义名称的容器，可以用 `@JvmRepeatable` 指定：

```kotlin
@JvmRepeatable(Tags::class)
annotation class Tag(val name: String)

annotation class Tags(val value: Array<Tag>)
```

读取重复注解时，Java 用 `getAnnotationsByType()`，Kotlin 用 `findAnnotations<T>()`。

### 使用处目标

当一个注解写在**主构造函数的属性**或**属性**上时，Kotlin 编译器可能把它放到多个 Java 元素上：构造参数、字段、getter、setter。为了精确指定落点，可以使用使用处目标（use-site target）：

```kotlin
class Example(
    @field:Ann val foo: String,     // 只标注 Java 字段
    @get:Ann val bar: String,       // 只标注 getter
    @param:Ann val quux: String     // 只标注构造参数
)
```

支持的使用处目标包括：

| 目标 | 落点 |
| :--- | :--- |
| `file` | 整个文件，需写在 `package` 之前 |
| `field` | Java 字段 |
| `property` | Kotlin 属性（Java 侧不可见） |
| `get` | 属性 getter |
| `set` | 属性 setter |
| `receiver` | 扩展函数/扩展属性的接收者参数 |
| `param` | 构造参数 |
| `setparam` | setter 的参数 |
| `delegate` | 委托属性保存委托对象的字段 |
| `all` | 一次性传播到 param、property、field、get、setparam 等所有适用位置 |

如果不写使用处目标，编译器会按注解自身 `@Target` 允许的范围，把所有适用的落点都标上：主构造参数上的注解通常同时落到构造参数和字段上；如果注解只支持 Kotlin 属性，则落到 `property`。例如：

```kotlin
// 假设 @Email 同时支持参数与字段
data class User(
    @Email val email: String   // 构造参数和字段上都会带上 @Email
)
```

文件级注解则写成：

```kotlin
@file:JvmName("Foo")

package org.jetbrains.demo
```

`@all:` 适合“希望参数、字段、getter 都带上同一个注解”的场景：

```kotlin
data class User(
    @all:Email val email: String
)
```

### 处理注解

由于开发者自定义的注解绝大多数情况下都是运行时注解，因此这里也主要介绍如何在代码中处理自定义的运行时注解。运行时注解发挥作用的主要方式就是利用[[4. 反射]]机制。

下面就是一个基于自定义注解实现 API 调用时检查请求方法的例子，思路来源于这篇博客 [https://juejin.cn/post/6959860379652456484#heading-12](https://juejin.cn/post/6959860379652456484#heading-12)：

```kotlin
enum class Method {
    GET,
    POST
}

@Target(AnnotationTarget.CLASS)
@Retention(AnnotationRetention.RUNTIME)
annotation class HttpMethod(val method: Method)

interface Api {
    val name: String
    val version: String
        get() = "1.0"
}

@HttpMethod(Method.GET)
class ApiGetArticles : Api {
    override val name: String = "/api/articles"
}

fun fire(api: Api) {
    // 直接从运行期类上取指定类型的注解
    val annotation = api.javaClass.getAnnotation(HttpMethod::class.java)
    println("通过注解得知该接口需要通过：${annotation?.method} 方式请求")
}
```

如果已经引入了 `kotlin-reflect`，也可以用 Kotlin 的写法，省掉 `.java`：

```kotlin
import kotlin.reflect.full.findAnnotation

val annotation = ApiGetArticles::class.findAnnotation<HttpMethod>()
```

`getAnnotation()` 返回当前类上的指定注解；如果该注解带 `@Inherited`，还会沿父类查找。只想要当前类自己声明的注解，用 `getDeclaredAnnotation()`。Kotlin 的 `findAnnotation()` 则只在当前元素的注解列表中筛选，不会自动沿父类查找。

### 编译期处理

运行时注解靠反射读取，灵活但有性能与包体代价。另一条路是**编译期注解处理**：由注解处理器在编译阶段扫描注解，直接生成代码，运行期没有任何反射开销。

在 Android 生态里，这类方案非常常见：

- Room、Hilt、Moshi 的代码生成；
- kotlinx.serialization 的编译器插件；
- 各类路由、ORM、视图绑定框架。

处理器的选择上，`kapt` 已进入维护模式，新项目应优先使用 **KSP**（Kotlin Symbol Processing）。KSP 直接基于 Kotlin 编译器前端解析符号，不需要生成 Java 存根，编译速度明显快于 kapt，也是目前主流库的推荐方式。

## 常见注解

Kotlin 标准库和 JVM 平台提供了一批高频注解，多数与 Java 互操作有关：

| 注解 | 作用 |
| :--- | :--- |
| `@JvmStatic` | 让伴生对象或 `object` 的成员生成真正的静态成员 |
| `@JvmField` | 把属性暴露为字段，不生成 getter/setter |
| `@JvmOverloads` | 为带默认值的参数生成重载方法，方便 Java 调用 |
| `@JvmName` | 修改生成的 JVM 名称（函数、文件、getter 等） |
| `@Throws` | 声明可能抛出的受检异常，供 Java 调用方感知 |
| `@Synchronized` | 将函数或属性访问器标记为同步，等价于 Java 的 `synchronized` 方法 |
| `@Volatile` | 保证字段的可见性，等价于 Java 的 `volatile` |
| `@Transient` | 序列化时忽略该字段 |
| `@Deprecated` | 标记废弃，可指定替换建议与级别 |
| `@Suppress` | 抑制指定的编译警告 |
| `@RequiresOptIn` / `@OptIn` | 标记和选择加入实验性 API |

Android 侧还有一类专用注解，例如 AndroidX 的 `@Keep`（防止被 R8 裁剪）、`@IntDef` / `@StringDef`（用注解替代枚举做取值约束），它们本质上仍是运行时或编译期注解，只是读取方从语言编译器换成了 Android 构建工具。
