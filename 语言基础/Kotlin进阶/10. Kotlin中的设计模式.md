## 第一部分　设计模式总览

### 1.1 设计模式的目的

设计模式的出现和使用，其目的在于**复用**以往成功的设计方案，而不必总是从头开始解决问题。使用设计模式是为了提高代码复用性和可维护性，应当灵活、恰当使用，**切勿过度设计**。

### 1.2 设计模式的基本要素

| 要素 | 含义 |
| --- | --- |
| 模式名称 | 描述一个设计模式的问题、解决方案以及效果 |
| 问题 | 描述何时使用模式 |
| 解决方案 | 描述该设计模式的组成部分，或者说提供一个模版 |
| 效果 | 描述该设计模式的使用对于程序性能的影响 |

### 1.3 三大分类

1. **创建型**：抽象实例化过程，将对象的创建与使用分离。含 Prototype、Singleton、Builder、Abstract Factory、Factory Method。
2. **结构型**：将类或对象按某种布局组成更大的结构。含 Adapter、Bridge、Composite、Decorator、Facade、Flyweight、Proxy。
3. **行为型**：描述多个类或对象之间如何相互协作共同完成任务，涉及算法与对象间职责的分配。含 Chain of Responsibility、Command、Interpreter、Iterator、Mediator、Memento、Observer、State、Strategy、Template Method、Visitor。

## 第二部分　面向对象设计的六大原则

### 2.1 单一职责原则（SRP）

> 一个类应该只有一个发生变化的原因。

一个对象不应承担过多职责，"万金油"式设计会造成代码冗余、耦合度上升。Kotlin 中可用**扩展函数**将附属职责从核心类中剥离，避免类体膨胀：

```kotlin
// 核心类只保留自身职责
class User(val name: String, val email: String)

// 序列化、校验等附属职责用扩展函数外置，不污染 User
fun User.toJson(): String = """{"name":"$name","email":"$email"}"""
fun User.isValidEmail(): Boolean = email.contains("@")
```

### 2.2 开闭原则（OCP）

> 对扩展开放，对修改关闭。

应利用抽象、继承、多态，而非直接修改顶层对象。Kotlin 的 `sealed` 与扩展函数是落实该原则的两大利器：

```kotlin
// 对扩展开放：新增状态只需新增一个子类型，不修改已有代码
sealed interface Payment { val amount: Double }
data class WeChatPay(override val amount: Double) : Payment
data class AliPay(override val amount: Double) : Payment

// 对修改关闭：Kotlin 类默认 final，需显式 open 才能被继承
open class BaseView
// class FinalView : BaseView() // 若 BaseView 未标记 open 则编译失败
```

### 2.3 里氏替换原则（LSP）

> 所有引用基类的地方必须能透明地使用其子类的对象。

可以用父类的地方同样可以用子类。Kotlin 默认 `final`，避免了 Java 中"默认可继承导致被随意重写"的隐患，让继承关系更受控：

```kotlin
open class Animal { open fun sound() = "..." }
class Dog : Animal() { override fun sound() = "汪" }

fun describe(a: Animal) = a.sound()   // 传 Dog 完全透明
```

### 2.4 迪米特法则（LoD）

> 只与你的直接朋友交谈，不跟"陌生人"说话。

不直接通信的实体不应发生直接调用，应通过第三方转发，以降低耦合。Kotlin 的可见性修饰符 `private` / `internal` 可强制约束"谁能和谁交谈"：

```kotlin
class Engine { fun start() {} }
class Car(private val engine: Engine) {           // 依赖注入，而非 new
    fun start() = engine.start()                   // Car 只与直接朋友 Engine 交谈
}
// internal：模块内可见，模块外不可访问，进一步收窄耦合面
internal class InternalHelper
```

### 2.5 接口隔离原则（ISP）

> 客户端不应该依赖它不需要的接口。

每个接口应承担独立角色。Kotlin 接口支持默认实现、且可用 `fun interface` 声明单抽象方法接口，便于拆分出小而专的接口：

```kotlin
interface Printer { fun print(doc: String) }
interface Scanner { fun scan(): String }

// 只实现需要的接口，而非一个臃肿的"万金油"接口
class SimplePrinter : Printer { override fun print(doc: String) = println(doc) }

// fun interface：单抽象方法接口，可用 lambda 直接实例化
fun interface OnClick { fun onClick(view: View) }
val listener = OnClick { view -> /* ... */ }
```

### 2.6 依赖倒置原则（DIP）

> 上层模块不应依赖底层模块，二者都应依赖抽象。

面向接口编程，不要面向实现编程。Kotlin 中抽象不仅可以是接口，**函数类型**本身也是一种抽象：

```kotlin
interface Repository { fun getUser(id: Int): User }

class UserService(private val repo: Repository) {   // 依赖抽象，不依赖具体实现
    fun get(id: Int) = repo.getUser(id)
}

// 更进一步：用函数类型作为抽象
class Cache(private val loader: (Int) -> User) {
    private val map = mutableMapOf<Int, User>()
    fun get(id: Int) = map.getOrPut(id) { loader(id) }
}
```

## 第三部分　创建型设计模式

### 3.1 Singleton（单例模式）

**保证一个类只有一个实例，并提供唯一的全局访问点。**

在 Kotlin 中，`object` 关键字一行即可声明线程安全、懒加载的单例，无需手写私有构造、静态变量与 `getInstance()`：

```kotlin
// Java 需数十行样板代码，Kotlin 仅需一行
object AppConfig {
    val baseUrl = "https://api.example.com"
    fun get(key: String): String = TODO()
}

// 使用：直接以类型名访问
val url = AppConfig.baseUrl
```

> 语法糖要点：`object` 声明编译为单例；首次访问时由 JVM 保证线程安全地初始化。类内部需要"每个类一个伴生单例"时用 `companion object`。

### 3.2 Abstract Factory（抽象工厂模式）

**提供一个创建一系列相关/相互依赖对象的接口，而无需指定其具体类。**

Kotlin 中可用接口 + `companion object` + `operator fun invoke` 让工厂调用更自然：

```kotlin
interface Button { fun render() }
interface Dialog { fun createButton(): Button }

class WinButton : Button { override fun render() = println("Windows 按钮") }
class MacButton : Button { override fun render() = println("Mac 按钮") }

class WinFactory : Dialog { override fun createButton() = WinButton() }
class MacFactory : Dialog { override fun createButton() = MacButton() }

// 工厂入口：companion object 提供静态工厂方法
object GUIFactory {
    fun create(os: String): Dialog = when (os) {
        "win" -> WinFactory()
        "mac" -> MacFactory()
        else -> throw IllegalArgumentException("未知系统: $os")
    }
}
```

> 语法糖要点：`companion object` 替代 Java 静态工厂方法；`when` 表达式替代 `if-else` 分支工厂。

### 3.3 Builder（生成器模式）

**将复杂对象的构建拆分为若干环节，实现相同的构建过程获得不同的对象表示。**

Kotlin 中**命名参数 + 默认参数 + `data class`** 已能覆盖绝大多数 Builder 场景，无需手写 Builder 类；需要链式配置时用 `apply` / `also`：

```kotlin
data class Request(
    val url: String,
    val method: String = "GET",               // 默认参数
    val headers: Map<String, String> = emptyMap(),
    val body: String? = null,
)

// 方式一：命名参数 + 默认参数（Kotlin 惯用，替代 Builder）
val req = Request(
    url = "https://api.example.com/user",
    method = "POST",
    body = """{"id":1}""",
)

// 方式二：apply 作用域函数实现链式构建
val dialog = AlertDialog.Builder(context).apply {
    setTitle("标题")
    setMessage("内容")
    setPositiveButton("确定", null)
}.create()
```

> 语法糖要点：默认参数消除了"标识参数/多构造器"问题；`apply` 返回接收者自身，天然支持链式调用；`copy()` 提供"基于已有对象微调"的轻量 Builder 能力。

### 3.4 Factory Method（工厂方法模式）

**定义创建对象的接口，让子类决定实例化哪个类，将实例化延迟到子类。**

Kotlin 中常用 `companion object` 提供静态工厂方法（可缓存、可返回子类型）：

```kotlin
interface Product { fun use() }
class RealProduct : Product { override fun use() = println("使用真实产品") }

class Factory {
    companion object {
        // 静态工厂：隐藏创建细节，可内部缓存
        fun getProduct(cached: Boolean): Product =
            if (cached) cache else RealProduct()
        private val cache: Product = RealProduct()
    }
}
```

### 3.5 Prototype（原型模式）

**通过复制现有对象创建一个新对象，后者与前者具有相同类型和属性。**

Kotlin 的 `data class` 自动生成 `copy()`，比手写 `clone()` 更安全、更直观：

```kotlin
data class Config(val host: String, val port: Int, val timeout: Long)

val base = Config(host = "localhost", port = 8080, timeout = 30_000)
val derived = base.copy(port = 9090)   // 仅替换 port，其余字段原样复制
```

> 语法糖要点：`copy()` 只复制值类型字段；对持有文件、Socket 等不可共享资源的对象，应谨慎使用（与原文"值对象才适合复制"的结论一致）。

## 第四部分　结构型设计模式

### 4.1 Adapter（适配器模式）

**将一个类的接口转换成客户期望的另一个接口，使不兼容的类能协同工作。**

Kotlin 中适配器的首选方案是**扩展函数**（无需新增 Adapter 类），或使用 `by` 接口委托：

```kotlin
// 方案一：扩展函数即"无类适配器"
fun Array<String>.toNames(): List<String> = this.toList()
fun String.trimAndUpper(): String = this.trim().uppercase()

// 方案二：by 委托适配旧接口
interface ModernApi { fun fetch(): String }
class LegacyService { fun legacyFetch(): String = "legacy-data" }

class LegacyAdapter(private val legacy: LegacyService) : ModernApi {
    override fun fetch(): String = legacy.legacyFetch()
}
```

### 4.2 Bridge（桥接模式）

**将抽象部分与实现部分分离，使二者可独立变化，避免子类数量爆炸。**

Kotlin 中直接用接口定义实现维度的抽象，通过组合而非继承扩展功能：

```kotlin
interface Renderer { fun render(shape: String) }   // 实现维度

class VectorRenderer : Renderer { override fun render(s: String) = println("矢量绘制 $s") }
class RasterRenderer : Renderer { override fun render(s: String) = println("栅格绘制 $s") }

abstract class Shape(protected val renderer: Renderer) {  // 抽象维度
    abstract fun draw()
}
class Circle(renderer: Renderer) : Shape(renderer) {
    override fun draw() = renderer.render("圆形")
}
// 抽象(Circle/Square)与实现(Vector/Raster)两个维度正交组合，无需 2×2 个子类
```

### 4.3 Composite（组合模式）

**将对象组合成树形结构以表示"部分-整体"层次，使单个对象与组合对象使用一致。**

Kotlin 的 `sealed class` 非常适合表达递归的树形结构：

```kotlin
sealed class Node {
    object Empty : Node()
    data class Leaf(val value: Int) : Node()
    data class Branch(val left: Node, val right: Node) : Node()
}

// when 穷尽所有子类型，对叶子与分支统一处理
fun Node.sum(): Int = when (this) {
    is Node.Empty -> 0
    is Node.Leaf -> value
    is Node.Branch -> left.sum() + right.sum()
}
```

### 4.4 Decorator（装饰模式）

**动态地给一个对象增添额外职责，而不改变其接口。**

Kotlin 的 `by` 接口委托让装饰者只需覆写关心的方法，其余方法自动转发：

```kotlin
interface Repository { fun getUser(id: Int): String }

class RealRepository : Repository {
    override fun getUser(id: Int): String = "user-$id"
}

// 委托：未覆写的方法自动转发给 inner，覆写的方法实现"增强"
class LoggingRepository(private val inner: Repository) : Repository by inner {
    override fun getUser(id: Int): String {
        println("调用 getUser($id)")
        return inner.getUser(id)
    }
}
```

> 语法糖要点：`by inner` 使 `Repository` 中所有方法默认委托给 `inner`，只在 `getUser` 上叠加日志逻辑，等价于 Java 的 `new BufferedInputStream(new FileInputStream(...))` 装饰链，但代码量显著更少。

### 4.5 Facade（外观模式）

**为子系统的一系列接口提供一个一致的统一入口，屏蔽内部细节。**

Kotlin 中用 `object` 或顶层函数即可提供轻量外观：

```kotlin
object PaymentFacade {
    private val auth = AuthService()
    private val risk = RiskControl()
    private val ledger = LedgerService()

    fun pay(order: Order) {
        auth.verify(order.user)          // 屏蔽三个子系统的调用细节
        risk.check(order.amount)
        ledger.record(order)
    }
}
```

### 4.6 Flyweight（享元模式）

**通过共享技术支持大量细粒度对象，节省内存、提升创建速度。**

Kotlin 中可用 `object` + `Map` 缓存不可变实例，复用 `Integer.valueOf()` 的缓存思想（`Int` 值在 -128~127 范围内同样被缓存）：

```kotlin
object FlyweightFactory {
    private val cache = mutableMapOf<String, Flyweight>()

    fun get(key: String): Flyweight = cache.getOrPut(key) { Flyweight(key) }
}

class Flyweight(val key: String)   // 一经创建不可变，才可安全共享
```

### 4.7 Proxy（代理模式）

**为其他对象提供代理，以控制对其的访问（鉴权、延迟加载、连接复用等）。**

Kotlin 的 `by` 委托同样适用于代理，且与 Decorator 的差异依然成立——Proxy 由调用方"无感知"地获得代理：

```kotlin
interface File { fun read(): String }
class RealFile(private val name: String) : File {
    override fun read(): String = "内容: $name"
}

// 保护代理：控制访问权限
class PermissionProxy(private val inner: File, private val allowed: Boolean) : File by inner {
    override fun read(): String =
        if (allowed) inner.read() else "拒绝访问"
}
```

## 第五部分　行为型设计模式

### 5.1 Chain of Responsibility（责任链模式）

**多个对象依次处理请求，直到有对象处理为止，避免发送者与接收者耦合。**

Kotlin 中可用**函数类型组合**或高阶函数表达处理链，比维护 Handler 链表更简洁：

```kotlin
typealias Handler = (Request) -> Request?

// 将多个处理器按顺序串联
fun chainOf(vararg handlers: Handler): Handler = { req ->
    handlers.firstNotNullOfOrNull { it(req) }
}

val authHandler: Handler = { req -> if (req.token != null) req else null }
val logHandler: Handler  = { req -> println("处理 ${req.id}"); req }

val pipeline = chainOf(authHandler, logHandler)
pipeline(Request(1, "token"))
```

### 5.2 Command（命令模式）

**将请求封装为命令对象，支持执行、undo、redo，将命令创建与执行分离。**

Kotlin 中命令本质是"可调用的动作"，可用**函数类型 / lambda**直接表达：

```kotlin
class Editor {
    private val executed = ArrayDeque<() -> Unit>()
    private val undone = ArrayDeque<() -> Unit>()

    fun execute(cmd: () -> Unit) { cmd(); executed.addLast(cmd) }
    fun undo() { undone.addLast(executed.removeLast()) }
    fun redo() { executed.addLast(undone.removeLast()) }
}
```

> 语法糖要点：`() -> Unit` 即"命令"，无需为每个命令新建类；需要携带状态的复杂命令再退回 `data class Command(val action: () -> Unit, val undo: () -> Unit)`。

### 5.3 Interpreter（解释器模式）

**给定一个语言，定义其文法表示，并用解释器解释该语言中的句子。**

Kotlin 中可用 `sealed class` + `when` 递归求值，替代笨重的 `AbstractExpression` 类层次：

```kotlin
sealed class Expr {
    data class Num(val value: Int) : Expr()
    data class Sum(val left: Expr, val right: Expr) : Expr()
    data class Mul(val left: Expr, val right: Expr) : Expr()
}

fun eval(e: Expr): Int = when (e) {
    is Expr.Num -> e.value
    is Expr.Sum -> eval(e.left) + eval(e.right)
    is Expr.Mul -> eval(e.left) * eval(e.right)
}
```

### 5.4 Iterator（迭代器模式）

**顺序访问聚合对象的所有元素而不暴露其内部表示。**

Kotlin 实现 `Iterable` 接口并覆写 `iterator()`，即可用 `for` 循环遍历；标准库的 `map/filter/forEach` 都是迭代器模式的现代形态：

```kotlin
class NameList(private val names: List<String>) : Iterable<String> {
    override fun iterator(): Iterator<String> = names.iterator()
}

for (name in NameList(listOf("A", "B", "C"))) println(name)

// 常见遍历场景无需自定义迭代器，直接使用集合扩展函数
listOf(1, 2, 3).filter { it > 1 }.map { it * 10 }.forEach(::println)
```

### 5.5 Mediator（中介者模式）

**用一个中介对象封装一系列对象交互，使各对象无需显式相互引用。**

Kotlin/协程生态中，`StateFlow` / `MutableSharedFlow` 是典型的中介者——组件之间只与"状态/事件流"通信，互不直接引用：

```kotlin
class ChatRoom {                          // 中介者
    private val _messages = MutableSharedFlow<String>()
    val messages: SharedFlow<String> = _messages

    fun send(user: User, msg: String) {   // 协调：转发给所有订阅者
        _messages.tryEmit("${user.name}: $msg")
    }
}
```

### 5.6 Memento（备忘录模式）

**在不破坏封装性的前提下捕获对象内部状态，并在未来恢复。**

Kotlin 的 `data class` + `copy()` 天然适合做"状态快照"，无需暴露内部字段：

```kotlin
data class EditorState(val text: String, val cursor: Int)   // 备忘录

class TextEditor {
    private var state = EditorState("", 0)
    private val history = ArrayDeque<EditorState>()

    fun type(t: String) { state = state.copy(text = state.text + t); history.addLast(state) }
    fun snapshot(): EditorState = state.copy()               // 捕获状态
    fun restore(s: EditorState) { state = s }                // 恢复状态
}
```

### 5.7 Observer（观察者模式）

**定义一对多的依赖关系，一个对象状态改变时，所有依赖它的对象自动更新。**

Kotlin 标准库提供 `Delegates.observable` 属性委托；协程生态中 `StateFlow` / `Flow` 是更强大的观察者实现：

```kotlin
import kotlin.properties.Delegates

// 属性委托：值变化时自动回调
var name: String by Delegates.observable("初始值") { _, old, new ->
    println("$old -> $new")
}

// StateFlow：响应式观察者
class ViewModel {
    private val _state = MutableStateFlow<UiState>(UiState.Loading)
    val state: StateFlow<UiState> = _state   // 观察者 collect 即可收到更新
}
```

### 5.8 State（状态模式）

**对象在其内部状态改变时改变行为，消除大量 `if-else`。**

Kotlin 的 `sealed class` + `when` 穷尽匹配，将状态分散到独立类型中，是状态模式的最优实现：

```kotlin
sealed interface UiState {
    object Loading : UiState
    data class Success(val data: List<Item>) : UiState
    data class Error(val message: String) : UiState
}

fun render(state: UiState) = when (state) {   // 编译期保证穷尽
    UiState.Loading -> showLoading()
    is UiState.Success -> showList(state.data)
    is UiState.Error -> showError(state.message)
}
```

### 5.9 Strategy（策略模式）

**将一系列可替换的算法封装，使算法与调用方相互独立，避免硬编码。**

Kotlin 中策略即**函数类型**，传入不同 lambda 即替换算法：

```kotlin
// 排序策略：以函数类型 (Int, Int) -> Int 承载
fun sort(list: MutableList<Int>, comparator: (Int, Int) -> Int) {
    list.sortWith(Comparator(comparator))
}

val asc:  (Int, Int) -> Int = { a, b -> a - b }
val desc: (Int, Int) -> Int = { a, b -> b - a }

sort(mutableListOf(3, 1, 2), asc)    // 升序
sort(mutableListOf(3, 1, 2), desc)   // 降序
```

### 5.10 Template Method（模板方法模式）

**定义算法框架，将部分步骤延迟到子类，使子类不改变算法结构即可重定义特定步骤。**

Kotlin 中可用**高阶函数**把"可变步骤"作为参数注入，比继承更灵活；需要强制骨架时保留 `open` + 抽象方法：

```kotlin
// 方案一：高阶函数——把可变步骤作为参数传入
fun runTask(before: () -> Unit = {}, after: () -> Unit = {}) {
    before()
    println("执行核心逻辑")   // 骨架固定
    after()
}
runTask(before = { println("预处理") }, after = { println("后处理") })

// 方案二：继承——骨架方法 final，原语步骤 open
abstract class Template {
    fun template() { step1(); step2() }          // final，禁止子类重写骨架
    abstract fun step1()
    abstract fun step2()
}
```

### 5.11 Visitor（访问者模式）

**在不改变元素类的前提下，定义作用于元素结构的新操作。**

Kotlin 中由于 `when` 表达式 + `sealed class` 已能在不"污染"元素类的情况下集中处理操作，多数场景可直接用 `when` 替代完整 Visitor：

```kotlin
sealed class Element {
    data class Text(val content: String) : Element()
    data class Image(val url: String) : Element()
}

// 新增操作只需新增函数，无需为每种 Element 添加 accept() 方法
fun render(e: Element): String = when (e) {
    is Element.Text -> "渲染文本: ${e.content}"
    is Element.Image -> "渲染图片: ${e.url}"
}
```

## 第六部分　《代码整洁之道》开发原则

### 6.1 注释

- **不恰当的信息**：注释只应描述技术性信息（尤其"为什么"），"做了什么/怎么做"交给代码自解释。Kotlin 用 KDoc 写注释，元数据（作者、时间）由版本控制系统记录，不写入注释。
- **废弃注释 / 废弃代码**：及时删除。Kotlin 可用 `@Deprecated` 标注废弃 API 并给出替代建议：

```kotlin
@Deprecated("使用 fetchUser() 替代", ReplaceWith("fetchUser(id)"), level = DeprecationLevel.WARNING)
fun getUserInfo(id: Int) = fetchUser(id)
```

- **冗余注释**：代码能自描述时不必注释。命名清晰的 Kotlin 代码（尤其配合 `data class`、`when`）通常无需冗余注释。

### 6.2 函数

- **过多的参数**：一个函数不超过三个入参。Kotlin 用**默认参数 + 命名参数**减少必填入参，或用 `data class` 封装常一起出现的参数：

```kotlin
// 之前：6 个参数
fun draw(rect: Rect, color: Color, alpha: Float, shadow: Boolean, blur: Int, dashed: Boolean) {}

// 之后：默认参数精简
fun draw(rect: Rect, color: Color, alpha: Float = 1f, shadow: Boolean = false) {}

// 或：data class 封装参数组
data class Style(val alpha: Float = 1f, val shadow: Boolean = false, val blur: Int = 0)
fun draw(rect: Rect, color: Color, style: Style = Style()) {}
```

- **输出参数**：不要用参数返回结果，应返回结果或修改对象自身状态。Kotlin 的 `data class` 不可变 + 返回新值，天然规避输出参数。
- **标识参数**：布尔参数宣告函数做了不止一件事。用命名参数提升可读性，或拆分为两个函数、用 `sealed class` 替代布尔分支：

```kotlin
// 差：标识参数
fun render(force: Boolean) {}

// 好：拆分为独立函数（调用点语义清晰）
fun render() {}
fun renderForced() {}
```

- **死函数**：永不被调用的方法应删除。IDE 可高亮未使用声明，`private` 函数尤其应保持"用即存在"。

### 6.3 命名

- **描述性名称**：变量/常量/函数/类都应名副其实。Kotlin 布尔属性惯用 `is` 前缀（`isEmpty`、`isBlank`），转换函数用 `toXxx`（`toString`、`toList`），工厂方法用 `of`/`from`。
- **名副其实**：命名与抽象层级相符。扩展函数命名应贴近动作语义：

```kotlin
// 差
fun List<String>.f() = filter { it.isNotBlank() }
// 好
fun List<String>.nonBlankItems(): List<String> = filter { it.isNotBlank() }
```

- **标准命名法**：遵循 Kotlin 官方规范——类用 `UpperCamelCase`，函数/属性用 `lowerCamelCase`，常量用 `UPPER_SNAKE_CASE`，且**禁止使用匈牙利命名法**。

### 6.4 测试

- **充分测试 / 覆盖率工具**：Kotlin 标准测试库 `kotlin.test` 提供 `assertEquals` 等断言；JUnit5 支持反引号命名，让测试名更可读：

```kotlin
@Test
fun `空列表求和应该返回 0`() {
    assertEquals(0, emptyList<Int>().sum())
}
```

- **快速测试 / 全面测试相近缺陷**：保持测试快且集中，缺陷常扎堆，发现一个缺陷应全面测试该函数。

### 6.5 其他问题

- **明显的行为未被实现**：遵循"最小惊异原则"。Kotlin 中运算符重载尤其要符合直觉——`plus` 应实现加法语义，不可借运算符做无关操作。
- **解耦**：降低耦合是设计模式的核心目标之一。Kotlin 的 `private`、`internal`、函数类型、扩展函数都是降低耦合的有效工具。
- **遵守编码规范**："结构甚于约定"。`sealed class` 的 `when` 穷尽检查、`fun interface` 的 SAM 约束、接口的强制实现，都是编译器层面的强制结构，比约定更有约束力。
- **不要掩蔽时序耦合**：若方法有调用次序要求，应让代码体现强制次序。Kotlin 的 `require`/`check` 前置条件与链式 `apply` 可显式约束次序：

```kotlin
fun buy() {
    require(selectedItems.isNotEmpty()) { "先选商品，再下单" }   // 强制前置次序
    // ...
}
```

## 附录　Kotlin 语法糖速查表

| 语法糖 | 经典模式映射 | 典型用法 |
| --- | --- | --- |
| `object` / `companion object` | Singleton、Facade | 一行声明单例、静态工厂方法 |
| `data class` + `copy()` | Prototype、Memento、Builder | 不可变值对象、状态快照、参数封装 |
| 命名参数 / 默认参数 | Builder、整洁函数 | 减少入参、替代标识参数 |
| `sealed class` / `sealed interface` | State、Composite、Interpreter、Visitor | 穷尽匹配的递归结构与状态机 |
| `by` 接口委托 | Decorator、Proxy、Adapter | 转发未覆写方法，只增强关心点 |
| 扩展函数 | Adapter、SRP、Facade | 无类适配、剥离附属职责 |
| 属性委托 `lazy` / `observable` | 懒加载、Observer | 延迟初始化、值变更回调 |
| 函数类型 / lambda | Strategy、Command、责任链、模板方法 | 算法即参数、动作即对象 |
| `operator fun`（运算符重载 / iterator） | Iterator | 自定义 `for` 遍历、自然语义运算符 |
| `when` 表达式 | 分支工厂、State、穷尽处理 | 替代冗长 `if-else`/`switch` |
| `apply` / `also` / `let` / `run` | Builder 链式调用 | 作用域内配置对象 |
| `require` / `check` | 时序耦合约束 | 前置条件校验 |
| `fun interface`（SAM） | Observer、Strategy 接口 | 单方法接口的 lambda 实例化 |
