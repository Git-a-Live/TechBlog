# Compose简介

## 何为Compose

Compose 是 Google推出的一种采用 **Kotlin DSL** 和 **声明式API** 的UI开发框架技术方案。广义的Compose，实际上包括了Android开发领域使用的[Jetpack Compose](https://developer.android.google.cn/jetpack/compose)，和跨平台开发领域所使用的[Compose Multiplatform](https://www.jetbrains.com/lp/compose-mpp/)。Jetpack Compose跟Compose Multiplatform本质上都是同一种开发技术方案的不同实现版本，而且后者很大程度上是从前者衍生发展出来的。对于Android开发者来说，使用Kotlin DSL这一点，会使得从Android平台往Windows、macOS、Linux甚至Web等其他平台迁移的难度比[Flutter](https://flutter.dev/)更小一些。

需要指出的是，Compose Multiplatform在桌面应用开发上，使用的图形渲染引擎是[Skia](https://github.com/google/skia)（经Skiko这一Kotlin绑定调用）。Flutter早期同样基于Skia渲染，但现已切换为自研的[Impeller](https://docs.flutter.dev/perf/impeller)引擎（iOS强制、Android默认启用），仅Web端仍使用Skia。Compose采用声明式UI的技术实现方案，可以粗略地理解为通过声明式API，直接在一块“画布（Canvas）”上使用“画笔（Paint）”绘制出所有的界面元素。这种方式相对于传统UI开发而言，其最大的优势就在于**极大降低了深层布局嵌套带来的性能开销**——传统View体系中每个控件都是携带测量、绘制逻辑的重量级对象，树越深对象越多越重；而Compose的组件本质上是轻量的函数调用，没有这类对象开销。因此嵌套本身并未消失，只是从性能问题降级成了可读性问题。

> 本节内容IDE截图均基于 **Android Studio Rabbit 2 | 2026.2.2 Patch 1**，实际开发以当前使用版本为准。

## Composable函数

在Gradle完成构建之后，打开模板项目的`MainActivity.kt`文件，可以看到类似下述的代码：

```
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        // Compose项目中，setContentView被全面替换成setContent
        setContent {
            ···
        }
    }
}
```

`setContent`取代了以往的`setContentView`，里面要执行的就是`Composable`函数。一个典型的`Composable`函数如下述代码所示：

```
// Composable函数需要使用@Composable注解进行标识
@Composable
// Composable函数使用大驼峰命名法，用以跟普通函数区分
fun Greeting(name: String) {
    // 和协程挂起函数类似，Composable函数也只能在Composable上下文内执行调用
    Text(text = "Hello $name!")
}
```

`Composable`函数是Compose框架的关键所在。从技术层面来说，它是声明式API的主要载体；从功能角度来说，每个`Composable`函数都是一个绘制界面元素的单元。尽管Compose的底层实现原理，可以让开发者不需要担心过大的嵌套深度会影响Compose性能，但是从代码可读性的角度来说，良好的封装可以避免`Composable`函数调用出现可怕的“嵌套地狱”。

## 可视化预览功能

和传统xml不同，Compose提供的可视化方案是：再写一个Composable函数，使用`@Preview`注解，Android Studio会自动识别并提供可视化预览功能。具体参考下述示例代码：

```
// 使用@Preview注解对Composable函数进行标识
@Preview(showBackground = true)
@Composable
// 用于可视化预览的Composable函数，跟单元测试的@Test函数类似，默认不能有参数传入（确有需要时用@PreviewParameter注入），也不能有返回值输出
fun DefaultPreview() {
    HelloComposeTheme {
        Greeting("Android")
    }
}
```

+ Start UI Check Mode：主要用于预览当前UI在不同屏幕下的显示效果；
+ Start Interactive Mode：进入交互模式，在预览点击、触摸、滑动等交互效果时会发挥作用；
+ Run Preview：连接实机或模拟器才能把当前部分的预览内容部署上去查看。
