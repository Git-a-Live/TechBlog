Flutter 的 UI 由 widget 组合而成。对已有 View 或 Compose 经验的开发者，理解重点在于 widget 与 View、Composable 的定位差异，以及 `build` 方法的调用契约。

## Widget 是配置而非控件

`Widget` 是一个不可变的 Dart 类，描述"界面在某一份数据下应当呈现的样子"。它不持有可变状态，不直接参与绘制，也不保存屏幕上的坐标。

由此产生三个直接后果：

1. **widget 会被频繁创建和丢弃**。父级重建时，子 widget 通常以新实例的形式重新构造。构造成本必须低廉，这也是 widget 普遍只有少量 `final` 字段的原因。
2. **widget 不保存状态**。需要跨重建保留的数据放在 `State` 对象中（第 6 节），而真正执行布局与绘制的是 `RenderObject`（第 14 节）。
3. **同一份配置可以复用**。`const` 构造的 widget 在编译期被规范化，相同参数只存在一个实例，比较时可跳过整棵子树的更新。

三者构成一条链：widget 是配置，element 是树中位置的持有者，render object 是布局与绘制的执行者。日常编码主要与第一层打交道。

### 与 View、Composable 的定位差异

| 维度 | Android View | Compose | Flutter |
| --- | --- | --- | --- |
| UI 单元 | `View` 对象，持有状态与绘制逻辑 | `@Composable` 函数 | `Widget`，不可变配置 |
| 构建方式 | XML 或 `new View(context)` | 函数调用 | `build()` 返回 widget |
| 更新方式 | 属性 setter + `invalidate()` | 状态读取触发重组 | 重建 widget，element 比对 |
| 样式表达 | XML 属性 / `setBackground` | `Modifier` 链 | 嵌套 widget |

View 是"对象 + 状态 + 绘制"的集合：`TextView` 自己保存文本、字号、颜色，并负责把它们画出来。Widget 不保存其中任何一项，它只描述"这一段应当显示什么"，真正持有尺寸与绘制指令的是 `RenderObject`。

Compose 与 Flutter 的定位接近，差别在表达方式。Compose 用 `Modifier` 链横向叠加能力，Flutter 用嵌套 widget 纵向包裹。`Container(width: 60, height: 60, decoration: ..., child: ...)` 与 `Modifier.size(60.dp).background(color).padding(...)` 描述同一组约束，前者多出若干层节点，后者拼装为一条链。

## StatelessWidget 的固定结构

无状态 widget 的骨架由四部分组成：基类声明、构造函数、字段、`build` 方法。

```dart
class Tile extends StatelessWidget {
  const Tile(this.letter, this.hitType, {super.key});

  final String letter;
  final HitType hitType;

  @override
  Widget build(BuildContext context) {
    return Container();
  }
}
```

### 构造函数与字段

`Tile` 接受两个位置参数与一个命名参数。位置参数适合"缺了就不成为该 widget"的必填数据，命名参数适合可选项与布尔开关。

`const` 修饰构造函数，要求所有字段都是 `final`。字段一旦声明为 `final`，实例创建后不可修改，这与 widget 的不可变语义一致。

`super.key` 把 `Key?` 透传给父类。`Key` 标识 widget 在同一父级子列表中的身份：当列表发生插入、删除、重排时，框架依据 key 判断哪个 element 可以复用。无 key 时按位置匹配，位置变化会导致 element 重建、状态丢失。静态结构中可以省略，动态列表与需要保留状态的组件应当提供。

### build 方法

`build` 是唯一必须实现的方法，签名固定为 `Widget build(BuildContext context)`，并且**必须返回一个 widget**，不能返回 `null`。

调用时机由框架决定，可能在每一帧发生。因此 `build` 有三条硬性要求：

- **无副作用**。不在其中发起网络请求、不写文件、不修改全局变量。
- **轻量**。耗时计算应提前完成并存入状态，`build` 只做组合。
- **只依赖入参与字段**。相同的输入应产出相同结构。

`BuildContext` 是该 widget 在树中位置的句柄。它提供向上查找能力，例如 `Theme.of(context)` 沿树向上找到最近的 `Theme` 并取出数据。这也是 Flutter 传递应用级配置的主要方式：不通过构造函数逐层透传，而是通过 context 就近读取。

## 参数驱动复用

一个方块需要呈现四种外观：白色空位、绿色命中、黄色位置错误、灰色未命中。四种外观的差异只有颜色与文字，结构完全一致。

```dart
class Tile extends StatelessWidget {
  const Tile(this.letter, this.hitType, {super.key});

  final String letter;
  final HitType hitType;

  @override
  Widget build(BuildContext context) {
    return Container(
      width: 60,
      height: 60,
      decoration: BoxDecoration(
        border: Border.all(color: Colors.grey.shade300),
        color: switch (hitType) {
          HitType.hit => Colors.green,
          HitType.partial => Colors.yellow,
          HitType.miss => Colors.grey,
          _ => Colors.white,
        },
      ),
      child: Center(
        child: Text(
          letter.toUpperCase(),
          style: Theme.of(context).textTheme.titleLarge,
        ),
      ),
    );
  }
}
```

把差异抽成构造参数，得到的是"一个类 + 四种取值"，而非"四个类"。这是 widget 复用的基本手段：结构固定、数据可变的部分由参数表达，结构本身在 `build` 中写死。

`HitType` 是游戏逻辑层提供的枚举，包含 `none`、`hit`、`partial`、`miss` 四个成员。`none` 表示尚未判定，对应白色空位。

## 容器类 widget：Container

`Container` 是使用频率最高、也最容易被误解的 widget。它本身不参与绘制，而是一个**组合器**：把若干单一职责的 widget 按固定顺序套在一起。

| `Container` 参数 | 实际组合出的 widget | 作用 |
| --- | --- | --- |
| `width` / `height` | `ConstrainedBox` + `SizedBox` | 施加紧约束 |
| `padding` | `Padding` | 内边距 |
| `color` | `ColoredBox` | 纯色背景 |
| `decoration` | `DecoratedBox` | 边框、渐变、阴影、圆角 |
| `alignment` | `Align` | 在自身范围内对齐子级 |
| `constraints` | `ConstrainedBox` | 自定义约束 |
| `child` | 直接作为最内层子级 | 唯一子 widget |

两条使用边界：

- `color` 与 `decoration` 不能同时提供。`decoration` 自身带有 `color` 字段，两者并存会触发断言失败，正确做法是把颜色写进 `decoration.color`。
- 仅需固定尺寸时，`SizedBox` 更直接；仅需内边距时，`Padding` 更直接。`Container` 的价值在于一次声明多项样式，而不是替代所有单一职责 widget。

## 装饰对象：BoxDecoration

`BoxDecoration` 描述盒子的视觉装饰，与 `Container` 分离，因此可以被其他需要装饰的 widget 复用（如 `DecoratedBox`、`AnimatedContainer`）。

| 字段 | 作用 |
| --- | --- |
| `color` | 背景色 |
| `border` | 边框，`Border.all(color:, width:)` 生成四边等宽边框 |
| `borderRadius` | 圆角，需与 `border` 配合或单独使用 |
| `gradient` | 渐变，与 `color` 互斥 |
| `boxShadow` | 阴影列表 |
| `shape` | `BoxShape.rectangle` 或 `BoxShape.circle` |

`Border.all(color: Colors.grey.shade300)` 生成 1 像素浅灰边框。`Colors.grey` 是 `MaterialColor`，`shade300` 取其色板中的一档；`Colors.grey` 本身是 500 档。

## 条件取值：switch 表达式

颜色取决于 `hitType`，用 `switch` 表达式直接产出值：

```dart
color: switch (hitType) {
  HitType.hit => Colors.green,
  HitType.partial => Colors.yellow,
  HitType.miss => Colors.grey,
  _ => Colors.white,
},
```

与 `switch` 语句的区别：

- 表达式有返回值，可以直接嵌入参数位置，不需要先声明变量再赋值。
- 对枚举做匹配时要求**穷尽所有成员**。若省略 `_` 分支且未覆盖 `none`，编译期报错，而不是运行期落到某个默认值。
- 每个分支是单表达式，不能包含多条语句；需要多条语句时应改用语句形式或抽出方法。

`_` 是通配符模式，匹配任何值且不绑定变量。此处承担"其余情况"的兜底职责，同时让编译器不再要求列举全部枚举成员。

## 子 widget 的命名约定

SDK 中的 widget 对子级参数遵循统一命名：

| 参数 | 语义 | 示例 |
| --- | --- | --- |
| `child` | 单个子 widget | `Center`、`Padding`、`Container` |
| `children` | 子 widget 列表 | `Column`、`Row`、`Stack` |

自定义 widget 沿用同一约定，使用者的认知成本最低。若自定义 widget 内部固定组合多个子级，也可以暴露 `child` 并在内部决定放置位置，例如一个带标题的卡片只接受内容区。

`Container.child` 只接受一个 widget。需要多个子级时，先放入 `Row`、`Column` 或 `Stack`，再把该容器作为 `child`。

## 文本样式取自主题

```dart
style: Theme.of(context).textTheme.titleLarge,
```

`Theme.of(context)` 从 context 向上查找最近的 `Theme`，`MaterialApp` 在根部注入默认主题。`textTheme` 是一组预定义的文本样式槽位，按字号与字重分为 `display`、`headline`、`title`、`body`、`label` 五组，每组含 `large`、`medium`、`small` 三档。

与硬编码 `TextStyle(fontSize: 22, fontWeight: FontWeight.w500)` 相比，读取主题槽位有三个好处：

- 全局换肤、深色模式、字体缩放自动生效，无需逐处修改。
- 同一层级的文本在不同页面保持一致。
- 不同平台的默认字体与度量由主题统一处理。

硬编码样式只适用于确实需要脱离主题体系的场景，例如品牌专用的标题字体。

Compose 中的 `MaterialTheme.typography.titleLarge` 属于同一机制：语义槽位由主题提供，业务代码只引用槽位名，不关心具体字号。

## 组合层级的可见性

源码中 `Tile.build` 返回一个 `Container`，但在 widget 检查器中会看到更深的层级：`Container` 展开为 `Padding`、`DecoratedBox`、`ConstrainedBox` 等节点。这与源码结构不一致并非错误，而是组合器展开的必然结果。

理解这一点对调试有直接价值：异常信息里出现的 widget 名称，可能是源码中并未直接书写的那个。

## 本节小结

widget 是不可变的配置对象，`build` 返回新的 widget 描述，真正的布局与绘制由 render object 完成。`StatelessWidget` 的结构固定为构造函数 + `final` 字段 + `build`，参数化是复用的唯一手段。`Container` 是组合器而非绘制单元，`BoxDecoration` 承担视觉装饰，二者分离使装饰可被动画组件复用。条件取值优先使用 `switch` 表达式，枚举匹配的穷尽性由编译器保证。文本样式从 `Theme` 读取，避免硬编码带来的主题割裂。
