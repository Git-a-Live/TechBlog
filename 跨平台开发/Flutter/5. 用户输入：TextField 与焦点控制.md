输入控件的复杂度不在样式，而在三件事的配合：谁来接收用户的编辑、谁把编辑结果交出去、焦点在何时该停留在哪里。三者分别对应 `TextEditingController`、回调、`FocusNode`。

## 组件的接口设计

输入组件不应当知道"提交之后做什么"。它只负责收集字符串并向上报告：

```dart
class GuessInput extends StatelessWidget {
  const GuessInput({super.key, required this.onSubmitGuess});

  final void Function(String) onSubmitGuess;
}
```

`void Function(String)` 是一个函数类型：接受一个 `String`，无返回值。把它声明为 `final` 字段并用 `required` 标注，意味着每次创建组件时都必须由父级提供具体实现。

这种"回调作为构造参数"的做法与直接在组件内部调用父级方法相比，有两点差异：

| 维度 | 回调参数 | 内部直接调用 |
| --- | --- | --- |
| 复用 | 同一组件可用于不同提交逻辑 | 与特定父级绑定 |
| 测试 | 传入假的回调即可断言调用 | 需要构造完整父级 |
| 依赖方向 | 子级不依赖父级类型 | 子级依赖父级 |

Flutter SDK 中同类签名有标准别名：`VoidCallback` 等价于 `void Function()`，`ValueChanged<T>` 等价于 `void Function(T)`。声明回调字段时使用这些别名可读性更好。

## 与 Android 输入控件的对应

| Android | Flutter | 说明 |
| --- | --- | --- |
| `EditText` / `TextInputEditText` | `TextField` | 文本输入 |
| `TextInputLayout` | `InputDecoration` | 边框、提示、错误、计数器 |
| `TextWatcher` | `onChanged`、`controller.addListener` | 文本变化监听 |
| `setText()` / `getText()` | `controller.text` | 整体读写 |
| `InputFilter.LengthFilter` | `maxLength` | 长度限制 |
| `requestFocus()` | `FocusNode.requestFocus()` | 请求焦点 |
| `ImageButton` | `IconButton` | 图标按钮 |
| `OnClickListener` | `VoidCallback` / `onPressed` | 点击回调 |

Android 的 `EditText` 内部持有 `Editable`，`setText()` 会重置光标；Flutter 的 `controller.text = ...` 行为相同，写入即整体替换并把光标移到末尾。需要保留光标或选区时，改写 `controller.value`（`TextEditingValue`）并同时给出 `selection`。

## TextField 的常用参数

| 参数 | 类型 | 作用 |
| --- | --- | --- |
| `controller` | `TextEditingController?` | 外部读写文本的句柄 |
| `focusNode` | `FocusNode?` | 焦点归属对象 |
| `autofocus` | `bool` | 首次挂载时是否请求焦点 |
| `maxLength` | `int?` | 最大字符数，设置后默认显示计数器 |
| `decoration` | `InputDecoration?` | 边框、提示、标签、图标 |
| `onChanged` | `ValueChanged<String>?` | 每次文本变化时回调 |
| `onSubmitted` | `ValueChanged<String>?` | 用户按下提交键（回车/完成）时回调 |
| `keyboardType` | `TextInputType?` | 软键盘类型 |
| `textInputAction` | `TextInputAction?` | 软键盘右下角按键的语义 |
| `enabled` | `bool` | 是否可编辑 |

`onChanged` 与 `onSubmitted` 的区别在于触发时机：前者每次输入都触发，适合实时校验；后者只在提交动作时触发，适合"一次提交一个完整值"的场景，例如提交一个五字母单词。

输入框外观由 `InputDecoration` 描述：

```dart
decoration: const InputDecoration(
  border: OutlineInputBorder(
    borderRadius: BorderRadius.all(Radius.circular(35)),
  ),
),
```

`OutlineInputBorder` 绘制四边描边，`BorderRadius.all(Radius.circular(35))` 把四角磨圆。半径取 35 是因为控件高度约 70 逻辑像素，达到半高时呈现胶囊形。`InputDecoration` 还提供 `hintText`（空值时的灰色提示）、`labelText`（浮动标签）、`errorText`（错误文本）、`counterText`（覆盖计数器显示）等字段。

`maxLength: 5` 会限制输入长度并在右下角显示 `0/5` 形式的计数器。计数器的存在会改变控件高度，若不需要可通过 `counterText: ''` 隐藏。

## TextEditingController

控制器是文本的外部句柄，持有当前文本、选区与组合输入状态。

| 成员 | 作用 |
| --- | --- |
| `text` | 读写当前文本；写入会把光标移到末尾 |
| `value` | 读写 `TextEditingValue`，包含文本与选区 |
| `selection` | 当前选区范围 |
| `clear()` | 清空文本并把选区归零 |
| `addListener()` / `removeListener()` | 监听每次编辑 |
| `dispose()` | 释放资源 |

三种典型用法：

```dart
final controller = TextEditingController();

controller.text;              // 读取
controller.text = 'aback';    // 整体替换
controller.clear();           // 清空
```

控制器与 `TextField` 是单向绑定的：`TextField` 的编辑会写回控制器，控制器的手动赋值也会反映到输入框。因此**不要用 `setState` 驱动输入框文本**——每次重建都赋值会重置光标位置，导致输入过程中光标跳到末尾。文本的权威来源应是控制器本身。

生命周期上，控制器需要在不再使用时调用 `dispose()`。持有它的对象负责释放：若在 `State` 中创建，应在 `State.dispose()` 中释放（第 6 节）。

## 焦点控制

焦点决定键盘输入投向哪个控件，也决定软键盘是否弹出。

`autofocus: true` 让控件在首次挂载时请求焦点。它只在挂载时生效一次，运行期把该值改为 `false` 不会让控件失焦。

运行期的焦点控制需要 `FocusNode`：

```dart
final FocusNode _focusNode = FocusNode();

TextField(
  focusNode: _focusNode,
  autofocus: true,
  // ...
);

_focusNode.requestFocus();   // 请求焦点
_focusNode.unfocus();        // 放弃焦点
```

`requestFocus()` 在移动端会唤起软键盘，在桌面端会把光标移入输入框。提交一次猜测后显式调用它，作用是让焦点留在输入框上：部分平台上提交动作会收起软键盘并使控件失焦，若不重新请求，下一次输入需要额外点击。

`FocusNode` 同样需要 `dispose()`。它还提供 `hasFocus`、`addListener()` 与 `onFocusChange` 回调，可用于"获得焦点时高亮边框"一类交互。焦点在树中按 `FocusScope` 分组，`FocusScope.of(context).nextFocus()` 可在同一组内按遍历顺序切换焦点，用于表单的连续输入。

## 按钮

Flutter 内置按钮按视觉权重区分：

| 按钮 | 视觉 | 适用 |
| --- | --- | --- |
| `ElevatedButton` | 填充 + 阴影 | 主操作 |
| `FilledButton` | 填充 | 主操作（Material 3 推荐） |
| `OutlinedButton` | 描边 | 次要操作 |
| `TextButton` | 纯文字 | 轻量操作、对话框动作 |
| `IconButton` | 图标 | 工具栏、紧凑位置 |

所有按钮的交互契约相同：`onPressed` 为回调，`child`（或 `icon`）为内容。`onPressed: null` 表示禁用——按钮置灰且不响应点击，这是表达"当前不可操作"的标准方式，优于自行绘制禁用态。

```dart
IconButton(
  padding: EdgeInsets.zero,
  icon: const Icon(Icons.arrow_circle_up),
  onPressed: _onSubmit,
)
```

`padding: EdgeInsets.zero` 移除默认内边距。`IconButton` 的点击响应区域由 `constraints` 与 `tapTargetSize` 控制，去掉内边距只改变视觉尺寸，实际可点击范围仍按最小触摸目标计算。

## 合并两处提交逻辑

输入框的提交动作与按钮点击需要执行同一段逻辑，但两者的回调签名不同：

- `TextField.onSubmitted` 的类型是 `void Function(String)`，回调会收到当前文本。
- `IconButton.onPressed` 的类型是 `VoidCallback`，即 `void Function()`。

签名不同，无法把同一个函数直接传给两处。解决办法是抽出一个无参方法，内部统一读取控制器：

```dart
void _onSubmit() {
  onSubmitGuess(_textEditingController.text.trim());
  _textEditingController.clear();
  _focusNode.requestFocus();
}

// 使用处
onSubmitted: (_) => _onSubmit(),
onPressed: _onSubmit,
```

`onSubmitted` 的参数被 `_` 忽略，因为文本统一从控制器读取，避免"回调参数与控制器内容不一致"的可能。`trim()` 去除首尾空白，防止用户输入"四个字母加一个空格"被当作五个字符通过长度校验。`clear()` 清空上一次输入，`requestFocus()` 保持焦点。输入内容的合法性（是否为五个字母、是否在词库内）不在输入组件中判断，交由游戏逻辑层处理，组件只负责收集与转发。

## 受控与非受控

`TextField` 自身持有编辑状态，控制器只是外部句柄。这种模式介于受控与非受控之间：

- 输入过程中的每次击键由 `TextField` 内部管理，不经过 `setState`，因此输入流畅、光标稳定。
- 外部通过控制器读取或写入最终值，写入是"整体替换"，会重置光标。

由此得出一条实践准则：只在提交、清空、程序化预填这三类时机写 `controller.text`；输入过程中的格式化（如自动加空格）应通过 `TextInputFormatter` 实现，而不是监听变化后回写文本。

## 本节小结

输入组件通过函数类型字段把结果交出去，自身不关心后续处理。`TextField` 的文本由 `TextEditingController` 承载，控制器是唯一权威来源，不应由 `setState` 驱动。焦点由 `FocusNode` 在运行期控制，`autofocus` 只在挂载时生效一次。两处提交入口签名不同，需要无参方法封装公共逻辑，并在提交后清空文本、恢复焦点。控制器与焦点对象都是需要显式释放的资源。
