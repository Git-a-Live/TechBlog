动画在 Flutter 中不需要手动逐帧计算。框架提供两类入口：隐式动画由属性变化自动驱动，显式动画由 `AnimationController` 逐帧驱动。绝大多数界面过渡只需前者。

## 两类动画的分界

| 维度 | 隐式动画 | 显式动画 |
| --- | --- | --- |
| 触发方式 | 目标属性值变化 | 主动调用 `forward()` / `reverse()` |
| 控制粒度 | 只能设定终点 | 可暂停、跳转、循环、反向 |
| 代码量 | 替换 widget 名 + 一个 `duration` | 需 `TickerProvider`、控制器、`AnimatedBuilder` |
| 典型组件 | `AnimatedContainer`、`AnimatedOpacity`、`AnimatedPadding`、`AnimatedAlign`、`AnimatedSwitcher` | `AnimationController` + `Tween` |

判据是"动画的终点是否由状态直接决定"。是，则用隐式；需要中途干预或循环，则用显式。

对应到 Compose 侧：

| 需求 | Compose | Flutter |
| --- | --- | --- |
| 属性变化自动过渡 | `animate*AsState` | 隐式动画 widget |
| 多属性同步编排 | `updateTransition` | 显式 `AnimationController` + `Tween` |
| 手势驱动 | `Animatable.snapTo` / `animateTo` | `AnimationController.value` |
| 无限循环 | `rememberInfiniteTransition` | `AnimationController.repeat()` |

隐式动画 widget 对应 `animate*AsState` 的定位：只声明目标值，插值由框架完成。区别在组织方式：Flutter 为每种可动画属性提供独立 widget（`AnimatedContainer`、`AnimatedOpacity`、`AnimatedPadding`），Compose 则把它们做成返回 `State` 的函数。

## 隐式动画的共同模型

所有隐式动画 widget 都实现同一套机制：

1. widget 持有目标值（来自构造参数）与当前值。
2. 每次重建时比较新旧目标值。
3. 目标值变化时，从**当前插值位置**出发，在 `duration` 内过渡到新目标。
4. 过渡过程中每帧重绘，过渡结束后稳定在新值。

因此隐式动画只要求两件事：提供 `duration`，并在状态变化后让 widget 以新参数重建。不需要保存动画进度，也不需要监听帧回调。

## AnimatedContainer

`AnimatedContainer` 与 `Container` 的参数一致，额外增加动画控制参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `duration` | `Duration` | 必填，过渡时长 |
| `curve` | `Curve` | 时间到进度的映射，默认 `Curves.linear` |
| `onEnd` | `VoidCallback?` | 一次过渡结束时回调 |

```dart
class Tile extends StatelessWidget {
  const Tile(this.letter, this.hitType, {super.key});

  final String letter;
  final HitType hitType;

  @override
  Widget build(BuildContext context) {
    return AnimatedContainer(
      duration: const Duration(milliseconds: 500),
      curve: Curves.bounceIn,
      width: 60,
      height: 60,
      decoration: BoxDecoration(
        border: Border.all(color: Colors.grey.shade300),
        color: switch (hitType) {
          HitType.hit => Colors.green,
          HitType.partial => Colors.yellow,
          HitType.miss => Colors.grey,
          _ => Colors.white,
        },
      ),
      child: Center(
        child: Text(
          letter.toUpperCase(),
          style: Theme.of(context).textTheme.titleLarge,
        ),
      ),
    );
  }
}
```

`Tile` 本身仍然是无状态 widget。动画状态由 `AnimatedContainer` 内部的 `State` 持有，`Tile` 只负责在 `hitType` 变化时以新参数重建。这是隐式动画的设计意图：把动画状态封装在组件内部，调用方保持纯粹。

`AnimatedContainer` 可插值的属性：

| 属性 | 插值对象 | 变化时的开销 |
| --- | --- | --- |
| `color` | `ColorTween` | 仅重绘 |
| `decoration` | `DecorationTween` | 仅重绘 |
| `foregroundDecoration` | `DecorationTween` | 仅重绘 |
| `width` / `height` | `Tween<double>` | 重新布局 |
| `constraints` | `BoxConstraintsTween` | 重新布局 |
| `padding` / `margin` | `EdgeInsetsTween` | 重新布局 |
| `alignment` | `AlignmentTween` | 重新布局 |
| `transform` | `Matrix4Tween` | 合成阶段 |

不可插值的属性（如 `child`）会在过渡开始时立即切换，不参与动画。

## 插值的实现条件

插值要求新旧值属于同一类型且该类型提供 `lerp` 方法。装饰的插值由 `Decoration.lerp` 完成，`BoxDecoration` 实现了该方法，逐项插值颜色、边框宽度、圆角半径、阴影模糊半径等。

由此产生一条限制：`BoxDecoration` 与 `ShapeDecoration` 之间无法插值。两者类型不同，`lerp` 无法定义中间形态，动画会直接跳到新值。需要渐变过渡时，两端必须使用同一种装饰类型。

`Color.lerp` 在 RGB 空间线性插值，白色到绿色的过渡中间会经过浅绿，而不是先变暗再变亮。这一行为符合直觉，但涉及品牌色时需注意中间色的观感。

## 曲线的作用

`curve` 只改变"时间到进度"的映射，不改变总时长。进度值仍是 0 到 1，曲线决定在某个时间点取到多大的进度。

| 曲线 | 特征 | 适用 |
| --- | --- | --- |
| `Curves.linear` | 匀速 | 默认，无个性 |
| `Curves.easeIn` | 慢起快终 | 元素离场 |
| `Curves.easeOut` | 快起慢终 | 元素入场 |
| `Curves.easeInOut` | 两端慢中间快 | 位置移动 |
| `Curves.fastOutSlowIn` | 强化的 easeInOut | Material 动效标准 |
| `Curves.bounceIn` | 进度在部分区间逆向变化，产生弹跳感 | 强调性反馈 |
| `Curves.elasticIn` | 越过终点后弹性振荡 | 强趣味性场景 |

`Curves.bounceIn` 的进度并非单调递增，中途会短暂回落，视觉效果是"弹一下才停稳"。这类曲线适合短时长的强调动画，时长过长会产生拖沓感。

曲线可以组合：`CurveTween(curve: Curves.easeIn)` 与 `Interval(0.0, 0.5)` 结合，可实现"前一半时间完成某个属性"的分段时序，这一能力在显式动画中更常用。

## 触发与中断

动画的触发条件是**重建时目标值与前一次不同**。

`hitType` 从 `HitType.none` 变为 `HitType.hit` 时，`AnimatedContainer` 收到新的 `decoration.color`，从白色过渡到绿色。若 `hitType` 未变化而其他属性变化（例如文本内容改变），颜色不会重新动画。

过渡进行中目标值再次变化时，动画从当前插值位置继续，而不是回到起点重来。这一行为保证了连续状态变化（快速连续提交、频繁切换）下的视觉连续性，也意味着无法通过"再次触发"来重启动画——需要重启动画时应使用显式控制器。

`Container` 与 `AnimatedContainer` 之间的类型切换会导致 element 重建：两者 `runtimeType` 不同，框架不会复用 element，内部动画状态被丢弃，切换瞬间以新值直接呈现。因此不应在同一个位置按条件交替使用两者。

## 性能边界

动画的每帧都要重新执行受影响的阶段：

| 变化的属性 | 触发的阶段 | 相对开销 |
| --- | --- | --- |
| 颜色、装饰、阴影 | 绘制（paint） | 低 |
| 尺寸、内边距、约束 | 布局（layout）+ 绘制 | 中 |
| 变换矩阵 | 合成（composite） | 低 |

60Hz 屏幕的帧预算是 16.7ms，120Hz 为 8.3ms。UI 线程需要在预算内完成构建、布局、绘制，超出即掉帧。方块颜色动画只涉及重绘，25 个格子同时在跑也在预算内；若对整页布局属性做动画，开销会显著上升。

`AnimatedContainer` 内部使用单个 `AnimationController` 驱动所有可插值属性，不存在"每个属性一个控制器"的额外开销。

## 何时改用显式动画

以下需求超出隐式动画的能力范围：

- 动画需要循环播放（呼吸效果、加载指示）。
- 动画进度由手势驱动（拖拽跟随、滑动进度）。
- 多个属性需要不同时长或不同曲线的编排。
- 需要在动画中途暂停、反向、跳转到指定进度。
- 需要监听每一帧的进度值来驱动其他计算。

这些场景使用 `AnimationController` + `Tween` + `AnimatedBuilder`，由调用方显式控制播放。隐式动画是它的封装，封装不了的部分才需要展开。

## 本节小结

隐式动画把动画状态封装进组件，调用方只需提供目标值与 `duration`，在状态变化后重建即可。`AnimatedContainer` 覆盖颜色、装饰、尺寸、内边距、对齐、变换等属性，插值依赖类型自身的 `lerp`，类型不同则直接跳变。`curve` 改变时间映射而非时长，`bounceIn` 一类曲线适合短时强调。颜色与装饰变化只触发重绘，尺寸变化触发重新布局，选择动画属性时需考虑帧预算。需要循环、手势驱动或多段编排时，改用显式动画控制器。
