[Coil](https://github.com/coil-kt/coil)是一个由Instacart开源、基于**Kotlin协程**的现代化图片加载库，其名称是"**Co**routine **I**mage **L**oader"（协程图片加载器）的缩写。Coil面向Android与Compose Multiplatform，是目前Kotlin/Compose生态中图片加载的首选方案。

按照官方说法，Coil具备以下特点：

+ **Fast（快速）**：内置内存缓存与磁盘缓存、图片降采样、自动暂停/取消请求等多项优化；
+ **Lightweight（轻量）**：核心库仅依赖Kotlin、Coroutines和Okio，与R8代码压缩器无缝协作；
+ **Easy to use（易用）**：充分利用Kotlin语言特性，样板代码极少；
+ **Modern（现代）**：Kotlin优先，与Compose、Coroutines、Okio、OkHttp、Ktor等现代库无缝互操作。

## 准备工作

Coil 3.x把功能拆分到多个模块中，需要按使用场景按需引入：

```kotlin
// Compose 项目
implementation("io.coil-kt.coil3:coil-compose:$specified_version")          // 提供 AsyncImage 等可组合函数
implementation("io.coil-kt.coil3:coil-network-okhttp:$specified_version")   // 基于 OkHttp 的网络加载

// 传统 View 项目
implementation("io.coil-kt.coil3:coil:$specified_version")                  // 内置单例 ImageLoader 及扩展函数
implementation("io.coil-kt.coil3:coil-network-okhttp:$specified_version")   // 基于 OkHttp 的网络加载
```

> 注：Coil 3.0 于 2024 年 11 月正式发布，此后 3.x 持续快速迭代，具体版本号请以[官方文档](https://coil-kt.github.io/coil/)为准。Coil 最低支持 Android 5.0（API 21）。若使用 Compose Multiplatform 跨平台开发，网络引擎需改用 Ktor（即`coil-network-ktor3`）。

## 基本使用

### Compose 中使用 AsyncImage

在Compose中，最直接的方式是使用`AsyncImage`可组合函数：

```kotlin
AsyncImage(
    model = "https://example.com/image.jpg",
    contentDescription = "示例图片",
    placeholder = painterResource(R.drawable.placeholder), // 加载占位图
    error = painterResource(R.drawable.error),             // 加载失败图
    contentScale = ContentScale.Crop,                      // 裁剪方式
)
```

### 在 View 体系中使用 load()

在传统View体系中，通过`ImageView.load()`扩展函数加载：

```kotlin
imageView.load("https://example.com/image.jpg") {
    placeholder(R.drawable.placeholder)
    error(R.drawable.error)
    crossfade(true)
}
```

`coil`模块内置了一个单例`ImageLoader`，上述便捷API会自动使用它，因此绝大多数场景无需手动初始化。如需自定义（例如统一配置交叉淡入、设置OkHttp缓存），可在应用入口配置该单例：

```kotlin
class CustomApplication : Application(), SingletonImageLoader.Factory {
    override fun newImageLoader(context: Context): ImageLoader {
        return ImageLoader.Builder(context)
            .crossfade(true)
            .build()
    }
}
```

Coil会根据图片实际显示尺寸进行**降采样**（只解码出控件所需大小的Bitmap），并在页面不可见或组件销毁时**自动暂停/取消**请求，无需手动处理生命周期，这在RecyclerView等滚动列表中尤其能减少内存占用与无谓的网络请求。

## 高级配置

### 配置 ImageLoader

`ImageLoader`是执行图片请求的核心引擎，拥有自己的内存缓存、磁盘缓存和网络客户端，建议在应用内只创建一个并全局共享。在之前单例配置的基础上，还可以进一步配置缓存大小、复用OkHttp客户端、注册解码器等：

```kotlin
class CustomApplication : Application(), SingletonImageLoader.Factory {
    override fun newImageLoader(context: Context): ImageLoader {
        return ImageLoader.Builder(context)
            .crossfade(true)
            // 内存缓存：按应用可用内存的 25% 分配
            .memoryCache {
                MemoryCache.Builder()
                    .maxSizePercent(context, percent = 0.25)
                    .build()
            }
            // 磁盘缓存：指定目录与最大体积（50 MB）
            .diskCache {
                DiskCache.Builder()
                    .directory(context.cacheDir.resolve("image_cache").toOkioPath())
                    .maxSizeBytes(50L * 1024 * 1024)
                    .build()
            }
            // 组件注册：复用已有 OkHttpClient、支持 SVG/GIF/视频帧解码
            .components {
                add(OkHttpNetworkFetcherFactory(callFactory = { sharedOkHttpClient }))
                add(SvgDecoder.Factory())
                add(GifDecoder.Factory())
                add(VideoFrameDecoder.Factory())
            }
            .build()
    }
}
```

几点说明：

+ `components{}`是扩展Coil能力的主要入口，用于注册自定义的Fetcher（取数据）与Decoder（解码）；
+ 复用已有OkHttpClient可共享连接池、拦截器与安全配置，避免重复建立连接池；
+ `SvgDecoder`、`GifDecoder`、`VideoFrameDecoder`需分别引入`coil-svg`、`coil-gif`、`coil-video`模块。

### 配置 ImageRequest

`ImageRequest`描述一次图片加载请求（数据源、目标尺寸、占位图、缓存策略、变换器等），用Builder按需配置：

```kotlin
val request = ImageRequest.Builder(context)
    .data("https://example.com/image.jpg")
    .size(Size(200, 200))                    // 指定解码尺寸，最多 200x200
    .crossfade(200)                          // 淡入 200ms
    .placeholder(R.drawable.placeholder)
    .error(R.drawable.error)
    .memoryCacheKey("avatar_${user.id}")     // 自定义内存缓存键
    .build()

// 将构建好的请求传给 AsyncImage 或 ImageView.load()
AsyncImage(model = request, contentDescription = null)
```

### 缓存策略（CachePolicy）

Coil用`CachePolicy`枚举统一控制内存、磁盘、网络三级缓存的读写行为：

|取值|读缓存|写缓存|说明|
|:--|:--|:--|:--|
|`CachePolicy.ENABLED`|✓|✓|默认，可读可写|
|`CachePolicy.READ_ONLY`|✓|✗|只读不写，适合离线模式|
|`CachePolicy.WRITE_ONLY`|✗|✓|只写不读，强制重新加载并回写|
|`CachePolicy.DISABLED`|✗|✗|完全禁用|

既可作用于`ImageLoader`（作为全局默认），也可作用于单个`ImageRequest`（按请求覆盖）：

```kotlin
val request = ImageRequest.Builder(context)
    .data(url)
    .memoryCachePolicy(CachePolicy.WRITE_ONLY) // 跳过旧缓存，重新加载并回写
    .diskCachePolicy(CachePolicy.DISABLED)     // 敏感图片不落盘
    .build()
```

## 图片变换（Transformation）

变换器（Transformation）在图片**解码之后、写入内存缓存之前**对像素数据做处理，常用于裁剪、圆角、模糊等效果。

### 内置转换器

Coil本身内置了两个常用转换器：

```kotlin
// 圆形裁剪
imageView.load(url) {
    transformations(CircleCropTransformation())
}

// 圆角裁剪
imageView.load(url) {
    transformations(RoundedCornersTransformation(radius = 16f))
}
```

> 注意：在Compose中使用圆角时，官方建议直接用`Modifier.clip(RoundedCornerShape(...))`而非`RoundedCornersTransformation`，前者更高效。

### 自定义转换器

自定义转换器只需继承`Transformation`抽象类，实现`cacheKey`与`transform()`两个成员：

```kotlin
// 自定义灰度变换示例
class CustomGrayscaleTransformation : Transformation() {
    override val cacheKey: String = "CustomGrayscaleTransformation"

    override suspend fun transform(input: Bitmap, size: Size): Bitmap {
        val output = Bitmap.createBitmap(input.width, input.height, input.config ?: Bitmap.Config.ARGB_8888)
        val paint = Paint().apply {
            colorFilter = ColorMatrixColorFilter(ColorMatrix().apply { setSaturation(0f) })
        }
        Canvas(output).drawBitmap(input, 0f, 0f, paint)
        return output
    }
}

// 使用
imageView.load(url) {
    transformations(CustomGrayscaleTransformation())
}
```

自定义变换器时有两点需要特别注意：

1. **cacheKey 必须稳定且唯一**：它参与内存缓存键的生成——不同变换若共用同一cacheKey会导致缓存串用，若cacheKey随参数变化则同一图片的不同变换会被分别缓存；
2. **多次调用 `transformations()` 是替换而非追加**：多个变换应一次性传入同一个`transformations()`（支持可变参数），它们会按顺序依次执行；再次调用会覆盖之前的列表。

### 第三方扩展

Coil内置变换较为精简，更丰富的效果可借助第三方库[coil-transformations](https://github.com/Commit451/coil-transformations)：

```kotlin
implementation("com.commit451.coiltransformations:transformations:${transformation_version}")

// 模糊（radius 为模糊半径，sampling 为采样率）
imageView.load(url) {
    transformations(BlurTransformation(context, radius = 10f, sampling = 5f))
}

// 组合多个变换（按顺序依次执行）
imageView.load(url) {
    transformations(CircleCropTransformation(), BlurTransformation(context, radius = 2f))
}
```

该库还提供基于GPUImage的滤镜系列（亮度、对比度、像素化等）与基于MLKit的人脸居中裁剪（`CenterOnFaceTransformation`）。

## 与Glide的对比

Coil与[[6. Glide]]同为Android主流的图片加载框架，二者都能完成"内存缓存 + 磁盘缓存 + 图片解码"这一核心工作，但在设计理念、语言栈与集成方式上有明显差异：

|对比项|Glide|Coil|
|:--|:--|:--|
|主要语言|Java（对Kotlin友好）|Kotlin（Kotlin-first）|
|出品方|bumptech（Google官方推荐）|Instacart|
|异步模型|自研线程池，协程需额外封装|原生基于Kotlin协程|
|Compose支持|需引入单独模块，API偏View风格|原生`AsyncImage`，Compose-first|
|跨平台（KMP）|不支持|支持Compose Multiplatform|
|缓存结构|内存Lru + ActiveResources弱引用 + 磁盘|内存缓存 + 磁盘缓存|
|默认图片格式|RGB_565（省内存）|自动选择（多为ARGB_8888）|
|GIF支持|内置|需额外引入`coil-gif`|
|依赖与体积|依赖较多、体积中等|核心仅Kotlin/Coroutines/Okio，更轻量|
|成熟度|久经考验、生态成熟|较新、采用率快速增长|

几点补充说明：

1. **API风格**：Glide以`Glide.with().load().into()`的链式调用为主，是面向View体系的经典写法；Coil则分别提供`AsyncImage`（Compose）与`ImageView.load()`（View）两套贴合各自平台的写法。
2. **协程**：Coil原生基于协程构建，请求取消与线程切换都融入协程机制，与协程项目天然契合；Glide使用自研线程池，在协程项目中需额外适配。
3. **默认解码质量**：Glide默认使用RGB_565以降低内存占用、代价是牺牲部分色彩；Coil默认优先保证质量（ARGB_8888），同时通过按显示尺寸降采样来控制内存。

## 集成趋势

综合二者近期的维护动态与Android生态的演进方向，可以归纳出以下集成趋势：

+ **Compose / KMP 项目普遍倾向 Coil**：随着Jetpack Compose与Kotlin Multiplatform的普及，Coil的原生协程、原生Compose支持以及跨平台能力，使其成为新项目的默认选择。
+ **存量 View 项目以 Glide 为主**：Glide成熟稳定、功能全面（内置GIF、丰富的Transform），仍是大量已上线View体系项目的既定选择，替换成本高、动力不足。
+ **维护节奏分化**：Glide近年更新明显放缓（最新4.16.0发布于2023年8月）；Coil则持续发布3.x版本、更新活跃。
+ **体积与启动敏感场景青睐 Coil**：Coil核心仅依赖Kotlin/Coroutines/Okio，包体积与启动开销更小，对APK体积敏感的应用更友好。

概括而言：**新项目（尤其 Kotlin + Compose）优先选 Coil；老项目、纯 View 体系或需要复杂 Transform / GIF 等成熟能力时，Glide 仍是稳妥之选。**
