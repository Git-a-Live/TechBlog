Android 通过 `android.hardware.usb` 包提供 USB 通信能力，支持两种模式：

- **USB Host（主机模式）**：Android 设备作为主机，为总线供电并枚举外接的 USB 设备（U 盘、键盘、串口模块、打印机等）。自 **Android 3.1（API 12）** 起支持。
- **USB Accessory（配件模式）**：Android 设备作为配件端，由外部的 USB 配件（如底座、车载主机）供电并与其通信。自 **Android 3.1（API 12）** 起支持。

两种模式互斥，设备硬件决定支持哪一种。实际项目中以 **Host 模式** 最为常见（接 USB 串口、读 U 盘、接打印机），本节以 Host 模式为主线展开。

## 核心类概览

Host 模式下涉及的类都在 `android.hardware.usb` 包下：

| 类 | 说明 |
| :---: | :---: |
| `UsbManager` | 入口，枚举设备、请求权限、打开连接 |
| `UsbDevice` | 代表一个连接的 USB 设备，含标识信息、接口、端点 |
| `UsbInterface` | 设备的一个接口，代表一组功能，设备可有多个接口 |
| `UsbEndpoint` | 接口的端点，即通信通道；通常含输入/输出两个端点 |
| `UsbDeviceConnection` | 与设备的连接，负责在端点上收发数据 |
| `UsbRequest` | 异步通信请求（仅异步收发时使用） |
| `UsbConstants` | 对应 Linux 内核 `linux/usb/ch9.h` 的常量定义 |

一次完整的通信流程：获取 `UsbManager` → 拿到 `UsbDevice` → 找到合适的 `UsbInterface` 与 `UsbEndpoint` → 打开 `UsbDeviceConnection` → 收发数据。

## Manifest 与设备过滤器

### 声明主机能力

```xml
<manifest>
    <!-- 声明使用 USB Host；若 USB 非必需，required="false" 并配合代码检测 -->
    <uses-feature android:name="android.hardware.usb.host" />
    <!-- USB Host API 最低要求 API 12 -->
    <uses-sdk android:minSdkVersion="21" />
    ...
</manifest>
```

### 设备过滤器

若希望设备插入时系统自动唤起应用，需要为 `USB_DEVICE_ATTACHED` 声明 intent-filter，并用 `meta-data` 指向一份设备过滤 XML：

```xml
<activity android:name=".UsbActivity">
    <intent-filter>
        <action android:name="android.hardware.usb.action.USB_DEVICE_ATTACHED" />
    </intent-filter>
    <meta-data
        android:name="android.hardware.usb.action.USB_DEVICE_ATTACHED"
        android:resource="@xml/device_filter" />
</activity>
```

`res/xml/device_filter.xml` 通过 `vendor-id`/`product-id`（匹配特定设备）或 `class`/`subclass`/`protocol`（匹配一类设备）过滤：

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <!-- 匹配特定厂商/产品 -->
    <usb-device vendor-id="1234" product-id="5678" />
    <!-- 或按类别匹配，例如大容量存储设备 -->
    <usb-device class="255" subclass="66" protocol="1" />
</resources>
```

> 这些属性可全部省略——不写任何属性会匹配**所有** USB 设备，通常只在确有需要时这么做。

## 发现设备

有两种方式发现设备：**intent filter**（设备插入时被通知）或**枚举**（主动查询已连接的设备）。

```kotlin
private lateinit var usbManager: UsbManager

override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    usbManager = getSystemService(UsbManager::class.java)
}

// 枚举当前已连接的所有 USB 设备
private fun listDevices() {
    val devices: HashMap<String, UsbDevice> = usbManager.deviceList
    devices.values.forEach { device ->
        // 通过 vendorId / productId 判断是否是要通信的设备
        val vendorId = device.vendorId
        val productId = device.productId
    }
}
```

## 请求权限

拿到 `UsbDevice` **并不代表有权通信**，必须显式申请授权。`requestPermission()` 通过一个 `PendingIntent` 异步回调授权结果：

```kotlin
private val ACTION_USB_PERMISSION = "com.example.USB_PERMISSION"

private val usbReceiver = object : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        if (ACTION_USB_PERMISSION == intent.action) {
            val device = intent.getParcelableExtra<UsbDevice>(UsbManager.EXTRA_DEVICE)
            val granted = intent.getBooleanExtra(UsbManager.EXTRA_PERMISSION_GRANTED, false)
            if (granted && device != null) {
                // 已授权，可打开设备通信
                openDevice(device)
            }
        }
    }
}

private fun requestPermission(device: UsbDevice) {
    val permissionIntent = PendingIntent.getBroadcast(
        this, 0,
        Intent(ACTION_USB_PERMISSION),
        PendingIntent.FLAG_IMMUTABLE   // Android 12+ 必须指定可变性
    )
    registerReceiver(usbReceiver, IntentFilter(ACTION_USB_PERMISSION))
    usbManager.requestPermission(device, permissionIntent)
}
```

> 授权与设备实例绑定，设备**重新插拔后需重新申请**。通信前建议再用 `usbManager.hasPermission(device)` 复查一次，因为设备可能在授权回调返回前已被拔出。

## 与设备通信

通信有同步（`bulkTransfer`/`controlTransfer`）与异步（`UsbRequest`）两种方式。无论哪种，都要在**子线程**执行，避免阻塞 UI 线程。

基本流程：拿到 `UsbDevice` → 选接口 `UsbInterface` → 选端点 `UsbEndpoint` → `openDevice()` 打开连接 → `claimInterface()` 声明接口 → 收发数据。

```kotlin
private fun openDevice(device: UsbDevice) {
    if (!usbManager.hasPermission(device)) {
        requestPermission(device)
        return
    }

    val connection = usbManager.openDevice(device) ?: return

    // 一般与 0 号接口通信；具体接口号视设备而定
    val intf = device.getInterface(0)
    connection.claimInterface(intf, true)   // force=true 强制声明

    // 找输入/输出端点
    val inEndpoint = intf.getEndpoint(0)
    val outEndpoint = intf.getEndpoint(1)

    // 在子线程执行收发
    thread {
        val buffer = ByteArray(64)
        // 同步批量传输：读数据，TIMEOUT=0 表示无超时
        val read = connection.bulkTransfer(inEndpoint, buffer, buffer.size, 0)
        // 同步批量传输：写数据
        val written = connection.bulkTransfer(outEndpoint, buffer, buffer.size, 0)
    }
}
```

`bulkTransfer()` 返回值含义：正数表示实际传输的字节数，负数表示传输失败。控制传输用 `controlTransfer()`，用于发送设备控制指令（如设置波特率等厂商自定义命令）。

## 清理与断开监听

通信结束或设备被拔出时，必须释放接口、关闭连接：

```kotlin
private val detachReceiver = object : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        if (UsbManager.ACTION_USB_DEVICE_DETACHED == intent.action) {
            val device = intent.getParcelableExtra<UsbDevice>(UsbManager.EXTRA_DEVICE)
            device?.let { cleanupConnection() }
        }
    }
}

private fun cleanupConnection() {
    connection?.apply {
        releaseInterface(intf)   // 释放接口
        close()                  // 关闭连接
    }
    connection = null
}
```

## USB Accessory 模式

当 Android 设备需要作为配件端（例如接入车载主机、相机底座）时，使用 Accessory 模式。它与 Host 模式的关键差异：

- 声明 `<uses-feature android:name="android.hardware.usb.accessory" />`；
- 通过 `android.hardware.usb.action.USB_ACCESSORY_ATTACHED` intent 或 `UsbManager.accessoryList` 发现配件；
- 通信核心类为 `UsbAccessory` 与 `ParcelFileDescriptor`（用文件描述符读写数据流），而非 Host 模式的端点模型。
