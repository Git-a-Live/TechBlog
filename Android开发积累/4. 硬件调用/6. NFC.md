NFC（Near Field Communication，近场通信）是一种短距离（通常几厘米）无线通信技术。Android 自 API 9（Android 2.3）起支持 NFC，提供了一套在 `android.nfc` 与 `android.nfc.tech` 包下的 API，用于读取/写入标签、以及让设备模拟卡片（HCE）。

与蓝牙、定位不同，NFC **没有运行时权限**——`android.permission.NFC` 是 normal 级权限，安装时即授予，无需弹窗。本节按「权限与 Manifest → 三种分发 Intent → 前台调度 → Reader Mode → NDEF 读写」的顺序展开。

## 权限与 Manifest 配置

NFC 的 Manifest 配置包含两部分：权限/特性声明，以及用于「标签分发系统」的 intent-filter。

```xml
<manifest>
    <!-- normal 权限，安装即授予，无需运行时申请 -->
    <uses-permission android:name="android.permission.NFC" />

    <!-- 声明 NFC 硬件需求；若非必需，required="false" 并配合代码检测 -->
    <uses-feature
        android:name="android.hardware.nfc"
        android:required="true" />
    ...
</manifest>
```

代码中检测设备是否支持 NFC：

```kotlin
val nfcAdapter = NfcAdapter.getDefaultAdapter(this)
if (nfcAdapter == null) {
    // 设备不支持 NFC
}
```

## 三种分发 Intent

当系统检测到一张 NFC 标签时，会构造一个 Intent 并分发给合适的 Activity。分发优先级从高到低依次是：

| Intent action | 说明 |
| :---: | :---: |
| `ACTION_NDEF_DISCOVERED` | 标签包含 NDEF 数据，且可被解析为已知 MIME 类型或 URI |
| `ACTION_TECH_DISCOVERED` | 标签不含 NDEF，或 NDEF 无法映射到 MIME/URI，但标签技术已知 |
| `ACTION_TAG_DISCOVERED` | 兜底，前面的 Intent 都没有匹配到任何 Activity 时触发 |

在 Manifest 中声明 intent-filter 后，应用无需打开也能被标签「唤醒」。以读取一个特定 URI 的 NDEF 标签为例：

```xml
<activity android:name=".NfcActivity">
    <intent-filter>
        <action android:name="android.nfc.action.NDEF_DISCOVERED" />
        <category android:name="android.intent.category.DEFAULT" />
        <data android:scheme="http"
              android:host="example.com"
              android:pathPrefix="/nfc" />
    </intent-filter>
</activity>
```

> 针对 `TECH_DISCOVERED`，需要额外一个 `meta-data` 指向 `res/xml/` 下的技术过滤列表（列出支持的标签技术，如 `android.nfc.tech.Ndef`、`android.nfc.tech.IsoDep`）。

## 前台调度系统

Intent filter 方案适合「标签拉起应用」，但应用在前台时，为了确保标签事件**优先**交给本 Activity（而不是被其他应用抢走），需要用**前台调度系统**（Foreground Dispatch，API 16+）。它让当前 Activity 拥有标签分发的最高优先级。

```kotlin
private lateinit var nfcAdapter: NfcAdapter
private lateinit var pendingIntent: PendingIntent

override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    nfcAdapter = NfcAdapter.getDefaultAdapter(this)

    // SINGLE_TOP 保证标签事件走 onNewIntent 而不是重建 Activity
    val intent = Intent(this, javaClass).apply {
        addFlags(Intent.FLAG_ACTIVITY_SINGLE_TOP)
    }
    pendingIntent = PendingIntent.getActivity(
        this, 0, intent,
        PendingIntent.FLAG_MUTABLE   // Android 12+ 必须显式指定可变性
    )
}

override fun onResume() {
    super.onResume()
    // 只处理 NDEF 标签：filters 与 techLists 可传 null 表示处理所有类型
    nfcAdapter.enableForegroundDispatch(
        this,
        pendingIntent,
        null,   // IntentFilter 数组
        null    // 技术列表数组
    )
}

override fun onPause() {
    super.onPause()
    // 必须配对调用，否则应用退后台后仍独占 NFC 事件
    nfcAdapter.disableForegroundDispatch(this)
}

override fun onNewIntent(intent: Intent) {
    super.onNewIntent(intent)
    handleNfcIntent(intent)
}
```

## Reader Mode

`enableReaderMode()`（API 19+）是比前台调度更现代的方案：它通过**回调**直接交付 `Tag`，不经过 Intent 分发，也**不会重启 Activity**，适合在协程等异步架构里处理标签。这是官方对「读取标签」推荐的首选方式。

```kotlin
private val readerCallback = NfcAdapter.ReaderCallback { tag ->
    // 在独立的 NFC 线程回调，拿到 Tag 对象
    handleTag(tag)
}

// flags 常用 FLAG_READER_NFC_A / FLAG_READER_NFC_B / FLAG_READER_SKIP_NDEF_CHECK 等
nfcAdapter.enableReaderMode(
    this,
    readerCallback,
    NfcAdapter.FLAG_READER_NFC_A or NfcAdapter.FLAG_READER_NFC_B,
    null
)

// 退出时关闭
nfcAdapter.disableReaderMode(this)
```

## NDEF 读写

NDEF（NFC Data Exchange Format）是 NFC 标签最通用的数据格式，由若干个 `NdefRecord` 组成一个 `NdefMessage`。读标签时从 Intent 中提取，写标签时通过 `Ndef` 技术类写入。

### 读取 NDEF 消息

```kotlin
private fun handleNfcIntent(intent: Intent) {
    if (intent.action == NfcAdapter.ACTION_NDEF_DISCOVERED) {
        // 直接从 Intent 读取（Android 13+ 需用带类型参数的 getParcelableArrayExtra）
        val messages = intent.getParcelableArrayExtra(NfcAdapter.EXTRA_NDEF_MESSAGES)
        messages?.forEach { msg ->
            (msg as NdefMessage).records.forEach { record ->
                val payload = record.payload
                // 解析 payload，得到文本或 URI 等
            }
        }
    }
}
```

### 写入 NDEF 消息

写标签前通常需要先连接 `Ndef` 技术对象，再写入 `NdefMessage`：

```kotlin
private fun writeText(tag: Tag, text: String) {
    val record = NdefRecord.createTextRecord("zh", text)
    val message = NdefMessage(arrayOf(record))

    val ndef = Ndef.get(tag) ?: return
    try {
        ndef.connect()
        if (!ndef.isWritable) {
            // 标签只读，无法写入
            return
        }
        ndef.writeNdefMessage(message)
    } finally {
        ndef.close()
    }
}
```

`NdefRecord` 提供了几个便捷工厂方法：

| 方法 | 说明 |
| :---: | :---: |
| `NdefRecord.createTextRecord(lang, text)` | 创建文本记录 |
| `NdefRecord.createUri(uri)` | 创建 URI 记录 |
| `NdefRecord.createMime(mimeType, data)` | 创建 MIME 类型记录 |
| `NdefRecord.createApplicationRecord(packageName)` | 创建 Android AAR 记录，用于指定打开标签的应用 |

> 写完 `writeNdefMessage()` 后，若希望标签从此只读，可再调用 `ndef.makeReadOnly()`。读写操作会阻塞，应在子线程或协程中执行。

## 非 NDEF 标签与技术类

不少卡（如门禁卡、银行卡）不含 NDEF 数据，需要借助 `android.nfc.tech` 下的技术类直接按底层协议通信。先拿到 `Tag`，再用对应技术类包装：

```kotlin
private fun handleTag(tag: Tag) {
    // 标签支持的技术列表
    val techList = tag.techList

    // ISO 14443-4 卡片（银行卡、NFC 智能卡）用 IsoDep 收发 APDU 指令
    val isoDep = IsoDep.get(tag)
    isoDep?.use {
        it.connect()
        val response = it.transceive(byteArrayOf(/* APDU 指令 */))
    }
}
```

常用的技术类：

| 技术类 | 说明 |
| :---: | :---: |
| `NfcA` / `NfcB` / `NfcF` / `NfcV` | 对应 ISO 14443 / FeliCa / ISO 15693 等底层协议 |
| `IsoDep` | ISO 14443-4，用于收发 APDU 指令 |
| `MifareClassic` / `MifareUltralight` | 特定存储卡类型的直接读写 |
| `Ndef` / `NdefFormatable` | NDEF 读写与格式化 |
