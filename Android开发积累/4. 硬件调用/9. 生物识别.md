生物识别认证（指纹、人脸、虹膜等）用于保护应用内的敏感信息或高级功能。Android 官方推荐的实现是 **`BiometricPrompt`**，它统一了指纹、人脸、虹膜等多种生物特征的认证流程，并提供了**系统级、跨 OEM 一致**的认证对话框。

关键背景：旧版的 `FingerprintManager` 仅支持指纹，已于 **API 28（Android 9）废弃**，新项目一律使用 `BiometricPrompt`。为兼容更低版本，应引入 **androidx.biometric** 兼容库（内部在 API 23–27 自动回退到 `FingerprintManagerCompat`，API 28+ 使用系统原生 `BiometricPrompt`）。

## 依赖与权限

```kotlin
dependencies {
    // androidx 兼容库；最新稳定版请以官方发布页为准
    implementation("androidx.biometric:biometric:1.1.0")
}
```

```xml
<!-- 使用生物识别的权限声明（normal 级，无需运行时申请） -->
<uses-permission android:name="android.permission.USE_BIOMETRIC" />
<!-- 旧版指纹路径（仅当需兼容 API 27 及以下的旧设备时保留） -->
<uses-permission android:name="android.permission.USE_FINGERPRINT" />
```

## 认证器类型

`BiometricManager.Authenticators` 定义了三种认证器，可用按位或组合：

| 常量 | 说明 |
| :---: | :---: |
| `BIOMETRIC_STRONG` | Class 3（强）生物特征，达到 CDD 定义的强安全等级，可用于解锁密钥 |
| `BIOMETRIC_WEAK` | Class 2（弱）生物特征，安全等级较低，**不能**用于解锁加密密钥 |
| `DEVICE_CREDENTIAL` | 锁屏凭据（PIN、图案、密码），作为生物识别的兜底 |

> `BIOMETRIC_WEAK` 是 `BIOMETRIC_STRONG` 的超集（`BIOMETRIC_STRONG or BIOMETRIC_WEAK == BIOMETRIC_WEAK`）。涉及加密（CryptoObject）时**必须**用 `BIOMETRIC_STRONG`。

## 检查可用性

弹出认证框前，先用 `BiometricManager.canAuthenticate()` 检查设备是否具备认证条件：

```kotlin
val biometricManager = BiometricManager.from(this)
when (biometricManager.canAuthenticate(BiometricManager.Authenticators.BIOMETRIC_STRONG)) {
    BiometricManager.BIOMETRIC_SUCCESS ->
        // 可认证，正常弹框
    BiometricManager.BIOMETRIC_ERROR_NO_HARDWARE ->
        // 设备无生物识别硬件
    BiometricManager.BIOMETRIC_ERROR_HW_UNAVAILABLE ->
        // 硬件暂时不可用
    BiometricManager.BIOMETRIC_ERROR_NONE_ENROLLED -> {
        // 未录入任何生物特征，引导用户去系统设置录入
        val enrollIntent = Intent(Settings.ACTION_BIOMETRIC_ENROLL).apply {
            putExtra(Settings.EXTRA_BIOMETRIC_AUTHENTICATORS_ALLOWED,
                BiometricManager.Authenticators.BIOMETRIC_STRONG)
        }
        startActivity(enrollIntent)
    }
}
```

## 显示认证对话框

`BiometricPrompt` 需要一个 `Executor`（回调执行线程）和一个 `AuthenticationCallback`：

```kotlin
private lateinit var biometricPrompt: BiometricPrompt

private fun initBiometricPrompt() {
    val executor = ContextCompat.getMainExecutor(this)
    biometricPrompt = BiometricPrompt(this, executor,
        object : BiometricPrompt.AuthenticationCallback() {
            override fun onAuthenticationSucceeded(result: BiometricPrompt.AuthenticationResult) {
                // 认证成功，result.cryptoObject 可能携带已解锁的 Cipher
            }

            override fun onAuthenticationError(errorCode: Int, errString: CharSequence) {
                // 认证出错：用户取消、锁屏锁定、硬件不可用等
            }

            override fun onAuthenticationFailed() {
                // 生物特征不匹配（指纹/人脸识别失败，但尚未达到锁定）
            }
        })
}

private fun showBiometricDialog() {
    val promptInfo = BiometricPrompt.PromptInfo.Builder()
        .setTitle("登录验证")
        .setSubtitle("请验证指纹以继续")
        .setAllowedAuthenticators(BiometricManager.Authenticators.BIOMETRIC_STRONG)
        .setNegativeButtonText("使用密码")   // 必须提供取消按钮（按钮文本不可省略）
        .build()
    biometricPrompt.authenticate(promptInfo)
}
```

> 若希望生物识别失败后还能用锁屏凭据兜底，将 `setAllowedAuthenticators()` 改为 `BIOMETRIC_STRONG or DEVICE_CREDENTIAL`。注意 **Android 10（API 29）及以下不支持 `DEVICE_CREDENTIAL` 组合**，需用 `KeyguardManager.isDeviceSecure()` 另行判断。

## 与加密密钥绑定（CryptoObject）

单纯「认证通过」只能证明用户在场，真正的安全需要把认证结果与**加密操作**绑定：用 Android Keystore 生成一把「每次使用都要求用户认证」的密钥，把它封装进 `CryptoObject` 一起交给 `BiometricPrompt`。这样即使应用逻辑被绕过，密钥也无法被解锁。

### 生成密钥

```kotlin
private fun getOrCreateSecretKey(keyName: String): SecretKey {
    val keyStore = KeyStore.getInstance("AndroidKeyStore").apply { load(null) }
    keyStore.getKey(keyName, null)?.let { return it as SecretKey }

    val keyGenerator = KeyGenerator.getInstance(
        KeyProperties.KEY_ALGORITHM_AES, "AndroidKeyStore"
    )
    val builder = KeyGenParameterSpec.Builder(
        keyName,
        KeyProperties.PURPOSE_ENCRYPT or KeyProperties.PURPOSE_DECRYPT
    ).setBlockModes(KeyProperties.BLOCK_MODE_GCM)
        .setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_NONE)
        .setUserAuthenticationRequired(true)               // 每次使用都需用户认证
        .setInvalidatedByBiometricEnrollment(true)         // 新增生物特征后密钥作废
    keyGenerator.init(builder.build())
    return keyGenerator.generateKey()
}
```

> `setInvalidatedByBiometricEnrollment(true)` 是关键安全措施：用户新录入指纹/人脸后，旧密钥立即失效，防止攻击者录入自己的生物特征来解锁他人数据。

### 初始化 Cipher 并认证

```kotlin
private fun authenticateWithCrypto() {
    val cipher = Cipher.getInstance("AES/GCM/NoPadding")
    val secretKey = getOrCreateSecretKey("my_secret_key")
    cipher.init(Cipher.ENCRYPT_MODE, secretKey)   // 或 DECRYPT_MODE + GCMParameterSpec

    val promptInfo = BiometricPrompt.PromptInfo.Builder()
        .setTitle("解锁数据")
        .setAllowedAuthenticators(BiometricManager.Authenticators.BIOMETRIC_STRONG)
        .setNegativeButtonText("取消")
        .build()

    biometricPrompt.authenticate(promptInfo, BiometricPrompt.CryptoObject(cipher))
}
```

认证成功后，在 `onAuthenticationSucceeded` 中取出已解锁的 Cipher 执行加解密：

```kotlin
override fun onAuthenticationSucceeded(result: BiometricPrompt.AuthenticationResult) {
    val cipher = result.cryptoObject?.cipher
    // 用 cipher 执行加密/解密
}
```

## 错误处理要点

- **`KeyPermanentlyInvalidatedException`**：密钥因生物特征变更而永久失效（或 `setInvalidatedByBiometricEnrollment(true)` 触发）。此时应删除旧密钥别名并**重新生成密钥**，引导用户重新认证，而不是反复重试。
- **`onAuthenticationError` 不等于用户密码错误**：很多是系统级错误（无录入、硬件不可用、认证次数过多被锁定），应区分处理并给出对应引导。
- **认证成功但加密失败**：认证与密钥有效性是两回事，若密钥已失效，会出现「认证通过但解密失败」的情况，需按上一条重建密钥。
