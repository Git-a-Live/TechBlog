JSON（JavaScript Object Notation）是当前网络接口的事实标准。它只保留数据，不含任何代码，因此比 Java 原生序列化安全，也比 XML 轻。

## 语法

只有六种值：

| 类型 | 写法 |
|:--|:--|
| 对象 | `{"key": value}` |
| 数组 | `[1, 2, 3]` |
| 字符串 | `"abc"`（必须双引号） |
| 数值 | `12`、`12.34`（不支持 NaN/Infinity） |
| 布尔 | `true` / `false` |
| 空值 | `null` |

几条硬规则：

+ 字符串**只能用双引号**，单引号非法；
+ 键必须带引号；
+ 不能有注释，不能有尾随逗号（需要这些特性的是 JSON5，见下文）；
+ 编码：规范要求系统间交换使用 **UTF-8**（RFC 8259）。但 Java 的`String`本身没有编码概念，只有在读写字节时才涉及编码，所以“JSON 不会乱码”的前提是两端都按 UTF-8 处理。

## 四套方案怎么选

| 方案 | 依赖 | 实现方式 | Kotlin 默认值 | 适合 |
|:--|:--|:--|:--:|:--|
| `org.json` | Android 内置 | 手动读写 | — | 结构简单、字段少、不想引依赖 |
| **Gson** | `com.google.code.gson:gson:2.15.0` | 反射 | **不生效** | 老项目、与 Java 互操作 |
| **Moshi** | `com.squareup.moshi:moshi:1.15.2` | 代码生成（KSP）/ 反射 | 生效 | 需要严格 Kotlin 语义 |
| **kotlinx.serialization** | `org.jetbrains.kotlinx:kotlinx-serialization-json:1.12.0` | 编译期插件 | **生效** | Kotlin 优先、KMP 项目 |

Jackson（`2.23.0`）在 JVM 后端很常见，但方法数多、包体大，Android 上一般不用。

## org.json：不引依赖的写法

Android 自带`org.json`，适合字段少、结构固定的场景：

```kotlin
val json = """
    {"id":1,"name":"Tom","vip":true,"tags":["a","b"]}
""".trimIndent()

val obj = JSONObject(json)
val id = obj.getLong("id")
val name = obj.getString("name")
val vip = obj.optBoolean("vip", false)

val tags = obj.optJSONArray("tags")
val list = buildList {
    for (i in 0 until (tags?.length() ?: 0)) {
        add(tags!!.getString(i))
    }
}
```

组装：

```kotlin
val out = JSONObject().apply {
    put("id", id)
    put("name", name)
}
val text = out.toString()
```

`getXxx()`在字段缺失或类型不符时抛`JSONException`，`optXxx()`返回默认值。**服务端字段不稳定时用`opt`，字段必填时用`get`快速失败**。

## Gson

```kotlin
implementation("com.google.code.gson:gson:2.15.0")
```

```kotlin
val gson = Gson()

// 序列化
val json = gson.toJson(user)

// 反序列化
val user2 = gson.fromJson(json, User::class.java)
```

### 泛型必须用 TypeToken

`List<User>`在运行时类型被擦除，直接传`List::class.java`会得到`List<LinkedTreeMap>`：

```kotlin
val type = object : TypeToken<List<User>>() {}.type
val users: List<User> = gson.fromJson(jsonArray, type)
```

### 字段映射

```kotlin
data class User(
    @SerializedName("user_id") val id: Long,
    val name: String,
    @Transient val tempCache: ByteArray? = null    // 不参与序列化
)
```

`@SerializedName`解决命名风格差异（下划线 / 驼峰）；`@Transient`（Kotlin 的`kotlin.jvm.Transient`）会生成 Java 的`transient`标记，Gson 会跳过。

### Gson 在 Kotlin 上的两个问题

Gson 用反射 + `Unsafe` 创建对象，**绕过构造方法**，于是：

```kotlin
data class User(val name: String, val age: Int = 18)

val user = Gson().fromJson("""{"name":"Tom"}""", User::class.java)
// 结果：age = 0，而不是默认值 18
```

第二类问题更危险：JSON 里缺字段或显式`null`时，**非空类型也会被赋成 null**，编译期看不出来，运行到使用处才崩。

```kotlin
val user = Gson().fromJson("""{"age":20}""", User::class.java)
println(user.name.length)     // NPE，name 实际是 null
```

所以用 Gson 时要么给所有字段可空类型 + 手动兜底，要么换 kotlinx.serialization / Moshi。

## kotlinx.serialization

Kotlin 官方的编译期序列化方案，无反射、支持 KMP。

```kotlin
// build.gradle.kts
plugins {
    // 版本必须与项目使用的 Kotlin 插件版本一致
    kotlin("plugin.serialization") version "2.4.21"
}

dependencies {
    implementation("org.jetbrains.kotlinx:kotlinx-serialization-json:1.12.0")
}
```

插件版本以项目实际的 Kotlin 版本为准（当前 Kotlin 最新稳定版是 2.4.21），两者不一致时编译会直接报错。

```kotlin
import kotlinx.serialization.SerialName
import kotlinx.serialization.Serializable
import kotlinx.serialization.encodeToString
import kotlinx.serialization.json.Json

@Serializable
data class User(
    val id: Long,
    val name: String,
    @SerialName("created_at") val createdAt: String? = null
)

val json = Json {
    ignoreUnknownKeys = true        // 服务端多返回字段不报错
    encodeDefaults = true           // 默认值也输出
    explicitNulls = false           // null 字段不输出
}

val text = json.encodeToString(user)
val user2 = json.decodeFromString<User>(text)
```

关键差异：**默认值会生效**。因为生成的反序列化代码调用的是真正的构造方法，JSON 里缺`createdAt`时用声明处的默认值，缺必填字段则抛`MissingFieldException`——问题在解析时暴露，而不是在后面某个业务调用里 NPE。

## Moshi

Square 的库，代码生成路线与 kotlinx 类似：

```kotlin
plugins {
    id("com.google.devtools.ksp")
}

dependencies {
    implementation("com.squareup.moshi:moshi:1.15.2")
    ksp("com.squareup.moshi:moshi-kotlin-codegen:1.15.2")
}
```

```kotlin
@JsonClass(generateAdapter = true)
data class User(val id: Long, val name: String)

val moshi = Moshi.Builder().build()
val adapter = moshi.adapter(User::class.java)

val json = adapter.toJson(user)
val user2 = adapter.fromJson(json)
```

不写`@JsonClass`也能跑，但会走`moshi-kotlin`的反射适配器，性能和 Kotlin 语义都差一些。**要用就用 codegen**。

## JSON5：手写配置用的 JSON

JSON5 是 JSON 的**超集**，加了 ES5 的语法糖，目的很明确——让配置文件更好手写。官方首页写得很直白：

> JSON5 is an extension to the popular JSON file format that aims to be easier to write and maintain by hand (e.g. for config files). It is **not intended to be used for machine-to-machine communication**.

它比 JSON 多出来的部分：

| 特性 | 例子 |
|:--|:--|
| 键可以不加引号 | `{name: "Tom"}` |
| 单引号字符串 | `'Tom'` |
| 对象/数组尾逗号 | `{"a": 1,}`、`[1, 2,]` |
| 单行/多行注释 | `// ...`、`/* ... */` |
| 十六进制数 | `0xdecaf` |
| 前导/后置小数点 | `.5`、`5.` |
| 正负无穷与 NaN | `Infinity`、`-Infinity`、`NaN` |
| 数字前导加号 | `+1` |

```js
{
  // 注释
  name: 'demo',          // 键不加引号、值用单引号
  timeout: +30,
  ratio: .5,
  mask: 0xdecaf,
  tags: ['a', 'b',],     // 尾逗号
}
```

### Android 上谁认它

**没有一个主流序列化库完整支持 JSON5**，只有部分宽松选项：

| 方案 | 能认什么 | 不能认什么 |
|:--|:--|:--|
| `org.json` | 只认严格 JSON | 全部 JSON5 特性 |
| Gson `Strictness.LENIENT` | 注释、单引号、无引号键、`NaN`/`Infinity`、`;` 分隔 | 十六进制、前导`+`、`.5`/`5.`、尾逗号 |
| Moshi `JsonReader.lenient = true` | 与 Gson 同一套放宽项（历史遗留的宽松语法） | 十六进制、前导`+`、`.5`/`5.`、尾逗号 |
| kotlinx.serialization 1.12 | `allowComments = true`、`allowTrailingComma = true` | 无引号键、单引号、十六进制、`NaN`/`Infinity` |

Gson 和 Moshi 的 lenient 尤其容易被误解：它们把**多余的数组分隔符**解释成“省略了一个 null 值”，所以`[1, 2,]`这类写法不会被优雅地忽略，而是可能多出一个 null 元素。要尾逗号就用 kotlinx 的`allowTrailingComma`，或者干脆别写。

Moshi 的 lenient 只能设在`JsonReader`上，`adapter.fromJson(String)`内部用的是严格 reader，需要自己构造：

```kotlin
val reader = JsonReader.of(Buffer().writeUtf8(source)).apply { lenient = true }
val user = adapter.fromJson(reader)
```

```kotlin
// Gson：宽松解析（不是完整 JSON5）
val gson = GsonBuilder().setStrictness(Strictness.LENIENT).create()

// kotlinx.serialization：只开这两个开关
val json = Json {
    allowComments = true
    allowTrailingComma = true
}
```

### 真要用完整 JSON5

两条路：

1. **构建期转换**（推荐）：用 Node 脚本或 Gradle 任务把`.json5`转成`.json`，打包进`assets`，运行时只读严格 JSON。不引运行时依赖，也不会把宽松解析带进生产环境。
2. **引入解析库**：`de.marhali:json5-java:3.0.0`，API 类似 Gson：

```kotlin
implementation("de.marhali:json5-java:3.0.0")
```

```kotlin
val json5 = Json5.builder { it.quoteless().quoteSingle().parseComments().build() }
val element = json5.parse(source)
```

这个库要求 **Java 11+**，在 Android 上要确认`minSdk`与脱糖配置，低端机型上不值得为了一份配置引入。

### 边界

+ **接口传输一律用严格 JSON**。JSON5 只是“人能写”的格式，很多服务端和中间件都不认；
+ 客户端**解析**可以宽松，**输出**必须严格；
+ 不要把“解析器能容忍”当成“格式合法”——线上数据出问题时，宽松解析只会让问题更晚暴露。

## 大 JSON：不要整读

`Gson().fromJson()`、`decodeFromString()`都是一次性把整棵树读进内存。几 MB 的 JSON 在低端机上就可能 OOM。

需要处理大数组时用流式读取：

```kotlin
Gson().newJsonReader(reader).use { jsonReader ->
    jsonReader.beginArray()
    while (jsonReader.hasNext()) {
        // 逐个对象解析，处理完即丢
        val item = Gson().fromJson<Item>(jsonReader, Item::class.java)
        handle(item)
    }
    jsonReader.endArray()
}
```

服务端分页永远是更好的方案——能在协议层解决，就不要在客户端硬扛。

## 安全

+ 不要反序列化不可信的类型信息。Gson 的`RuntimeTypeAdapterFactory`、Jackson 的默认类型（`enableDefaultTyping`）都允许 JSON 指定类名，等于把“实例化任意类”的开关交给对方；
+ Fastjson 历史上多次出现 `autoType` 反序列化漏洞，新项目不要用；老项目至少关闭 autoType 并升级到修复版本；
+ 只解析预期的字段，配合`ignoreUnknownKeys`过滤噪声。

## 常见问题

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| `List<User>`里全是 Map | 泛型擦除，没用`TypeToken` | 用`object : TypeToken<List<User>>() {}.type` |
| Kotlin 默认值不生效 | Gson 用 Unsafe 绕过构造方法 | 换 kotlinx.serialization / Moshi codegen |
| 非空字段变 null | 同上，JSON 缺字段 | 同上，或全部声明为可空并兜底 |
| 服务端加字段后解析失败 | kotlinx 默认不容忍未知字段 | `Json { ignoreUnknownKeys = true }` |
| 配置文件里有注释/尾逗号，解析失败 | 那是 JSON5 而非 JSON | 开对应宽松开关，或构建期转换 |
| 字段名对不上 | 命名风格差异 | `@SerialName` / `@SerializedName` |
| 大 JSON OOM | 一次性整读 | 流式解析或分页 |
| 浮点精度丢失 | 用`Double`存金额 | 金额用字符串或整数分 |
| 日期解析失败 | 格式不统一 | 显式指定格式，别依赖默认 |

> 选型建议：**Kotlin 新项目用 kotlinx.serialization，Java/老项目用 Gson，需要严格 Kotlin 语义又不想上编译器插件用 Moshi codegen；只读几个字段时`org.json`最省事。**
