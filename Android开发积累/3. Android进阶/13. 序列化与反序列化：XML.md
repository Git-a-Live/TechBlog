XML（eXtensible Markup Language）是一种用标签描述结构的文本格式。它和 JSON 一样，主要用于**存储和传输数据**，也是跨系统交换的通用格式。

Android 自己就是重度 XML 用户：`AndroidManifest.xml`、`res/layout`、`res/values`、`res/xml`，全是 XML。

## XML 与 JSON 怎么选

| 维度 | XML | JSON |
|:--|:--|:--|
| 体积 | 大，闭合标签带来大量冗余 | 小 |
| 类型 | 只有文本，数字/布尔都靠 schema 约定 | 原生区分字符串/数字/布尔/null |
| 结构约束 | 强，可用 XSD、命名空间做校验 | 弱，靠 JSON Schema（生态不如 XSD 成熟） |
| 注释 | 支持 | 不支持 |
| 解析 | 解析器多，Pull/SAX/DOM 各有取舍 | 解析简单，库更轻 |
| 典型场景 | 配置文件、需要 schema 校验的系统间交换 | 网络接口、移动端与前端通信 |

“XML 不适合复杂嵌套”是个常见的误解：嵌套本身 XML 完全能表达，问题在于**每层都要闭合标签**，结构一深体积就膨胀得厉害。结构固定、需要严格校验时，XML 反而更合适。

## 写 XML

### XmlSerializer（推荐）

Android 自带`android.util.Xml`，不需要任何依赖：

```kotlin
val serializer = Xml.newSerializer()
val writer = StringWriter()
serializer.setOutput(writer)
serializer.startDocument("utf-8", true)

serializer.startTag(null, "users")
users.forEach { user ->
    serializer.startTag(null, "user")
    serializer.attribute(null, "id", user.id.toString())

    serializer.startTag(null, "name")
    serializer.text(user.name)          // 会自动转义 < > & 等字符
    serializer.endTag(null, "name")

    serializer.endTag(null, "user")
}
serializer.endTag(null, "users")
serializer.endDocument()

val xml = writer.toString()
```

直接写文件：

```kotlin
FileOutputStream(file).use { output ->
    val serializer = Xml.newSerializer()
    serializer.setOutput(output, "utf-8")
    serializer.startDocument("utf-8", true)
    // ... 同样的标签结构
    serializer.endDocument()
    serializer.flush()                  // 别忘了，否则缓冲区可能没落盘
}
```

`startTag(namespace, name)`的第一个参数传`null`表示不用命名空间。`text()`会做实体转义，不要自己拼`&lt;`。

### dom4j（迁移旧代码时才用）

dom4j 是 Java 生态里常用的 XML 库，API 友好、支持 XPath。但在 Android 上它属于“额外负担”：包体几百 KB，而系统自带的`XmlSerializer`/`XmlPullParser`已经够用。

只有两种情况值得引入：从既有 Java 项目迁移代码，或者确实需要 XPath / 复杂的 DOM 操作。

```kotlin
// build.gradle.kts
implementation("org.dom4j:dom4j:2.2.0")
```

```kotlin
val doc = DocumentHelper.createDocument()
val root = doc.addElement("users")
users.forEach { user ->
    root.addElement("user")
        .addAttribute("id", user.id.toString())
        .addElement("name")
        .addText(user.name)
}

val format = OutputFormat.createPrettyPrint()
XMLWriter(FileOutputStream(file), format).use { writer ->
    writer.write(doc)
}
```

`XMLWriter`没有无参构造，必须传`OutputFormat`；输出流要自己管理（或用`use`包住 writer）。

## 读 XML

三种解析方式，差别在“什么时候读、占多少内存”：

| 方式 | 模型 | 内存 | 速度 | 能否修改 | 适用 |
|:--|:--|:--:|:--:|:--:|:--|
| **Pull**（`XmlPullParser`） | 事件流，主动`next()` | 低 | 快 | 否 | **Android 首选** |
| SAX | 事件流，回调驱动 | 低 | 快 | 否 | 大文件、只需顺序扫描 |
| DOM | 整棵树加载进内存 | 高 | 慢 | 是 | 小文件、需要随机访问/修改 |

### Pull（推荐）

```kotlin
val parser = Xml.newPullParser()
parser.setFeature(XmlPullParser.FEATURE_PROCESS_NAMESPACES, false)
parser.setInput(StringReader(xml))

val users = mutableListOf<User>()
var id = 0L
var name = ""

var event = parser.eventType
while (event != XmlPullParser.END_DOCUMENT) {
    when (event) {
        XmlPullParser.START_TAG -> when (parser.name) {
            "user" -> {
                id = parser.getAttributeValue(null, "id")?.toLongOrNull() ?: 0L
                name = ""
            }
            "name" -> name = parser.nextText()      // 读到结束标签，返回文本内容
        }
        XmlPullParser.END_TAG -> if (parser.name == "user") {
            users += User(id, name)
        }
    }
    event = parser.next()
}
```

要点：

+ `Xml.newPullParser()`就是`XmlPullParserFactory.newInstance().newPullParser()`的便捷写法；
+ `nextText()`要求当前事件是`START_TAG`，它会一直读到对应的`END_TAG`；
+ 属性用`getAttributeValue(null, "id")`取，第一个参数是命名空间；
+ 输入可以来自`StringReader`、`InputStream`、`resources.getXml(R.xml.xxx)`。

### SAX

SAX 通过回调推进，自己不控制循环：

```kotlin
class UserHandler : DefaultHandler() {
    val users = mutableListOf<User>()
    private var id = 0L
    private var inName = false
    private val buffer = StringBuilder()

    override fun startElement(
        uri: String?, localName: String?, qName: String?, attributes: Attributes?
    ) {
        when (qName) {
            "user" -> id = attributes?.getValue("id")?.toLongOrNull() ?: 0L
            "name" -> { inName = true; buffer.clear() }
        }
    }

    // 注意：文本可能分多次回调，必须累积
    override fun characters(ch: CharArray, start: Int, length: Int) {
        if (inName) buffer.append(ch, start, length)
    }

    override fun endElement(uri: String?, localName: String?, qName: String?) {
        when (qName) {
            "name" -> inName = false
            "user" -> users += User(id, buffer.toString())
        }
    }
}
```

```kotlin
val factory = SAXParserFactory.newInstance()
val reader = factory.newSAXParser().xmlReader
reader.contentHandler = UserHandler()
reader.parse(InputSource(StringReader(xml)))
```

最易出错的是 `characters()`：一段文本可能因为缓冲区边界被拆成多次回调，直接`toString()`会丢字符，必须用`StringBuilder`累积。

### DOM

```kotlin
val factory = DocumentBuilderFactory.newInstance()
val document = factory.newDocumentBuilder()
    .parse(InputSource(StringReader(xml)))

val nodes = document.getElementsByTagName("user")
for (i in 0 until nodes.length) {
    val element = nodes.item(i) as Element
    val id = element.getAttribute("id").toLong()
    val name = element.getElementsByTagName("name")
        .item(0).textContent
}
```

DOM 会把整棵树建在内存里，几 MB 的 XML 就能吃掉几十 MB 堆内存。Android 上只建议处理配置级别的小文件。

### 解析 res/xml 资源

```kotlin
val parser = resources.getXml(R.xml.users)
// 之后与 Pull 解析完全一样
```

`getXml()`返回的解析器已经定位在文档开头，不要重复`setInput`。

## 安全：XXE

XML 支持外部实体（DTD），攻击者可以构造这样的文档读取本地文件或发起内网请求：

```xml
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<foo>&xxe;</foo>
```

防护原则：

+ **不要解析不可信来源的 XML**，能换 JSON 就换；
+ 必须解析时，关闭 DOCTYPE 与外部实体：

```kotlin
val factory = SAXParserFactory.newInstance()
try {
    factory.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true)
} catch (e: Exception) {
    // 某些解析器不支持该特性，会抛 SAXNotRecognizedException
}
```

+ `XmlPullParser`不展开外部实体，风险面比 DOM/SAX 小，但这不构成“可以随便解析不可信 XML”的理由。

## 常见问题

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 中文乱码 | 声明了`utf-8`，实际按别的编码写出 | `setOutput(stream, "utf-8")`与`startDocument("utf-8", true)`保持一致 |
| 文本丢字符 | SAX 的`characters()`被多次回调 | 用`StringBuilder`累积 |
| `nextText()`崩溃 | 当前事件不是`START_TAG` | 只在`START_TAG`分支调用 |
| 解析大文件 OOM | 用了 DOM | 换 Pull/SAX |
| 属性取不到 | 没开命名空间，或名称拼错 | 明确`FEATURE_PROCESS_NAMESPACES`，用`getAttributeValue` |
| 写出文件为空 | 忘了`flush()`或没关闭流 | `use` + `flush()` |

> XML 在 Android 上的角色更多是“资源格式”而非“业务数据格式”。业务数据优先 JSON：体积小、解析简单、前后端一致。
