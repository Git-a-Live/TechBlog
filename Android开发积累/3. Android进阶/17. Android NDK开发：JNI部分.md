NDK（Native Development Kit，原生开发套件）是 Android 应用开发中的一项重要技术，主要用途包括：

- 复用已有的 C/C++ 库；
- 调用 Java/Kotlin 层没有暴露的平台能力或硬件接口；
- 把计算密集型逻辑下沉到 Native 层；
- 提高核心算法的逆向成本（只是提高成本，不是绝对安全）。

NDK 的大致工作流程是：在 Android Studio 中把 C/C++ 代码编译成 Native 库，由 Gradle 打包进 APK，最后通过 JNI（Java Native Interface）调用库中的函数。

需要先纠正一个常见误解：**NDK 不是“让 Java 变快”的万能药**。每次跨越 JNI 边界都有参数转换和调用开销，频繁的小调用可能比纯 Java 更慢。适合下沉的是批量计算、音视频处理、已有 C/C++ 库这类“单次调用、内部工作量大”的场景。

语言层前置：[[1. 指针、数组与字符串]]、[[4. STL 与智能指针]]、[[7. JNI 边界语义]]。

## JNI基本概念

JNI 是 Java 与其他语言（通常是 C/C++）通信的桥梁。当出现仅靠 Java 难以处理的任务时，JNI 可以派上用场，例如使用依赖操作系统平台特性的功能、整合已有的非 Java 系统、调用底层硬件能力等。JNI 是**双向**的：Java 可以通过 JNI 访问 Native 代码，Native 代码也可以通过 JNI 回调 Java。

Native 代码在 Android 应用中的基本载体是 `.so` 文件，这是 Linux 下的共享库，文件格式为 ELF（Executable and Linking Format）。直接打开 `.so` 只能看到二进制内容，通常需要借助工具分析：

| 工具 | 用途 |
| :--- | :--- |
| `readelf` / `objdump` / `nm` | 查看 ELF 头、段表、符号表，确认导出的 JNI 符号 |
| Ghidra | NSA 开源的逆向工具，免费 |
| IDA Pro | 商业逆向工具，有免费版和付费版 |

`.so` 会增加逆向难度，但不能等同于“防破解”：符号表、字符串、控制流都可能被还原，真正的敏感逻辑还应配合混淆、加固和服务端校验。

JNI 最核心的部分是 Native 方法注册，以下展开介绍。

## Native方法注册

Native 方法注册有两种方式：

- **静态注册**：靠固定的 JNI 函数命名规则，让虚拟机按名字找到实现；
- **动态注册**：在 `JNI_OnLoad` 中用 `RegisterNatives` 把 Java 方法和函数指针建立映射。

这两种方式在 **NDK 应用和 Framework 中都会使用**，并不是“静态注册只用于 NDK、动态注册只用于 Framework”。动态注册在应用里也很常见，例如批量注册、隐藏符号名、避免长函数名。

两者都需要以下步骤：

1. 一个 Java/Kotlin 类声明要用 C/C++ 实现的 Native 方法；
2. 在 C/C++ 文件中实现具体逻辑；
3. 在 Java/Kotlin 类中加载 `.so`。

区别在于关联方式：静态注册依赖方法名格式，动态注册依赖 `JNINativeMethod` 结构体数组。

### 静态注册

#### 声明Native方法和加载动态库

以 Android Studio 的 NDK 模板项目为例，声明 Native 方法和加载 `.so` 的类通常是 `MainActivity`：

```kotlin
class MainActivity : AppCompatActivity() {

    private lateinit var binding: ActivityMainBinding

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        binding = ActivityMainBinding.inflate(layoutInflater)
        setContentView(binding.root)

        binding.sampleText.text = stringFromJNI()
    }

    /**
     * 由 libmyapplication.so 实现的 Native 方法。
     */
    external fun stringFromJNI(): String

    companion object {
        init {
            System.loadLibrary("myapplication")
        }
    }
}
```

两处关键代码：

- `external fun stringFromJNI(): String`：声明 Native 方法。`external` 相当于 Java 的 `native`，表示方法不在 Kotlin/Java 中实现，因此不需要方法体。
- `System.loadLibrary("myapplication")`：加载名为 `myapplication` 的动态库。构建产物是 `libmyapplication.so`，`loadLibrary` 的参数不包含 `lib` 前缀和 `.so` 后缀。需要绝对路径时用 `System.load("/absolute/path/libxxx.so")`。

`System.loadLibrary` 通常放在 `companion object` 的 `init` 块或 `Application` 中，保证类初始化时只加载一次。加载失败会抛 `UnsatisfiedLinkError`。

Kotlin 有几个会影响 JNI 名字的细节：

- `external fun` 写在类体中，是实例方法，JNI 第二个参数是 `jobject`；
- 写在 `companion object` 里且**没有** `@JvmStatic`，它是 `Companion` 对象的实例方法，JNI 名字里会出现 `Companion`；
- 加 `@JvmStatic` 后，方法变成外部类的静态方法，JNI 名字回到外部类，第二个参数是 `jclass`；
- `@JvmName("foo")` 会改变 JVM 方法名，静态注册的 JNI 名字也要跟着改；
- 顶层 `external fun` 会编译到 `文件名Kt` 这个类里，JNI 名字要用这个类名。

#### 在C/C++文件中静态注册

`src/main/cpp/native-lib.cpp` 的典型内容：

```cpp
#include <jni.h>
#include <string>

extern "C" JNIEXPORT jstring JNICALL
Java_com_example_myapplication_MainActivity_stringFromJNI(
        JNIEnv* env,
        jobject /* thiz */) {
    std::string hello = "Hello from C++";
    return env->NewStringUTF(hello.c_str());
}
```

如果方法是 `static native`，第二个参数是 `jclass` 而不是 `jobject`：

```cpp
extern "C" JNIEXPORT jstring JNICALL
Java_com_example_myapplication_MainActivity_staticHello(
        JNIEnv* env,
        jclass /* clazz */) {
    return env->NewStringUTF("Hello from static native");
}
```

以下逐项解释。

**`jni.h`**：所有 Java/Kotlin 与 C/C++ 交互的源文件都必须包含它。里面定义了 JNI 数据类型映射（`jstring`、`jobject` 等）、`JNIEnv`、`JavaVM`、`JNINativeMethod` 等。

**`extern "C"`**：让编译器以 C 语言的链接规则处理被修饰的函数，避免 C++ 名称修饰（name mangling）。静态注册的 `Java_*` 函数会被虚拟机按名字 `dlsym` 查找，因此**必须是 C 链接**；`JNI_OnLoad` 也会被按名字查找，同样必须是 C 链接。动态注册的目标函数因为是通过函数指针调用的，名字不重要，可以不加 `extern "C"`，但 `JNI_OnLoad` 仍然要加。这一点很容易被误解为“动态注册完全不需要 `extern "C"`”。

**`JNIEXPORT`**：定义在 `jni.h` 中，作用类似 `public`，确保函数以默认可见性导出。Android 上它通常是 `__attribute__ ((visibility ("default")))`。如果编译时开了 `-fvisibility=hidden`，没有 `JNIEXPORT` 的函数不会被导出。

**`JNICALL`**：调用约定宏。Linux/Android 上通常为空，Windows 上是 `__stdcall`。Android 项目可以去掉，但保留有利于跨平台。

**函数名**：`Java_com_example_myapplication_MainActivity_stringFromJNI` 按固定规则与 Java 方法关联：

```text
Java_<类的全限定名，点换成下划线>_<方法名>
```

JNI 的名称修饰（mangling）规则：

| 原字符 | 转义 |
| :--- | :--- |
| `.` | `_` |
| `_` | `_1` |
| `;` | `_2` |
| `[` | `_3` |
| `$`（内部类） | `_00024` |
| 其他非 ASCII 字符 | `_0xxxx` |

如果 Native 方法被**重载**，短名字无法区分，虚拟机要求使用长名字：`__` 后接参数签名，分号、方括号按上表转义。例如：

```text
Java_com_example_myapplication_MainActivity_foo__I
Java_com_example_myapplication_MainActivity_foo__Ljava_lang_String_2
```

这也是为什么更推荐用 `javap -s -p` 生成签名，而不是手算。

**参数列表**：静态注册的 JNI 函数比 Java 方法多两个参数：

- 第一个是 `JNIEnv*`，代表当前线程的 JNI 环境；
- 第二个在实例方法中是 `jobject thiz`，在静态方法中是 `jclass clazz`。

`jobject` 是一个不透明指针，C/C++ 里不能直接访问它的字段，但可以先用 `env->GetObjectClass()` 拿到 `jclass`，再用 `GetFieldID()`、`GetMethodID()` 等 JNI 函数操作。它不是“什么都调不出来”，只是不能像 C++ 对象那样直接点出成员。

对于 Kotlin 的 `companion object`，方法默认是 `Companion` 的实例方法，第二个参数是 `jobject`（指向 Companion 实例）；加 `@JvmStatic` 后才变成外部类的静态方法，第二个参数才是 `jclass`。`ndk.png` 展示的就是在调试器里查看 `thiz` 实际指向的对象：

```c
Java_com_example_myapplication_MainActivity_stringFromJNI(
    JNIEnv* env,
    jobject MainActivity /* this，指向 MainActivity 实例 */) {
```

### 动态注册

静态注册的缺点很直接：

- 函数名过长；
- 包名、类名、方法名一改，JNI 函数名就要跟着改；
- 重载方法需要长名字，容易写错；
- 首次调用时虚拟机要按名字查找并建立关联。

动态注册通过 `RegisterNatives` 在库加载时一次性建立映射，函数名可以任意取，也不受包名/类名变化影响（但注册时使用的 `jclass` 仍然要对）。

动态注册的核心是两步：

1. 定义 `JNINativeMethod` 数组，记录 Java 方法名、签名和函数指针；
2. 在 `JNI_OnLoad` 中调用 `RegisterNatives`。

#### JNINativeMethod结构体

`JNINativeMethod` 定义在 `jni.h` 中：

```cpp
typedef struct {
    const char* name;       // Java 方法名
    const char* signature;  // 方法签名
    void*       fnPtr;      // C/C++ 函数指针
} JNINativeMethod;
```

它不包含 Java 类名，所以注册时必须把它和某个 `jclass` 绑定。**类名改了，注册代码里的 `FindClass` 或传入的 `jclass` 也要改**；只有“Native 方法名不变”并不能保证注册不受影响。

一个最小的动态注册示例：

```cpp
#include <jni.h>

static jstring stringFromJNI(JNIEnv* env, jobject /* thiz */) {
    return env->NewStringUTF("Hello from C++");
}

static const JNINativeMethod kMethods[] = {
    {"stringFromJNI", "()Ljava/lang/String;", reinterpret_cast<void*>(stringFromJNI)},
};

extern "C" JNIEXPORT jint JNICALL JNI_OnLoad(JavaVM* vm, void* /* reserved */) {
    JNIEnv* env = nullptr;
    if (vm->GetEnv(reinterpret_cast<void**>(&env), JNI_VERSION_1_6) != JNI_OK) {
        return JNI_ERR;
    }

    jclass clazz = env->FindClass("com/example/myapplication/MainActivity");
    if (clazz == nullptr) {
        return JNI_ERR;
    }

    if (env->RegisterNatives(
            clazz,
            kMethods,
            sizeof(kMethods) / sizeof(kMethods[0])) != JNI_OK) {
        return JNI_ERR;
    }

    return JNI_VERSION_1_6;
}
```

`JNI_OnLoad` 在 `System.loadLibrary` 加载库时被调用，返回值是支持的 JNI 版本，失败返回 `JNI_ERR`。`GetEnv` 的第二个参数必须是 `JNI_VERSION_1_6`（或 `1_4`），否则会失败。

AOSP 的 MediaRecorder 是动态注册的典型例子。`android_media_MediaRecorder.cpp` 中定义数组：

```cpp
static const JNINativeMethod gMethods[] = {
    {"setCamera",           "(Landroid/hardware/Camera;)V", (void*)android_media_MediaRecorder_setCamera},
    {"setVideoSource",      "(I)V",                         (void*)android_media_MediaRecorder_setVideoSource},
    {"setAudioSource",      "(I)V",                         (void*)android_media_MediaRecorder_setAudioSource},
    {"setPrivacySensitive", "(Z)V",                         (void*)android_media_MediaRecorder_setPrivacySensitive},
    {"isPrivacySensitive",  "()Z",                          (void*)android_media_MediaRecorder_isPrivacySensitive},
};
```

注册函数：

```cpp
int register_android_media_MediaRecorder(JNIEnv* env) {
    return AndroidRuntime::registerNativeMethods(
            env,
            "android/media/MediaRecorder",
            gMethods,
            NELEM(gMethods));
}
```

`AndroidRuntime::registerNativeMethods` 内部最终调用 `jniRegisterNativeMethods`，再到 `env->RegisterNatives`。这条链路是 Framework 的封装，应用层直接用 `RegisterNatives` 即可。

`JNI_OnLoad` 中调用注册函数：

```cpp
extern "C" JNIEXPORT jint JNICALL JNI_OnLoad(JavaVM* vm, void* /* reserved */) {
    JNIEnv* env = nullptr;
    if (vm->GetEnv(reinterpret_cast<void**>(&env), JNI_VERSION_1_6) != JNI_OK) {
        return JNI_ERR;
    }

    if (register_android_media_MediaRecorder(env) < 0) {
        return JNI_ERR;
    }

    return JNI_VERSION_1_6;
}
```

注册函数不必“只能”放在 `JNI_OnLoad` 里，也可以在之后的某个 JNI 调用中执行；但放在 `JNI_OnLoad` 能保证在 Java 调用 Native 方法之前完成注册，是最常见的做法。

静态注册与动态注册的对比：

| 对比项 | 静态注册 | 动态注册 |
| :--- | :--- | :--- |
| 关联方式 | 固定函数名 | `JNINativeMethod` + `RegisterNatives` |
| 函数名 | 必须符合 JNI mangling | 可任意命名 |
| 改名影响 | 包名/类名/方法名变化都要改 | 只需改注册时的 `jclass`/方法名 |
| 注册时机 | 首次调用时按名字查找 | `JNI_OnLoad` 中一次性注册 |
| 适用场景 | 方法少、结构稳定 | 方法多、需要批量注册或隐藏符号 |

## JNI重要数据结构

### 数据类型转换与方法签名

Java 类型在 `jni.h` 中有对应的 C/C++ 类型，动态注册和签名都要用到这些映射：

| Java 类型 | jni.h 定义 | C/C++ 类型 | 签名 |
| :--- | :--- | :--- | :--- |
| `byte` | `jbyte` | `signed char` | `B` |
| `char` | `jchar` | `unsigned short` | `C` |
| `double` | `jdouble` | `double` | `D` |
| `float` | `jfloat` | `float` | `F` |
| `int` | `jint` | `int` | `I` |
| `short` | `jshort` | `short` | `S` |
| `long` | `jlong` | `long long` | `J` |
| `boolean` | `jboolean` | `unsigned char` | `Z` |
| `void` | `void` | `void` | `V` |
| 任意对象 | `jobject` | `_jobject*` | `L<全限定类名>;` |
| `Class` | `jclass` | `_jclass*` | `Ljava/lang/Class;` |
| `String` | `jstring` | `_jstring*` | `Ljava/lang/String;` |
| `Throwable` | `jthrowable` | `_jthrowable*` | `Ljava/lang/Throwable;` |
| `Object[]` | `jobjectArray` | `_jobjectArray*` | `[Ljava/lang/Object;` |
| `String[]` | `jobjectArray` | `_jobjectArray*` | `[Ljava/lang/String;` |
| `byte[]` | `jbyteArray` | `_jbyteArray*` | `[B` |
| `char[]` | `jcharArray` | `_jcharArray*` | `[C` |
| `double[]` | `jdoubleArray` | `_jdoubleArray*` | `[D` |
| `float[]` | `jfloatArray` | `_jfloatArray*` | `[F` |
| `int[]` | `jintArray` | `_jintArray*` | `[I` |
| `short[]` | `jshortArray` | `_jshortArray*` | `[S` |
| `long[]` | `jlongArray` | `_jlongArray*` | `[J` |
| `boolean[]` | `jbooleanArray` | `_jbooleanArray*` | `[Z` |

方法签名的格式是 `(参数签名)返回值签名`，多个参数直接并排。例如：

- `void setCamera(Camera c)` → `(Landroid/hardware/Camera;)V`
- `fun foo(a: Int, b: Float, c: String): Demo` → `(IFS)Lcom/example/app/Demo;`
- `String getName()` → `()Ljava/lang/String;`

`this` 不参与签名，只写显式参数。内部类的类名用 `$` 分隔，例如 `Lcom/example/Outer$Inner;`。

不要手算签名，用 `javap` 最稳：

```bash
javap -s -p app/build/tmp/kotlin-classes/debug/com/example/myapplication/MainActivity.class
```

输出类似：

```text
Compiled from "MainActivity.kt"
public final class com.example.myapplication.MainActivity extends androidx.appcompat.app.AppCompatActivity {
  public static final com.example.myapplication.MainActivity$Companion Companion;
    descriptor: Lcom/example/myapplication/MainActivity$Companion;

  public final native java.lang.String stringFromJNI();
    descriptor: ()Ljava/lang/String;

  static {};
    descriptor: ()V
}
```

成员变量看 `descriptor` 的类型，方法看 `descriptor` 的完整签名。`-s` 输出签名，`-p` 包含私有成员。

Kotlin 的 class 文件通常在 `build/tmp/kotlin-classes/<variant>/...`；Java 代码在 `build/intermediates/javac/<variant>/classes/...`。路径随 AGP 版本可能变化，找不到时用 Android Studio 的 “Show Bytecode” 或直接在 `build/` 下搜索 `.class`。

### JNIEnv与JavaVM

`JNIEnv` 是当前线程的 JNI 环境，通过它可以调用 Java 方法、访问字段、创建对象。`JNIEnv*` **只在创建它的线程有效，不能跨线程传递**；不同线程的 `JNIEnv` 彼此独立。`JavaVM` 则是进程级的，可以在线程间共享，用来获取当前线程的 `JNIEnv` 或附加线程。

`jni.h` 中 C 和 C++ 的定义不同：

```cpp
#if defined(__cplusplus)
typedef _JNIEnv JNIEnv;
typedef _JavaVM JavaVM;
#else
typedef const struct JNINativeInterface* JNIEnv;
typedef const struct JNIInvokeInterface* JavaVM;
#endif
```

C++ 下 `_JNIEnv` 是一个包装结构体，内部持有 `JNINativeInterface*`，每个方法转调函数表：

```cpp
struct _JNIEnv {
    const struct JNINativeInterface* functions;

    jclass FindClass(const char* name) {
        return functions->FindClass(this, name);
    }

    jmethodID GetMethodID(jclass clazz, const char* name, const char* sig) {
        return functions->GetMethodID(this, clazz, name, sig);
    }

    // ...
};
```

C 下 `JNIEnv` 就是函数表指针，调用形式是 `(*env)->FindClass(env, ...)`；C++ 下是 `env->FindClass(...)`。

常用函数：

| 函数 | 用途 |
| :--- | :--- |
| `FindClass` | 按全限定名查找类 |
| `GetObjectClass` | 获取对象的类 |
| `GetFieldID` / `GetStaticFieldID` | 获取字段 ID |
| `GetMethodID` / `GetStaticMethodID` | 获取方法 ID |
| `NewObject` | 创建 Java 对象 |
| `NewStringUTF` | 创建 Java 字符串（modified UTF-8） |
| `NewIntArray` / `NewByteArray` 等 | 创建基础类型数组 |
| `GetIntField` / `SetIntField` 等 | 读写字段 |
| `CallVoidMethod` / `CallStaticObjectMethod` 等 | 调用方法 |
| `GetArrayLength` / `GetIntArrayElements` / `ReleaseIntArrayElements` | 操作数组 |
| `ExceptionCheck` / `ExceptionClear` / `ThrowNew` | 异常处理 |

`JNINativeInterface` 是函数指针表，`JNIEnv` 的所有操作最终都落到这张表：

```cpp
struct JNINativeInterface {
    void*       reserved0;
    void*       reserved1;
    void*       reserved2;
    void*       reserved3;

    jint        (*GetVersion)(JNIEnv*);
    jclass      (*FindClass)(JNIEnv*, const char*);
    jmethodID   (*GetMethodID)(JNIEnv*, jclass, const char*, const char*);
    // ...
    jobjectRefType (*GetObjectRefType)(JNIEnv*, jobject);
};
```

### 线程附加

Native 自己创建的线程如果要调用 Java，必须先附加到 JVM：

```cpp
JavaVM* gVm = nullptr;
JNIEnv* env = nullptr;

// 在 JNI_OnLoad 中保存 JavaVM
env->GetJavaVM(&gVm);

// 在 Native 线程中
if (gVm->AttachCurrentThread(&env, nullptr) != JNI_OK) {
    return;
}

// 使用 env 调用 Java

gVm->DetachCurrentThread();
```

附加过的线程在退出前必须 `DetachCurrentThread`，否则线程结束时 JVM 可能崩溃或泄漏。主线程和已经在 Java 侧创建的线程不需要手动附加。

## 字符串、数组与异常

### 字符串

```cpp
jstring jstr = env->NewStringUTF("hello");

const char* chars = env->GetStringUTFChars(jstr, nullptr);
if (chars == nullptr) {
    return; // 内存不足
}
std::string copy(chars);
env->ReleaseStringUTFChars(jstr, chars);
```

`GetStringUTFChars` 返回的指针必须用 `ReleaseStringUTFChars` 释放，否则会泄漏。`NewStringUTF` 使用的是 **modified UTF-8**：`\0` 编码为两字节，补充平面字符用代理对表示。如果要处理任意 Unicode，使用 UTF-16 的 `NewString` / `GetStringChars` 更稳妥。

### 数组

```cpp
jintArray array = env->NewIntArray(len);
env->SetIntArrayRegion(array, 0, len, data);

jsize size = env->GetArrayLength(array);
jint* elements = env->GetIntArrayElements(array, nullptr);
if (elements != nullptr) {
    // 读写 elements
    env->ReleaseIntArrayElements(array, elements, 0);
}
```

`GetIntArrayElements` 可能返回副本，也可能返回指向原数组的指针；无论哪种，都必须 `ReleaseIntArrayElements`。只读写一段时用 `GetIntArrayRegion` / `SetIntArrayRegion`，避免整数组拷贝。

### 异常

JNI 调用 Java 方法后可能留下“待处理异常”。在异常挂起时，大多数 JNI 函数不能再调用，必须先检查并处理：

```cpp
if (env->ExceptionCheck()) {
    env->ExceptionDescribe(); // 打印到日志，调试用
    env->ExceptionClear();    // 清除异常，继续执行
    return nullptr;
}
```

如果要向 Java 抛异常，用 `ThrowNew`：

```cpp
jclass clazz = env->FindClass("java/lang/IllegalStateException");
if (clazz != nullptr) {
    env->ThrowNew(clazz, "native error");
}
```

`ExceptionDescribe` 只适合调试；正式代码应记录日志或转换成合适的 Java 异常，不要静默 `ExceptionClear`。

## JNI引用类型

JNI 引用分为本地引用、全局引用和弱全局引用。它们决定对象能否被 GC 回收、能否跨线程使用。

### 本地引用

本地引用是最常见的引用类型，JNI 函数返回的对象引用基本都是本地引用。特点：

- Native 方法返回时自动释放；
- 只在创建它的线程有效，不能跨线程使用；
- 由 VM 管理。

在循环中创建大量本地引用会撑爆局部引用表，出现 `JNI ERROR (app bug): local reference table overflow`。解决方法是及时 `DeleteLocalRef`，或者用 `PushLocalFrame` / `PopLocalFrame` 批量管理：

```cpp
if (env->PushLocalFrame(16) != JNI_OK) {
    return;
}

jobject obj = env->NewObject(...);
// 使用 obj

env->PopLocalFrame(nullptr); // 释放这一帧内的所有本地引用
```

### 全局引用

全局引用不会自动释放，必须手动 `DeleteGlobalRef`；它会**阻止被引用对象被 GC 回收**，因此可以跨线程长期持有。创建和释放：

```cpp
jobject global = env->NewGlobalRef(localObj);
// 长期使用
env->DeleteGlobalRef(global);
```

常见用途：`JNI_OnLoad` 中缓存 `jclass`、`jmethodID` 对应的类/方法，或者在 Native 层保存 Java 回调对象。全局引用泄漏会导致对象和类加载器无法回收，必须成对释放。

### 弱全局引用

弱全局引用不会阻止 GC。对象被回收后，弱引用会被清除，可以用 `IsSameObject(ref, nullptr)` 判断：

```cpp
jweak weak = env->NewWeakGlobalRef(obj);

if (env->IsSameObject(weak, nullptr)) {
    // 对象已被回收
}

env->DeleteWeakGlobalRef(weak);
```

弱全局引用适合缓存“有就用、没有就重建”的对象，不适合持有必须存活的对象。

## 常见问题

| 现象 | 常见原因 | 排查方式 |
| :--- | :--- | :--- |
| `UnsatisfiedLinkError: No implementation found for ...` | JNI 函数名/签名不匹配；方法被 `@JvmName`/`@JvmStatic` 改了名 | `javap -s -p` 看 JVM 名字和签名；用 `nm -D libxxx.so` 看导出符号 |
| `dlopen failed: library "libxxx.so" not found` | 库没打包、ABI 不匹配、`loadLibrary` 名字写错 | 检查 APK 的 `lib/<abi>/`；确认设备 ABI |
| `local reference table overflow` | 循环中创建大量本地引用 | 及时 `DeleteLocalRef` 或用 `PushLocalFrame` |
| 调用 Java 后行为异常/崩溃 | 有 pending exception 未处理 | `ExceptionCheck` / `ExceptionDescribe` / `ExceptionClear` |
| `SIGSEGV` / `SIGABRT` | 空指针、越界、double free、ABI/STL 不匹配 | 看 tombstone；用 `ndk-stack` 符号化 |
| Android 15+ 设备上 `dlopen` 失败 | `.so` 未按 16 KB 页对齐 | 用 NDK r28+ 重建，或加 16 KB 链接参数（见 NDK 篇） |

JNI 的调试成本主要来自“跨语言边界”：Java 栈和 Native 栈是两套，崩溃时的 tombstone 只给地址。保留带符号的 `.so`、用 `ndk-stack` 还原行号，是排查 Native 崩溃的基本功。
