## 基本概念

IO 是 Input/Output。它以**内存**为中心：

+ **Input**：把外部数据读进内存（磁盘 → 内存、网络 → 内存）；
+ **Output**：把内存中的数据写到外部（内存 → 磁盘、内存 → 网络）。

流（Stream）是顺序读写的数据通道，**单向**、不能回头。按最小单位分两种：

| 类型 | 单位 | 基类 | 适合 |
|:--|:--|:--|:--|
| 字节流 | `byte` | `InputStream` / `OutputStream` | 图片、音视频、压缩包等二进制数据 |
| 字符流 | `char` | `Reader` / `Writer` | 文本，且涉及编码转换 |

字符流不是另一套底层通道，它是在字节流之上加了一层**编码/解码**：`InputStreamReader` 把字节按指定字符集解成字符，`OutputStreamWriter` 反过来。所以“读文本用字符流”真正的收益是——不用自己算一个字符占几个字节。

## File 类

`File` 是 `java.io` 里表示“文件或目录路径”的类。它**只描述路径**，不持有文件内容。

### 构造与路径

```kotlin
val file = File("/data/user/0/com.example.app/files/demo.txt")

// 更常用的写法：父目录 + 子路径，避免手工拼接分隔符
val child = File(context.filesDir, "demo.txt")
```

路径分两种：

+ **绝对路径**：从根目录写起，如 `/data/user/0/...`、`/storage/emulated/0/...`；
+ **相对路径**：省略根目录，以进程的**工作目录**为基准。

Android 应用的进程工作目录是 `/`，所以相对路径 `"demo.txt"` 实际指向 `/demo.txt`——普通应用没有写权限。**实际开发一律用绝对路径**，目录从 `context.filesDir`、`getExternalFilesDir()` 这类 API 拿，不要自己拼。

三种取路径的方法：

| 方法 | 返回 |
|:--|:--|
| `getPath()` | 构造时传入的原样路径 |
| `getAbsolutePath()` | 绝对路径，但不解析 `.`、`..` |
| `getCanonicalPath()` | 规范化后的唯一绝对路径：消掉 `.`/`..`、解析符号链接 |

构造 `File` **不会触碰磁盘**，路径不存在也不会报错；只有调用 `exists()`、`length()`、`listFiles()` 这些方法时才真正访问文件系统。

### 文件与目录操作

| 方法 | 用途 | 注意 |
|:--|:--|:--|
| `exists()` | 是否存在 | 无权限时也可能返回 false |
| `isFile()` / `isDirectory()` | 类型判断 | 不存在时都返回 false |
| `getName()` / `getParent()` | 名称 / 父目录路径 | `getParent()` 可能为 null（已是根） |
| `length()` | 文件字节数 | **目录的返回值由文件系统决定，不是目录总占用** |
| `list()` / `listFiles()` | 列出子项 | 不是目录或读取失败时返回 **null**，必须判空 |
| `createNewFile()` | 创建空文件 | 已存在返回 false；父目录不存在抛 `IOException` |
| `mkdir()` / `mkdirs()` | 建一级 / 建多级目录 | 父目录不存在时 `mkdir()` 失败 |
| `delete()` | 删除 | **目录必须为空**；递归删用 `deleteRecursively()` |
| `renameTo()` | 重命名 / 移动 | 跨分区可能失败，失败返回 false |
| `canRead()` / `canWrite()` / `canExecute()` | 权限判断 | 只反映当前进程，不保证后续操作成功 |
| `getFreeSpace()` / `getUsableSpace()` / `getTotalSpace()` | 所在分区空间 | 是**分区**的，不是这个文件的 |

### Kotlin 扩展函数

Kotlin 标准库给 `File` 加了一批扩展，内部自己负责流的创建与关闭，调用方不需要再管 `close()`：

| 函数 | 用途 | 适用 |
|:--|:--|:--|
| `readText(charset = UTF_8)` | 一次性读成 String | 小文件 |
| `writeText(text, charset = UTF_8)` | 写入 String，覆盖原内容 | 小文件 |
| `appendText(text, charset = UTF_8)` | 追加 String | 小文件 |
| `readBytes()` / `writeBytes(array)` / `appendBytes(array)` | 字节数组读写 | 小文件 |
| `readLines(charset = UTF_8)` | 读成 `List<String>` | 小文件 |
| `forEachLine(charset = UTF_8) { }` | 逐行读取 | 大文件 |
| `useLines(charset = UTF_8) { }` | 读成 `Sequence<String>`，块结束自动关闭 | 大文件 |
| `forEachBlock(bufferSize = DEFAULT_BUFFER_SIZE) { buffer, bytesRead -> }` | 按固定大小分块读 | 大文件、二进制 |
| `copyTo(target, overwrite = false)` | 复制文件 | — |
| `copyRecursively(target)` | 递归复制目录 | — |
| `deleteRecursively()` | 递归删除 | 清理目录 |
| `inputStream()` / `outputStream()` | 拿到字节流，交给下游处理 | — |

“小文件”没有严格界线，经验上几 MB 以内可以一次性读；再大就用流，否则一次 `readBytes()` 会把整个文件塞进堆里。

### java.nio.file（API 26+）

`java.nio.file` 的 `Files` 与 `Paths` 从 **Android 8.0（API 26）** 才可用，适合简单的小文件操作：

```kotlin
val path = Paths.get(context.filesDir.absolutePath, "demo.txt")

Files.write(path, "hello".toByteArray())          // 写入，默认覆盖
val text = String(Files.readAllBytes(path))       // 读出
Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING)
Files.move(source, target, StandardCopyOption.REPLACE_EXISTING)
Files.deleteIfExists(path)
Files.exists(path)
```

好处是 API 简洁；限制是**低版本不可用**，且同样不适合大文件（`readAllBytes()` 是整读）。

## 字节流

`InputStream` 和 `OutputStream` 是所有字节流的抽象基类。

### InputStream

核心方法 `read()` 有三种重载：

| 方法 | 返回 | 说明 |
|:--|:--|:--|
| `read()` | 0~255 或 -1 | 读一个字节，返回其无符号值 |
| `read(byte[])` | 实际读到的字节数或 -1 | 读到数组里，返回值可能小于数组长度 |
| `read(byte[], off, len)` | 实际读到的字节数或 -1 | 指定写入起点与最大长度 |

**三种都以返回 `-1` 表示流结束**。判断时用 `!= -1`，不要用 `> 0`——`read(byte[], off, len)` 在 `len == 0` 时返回 0，用 `> 0` 会误判成结束。

`read(byte[])` 的返回值只代表“这次读了多少”，不保证填满数组，所以要用返回值而不是数组长度来构造后续数据。

#### FileInputStream

```kotlin
// 推荐：use 会自动关闭，异常时也关
FileInputStream(file).use { input ->
    val buffer = ByteArray(8 * 1024)
    while (true) {
        val read = input.read(buffer)
        if (read == -1) break
        // buffer 的前 read 个字节是本次读到的数据
    }
}
```

对应的 Java 写法是 try-with-resources：

```java
try (InputStream input = new FileInputStream(file)) {
    // ...
}
```

Kotlin **不支持** try-with-resources 语法，等价物就是 `use`：

```kotlin
FileInputStream(file).use { input ->
    var b = input.read()
    while (b != -1) {
        // 处理这一个字节
        b = input.read()
    }
}
```

`use` 定义在 `Closeable` 上，凡是实现了 `Closeable`（或 `AutoCloseable`）的对象都能用；无论块内是否抛异常，退出时都会关闭。

#### ByteArrayInputStream

用内存里的一个字节数组模拟数据源，适合测试、或数据本来就在内存里的场景：

```kotlin
ByteArrayInputStream("hello".toByteArray()).use { input ->
    // 用法与 FileInputStream 完全一致
}
```

#### 装饰器：给流加能力

`FilterInputStream` 是装饰器的基类，它本身只是把调用转发给内部的流，真正的功能由子类加。

**BufferedInputStream**：内部维护缓冲区，减少系统调用次数。

```kotlin
FileInputStream(file).buffered().use { input ->
    // 单字节读取也变快了
}
```

**DataInputStream**：按 Java 基本类型读取，**必须与 `DataOutputStream` 配对**，写入顺序和读取顺序要完全一致。

```kotlin
DataInputStream(BufferedInputStream(FileInputStream(file))).use { input ->
    val flag = input.readBoolean()
    val count = input.readInt()
    val name = input.readUTF()
    val ratio = input.readFloat()
}
```

**ZipInputStream**：读取 zip 压缩包，逐个条目遍历。

```kotlin
ZipInputStream(BufferedInputStream(FileInputStream(zipFile))).use { zis ->
    var entry = zis.nextEntry
    while (entry != null) {
        if (!entry.isDirectory) {
            // 此时 zis 定位在该条目的数据起点，直接读即可
            val content = zis.readBytes()      // 单条目很大时改用缓冲区循环读
        }
        zis.closeEntry()                      // 读完当前条目再取下一个
        entry = zis.nextEntry
    }
}
```

### OutputStream

| 方法 | 说明 |
|:--|:--|
| `write(int)` | 写一个字节（取低 8 位） |
| `write(byte[])` | 写整个数组 |
| `write(byte[], off, len)` | 写数组的一段 |
| `flush()` | 强制把缓冲区内容推给下层 |

`flush()` 只对**有缓冲**的流有意义。`close()` 本身会先 flush，所以“关闭前必须手动 flush”不成立；需要手动 flush 的场景是**不关闭但要求数据立刻到达**（长连接、日志实时落盘）。

#### FileOutputStream

```kotlin
FileOutputStream(file).use { output ->
    output.write("hello".toByteArray())
}

// 追加模式
FileOutputStream(file, true).use { output ->
    output.write("more".toByteArray())
}
```

#### ByteArrayOutputStream

把数据写进内存缓冲区，最后 `toByteArray()` 取出：

```kotlin
val buffer = ByteArrayOutputStream()
buffer.use { output ->
    output.write("hello".toByteArray())
}
val bytes = buffer.toByteArray()
```

`ByteArrayOutputStream` 的 `close()` 是空实现，用 `use` 只是为了风格统一。

#### BufferedOutputStream

```kotlin
BufferedOutputStream(FileOutputStream(file)).use { output ->
    output.write(data)
}
```

数据先落到缓冲区，写满才真正落盘；`close()` 会 flush，**不需要**手动调。只有流不关闭又要立即落盘时才手动 `flush()`。

#### DataOutputStream

```kotlin
DataOutputStream(BufferedOutputStream(FileOutputStream(file))).use { output ->
    output.writeBoolean(true)
    output.writeInt(42)
    output.writeUTF("hello")
    output.writeFloat(1.2f)
    output.flush()
}
```

写入的每个值都带类型标记，`DataInputStream` 靠这些标记还原类型，所以两边顺序必须严格对应。

#### ZipOutputStream

写压缩包的顺序是：**开条目 → 写数据 → 关条目**，再开下一个：

```kotlin
ZipOutputStream(BufferedOutputStream(FileOutputStream(zipFile))).use { zos ->
    zos.putNextEntry(ZipEntry("readme.txt"))
    zos.write("hello".toByteArray())
    zos.closeEntry()                       // 必须关，否则下个条目打不开

    zos.putNextEntry(ZipEntry("data/info.txt"))
    zos.write(infoBytes)
    zos.closeEntry()
}
```

`putNextEntry()` 只是**打开一个条目**，数据仍然用 `write()` 写；`closeEntry()` 结束当前条目。漏掉 `closeEntry()` 会抛 `ZipException`。

#### PrintStream

`PrintStream` 在输出流上加了 `print()` / `println()` 这类格式化方法，`System.out` 和 `System.err` 就是它的实例。它**吞掉 `IOException`**，只把错误记在内部标志里，需要主动调 `checkError()` 才能发现写入失败——这也是它不适合做重要数据写入的原因。

## 字符流

`Reader` / `Writer` 处理字符，**负责编码转换**。它们是抽象类，不是接口。

### 编码与乱码

同一个字符在不同字符集下字节序列不同：

| 字符 | UTF-8 | GBK |
|:--|:--|:--|
| 中 | `E4 B8 AD`（3 字节） | `D6 D0`（2 字节） |

**用 A 编码写入、用 B 解码读取，就会乱码**。所以两端必须约定同一个字符集。Android 内部默认 UTF-8，但与外部系统交换文件（Windows 上的旧文本、CSV 导出）时经常是 GBK。

不要依赖平台默认值，显式指定：

```kotlin
FileInputStream(file).reader(Charsets.UTF_8).use { reader ->
    val text = reader.readText()
}
```

`FileReader` 使用默认字符集，且没有可靠的指定编码方式（带 `Charset` 的构造器在低版本不可用）。**需要指定编码时，一律用 `InputStreamReader(FileInputStream(file), charset)`**，各版本行为一致。

### Reader

```kotlin
InputStreamReader(FileInputStream(file), Charsets.UTF_8).use { reader ->
    val buffer = CharArray(1024)
    while (true) {
        val read = reader.read(buffer)
        if (read == -1) break
        // buffer 的前 read 个字符有效
    }
}
```

#### BufferedReader

最常用的文本读取方式，提供按行读取：

```kotlin
FileInputStream(file).bufferedReader(Charsets.UTF_8).use { reader ->
    reader.forEachLine { line ->
        // 逐行处理，不把整个文件读进内存
    }
}
```

`readLine()` 返回 null 表示读完；`forEachLine` / `lineSequence()` 是它的 Kotlin 封装。

#### 内存数据源

```kotlin
CharArrayReader(charArrayOf('A', 'B', 'C')).use { reader -> /* ... */ }
StringReader("hello").use { reader -> /* ... */ }
```

用途与 `ByteArrayInputStream` 相同：测试时避免落盘。

### Writer

```kotlin
FileOutputStream(file).bufferedWriter(Charsets.UTF_8).use { writer ->
    writer.write("第一行")
    writer.newLine()
    writer.write("第二行")
}
```

`Writer` 实现了 `Flushable`，所以也有 `flush()`；它的 `close()` 同样会先 flush。

#### FileWriter

```kotlin
FileWriter(file).use { writer ->
    writer.write("hello")
}
```

同样受默认字符集限制，需要指定编码时用 `OutputStreamWriter(FileOutputStream(file), Charsets.UTF_8)`。

#### CharArrayWriter / StringWriter

两者都在内存里拼字符，区别是内部缓冲：`CharArrayWriter` 用 `CharArray`，`StringWriter` 用 `StringBuffer`。

```kotlin
val writer = StringWriter()
writer.use {
    it.write("hello, ")
    it.write("world")
}
val text = writer.toString()
```

`StringWriter` 的 `close()` 是空实现，`toString()` 在关闭后仍可调用。

#### OutputStreamWriter

把字节流包装成字符流，是 `InputStreamReader` 的反向操作：

```kotlin
OutputStreamWriter(FileOutputStream(file), Charsets.UTF_8).use { writer ->
    writer.write("hello")
}
```

#### PrintWriter

`PrintWriter` 提供 `print()` / `printf()` / `println()`，和 `PrintStream` 用法几乎一样，区别是它写字符。两者还有一个共同点：**都会吞掉 `IOException`**，只能靠 `checkError()` 发现写入失败。重要数据用 `BufferedWriter` 或 `File.writeText()`，让异常正常抛出。

## 资源关闭

三种写法，按推荐程度排序：

```kotlin
// 1. Kotlin 的 use：最简洁，异常也会关
FileInputStream(file).use { input -> /* ... */ }

// 2. try-catch-finally：老写法，必须判空
var input: InputStream? = null
try {
    input = FileInputStream(file)
    // ...
} finally {
    input?.close()
}

// 3. Java 的 try-with-resources：Kotlin 不支持
```

`use` 的可靠性源于它在 `finally` 里调用 `close()`，并且会**压制关闭时抛出的异常**，保证原始异常不被覆盖。

## 常见问题

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 读到一半就“结束” | 用 `read(...) > 0` 判断，遇到返回 0 就退出 | 统一用 `!= -1` |
| 中文乱码 | 写入与读取用了不同字符集 | 两端显式指定同一个 `Charset` |
| 文件内容缺一段 | 用了缓冲流但没关闭、没 flush | 用 `use`，或在不关闭时手动 `flush()` |
| 大文件 OOM | `readBytes()` / `readText()` 整读 | 改用 `forEachBlock` / 流式循环 |
| `listFiles()` 空指针 | 不是目录或读取失败时返回 null | 先判空 |
| `delete()` 删不掉目录 | 目录非空 | 用 `deleteRecursively()` |
| 文本在 Windows 打不开 | 写了 UTF-8，对方按 GBK 解 | 按目标环境选编码 |

> Android 上的文件读写都是**同步阻塞**的，主线程直接调用会触发 ANR。界面相关的读写放到协程的`Dispatchers.IO`，见[[7. Kotlin协程：入门基础#调度器|调度器]]。
