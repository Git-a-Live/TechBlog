端侧大模型的落地依赖「模型 + 推理引擎」的组合。模型准备环节解决「从哪下载、转成什么格式」，推理引擎环节解决「如何在设备上跑起来」。本章梳理模型准备流程，并逐一介绍主流端侧框架的集成用法。

## 模型准备

端侧部署前，需要先获取模型文件，再把它转换成目标引擎支持的格式。

### 模型下载源

国内可直接访问、规模最大的大模型社区是阿里达摩院出品的 **ModelScope（魔搭社区，modelscope.cn）**。它与 Hugging Face 定位相同，都是模型托管与分发平台，但服务器部署在国内、免翻墙、下载速度快，且中文模型（Qwen、DeepSeek、ChatGLM、MiniCPM 等）覆盖最全，是国内开发者获取端侧模型的首选渠道。

除魔搭外，国内可访问的主流渠道如下：

|社区|网址|定位|
|:--|:--|:--|
|ModelScope（魔搭）|modelscope.cn|国内规模最大，中文模型最全，官方/国产模型首发地|
|HF-Mirror|hf-mirror.com|Hugging Face 的国内镜像，用于下载 HF 上的模型|
|Gitee AI|ai.gitee.com|代码托管平台的 AI 子站，部分模型镜像|
|始智 AI（WiseModel）|wisemodel.cn|模型资源丰富，支持直链下载|

魔搭社区提供三种下载方式（以 GGUF 量化模型为例）：

```bash
# 1. CLI 下载（自动校验 + 断点续传）
pip install modelscope
modelscope download --model Qwen/Qwen2.5-0.5B-Instruct-GGUF \
    --local_dir . qwen2.5-0.5b-instruct-q5_k_m.gguf
```

```python
# 2. Python SDK 下载
from modelscope import snapshot_download
model_dir = snapshot_download('Qwen/Qwen2.5-0.5B-Instruct-GGUF', cache_dir='./models')
```

```bash
# 3. Git 下载
git clone https://www.modelscope.cn/Qwen/Qwen2.5-0.5B-Instruct-GGUF.git
```

> 若模型只发布在 Hugging Face 上，可用 HF-Mirror 镜像加速下载：设置环境变量 `HF_ENDPOINT=https://hf-mirror.com` 后再用 `huggingface-cli download` 即可。

### 格式转换

获取到模型后，需转换成目标引擎支持的格式：

+ **GGUF**（llama.cpp）：在社区直接下载现成的 `*-GGUF` 量化模型，或自行用转换脚本量化；
+ **MNN 格式**（MNN-LLM）：用阿里提供的 `llm_export` 工具把 HuggingFace 格式转成 `.mnn`（见下文 MNN-LLM 章节的具体命令）；
+ **MediaPipe `.task` bundle**：用 Google 提供的脚本把 Gemma/Phi 等转成 MediaPipe 可加载的格式；
+ **LiteRT-LM `.litertlm`**：用 `litert-lm` CLI 从 Hugging Face 转换或直接下载预转换模型（见下文 LiteRT-LM 章节）。

## Gemini Nano 与 AICore

AICore 是 Android 系统级服务，托管 Gemini Nano 模型——模型由系统共享、免每应用下载、通过 NPU 硬件加速、经 Play Services 自动更新。应用层通过 Google 官方提供的 **ML Kit GenAI Prompt API**（`com.google.mlkit:genai-prompt`）直接调用，无需碰底层推理引擎。

> 需要注意，早期的 `com.google.ai.client.generativeai:generativeai` 已由官方迁移到 ML Kit GenAI Prompt API，新项目应以 `com.google.mlkit:genai-prompt` 为准。

### 集成

在模块级 build.gradle 中添加依赖：

```groovy
dependencies {
    // ML Kit GenAI Prompt API（直接模型访问）
    implementation 'com.google.mlkit:genai-prompt:1.0.0-beta4'
    // 若需要结构化输出（typed structured output），需额外引入 schema 并配置 KSP
    implementation 'com.google.mlkit:genai-schema:1.0.0-alpha2'
}
```

```groovy
android {
    defaultConfig {
        // 要求 minSdk 26 及以上
        minSdk 26
    }
}
```

> 依赖版本仍在快速演进（beta 阶段），具体以 [官方文档](https://developers.google.com/ml-kit/genai/prompt/android/get-started) 为准。

### 获取模型并检查状态

AICore 中的 Gemini Nano 模型并非在所有设备上都预装，因此推理前必须通过 `checkStatus()` 检查可用性，不可直接调用：

```kotlin
import com.google.mlkit.genai.prompt.FeatureStatus
import com.google.mlkit.genai.prompt.Generation

val generativeModel = Generation.getClient()

when (generativeModel.checkStatus()) {
    // 设备不支持，或尚未拉取到最新配置
    FeatureStatus.UNAVAILABLE -> { /* 提示用户降级到云端，或改用其他端侧方案 */ }
    // 可下载，但尚未下载完成
    FeatureStatus.DOWNLOADABLE -> { /* 触发下载，监听进度，下载完成后再调用 */ }
    // 可直接推理
    FeatureStatus.AVAILABLE -> { /* 开始生成 */ }
}
```

### 文本生成

纯文本流式生成是最基本的用法，通过 `generateContentStream()` 逐块返回，配合 Compose 的 `StateFlow` 实现打字机效果：

```kotlin
import com.google.mlkit.genai.prompt.TextPart
import com.google.mlkit.genai.prompt.generateContentRequest

val request = generateContentRequest(TextPart("总结这段话：$text"))

generativeModel.generateContentStream(request)
    .catch { e -> /* 处理生成异常，避免协程崩溃 */ }
    .collect { chunk ->
        // 每收到一块就追加到 UI 状态，实现流式展示
        uiState.update { it.copy(text = it.text + chunk.text) }
    }
```

### Function Calling

Gemini Nano 支持函数调用（function calling）——模型不直接输出文本，而是预测一个或多个工具调用（`FunctionCall`），由应用本地执行后把结果回传，实现「让模型操作应用内功能」。这是端侧 Agent 能力的基础。

先定义工具 schema（声明工具名、描述与参数）：

```kotlin
import com.google.mlkit.genai.schema.FunctionDeclaration
import com.google.mlkit.genai.schema.FunctionSchema
import com.google.mlkit.genai.schema.FunctionType

val getWeatherTool = FunctionDeclaration.builder()
    .setName("get_weather")
    .setDescription("查询指定城市的天气")
    .setParameters(
        FunctionSchema.builder()
            .setType(FunctionType.OBJECT)
            .putProperty("city", FunctionSchema.builder().setType(FunctionType.STRING).build())
            .addRequired("city")
            .build()
    )
    .build()
```

然后发起带系统指令与工具的请求，并处理模型返回的工具调用：

```kotlin
import com.google.mlkit.genai.prompt.FunctionResponsePart
import com.google.mlkit.genai.prompt.SystemInstruction
import com.google.mlkit.genai.prompt.TextPart
import com.google.mlkit.genai.prompt.generateContentRequest

// 第一轮：让模型决定是否调用工具
val request = generateContentRequest(
    SystemInstruction("你是一个天气助手，必要时调用工具查询天气。"),
    TextPart("北京今天天气怎么样？")
) {
    setTools(listOf(getWeatherTool))
    temperature = 0.2f   // 低温保证工具选择的确定性
}
val response = generativeModel.generateContent(request)

// 检查模型是否预测了工具调用
val functionCalls = response.candidates.firstOrNull()?.functionCalls ?: emptyList()
if (functionCalls.isNotEmpty()) {
    val call = functionCalls.first()
    val city = call.args?.get("city")?.stringValue

    // 本地执行工具
    val weather = queryWeather(city)

    // 第二轮：把执行结果回传，模型据此生成最终文本回答
    val followUp = generateContentRequest(
        FunctionResponsePart(call, weather)
    ) {
        setTools(listOf(getWeatherTool))
    }
    val finalResponse = generativeModel.generateContent(followUp)
}
```

> 函数调用分单轮与多轮两种：单轮只返回工具调用、不生成后续文本；多轮则在应用回传结果后，模型再生成最终的自然语言回答。上面的示例即多轮流程。

## MediaPipe LLM Inference

如需跑开源模型（Gemma、Phi、Falcon、Llama、Qwen 等），可用 MediaPipe LLM Inference——它内部封装了 llama.cpp，应用层仍是纯 Kotlin，并自动处理 GPU 加速。与 Gemini Nano 相比，它的优势是**不绑定特定设备、可自由选择模型**，代价是**需要自行准备并分发模型文件**。

### 集成

```groovy
dependencies {
    implementation 'com.google.mediapipe:tasks-genai:0.10.24'
}
```

### 加载模型并流式生成

MediaPipe 需要先把模型转成 `.task` bundle 格式（见「模型准备」章节），然后通过 `LlmInference` 加载、`LlmInferenceSession` 生成。流式输出用 `generateResponseAsync()`，它通过回调逐步返回结果，适合用 `callbackFlow` 封装成 Flow 供 ViewModel 消费：

```kotlin
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.channels.awaitClose
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.callbackFlow
import kotlinx.coroutines.withContext
import com.google.mediapipe.tasks.genai.llminference.LlmInference
import com.google.mediapipe.tasks.genai.llminference.LlmInferenceSession

class LocalLlmRepository(private val context: Context) {

    private var llm: LlmInference? = null

    // 模型加载耗时数秒，放在 IO 线程执行
    suspend fun initialize(modelPath: String) = withContext(Dispatchers.IO) {
        llm = try {
            createLlm(modelPath, LlmInference.Backend.GPU)
        } catch (e: MediaPipeException) {
            // GPU 后端初始化失败（模拟器或部分低端机常见），回退 CPU
            createLlm(modelPath, LlmInference.Backend.CPU)
        }
    }

    private fun createLlm(modelPath: String, backend: LlmInference.Backend): LlmInference {
        val options = LlmInference.LlmInferenceOptions.builder()
            .setModelPath(modelPath)    // .task 模型文件路径
            .setMaxTokens(512)          // 输出长度上限
            .setPreferredBackend(backend)
            .build()
        return LlmInference.createFromOptions(context, options)
    }

    fun summarize(text: String): Flow<String> = callbackFlow {
        val session = LlmInferenceSession.createFromOptions(
            llm!!,
            LlmInferenceSession.LlmInferenceSessionOptions.builder()
                .setTopK(40)
                .setTopP(0.95f)
                .setTemperature(0.8f)
                .build()
        )
        session.addQueryChunk("用三点总结：\n$text")
        session.generateResponseAsync { partial, done ->
            trySend(partial)   // 逐块返回给下游
            if (done) close()  // 生成结束，关闭 Flow
        }
        awaitClose { session.close() }  // 下游取消时释放会话
    }
}
```

> 注意：GPU 后端在模拟器或部分低端机上可能初始化失败，此时应捕获 `MediaPipeException` 并回退到 `LlmInference.Backend.CPU`。

### 模型下载与校验

模型文件动辄数百 MB，通常不在打包时内置，而是在首次启动时按需下载。为避免加载到**下载了一半的损坏文件**，应先把内容写入临时文件、校验 SHA256 通过后再改名，才能保证 `initialize()` 拿到的是完整模型：

```kotlin
import java.io.File
import java.security.MessageDigest

suspend fun ensureModel(context: Context): String = withContext(Dispatchers.IO) {
    val modelDir = File(context.filesDir, "models")
    val modelFile = File(modelDir, "gemma-2b-it.task")

    // 已存在且校验通过，直接复用
    if (modelFile.exists() && verifySha256(modelFile, EXPECTED_SHA256)) {
        return@withContext modelFile.absolutePath
    }

    // 下载到临时文件，成功后校验并改名
    modelDir.mkdirs()
    val tmp = File(modelDir, "gemma-2b-it.task.part")
    download(MODEL_URL, tmp)              // 下载到 .part 临时名
    check(verifySha256(tmp, EXPECTED_SHA256)) { "模型文件校验失败" }
    tmp.renameTo(modelFile)               // 校验通过才改名，避免加载半截文件
    modelFile.absolutePath
}

private fun verifySha256(file: File, expected: String): Boolean {
    val digest = MessageDigest.getInstance("SHA-256")
    file.inputStream().use { input ->
        val buffer = ByteArray(8192)
        while (true) {
            val n = input.read(buffer)
            if (n < 0) break
            digest.update(buffer, 0, n)
        }
    }
    return digest.digest().joinToString("") { "%02x".format(it) } == expected
}
```

> 下载渠道可选用系统 `DownloadManager`（见 [[DownloadManager]]）或 OkHttp（见 [[OkHttp]]）；关键是**临时名 + 校验 + 改名**三步，任何一步缺失都可能让应用加载到残缺模型。

### 多轮对话

`LlmInferenceSession` 本身是有状态的：连续调用 `addQueryChunk()` 会把多段输入累积为同一段对话上下文，再调用 `generateResponse()` 即实现多轮对话：

```kotlin
val session = LlmInferenceSession.createFromOptions(llm, sessionOptions)

session.addQueryChunk("给我讲讲 MVI 架构")     // 第一轮
val first = session.generateResponse()

session.addQueryChunk("它和 MVVM 的区别是什么？") // 第二轮，基于上一轮上下文
val second = session.generateResponse()
```

## LiteRT-LM

LiteRT-LM 是 Google 目前主推的端侧大模型推理框架，被视为 MediaPipe LLM Inference 的继任者（Google 官方已建议新项目从 MediaPipe 迁移到 LiteRT-LM）。它提供统一的 Kotlin API，同时支持 Android 与 JVM（Linux/macOS/Windows），并内置 CPU、GPU、NPU 三种后端与多模态、工具调用能力。

与 MediaPipe 相比，LiteRT-LM 的 API 更简洁：以 `Engine` 为入口、以 `Conversation` 承载对话，流式输出直接返回 `Flow`，天然契合协程。

### 集成

```groovy
dependencies {
    // Android 平台
    implementation 'com.google.ai.edge.litertlm:litertlm-android:0.17.0'
    // JVM 平台（Linux/macOS/Windows）
    // implementation 'com.google.ai.edge.litertlm:litertlm-jvm:0.17.0'
}
```

> 版本仍在快速迭代，可用 `latest.release` 获取最新版；具体以 [官方文档](https://ai.google.dev/edge/litert-lm/android) 为准。若使用 GPU 后端，Android 12（API 31）及以上还需在 `AndroidManifest.xml` 中声明 OpenCL 原生库，否则 `initialize()` 会成功但首条消息会报「Can not find OpenCL library」。

### 初始化 Engine 并创建对话

`Engine` 是 LiteRT-LM 的入口，`initialize()` 加载模型可能耗时数秒（官方建议可达 10 秒），必须放在后台线程/协程执行：

```kotlin
import com.google.ai.edge.litertlm.Backend
import com.google.ai.edge.litertlm.ConversationConfig
import com.google.ai.edge.litertlm.Engine
import com.google.ai.edge.litertlm.EngineConfig

val engineConfig = EngineConfig(
    modelPath = "/path/to/model.litertlm",   // .litertlm 模型文件路径
    backend = Backend.GPU(),                  // 或 Backend.CPU()、Backend.NPU(...)
    cacheDir = context.cacheDir.absolutePath, // 可选：加速二次加载
)
val engine = Engine(engineConfig)
engine.initialize()                           // 耗时操作，放后台线程

// 配置系统指令与采样参数
val conversationConfig = ConversationConfig(
    systemInstruction = Contents.of("你是一个运行在本地的助手。"),
    maxOutputToken = 1024,
)

val conversation = engine.createConversation(conversationConfig)
```

### 生成回复

LiteRT-LM 提供三种发送消息的方式，其中 `sendMessageAsync(message): Flow<String>` 是协程用户推荐的方式——返回 `Flow`，逐 token 流式输出，直接 `collect` 即可：

```kotlin
import com.google.ai.edge.litertlm.Message

// 流式生成（返回 Flow，逐 token 输出）
conversation.sendMessageAsync(Message.of("解释一下端侧大模型"))
    .collect { token ->
        // 每收到一个 token 就追加到 UI
        uiState.update { it.copy(text = it.text + token) }
    }
```

若只需一次性拿到完整回复，可用同步的 `sendMessage()`（注意它会阻塞到生成结束，应放在 `Dispatchers.IO`）：

```kotlin
val reply = conversation.sendMessage(Message.of("你好"))
// reply 为完整的 Message 对象
```

> 使用完毕后应调用 `conversation.close()` 与 `engine.close()` 释放资源；`Engine` 与 `Conversation` 均实现 `AutoCloseable`，短生命周期场景可直接用 `use {}` 块自动关闭。

## ML Kit GenAI Agent

若要做「能调用工具、多步推理」的端侧 Agent，Google 提供了官方 Agent 框架 `com.google.mlkit:genai-agent`。它构建在 `GenerativeModel` 之上，通过 `Agent` 定义行为、通过 `AgentRunner` 自动管理多轮会话与工具调用循环——应用无需自己写「规划 → 调工具 → 回传结果」的循环。

### 定义工具

Agent 的工具来自 AndroidX AppFunctions：用 `@AppFunctionDeclaration` 注解一个普通函数即可将其暴露为模型可调用的工具，返回类型须为基本类型或 `@AppFunctionSerializable` 数据类：

```kotlin
import androidx.appfunctions.AppFunctionDeclaration
import androidx.appfunctions.AppFunctionSerializable

@AppFunctionSerializable
data class CalendarEvents(val date: String, val events: List<String>)

class CalendarTools {
    /**
     * 查询指定日期的日程安排。
     *
     * @param date 日期字符串，格式 YYYY-MM-DD
     */
    @AppFunctionDeclaration(isDescribedByKDoc = true)
    fun fetch_calendar(date: String): CalendarEvents {
        return CalendarEvents(
            date = date,
            events = listOf("10:00 站会", "14:00 方案评审")
        )
    }
}
```

> `isDescribedByKDoc = true` 表示用 KDoc 注释作为工具描述传给模型，模型据此判断何时调用该工具，因此注释质量直接影响调用准确率。

### 构建 Agent 并注册工具

```kotlin
import com.google.mlkit.genai.agent.Agent
import com.google.mlkit.genai.agent.AgentRunner

val agent = Agent.builder()
    .setName("CalendarAssistant")
    .setInstructions("你是日程助手，帮用户查询日程。")
    // 自动发现应用包内的所有 AppFunction
    .enableAppFunctions(true)
    // 可选：将工具范围严格限定到指定 ID，缩小动作空间以提升稳定性
    .addAppFunctionIds("fetch_calendar")
    // 最大工具调用轮数，默认 10，防止失控循环
    .setMaxTurns(10)
    .build()

val runner = AgentRunner(agent)
```

### 多轮对话与生命周期管理

`AgentSession` 会在内存中维护多轮历史，但它**不是 Parcelable**，无法跨配置变更（如屏幕旋转）存活，因此应把 session 持有在 `ViewModel` 中，并在 `onCleared()` 时显式释放：

```kotlin
import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import com.google.mlkit.genai.agent.Agent
import com.google.mlkit.genai.agent.AgentRunner
import com.google.mlkit.genai.agent.textTokens
import com.google.mlkit.genai.common.GenAiException
import com.google.mlkit.genai.prompt.Content
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.launch

class ChatViewModel : ViewModel() {

    private val agent = Agent.builder()
        .setInstructions("你是一个运行在本地的助手。")
        .build()
    private val runner = AgentRunner(agent)
    // 会话在 ViewModel 中持有，跨配置变更存活
    private val session = runner.getOrCreateSession("chat")

    private val _uiState = MutableStateFlow<ChatUiState>(ChatUiState.Idle)
    val uiState: StateFlow<ChatUiState> = _uiState.asStateFlow()

    fun send(prompt: String) {
        viewModelScope.launch {
            _uiState.value = ChatUiState.Loading("")
            try {
                // runAsync 接受 Content，须用 Content.builder() 构造
                val content = Content.builder().text(prompt).build()
                var full = ""
                // textTokens() 是 Flow<String> 的扩展，逐 token 返回
                session.runAsync(content).textTokens().collect { token ->
                    full += token
                    _uiState.value = ChatUiState.Loading(full)
                }
                _uiState.value = ChatUiState.Success(full)
            } catch (e: GenAiException) {
                _uiState.value = ChatUiState.Error(e.localizedMessage ?: "AI error (${e.errorCode})")
            }
        }
    }

    override fun onCleared() {
        super.onCleared()
        // 释放会话占用的内存并取消未完成任务
        session.close()
    }
}
```

### 观察工具调用过程

若不直接 `collect` 文本流、而是消费 `AgentEvent` 事件流，可以观察到模型何时发起工具调用、工具何时返回，从而在 UI 上展示「正在查询日程…」之类的状态：

```kotlin
import com.google.mlkit.genai.agent.AgentEvent

session.runAsync(content).collect { event ->
    when (event) {
        is AgentEvent.TextMessage -> {
            // event.text：增量文本；event.isPartial：是否为流式中间片段
            _uiState.update { it.copy(responseText = it.responseText + event.text) }
        }
        is AgentEvent.FunctionCall -> {
            // event.name / event.args：模型发起的工具调用
            _uiState.update { it.copy(status = "正在执行 ${event.name}") }
        }
        is AgentEvent.FunctionResponse -> {
            // event.name / event.response：工具执行结果
            _uiState.update { it.copy(status = "${event.name} 已完成") }
        }
        else -> {}   // AgentEvent 非穷尽，必须保留 else 分支以兼容未来扩展
    }
}
```

> 对取消订单、付款、删除数据等敏感操作，应引入人工确认（Human-in-the-Loop）：用 `AgentTool(delegate)` 装饰器包裹工具，在执行前弹窗让用户确认，拒绝则返回取消标记。

### MNN-LLM

MNN-LLM 是国产引擎中 Android 集成最友好的方案：官方提供 AAR，直接 Gradle 引入，无需自己搞 NDK 构建。

#### 模型转换

MNN 需要把 HuggingFace 格式的模型转成 `.mnn` 格式，官方提供 `llm_export` 工具：

```bash
pip install transformers torch MNN

python -m MNNTools.llm_export \
    --path Qwen/Qwen2.5-1.5B-Instruct \
    --dst_path ./qwen2.5_1.5b_int4 \
    --quant_bit 4 \
    --quant_block 128 \
    --lm_quant_bit 8
```

> `--lm_quant_bit 8` 表示将 LM head（最后的词表投影层）用 8-bit 量化——该层参数量不大，用 4-bit 会导致输出概率分布明显退化，8-bit 带来的体积增量可忽略，属性价比最高的取舍。

#### 集成与推理

```groovy
dependencies {
    implementation 'com.alibaba:MNN-LLM:2.9.0'
    // GPU 后端（按需选择）
    implementation 'com.alibaba:MNN-LLM-opencl:2.9.0'

```


## 工程实践要点

端侧大模型的难点不在「调通」，而在「工程化」。以下几点是跨方案通用的最佳实践：

### 模型分发

模型文件动辄数百 MB 到数 GB，不宜打进 APK。常用策略：

+ **首次启动从 CDN 下载**（推荐）：避免 APK 超限，配合进度条与「仅 Wi-Fi 下载」开关；
+ **Play Asset Delivery / 分包**：将模型作为按需资源交付；
+ **只打包小模型**：仅当模型足够小（如 0.5B Q4，约数百 MB 以内）时才考虑随包分发。

下载时须以临时文件名落盘、校验通过后再改名，避免加载到半截文件。

### 错误处理与降级

端侧模型并非在所有设备上都可用，必须设计降级路径：

+ 设备不支持 / 模型未下载 → 降级到云端 API（见 [[AI能力接入：云端对接]]），或提示用户；
+ GPU 后端初始化失败 → 回退 CPU 后端；
+ 生成异常（`GenAiException` 等）→ 捕获并给出友好提示，避免崩溃。

### 内存与生命周期

+ 模型加载耗时数秒，**只加载一次并复用**，不要每次请求重建；
+ 会话对象须随 `ViewModel`/组件生命周期释放，避免内存泄漏（如 `AgentSession.close()`、`LlmInferenceSession.close()`）；
+ 流式生成的协程要可取消，切换页面或换 prompt 时及时中断。

### 上下文窗口管理

端侧模型上下文窗口有限（通常 4K~8K），长对话会撑爆 KV Cache，需要主动管理：

+ **滑动窗口截断**：保留最近 N 轮，超出部分从头裁剪（保留 system prompt）；
+ **对话摘要压缩**：超出限制时用模型自身生成历史摘要，重置 KV Cache 到「摘要 + 当前」；
+ **硬限制 max_seq_len**：在导出模型时限制最大 sequence length，从根源杜绝 KV Cache 无限增长。

一个滑动窗口管理的简化实现：

```kotlin
class ConversationManager(private val maxTokens: Int = 800) {

    private val history = mutableListOf<Message>()
    private var totalTokens = 0

    fun addMessage(role: String, content: String, tokenCount: Int) {
        history.add(Message(role, content, tokenCount))
        totalTokens += tokenCount
        // 超出限制时从最早的对话（index 1）开始裁剪，保留 index 0 的 system prompt
        while (totalTokens > maxTokens && history.size > 1) {
            totalTokens -= history.removeAt(1).tokenCount
        }
    }

    fun buildPrompt(systemPrompt: String, newUserInput: String): String {
        val sb = StringBuilder()
        sb.append("<|system|>\n$systemPrompt\n")
        for (msg in history) {
            sb.append("<|${msg.role}|>\n${msg.content}\n")
        }
        sb.append("<|user|>\n$newUserInput\n<|assistant|>\n")
        return sb.toString()
    }
}
```
