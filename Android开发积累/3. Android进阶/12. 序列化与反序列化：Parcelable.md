`Parcelable` 是 Android 为 **Binder IPC** 设计的序列化协议：把对象写进一块内存缓冲区（`Parcel`），由 Binder 驱动搬到另一个进程，再按同样的顺序读出来。

它的定位非常明确，官方文档原话：

> Parcel is not a general-purpose serialization mechanism. This class ... is designed as a high-performance IPC transport. As such, it is not appropriate to place any Parcel data in to persistent storage: changes in the underlying implementation of any of the data in the Parcel can render older data unreadable.

所以：

+ **能用于**：`Intent` 传参、`Bundle`、`Binder`/`AIDL`、`savedInstanceState`；
+ **不能用于**：存文件、存数据库、跨版本长期保存——底层实现一变，旧数据就读不出来了。要持久化用 JSON（[[14. 序列化与反序列化：JSON]]）或 Serializable（[[11. 序列化与反序列化：Serializable]]）。

## 与 Serializable 的差别

| 维度 | Parcelable | Serializable |
|:--|:--|:--|
| 实现方式 | 手写读写，或`@Parcelize`生成 | 反射，无需写代码 |
| 速度 | 快，无反射 | 慢，反射 + 大量临时对象 |
| 体积 | 小，只写数据 | 大，含类元信息 |
| 持久化 | **不可以** | 可以 |
| 适用 | Android 进程间/组件间 | Java 生态、简单落盘 |

## 手写实现

接口有三个成员：`writeToParcel()`、`describeContents()`、静态的`CREATOR`。

```kotlin
class User(val id: Long, val name: String) : Parcelable {

    // 反序列化用的构造方法：读取顺序必须与写入顺序一致
    private constructor(parcel: Parcel) : this(
        parcel.readLong(),
        parcel.readString().orEmpty()
    )

    override fun writeToParcel(parcel: Parcel, flags: Int) {
        parcel.writeLong(id)
        parcel.writeString(name)
    }

    override fun describeContents(): Int = 0

    companion object CREATOR : Parcelable.Creator<User> {
        override fun createFromParcel(parcel: Parcel): User = User(parcel)
        override fun newArray(size: Int): Array<User?> = arrayOfNulls(size)
    }
}
```

Java 版本结构一样，只是`CREATOR`写成匿名类：

```java
public class User implements Parcelable {
    private final long id;
    private final String name;

    protected User(Parcel in) {
        id = in.readLong();
        name = in.readString();
    }

    public static final Creator<User> CREATOR = new Creator<User>() {
        @Override
        public User createFromParcel(Parcel in) {
            return new User(in);
        }

        @Override
        public User[] newArray(int size) {
            return new User[size];
        }
    };

    @Override
    public int describeContents() {
        return 0;
    }

    @Override
    public void writeToParcel(Parcel dest, int flags) {
        dest.writeLong(id);
        dest.writeString(name);
    }
}
```

### describeContents 返回什么

它返回的是**内容描述位掩码**，目前只有一个有效位：`CONTENTS_FILE_DESCRIPTOR`（`0x00000001`），表示这个对象里包含文件描述符。

普通数据类一律返回`0`。返回 1 不是“特殊对象”，而是明确告诉系统“我持有 fd，需要特殊处理”——乱返回会让系统走不必要的慢路径。

## @Parcelize：现在应该这么写

手写`writeToParcel`和`CREATOR`既啰嗦又容易把读写顺序写错。Kotlin 项目直接用`kotlin-parcelize`插件生成：

```kotlin
// build.gradle.kts
plugins {
    id("kotlin-parcelize")
}
```

```kotlin
import kotlinx.parcelize.Parcelize

@Parcelize
data class User(
    val id: Long,
    val name: String,
    val tags: List<String> = emptyList()
) : Parcelable
```

编译期会生成完整的`writeToParcel`、`CREATOR`，运行时零反射。

### 限制

| 限制 | 说明 |
|:--|:--|
| 属性必须在**主构造**里 | 类体里的属性不参与序列化，需加`@IgnoredOnParcel`消除警告 |
| 主构造的参数必须是属性 | `class A(x: Int)`这种只传参不声明`val/var`的写法不能用 |
| 类型必须可 parcel | 基本类型、`String`、`Bundle`、`Parcelable`、`Serializable`、数组、`List`、`SparseArray` 等 |
| 泛型擦除的类型不行 | `List<Any>`、`Map<String, *>` 这类需要`@RawValue`（走`Parcel.writeValue`，慢） |

需要自定义读写逻辑时，实现`Parceler`：

```kotlin
@Parcelize
data class Money(val cents: Long) : Parcelable {
    private companion object : Parceler<Money> {
        override fun Money.write(parcel: Parcel, flags: Int) {
            parcel.writeLong(cents)
        }

        override fun create(parcel: Parcel) = Money(parcel.readLong())
    }
}
```

## 传递对象

```kotlin
// 发送
val intent = Intent(this, DetailActivity::class.java).apply {
    putExtra("user", user)
}
startActivity(intent)

// 接收
val user = IntentCompat.getParcelableExtra(intent, "user", User::class.java)
```

> `getParcelableExtra(String)`从 **API 33** 起废弃，新 API 需要传`Class`。用`androidx.core`的`IntentCompat.getParcelableExtra(intent, key, Class)`可以一套代码兼容所有版本，不必自己判断`Build.VERSION`。`Bundle`同理，用`BundleCompat.getParcelable(bundle, key, Class)`。

数组和列表：

```kotlin
intent.putParcelableArrayListExtra("users", ArrayList(users))
val users = IntentCompat.getParcelableArrayListExtra(intent, "users", User::class.java)
```

## Bundle 的 1 MB 上限

`Intent`、`Bundle`、`Binder` 的参数都走 Binder 事务缓冲区。官方文档写明：

> The Binder transaction buffer has a limited fixed size, currently 1MB, which is shared by all transactions in progress for the process.

超过就抛`TransactionTooLargeException`，而且这个 1 MB 是**整个进程共享**的，不是每个调用 1 MB。

实践规则：

+ 不要通过 Intent 传 Bitmap、大数组、长字符串；
+ 图片传`Uri`或文件路径，让接收方自己加载；
+ 大对象走数据库、文件或单例仓库，Intent 只传 id；
+ `onSaveInstanceState()` 的 Bundle 同样受限，只放轻量 UI 状态。

## 常见问题

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 读出来的字段全错位 | 读写顺序不一致，或漏写某个字段 | 保持`writeToParcel`与构造方法严格对应 |
| 崩溃`ClassNotFoundException` | 嵌套 Parcelable 用了错误的 ClassLoader | 用`parcel.readParcelable<T>(T::class.java.classLoader)` |
| 传大图崩溃 | 超过 Binder 事务上限 | 传 Uri / 路径 |
| 想存到文件复用 | Parcel 格式不保证跨版本兼容 | 改用 JSON 或 Serializable |
| `@Parcelize`报错“property must be initialized” | 属性写在类体而不是主构造 | 移到主构造，或加`@IgnoredOnParcel` |
| Android 13 上编译警告 `getParcelableExtra` 废弃 | 旧 API 被弃用 | 用`IntentCompat`/`BundleCompat` |

> 结论：**进程间传递用 Parcelable（优先`@Parcelize`），持久化用 JSON**。这两件事不要混。
