本篇聚焦 `ExoPlayer` 在音频播放场景下的实践，覆盖音频属性、音频焦点、耳机拔出处理、音量控制、音轨选择、音频 offload 以及后台播放等内容。视频渲染相关的话题参见[[24. 原生音视频开发：视频部分|视频部分]]。

## 音频属性

音频属性（`AudioAttributes`）用于向系统描述当前播放内容的用途与类型，系统据此决定音量曲线、音频路由等行为。`ExoPlayer` 使用的是 Media3 自带的 `androidx.media3.common.AudioAttributes`，通过 `ExoPlayer.Builder` 传入：

```kotlin
import androidx.media3.common.AudioAttributes
import androidx.media3.common.C

val audioAttributes = AudioAttributes.Builder()
    // 用途：媒体播放。决定了音量曲线与焦点行为
    .setUsage(C.USAGE_MEDIA)
    // 内容类型：音乐
    .setContentType(C.AUDIO_CONTENT_TYPE_MUSIC)
    .build()

val player = ExoPlayer.Builder(context)
    .setAudioAttributes(audioAttributes, /* handleAudioFocus = */ true)
    .build()
```

其中两个配置项的取值直接影响播放行为：

+ `usage`（用途）：常见取值有 `C.USAGE_MEDIA`（媒体）、`C.USAGE_GAME`（游戏）、`C.USAGE_VOICE_COMMUNICATION`（语音通话）等。它决定系统采用哪条音量曲线，也决定来电、通知等事件介入时的处理方式。
+ `contentType`（内容类型）：常见取值有 `C.AUDIO_CONTENT_TYPE_MUSIC`（音乐）、`C.AUDIO_CONTENT_TYPE_MOVIE`（影片）、`C.AUDIO_CONTENT_TYPE_SPEECH`（语音）等。

> 说明：在 Media3 中，`setAudioAttributes` 的第二个参数 `handleAudioFocus` 声明了是否由 `ExoPlayer` 自动处理音频焦点（详见下节）。当设为 `true` 时，`usage` 必须为 `C.USAGE_MEDIA` 或 `C.USAGE_GAME`，否则会抛出 `IllegalArgumentException`。

## 音频焦点

音频焦点用于协调设备上多个应用之间的音频播放，例如：当用户正在听音乐时来了电话，系统会通知音乐应用暂停，把「发声权」让给通话。合理的音频焦点处理是良好用户体验的基础。

在 Media3 中，音频焦点的处理方式取决于是否使用了 `MediaSession`：

### 通过 MediaSession 自动处理（推荐）

当应用使用 `MediaSession`（通常配合 `MediaSessionService`，见下文「后台播放」）时，音频焦点由会话组件自动管理，应用无需手动申请或释放焦点。这是官方推荐的做法，也是实现后台播放的必经之路。

### 由 ExoPlayer 自行处理

在不使用 `MediaSession`、仅用 `ExoPlayer` 做前台播放的轻量场景下，可以让 `ExoPlayer` 自行处理音频焦点：

```kotlin
val player = ExoPlayer.Builder(context)
    .setAudioAttributes(audioAttributes, /* handleAudioFocus = */ true)
    .build()
```

当 `handleAudioFocus` 为 `true` 时，`ExoPlayer` 会在开始播放时申请音频焦点，在暂停、停止或释放时归还焦点；当焦点被其他应用抢占时，会自动暂停播放，焦点恢复后按系统策略决定是否续播。

> 提示：一旦决定使用 `MediaSession`，就不要再在 `setAudioAttributes` 中把 `handleAudioFocus` 设为 `true`，避免焦点处理逻辑重复。

## 耳机拔出处理

播放过程中耳机（或蓝牙设备）被拔出，音频会突然从扬声器外放，这在很多场景下并不合适。`ExoPlayer` 提供了自动处理：

```kotlin
val player = ExoPlayer.Builder(context)
    .setHandleAudioBecomingNoisy(true)
    .build()
```

当 `setHandleAudioBecomingNoisy(true)` 时，`ExoPlayer` 会在音频输出设备断开、路由发生变化时自动暂停播放。对于音乐、播客等场景，这是符合预期的默认行为。

## 音量控制

`ExoPlayer` 提供两层音量控制：应用内音量与设备音量。

### 应用内音量

通过 `Player.volume`（即 `setVolume`/`getVolume`）控制应用内的音量缩放，取值范围 `0.0` 到 `1.0`：

```kotlin
// 将音量减半（应用内缩放）
player.volume = 0.5f

// 静音（等价于 setVolume(0f)）
player.volume = 0f

// 恢复满音量
player.volume = 1f
```

应用内音量只影响当前播放器实例，不影响系统音量，适合做播放器内的独立音量调节。

### 设备音量

若需要直接控制设备系统音量，需先显式开启该能力，再调用相应方法：

```kotlin
val player = ExoPlayer.Builder(context)
    // 允许播放器直接设置设备音量
    .setDeviceVolumeControlEnabled(true)
    .build()

// 调整设备音量（0~deviceMaxVolume）
player.setDeviceVolume(5)

// 设置设备静音
player.setDeviceMuted(true)
```

> 提示：直接操控设备音量对用户体验影响较大，需谨慎使用，并遵循 Android 对音频路由的相关规范。

## 音轨选择

多语言影片、含多音轨的媒体通常包含多个音频轨道，`ExoPlayer` 通过 `TrackSelectionParameters` 来配置轨道选择偏好。最常见的是设置首选音频语言：

```kotlin
player.trackSelectionParameters = player.trackSelectionParameters
    .buildUpon()
    // 优先选择中文音轨
    .setPreferredAudioLanguage("zh")
    .build()
```

此外，还可以通过 `addOverride` 精确指定或禁用某个轨道：

```kotlin
player.trackSelectionParameters = player.trackSelectionParameters
    .buildUpon()
    // 禁用某个音轨分组（trackIndices 为空表示不选择该分组中的任何轨道）
    .addOverride(
        TrackSelectionOverride(disabledTrackGroup.mediaTrackGroup, listOf())
    )
    .build()
```

`DefaultTrackSelector` 是 Media3 提供的默认轨道选择器，对绝大多数场景足够，通常无需替换。

## 音频 offload 播放

音频 offload（卸载播放）是指将音频解码与播放直接交给音频硬件处理，从而减少 CPU 开销、显著省电，尤其适合屏幕关闭后的长时间播放。可以通过 `AudioOffloadPreferences` 声明启用偏好：

```kotlin
val audioOffloadPreferences = AudioOffloadPreferences.Builder()
    // 启用 offload 播放
    .setAudioOffloadMode(AudioOffloadPreferences.AUDIO_OFFLOAD_MODE_ENABLED)
    // 是否要求支持无缝播放（gapless）
    .setIsGaplessSupportRequired(true)
    .build()

player.trackSelectionParameters = player.trackSelectionParameters
    .buildUpon()
    .setAudioOffloadPreferences(audioOffloadPreferences)
    .build()
```

> 说明：offload 是否真正生效还取决于设备硬件、编码格式与当前是否开启音效（如均衡器）等因素，上述设置表达的是「在条件满足时优先启用」的偏好。

## 后台播放

后台播放是音频应用的核心诉求：当用户锁屏或切到其他应用时，音乐应能继续播放。Media3 通过 `MediaSessionService` 承载播放器与会话，并提供系统级媒体控制。

### 实现 MediaSessionService

创建继承 `MediaSessionService` 的服务，在 `onCreate()` 中构建 `ExoPlayer` 与 `MediaSession`，在 `onDestroy()` 中释放：

```kotlin
class PlaybackService : MediaSessionService() {

    private var mediaSession: MediaSession? = null

    override fun onCreate() {
        super.onCreate()
        val player = ExoPlayer.Builder(this).build()
        mediaSession = MediaSession.Builder(this, player).build()
    }

    override fun onDestroy() {
        mediaSession?.run {
            player.release()
            release()
            mediaSession = null
        }
        super.onDestroy()
    }

    // 向外部客户端暴露会话
    override fun onGetSession(
        controllerInfo: MediaSession.ControllerInfo
    ): MediaSession? = mediaSession
}
```

### 声明服务与权限

在 `AndroidManifest.xml` 中声明前台服务所需权限与服务：

```xml
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK" />

<service
    android:name=".PlaybackService"
    android:foregroundServiceType="mediaPlayback"
    android:exported="true">
    <intent-filter>
        <action android:name="androidx.media3.session.MediaSessionService" />
    </intent-filter>
</service>
```

### 媒体通知

`MediaSessionService` 会自动发布一条 MediaStyle 通知，实时同步播放状态并附带播放控制按钮，系统也会将其显示在锁屏与通知栏的媒体控制区。绝大多数场景无需额外处理；如需自定义通知样式，可通过 `setMediaNotificationProvider` 注入自定义实现。

### 通过 MediaController 控制播放

在 UI 侧的 `Activity` 或 `Fragment` 中，通过 `MediaController` 连接到会话并控制播放。`MediaController` 同样实现了 `Player` 接口，因此用法与直接操作 `ExoPlayer` 一致：

```kotlin
override fun onStart() {
    super.onStart()
    val controllerFuture =
        MediaController.Builder(this, sessionToken).buildAsync()
    controllerFuture.addListener({
        val controller = controllerFuture.get()
        // 绑定到 UI 视图
        playerView.player = controller
    }, MoreExecutors.directExecutor())
}

override fun onStop() {
    // 释放控制器，避免泄漏
    MediaController.releaseFuture(controllerFuture)
    super.onStop()
}
```

> 说明：`MediaController` 与 `MediaSession` 之间通过 `SessionToken` 关联，`controllerFuture.get()` 需在异步回调完成后调用。释放时调用 `MediaController.releaseFuture()`。

至此，音频播放的完整链路（音频属性 → 焦点 → 后台服务 → 外部控制）已经贯通。
