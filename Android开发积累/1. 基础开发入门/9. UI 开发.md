Android 的界面由三层东西拼起来：**布局**负责摆放，**控件**负责内容与交互，**自定义 View** 负责填补官方控件覆盖不到的部分。

在传统开发里这三层都靠 XML 描述，Android Studio 的可视化编辑器则把“所见即所得”补了进来。**掌握 XML 能理解布局和控件的运作原理，掌握可视化操作能提高效率**，二者不冲突。

> 贯穿全篇的一条原则：**避免布局过度嵌套**。层级每深一层，measure 与 layout 就多一轮，最终都体现在掉帧上。

## 布局

### View 与 ViewGroup

所有控件都直接或间接继承自`View`，所有布局都继承自`ViewGroup`（而`ViewGroup`本身也是`View`）。三者的分工：

| 类型 | 职责 |
|:--|:--|
| `View` | 占据屏幕上一块矩形区域，负责绘制自己、处理落在自己身上的触摸事件 |
| `ViewGroup` | 继承`View`，额外承担“测量并摆放子 View”的职责 |
| 具体布局 | `ViewGroup`的子类，用不同规则决定子 View 的位置 |

一次绘制要经过三个阶段，自定义 View 的所有问题几乎都出在这三个方法上：

```text
measure（量多大） → layout（放哪里） → draw（画什么）
```

### ConstraintLayout

`ConstraintLayout`是目前官方推荐的默认布局，为**扁平化**而生：它让子 View 通过“约束”定位，而不是靠一层层嵌套的容器，因此能在保持层级很浅的同时摆出复杂界面。

依赖（新建工程一般已自带）：

```kotlin
implementation("androidx.constraintlayout:constraintlayout:2.2.2")
```

一条约束由三部分组成：**自己的哪一边**、**相对谁的哪一边**、**偏移多少**。例如把按钮放到父容器水平居中、距顶部 24dp：

```xml
<Button
    android:id="@+id/submit"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="提交"
    app:layout_constraintTop_toTopOf="parent"
    app:layout_constraintStart_toStartOf="parent"
    app:layout_constraintEnd_toEndOf="parent"
    android:layout_marginTop="24dp" />
```

常用能力：

| 能力 | 写法 | 说明 |
|:--|:--|:--|
| 相对父容器 | `layout_constraintTop_toTopOf="parent"` | 四个方向同理，`Start/End`比`Left/Right`更利于 RTL |
| 相对兄弟控件 | `layout_constraintStart_toEndOf="@id/avatar"` | 被参照的控件必须先声明 |
| 居中偏移 | `layout_constraintHorizontal_bias="0.3"` | 0 最左、1 最右；只有两侧约束同时存在才生效 |
| 固定比例 | `layout_constraintDimensionRatio="16:9"` | 需要至少一边是`0dp` |
| 宽度百分比 | `layout_constraintWidth_percent="0.6"` | 配合`layout_width="0dp"`使用 |
| 引导线 | `<Guideline android:orientation="vertical" app:layout_constraintGuide_percent="0.5" />` | 用比例或 dp 定位的“看不见的参考线” |
| 屏障 | `<Barrier app:barrierDirection="end" app:constraint_referenced_ids="a,b" />` | 取多个控件的最外边缘，适合文案长度不定的场景 |
| 成组控制 | `<Group app:constraint_referenced_ids="a,b" />` | 一次改多个控件的可见性，不增加层级 |
| 流式排列 | `androidx.constraintlayout.helper.widget.Flow` | 需要换行的标签云，避免手写多行 LinearLayout |

两个常见问题：

+ **约束不足**：只给了一侧约束，控件会贴在 0 位置；宽高为`wrap_content`又需要被约束住时，用`app:layout_constrainedWidth="true"`。
+ **过度约束**：左右（或上下）同时给了固定位置又没有`bias`，布局会按居中处理，看起来“怎么调都不动”。

### LinearLayout

`LinearLayout`把子 View 沿一个方向依次排列，方向由`android:orientation`决定，**默认是`horizontal`**。

两个容易混淆的属性：

| 属性 | 作用对象 | 含义 |
|:--|:--|:--|
| `android:gravity` | 容器自己 | 容器内部所有子 View 的整体对齐方式 |
| `android:layout_gravity` | 子 View | 这一个子 View 在容器里的对齐方式 |

`android:layout_weight`分配的是**剩余空间**，不是屏幕比例：

+ 子 View 先按自己的`layout_width`/`layout_height`测量，占掉一部分；
+ 容器把剩下的空间按各子 View 的`weight`比例分下去；
+ 所以想让比例严格按权重来，必须把对应方向设成`0dp`——此时“已占用空间”为 0，剩余空间就是全部空间。

```xml
<!-- 两个按钮各占一半宽度：宽度写 0dp 才成立 -->
<Button android:layout_width="0dp" android:layout_height="wrap_content"
    android:layout_weight="1" />
<Button android:layout_width="0dp" android:layout_height="wrap_content"
    android:layout_weight="1" />
```

如果宽度写的是`wrap_content`，weight 只会在“按钮自身文字宽度”的基础上加空间，两个按钮不会等宽。需要控制总权重时用`android:weightSum`。

### RelativeLayout

`RelativeLayout`用“相对于父容器”或“相对于兄弟控件”的方式定位，属性分两类：

| 相对谁 | 属性 |
|:--|:--|
| 父容器 | `layout_alignParentTop/Bottom/Start/End`、`layout_centerInParent`、`layout_centerHorizontal`、`layout_centerVertical` |
| 兄弟控件 | `layout_toStartOf`/`toEndOf`/`above`/`below`、`layout_alignStart`/`alignTop`/`alignEnd`/`alignBottom`、`layout_alignBaseline` |

```xml
<ImageView android:id="@+id/avatar" ... />
<TextView
    android:layout_toEndOf="@id/avatar"
    android:layout_alignTop="@id/avatar"
    android:layout_marginStart="12dp" ... />
```

两点注意：

+ **顺序敏感**：被参照的控件必须在前面声明，否则运行时解析不到（用`@id/`而不是`@+id/`可以引用后声明的控件，但可读性差）；
+ **性能**：`RelativeLayout`在约束互相依赖时会测量两次。层级简单时无所谓，复杂界面直接用`ConstraintLayout`更划算。

### FrameLayout

`FrameLayout`是最简单的容器：所有子 View 默认堆在**左上角**，后添加的盖在上面，用`android:layout_gravity`调整各自的位置。

它最适合“同一块区域同时只显示一个页面”的场景——Fragment 的容器本质上就是它（现在推荐`FragmentContainerView`，见[[8. Fragment#手动管理事务]]）。另外`android:foreground`可以给整个容器加一层前景（点击涟漪、遮罩），不影响子 View 的事件。

### 滚动容器与占位

| 容器 | 特点 |
|:--|:--|
| `ScrollView` / `HorizontalScrollView` | **只能有一个直接子 View**，且子 View 的高度（宽度）应为`wrap_content` |
| `NestedScrollView` | 支持嵌套滚动，能和`CoordinatorLayout`、`AppBarLayout`联动；内容不足一屏时用`android:fillViewport="true"`撑满 |
| `ViewStub` | 占位但**不膨胀**，调用`inflate()`后才真正创建视图，创建后自身从视图树移除，且**只能 inflate 一次** |

`ViewStub`适合“错误页、空页面、引导层”这类平时不显示的整块布局：比起`visibility="gone"`，它连 measure 都不做。

```xml
<ViewStub
    android:id="@+id/stub_empty"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:layout="@layout/layout_empty" />
```

```kotlin
binding.stubEmpty.inflate()      // 之后 stubEmpty 本身就不在视图树里了
```

> 不要把`RecyclerView`塞进`ScrollView`：两者都会滚动，RecyclerView 还会失去回收复用，长列表必然卡顿。

### include 与 merge

`<include>`用于复用一段布局：

```xml
<include
    android:id="@+id/header"
    layout="@layout/layout_header"
    android:layout_width="match_parent"
    android:layout_height="wrap_content" />
```

两个细节：

+ `include`上**同时**写`layout_width`和`layout_height`才会覆盖被引用布局的尺寸，只写一个不生效；
+ 给了`id`才能通过 binding 或`findViewById`拿到这段子布局。

`<merge>`用在被复用的布局根节点上，表示“不要多包一层容器”，直接把自己的子 View 塞进宿主：

```xml
<!-- layout_header.xml -->
<merge xmlns:android="http://schemas.android.com/apk/res/android">
    <ImageView android:id="@+id/icon" ... />
    <TextView android:id="@+id/title" ... />
</merge>
```

`merge`必须挂在已有父容器上：用`LayoutInflater`时`attachToRoot`必须传`true`，传`false`会直接抛`InflateException`（“`<merge />` can be used only with a valid ViewGroup root and attachToRoot=true”）。它的作用是**减少一层嵌套**，在`LinearLayout`套`LinearLayout`这类场景收益最明显。

### 布局选型

| 场景 | 选择 |
|:--|:--|
| 绝大多数界面 | `ConstraintLayout` |
| 简单的横/竖排列，且需要按比例分配 | `LinearLayout` + `layout_weight` |
| 单一子 View、Fragment 容器 | `FrameLayout` / `FragmentContainerView` |
| 内容高度不定、需要滚动 | `NestedScrollView` |
| 需要折叠头部的长列表 | `CoordinatorLayout` + `AppBarLayout` |
| 平时不显示的整块内容 | `ViewStub` |

层级优化的三板斧：**用 ConstraintLayout 摊平**、**用 merge 去掉多余容器**、**用 ViewStub 推迟加载**。排查工具是 Layout Inspector（能看到每个 View 的 measure/layout/draw 耗时）。

## 常用官方控件

这一节里带`com.google.android.material`包名的控件（Card、Drawer、BottomNavigation 等）都来自 Material Components：

```kotlin
implementation("com.google.android.material:material:1.14.0")
```

使用前 **App 主题必须是`Theme.Material3.*`或`Theme.MaterialComponents.*`**，否则运行时会抛`IllegalArgumentException`：`The style on this component requires your app theme to be Theme.MaterialComponents (or a descendant).`

### RecyclerView

列表的唯一正确选择。它只做三件事：回收视图、按`LayoutManager`摆放、把数据变化通知给`Adapter`。

依赖：

```kotlin
implementation("androidx.recyclerview:recyclerview:1.4.0")
```

三个角色：

| 角色 | 职责 |
|:--|:--|
| `Adapter` | 创建并绑定 ViewHolder，报告条目数量 |
| `ViewHolder` | 持有一个条目的视图引用，避免重复`findViewById` |
| `LayoutManager` | 决定排列方式：`LinearLayoutManager`、`GridLayoutManager`、`StaggeredGridLayoutManager` |

配合`ListAdapter` + `DiffUtil`，列表更新只算差异，不做整体刷新：

```kotlin
// 差异比较器：id 相同视为同一个条目，内容相等才跳过重绑
private object UserDiff : DiffUtil.ItemCallback<User>() {
    override fun areItemsTheSame(oldItem: User, newItem: User) = oldItem.id == newItem.id
    override fun areContentsTheSame(oldItem: User, newItem: User) = oldItem == newItem
}

class UserAdapter(
    private val onClick: (User) -> Unit
) : ListAdapter<User, UserAdapter.VH>(UserDiff) {

    class VH(val binding: ItemUserBinding) : RecyclerView.ViewHolder(binding.root)

    override fun onCreateViewHolder(parent: ViewGroup, viewType: Int): VH {
        val binding = ItemUserBinding.inflate(
            LayoutInflater.from(parent.context), parent, false
        )
        return VH(binding)
    }

    override fun onBindViewHolder(holder: VH, position: Int) {
        val user = getItem(position)
        holder.binding.name.text = user.name
        holder.binding.root.setOnClickListener { onClick(user) }
    }
}
```

```kotlin
binding.recycler.layoutManager = LinearLayoutManager(this)
binding.recycler.adapter = adapter
binding.recycler.setHasFixedSize(true)      // 条目尺寸不随内容变化时才设
adapter.submitList(users)
```

常用扩展点：

| API | 用途 |
|:--|:--|
| `addItemDecoration()` | 分割线、间距、吸顶（`ItemDecoration`） |
| `ItemTouchHelper` | 侧滑删除、长按拖拽排序 |
| `setItemAnimator()` | 增删动画，默认已有；要自定义就换实现 |
| `ConcatAdapter` | 把多个 Adapter 拼成一个列表（头部、内容、尾部） |
| `scrollToPosition()` / `smoothScrollToPosition()` | 定位，前者瞬间、后者带动画 |

两个必知约束：

+ `submitList()`传的是**新列表对象**，原地修改再传同一个引用不会触发 diff；
+ 在`onBindViewHolder`里做耗时操作会直接卡住滑动——图片加载交给 Glide/Coil，别在这里解码。

### ViewPager2 与 TabLayout

`ViewPager2`基于 RecyclerView 实现，支持横向/纵向翻页，取代了已废弃的`ViewPager`。

```kotlin
class TabAdapter(activity: FragmentActivity) : FragmentStateAdapter(activity) {
    override fun getItemCount() = 3
    override fun createFragment(position: Int): Fragment = when (position) {
        0 -> HomeFragment()
        1 -> DiscoverFragment()
        else -> ProfileFragment()
    }
}
```

```kotlin
binding.pager.adapter = TabAdapter(this)

// 把 TabLayout 和 ViewPager2 绑起来，标签文字在回调里设置
TabLayoutMediator(binding.tabLayout, binding.pager) { tab, position ->
    tab.text = titles[position]
}.attach()
```

`TabLayoutMediator.attach()`必须在**设置 adapter 之后**调用，重复 attach 会抛`IllegalStateException`。

`FragmentStateAdapter`会回收超出`offscreenPageLimit`的页面，只保留状态；不要自己再维护一份 Fragment 列表，否则等于绕开了它的回收机制（详见[[8. Fragment#ViewPager2 已经替你回收]]）。

### CoordinatorLayout + AppBarLayout

这一组负责“头部随内容滚动收起”的效果。三个角色的分工：

+ `CoordinatorLayout`：调度中心，按 Behavior 协调子 View 的滚动；
+ `AppBarLayout`：把头部标记为“可被滚动驱动”；
+ `CollapsingToolbarLayout`：具体实现折叠与视差。

```xml
<androidx.coordinatorlayout.widget.CoordinatorLayout
    android:layout_width="match_parent"
    android:layout_height="match_parent">

    <com.google.android.material.appbar.AppBarLayout
        android:layout_width="match_parent"
        android:layout_height="wrap_content">

        <com.google.android.material.appbar.CollapsingToolbarLayout
            android:layout_width="match_parent"
            android:layout_height="220dp"
            app:contentScrim="?attr/colorPrimary"
            app:layout_scrollFlags="scroll|exitUntilCollapsed">

            <ImageView
                android:layout_width="match_parent"
                android:layout_height="match_parent"
                android:scaleType="centerCrop"
                app:layout_collapseMode="parallax" />

            <androidx.appcompat.widget.Toolbar
                android:layout_width="match_parent"
                android:layout_height="?attr/actionBarSize"
                app:layout_collapseMode="pin" />
        </com.google.android.material.appbar.CollapsingToolbarLayout>
    </AppBarLayout>

    <androidx.recyclerview.widget.RecyclerView
        android:layout_width="match_parent"
        android:layout_height="match_parent"
        app:layout_behavior="@string/appbar_scrolling_view_behavior" />
</androidx.coordinatorlayout.widget.CoordinatorLayout>
```

关键在最后那行`app:layout_behavior="@string/appbar_scrolling_view_behavior"`：它把内容区与 AppBarLayout 关联起来，缺了它头部不会跟着滚。

`layout_scrollFlags`的常用组合：

| 标志 | 效果 |
|:--|:--|
| `scroll` | 内容上滑时头部一起滚出屏幕（其余标志的前提） |
| `exitUntilCollapsed` | 只滚到折叠高度就停住，保留 Toolbar |
| `enterAlways` | 内容下滑时头部立刻回弹，不等滚到顶部 |
| `enterAlwaysCollapsed` | 回弹时先显示折叠高度，再逐步展开 |
| `snap` | 松手后自动吸附到展开或折叠状态 |

> 联动依赖**嵌套滚动**：内容区必须是`RecyclerView`或`NestedScrollView`。普通`ScrollView`不会把滚动事件传给 CoordinatorLayout。

### DrawerLayout + NavigationView

侧滑菜单的标准组合：`DrawerLayout`做根容器，内容区和抽屉各占一个直接子 View。

```xml
<androidx.drawerlayout.widget.DrawerLayout
    android:id="@+id/drawer"
    android:layout_width="match_parent"
    android:layout_height="match_parent">

    <!-- 第一个子 View 是主内容 -->
    <include layout="@layout/content_main" />

    <!-- 第二个子 View 是抽屉，必须用 layout_gravity 指定方向 -->
    <com.google.android.material.navigation.NavigationView
        android:id="@+id/navView"
        android:layout_width="wrap_content"
        android:layout_height="match_parent"
        android:layout_gravity="start"
        app:menu="@menu/menu_drawer" />
</androidx.drawerlayout.widget.DrawerLayout>
```

```kotlin
// 打开/关闭
binding.drawer.openDrawer(GravityCompat.START)
binding.drawer.closeDrawer(GravityCompat.START)

// 菜单点击
binding.navView.setNavigationItemSelectedListener { item ->
    when (item.itemId) {
        R.id.nav_settings -> { /* TODO */ }
    }
    binding.drawer.closeDrawer(GravityCompat.START)
    true
}
```

两个注意点：

+ 抽屉的方向、宽度都由`layout_gravity`与宽高决定，`DrawerLayout`本身不再包一层；
+ 抽屉打开时按返回键应先关闭抽屉。`DrawerLayout`提供了`addDrawerListener`，也可以在`OnBackPressedCallback`里判断`isDrawerOpen`（写法见[[1. Activity：基础使用#返回键处理]]）。

### SwipeRefreshLayout

下拉刷新容器，**只能有一个直接子 View**，且这个子 View 必须可滚动（RecyclerView、NestedScrollView、ListView）。

```xml
<androidx.swiperefreshlayout.widget.SwipeRefreshLayout
    android:id="@+id/swipe"
    android:layout_width="match_parent"
    android:layout_height="match_parent">

    <androidx.recyclerview.widget.RecyclerView
        android:id="@+id/recycler"
        android:layout_width="match_parent"
        android:layout_height="match_parent" />
</androidx.swiperefreshlayout.widget.SwipeRefreshLayout>
```

```kotlin
binding.swipe.setOnRefreshListener { viewModel.refresh() }

// 请求结束（成功或失败）都要收起，否则指示器一直转
binding.swipe.isRefreshing = false
```

### BottomNavigationView

底部导航，菜单用`res/menu`描述，**最多 6 项**（设计规范建议 3~5 项），超出会抛`IllegalArgumentException`。

```xml
<com.google.android.material.bottomnavigation.BottomNavigationView
    android:id="@+id/bottomNav"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    app:menu="@menu/menu_bottom" />
```

```kotlin
// 与 Navigation 组件联动：点击自动切换 NavHostFragment 的目标页
binding.bottomNav.setupWithNavController(navController)
```

手写切换时监听`setOnItemSelectedListener`，并自己处理状态恢复（返回栈、选中态），这也是为什么更推荐 Navigation。

### MaterialCardView 与 ShapeableImageView

`MaterialCardView`在`CardView`基础上支持描边、选中态、水波纹：

```xml
<com.google.android.material.card.MaterialCardView
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    app:cardCornerRadius="12dp"
    app:cardElevation="2dp"
    app:strokeWidth="1dp"
    app:strokeColor="?attr/colorOutline"
    app:checkable="true">

    <TextView
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:padding="16dp"
        android:text="卡片内容" />
</com.google.android.material.card.MaterialCardView>
```

`ShapeableImageView`用`shapeAppearance`裁切图片，圆形头像不用再写自定义 View：

```xml
<com.google.android.material.imageview.ShapeableImageView
    android:layout_width="64dp"
    android:layout_height="64dp"
    app:shapeAppearanceOverlay="@style/ShapeAppearance.Circle"
    app:srcCompat="@drawable/avatar" />
```

```xml
<style name="ShapeAppearance.Circle" parent="">
    <item name="cornerFamily">rounded</item>
    <item name="cornerSize">50%</item>
</style>
```

### 控件选型速查

| 需求 | 控件 |
|:--|:--|
| 长列表、网格 | `RecyclerView` |
| 分页 + 顶部标签 | `ViewPager2` + `TabLayout` |
| 可折叠的顶部导航 | `CoordinatorLayout` + `AppBarLayout` + `CollapsingToolbarLayout` |

## 自定义 View

### 两条路线

| 路线 | 做法 | 难度 | 适用 |
|:--|:--|:--:|:--|
| **组合式** | 继承一个 ViewGroup，把几个原生控件拼起来 | 低 | 固定排布的可复用模块（标题栏、表单项） |
| **绘制式** | 继承 View（或某个控件），自己调`Canvas`画 | 高 | 原生控件表达不了的东西（折线图、仪表盘、手写板） |

判断标准很简单：**能用现成控件拼出来的，就不要自己画**。组合式自定义 View 本质上和往布局里拖控件没有区别，只是把重复的部分封装了起来。

### 组合式：继承 ViewGroup

```kotlin
class ExampleView @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null,
    defStyleAttr: Int = 0
) : ConstraintLayout(context, attrs, defStyleAttr) {

    // 布局根节点是普通容器：三参 inflate，attachToRoot 传 true，视图直接挂到 this 上
    private val binding = ViewExampleBinding.inflate(
        LayoutInflater.from(context), this, true
    )

    init {
        binding.action.setOnClickListener { /* 内部固定的响应 */ }
    }

    // 需要外部决定点击行为时，暴露一个函数而不是把 binding 暴露出去
    fun setOnAction(action: () -> Unit) {
        binding.action.setOnClickListener { action() }
    }
}
```

`@JvmOverloads`让三个构造方法只写一次；三个参数分别对应“代码创建”“XML 创建”“XML + 主题样式”，缺一个就可能在某些场景下拿不到自定义属性。

**必须继承`ViewGroup`的子类**（`ConstraintLayout`、`LinearLayout`、`FrameLayout`都可以），因为组合式自定义 View 要有地方承载子控件，而`View`本身不是容器。这也解释了一个常见现象：把根节点写成`View`、再用`inflate(layout, null)`去加载，Android Studio 预览会是一片空白——不是“View Binding 不支持继承 View”，而是布局根本没有被挂到任何容器上。

inflate 时的两个细节：

+ 布局根节点是**普通容器**：三参的`inflate(inflater, this, true)`直接挂到`this`上；传`false`则要自己`addView(binding.root)`，适合还想再包一层的场景；
+ 布局根节点是**`<merge>`**：生成的绑定类**只有两参**`inflate(inflater, parent)`，没有`attachToRoot`。merge 没有自己的根，必须挂到宿主上，调用后子 View 就直接成为`this`的子 View。

判断方法：输入 `inflate(` 时，若 IDE 补全出三个参数或两个参数，即可知布局根节点是否为 `merge`。

### 绘制式：坐标系

屏幕坐标系以**左上角为原点**，X 向右为正，Y 向下为正：

![[view.png]]

View 自身的位置是相对于**父容器**（而不是屏幕）描述的，`getLeft()`、`getTop()`、`getRight()`、`getBottom()`拿到的是四条边到父容器坐标轴的距离，宽高由它们相减得到。

触摸点的坐标有两组：

| 方法 | 参考系 |
|:--|:--|
| `getX()` / `getY()` | 相对于**当前 View 的左上角** |
| `getRawX()` / `getRawY()` | 相对于**屏幕左上角** |

![[view2.png]]

做拖拽、滑动冲突处理时，判断“是否还在自己身上”要用前者，换算全局位置用后者。

### Paint

`Paint`是画笔，控制颜色、样式、线宽、字体等。**它必须在初始化阶段创建并复用**——在`onDraw()`里`new Paint()`会在每一帧产生垃圾对象，掉帧就是这么来的。

```kotlin
class ExampleView2 @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null,
    defStyleAttr: Int = 0
) : View(context, attrs, defStyleAttr) {

    // 初始化时创建一次，后续只改属性
    private val paint = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        color = Color.parseColor("#3F51B5")
        style = Paint.Style.FILL
    }

    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)
        // 这里不要再 new Paint()
    }
}
```

| 配置 | 用途 |
|:--|:--|
| `color` | 颜色，Int 型色值 |
| `style` | `FILL`只填充、`STROKE`只描边、`FILL_AND_STROKE`两者都画 |
| `strokeWidth` | 描边宽度，单位像素 |
| `typeface` | 字体（等宽、加粗、自定义字体） |
| `textSize` | 文字大小，单位**像素**，从 sp 换算过来才不会随系统字号失效 |
| `pathEffect` | 路径效果，虚线、圆角拐点等 |
| `shader` | 渐变、Bitmap 纹理 |
| `isAntiAlias` | 抗锯齿，画圆和文字必开 |

> 官方文档：https://developer.android.google.cn/reference/android/graphics/Paint

### Canvas

`Canvas`是画布，提供一组`drawXxx()`方法。它只在`onDraw()`里使用：

```kotlin
override fun onDraw(canvas: Canvas) {
    super.onDraw(canvas)
    canvas.drawCircle(cx, cy, radius, paint)
}
```

| 方法 | 用途 |
|:--|:--|
| `drawLine` / `drawCircle` / `drawRect` / `drawOval` / `drawArc` / `drawPoint` | 基本图形 |
| `drawText` | 文字（基线在左下，`y`传的是基线位置） |
| `drawBitmap` | 图片 |
| `drawPath` | 任意路径，配合`Path`使用 |
| `translate` / `rotate` / `scale` / `skew` | 变换画布 |
| `save` / `restore` / `restoreToCount` | 保存与还原画布状态，变换前必须配对使用 |
| `clipRect` / `clipPath` | 裁剪绘制区域 |

Kotlin 侧还有一组更安全的扩展函数（来自`androidx.core:core-ktx`，需`import androidx.core.graphics.withTranslation`等），它们在块结束时自动`restore`：

```kotlin
canvas.withTranslation(100f, 0f) {
    drawCircle(0f, 0f, 40f, paint)     // 坐标原点是平移后的位置
}
```

| 扩展函数 | 作用 |
|:--|:--|
| `withSave` | 保存并在结束后还原 |
| `withTranslation` | 平移 |
| `withRotation` | 旋转 |
| `withScale` | 缩放 |
| `withSkew` | 倾斜 |
| `withMatrix` | 应用矩阵 |
| `withClip` | 裁剪 |

绘制逻辑一多，`onDraw()`会变成一坨流水账。习惯做法是把每种图元拆成私有方法（`drawAxes()`、`drawData()`），`onDraw()`只负责按顺序调度。

“先平移画布再画”和“直接按绝对坐标画”效果一样，区别只在参考系：前者以画布当前位置为原点，后者以 View 左上角为原点。选定一种就别混用，否则坐标很难算。

### 测量、布局与绘制

| 方法 | 职责 | 关键点 |
|:--|:--|:--|
| `onMeasure()` | 决定自己和子 View 多大 | 必须调`setMeasuredDimension()`，否则崩溃 |
| `onLayout()` | 决定子 View 放哪 | 只有`ViewGroup`需要重写 |
| `onDraw()` | 画内容 | 不要在里面分配对象 |

`onMeasure`拿到的两个参数是**测量约束**（`MeasureSpec`），它把“模式”和“尺寸”打包在一个 int 里：

| 模式 | 含义 | 典型来源 |
|:--|:--|:--|
| `EXACTLY` | 父容器已定死大小 | `match_parent`、固定 dp |
| `AT_MOST` | 最大只能是这个值 | `wrap_content` |
| `UNSPECIFIED` | 不限，随便多大 | `ScrollView`里的子 View |

自定义 View 必须自己处理`wrap_content`，否则会退化成`match_parent`。标准写法是用`resolveSize()`把“我想要的尺寸”和约束合起来：

```kotlin
class CircleView @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null,
    defStyleAttr: Int = 0
) : View(context, attrs, defStyleAttr) {

    private val paint = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        color = Color.parseColor("#3F51B5")
    }

    override fun onMeasure(widthMeasureSpec: Int, heightMeasureSpec: Int) {
        val density = resources.displayMetrics.density
        val desiredW = (96 * density).toInt() + paddingLeft + paddingRight
        val desiredH = (96 * density).toInt() + paddingTop + paddingBottom
        setMeasuredDimension(
            resolveSize(desiredW, widthMeasureSpec),
            resolveSize(desiredH, heightMeasureSpec)
        )
    }

    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)
        val contentW = width - paddingLeft - paddingRight
        val contentH = height - paddingTop - paddingBottom
        val radius = min(contentW, contentH) / 2f
        canvas.drawCircle(
            paddingLeft + contentW / 2f,
            paddingTop + contentH / 2f,
            radius,
            paint
        )
    }
}
```

几个固定规则：

+ **所有绘制都要减去 padding**，否则加了内边距后内容会被裁掉一部分；
+ 尺寸变化调`requestLayout()`，只是内容变化调`invalidate()`；前者会重新走 measure/layout，代价更大；
+ 在`onDraw`里创建`Paint`、`Rect`、`Path`等对象会制造 GC 压力，能提出来的一律提出来。

### 事件处理

`onTouchEvent()`的返回值决定“这个事件我要不要”：`ACTION_DOWN`返回`false`，后续的`MOVE`、`UP`都不会再送到这里。

```kotlin
override fun onTouchEvent(event: MotionEvent): Boolean {
    when (event.actionMasked) {
        MotionEvent.ACTION_DOWN -> {
            isPressed = true
            return true
        }
        MotionEvent.ACTION_UP -> {
            isPressed = false
            performClick()          // 触摸抬起时补一次点击，保证 setOnClickListener 与无障碍都正常
            return true
        }
        MotionEvent.ACTION_CANCEL -> {
            isPressed = false
            return true
        }
    }
    return super.onTouchEvent(event)
}

override fun performClick(): Boolean {
    return super.performClick()
}
```

放进`RecyclerView`、`ViewPager2`这类会自己处理滑动的容器时，横向拖动要告诉父容器“别抢”：

```kotlin
MotionEvent.ACTION_MOVE -> {
    parent.requestDisallowInterceptTouchEvent(true)
}
```

### 自定义属性

要让自定义 View 能在 XML 里配参数（比如圆形头像的描边宽度），需要两步。

**第一步：在`res/values/attrs.xml`里声明**（文件名任意，习惯叫`attrs.xml`）：

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <declare-styleable name="WatchView">
        <attr name="time_format" format="string" />
        <attr name="color_hour_hand" format="color|reference" />
    </declare-styleable>
</resources>
```

几点说明：

+ `declare-styleable`的`name`建议与类名一致，便于阅读，但**不是强制要求**——代码里通过`R.styleable.<name>`引用它；
+ `attr`的`name`不要与系统属性重名；
+ `format`必须声明，否则`TypedArray`取不到值；
+ 使用时的命名空间是`app:`（自定义属性）而不是`android:`（系统属性）。

`format`支持的类型：

| 类型 | 说明 |
|:--|:--|
| `string` | 字符串 |
| `color` | 颜色 |
| `boolean` | 布尔 |
| `reference` | 资源引用（`@drawable/xxx`、`@color/xxx`） |
| `integer` / `float` | 数值 |
| `dimension` | 带单位的尺寸（dp、sp） |
| `fraction` | 百分比 |
| `enum` | 枚举，只能选一个 |
| `flags` | 位或，可组合多个 |

枚举与位或的写法相近，区别只在标签：

```xml
<attr name="orientation">
    <enum name="horizontal" value="0" />
    <enum name="vertical" value="1" />
</attr>

<attr name="windowSoftInputMode">
    <flag name="stateUnspecified" value="0" />
    <flag name="stateHidden" value="2" />
</attr>
```

**第二步：在初始化阶段解析**：

```kotlin
// import androidx.core.content.res.use
init {
    context.obtainStyledAttributes(attrs, R.styleable.WatchView).use { a ->
        val format = a.getString(R.styleable.WatchView_time_format) ?: "HH:mm"
        val handColor = a.getColor(
            R.styleable.WatchView_color_hour_hand,
            Color.BLUE
        )
        // 赋给字段，后续绘制时使用
    }
}
```

`TypedArray`持有原生资源，用完必须`recycle()`；`use {}`扩展函数会在结束时自动回收，比手写`try/finally`可靠。

| 方法 | 读取的类型 |
|:--|:--|
| `getString()` | 字符串，可能为 null |
| `getDimension()` | 浮点尺寸（px） |
| `getDimensionPixelOffset()` | 整型尺寸，舍弃小数（适合坐标偏移） |
| `getDimensionPixelSize()` | 整型尺寸，四舍五入（适合宽高、字号） |
| `getColor()` | 单色 |
| `getColorStateList()` | 带状态的颜色 |
| `getInteger()` / `getInt()` | 整数 / 枚举与位或 |
| `getFloat()` / `getFraction()` | 浮点 / 百分比 |
| `getBoolean()` | 布尔 |
| `getResourceId()` | 资源 id |
| `getDrawable()` | Drawable |
| `getTextArray()` | 文本数组 |

### SurfaceView

`SurfaceView`拥有**独立的绘图表层**，可以在子线程绘制，不占用主线程的渲染资源，适合高频刷新（相机预览、游戏、视频）。

三个关键点：

+ 通过`holder.surface.isValid`判断表层是否可用，未创建时绘制会崩；
+ 用`holder.addCallback()`监听表层的创建与销毁，在`surfaceCreated`里起线程、`surfaceDestroyed`里停线程；
+ 绘制必须成对：`lockCanvas()`拿到的画布，要用`unlockCanvasAndPost()`提交。

```kotlin
override fun surfaceCreated(holder: SurfaceHolder) {
    renderThread = Thread {
        while (running) {
            val canvas = holder.lockCanvas() ?: continue
            try {
                drawFrame(canvas)
            } finally {
                holder.unlockCanvasAndPost(canvas)
            }
        }
    }.also { it.start() }
}

override fun surfaceDestroyed(holder: SurfaceHolder) {
    running = false
    renderThread?.join()
}
```

两条边界：

+ `lockCanvas()`可能返回`null`（表层尚未创建或不可编辑），必须判空；
+ 锁定的画布**不会保留上一帧**，每次都要重绘完整画面。需要 GPU 加速时用`lockHardwareCanvas()`（API 26+）。

`SurfaceView`不支持平移、缩放、透明度等 View 变换动画；需要这些效果时用`TextureView`，代价是性能略低、且必须在硬件加速环境下使用。

## 番外：动态调整尺寸

这一节与自定义 View 关系不大，但实际开发里常用。这里的 View 不限于控件，也包括 Dialog、Activity、Fragment。

### 控件尺寸

改控件的`layoutParams`：

```kotlin
// 方式一：整体替换
view.layoutParams = ConstraintLayout.LayoutParams(0, 0).apply {
    width = 200
    height = 100
}

// 方式二：取出后修改，再赋回去
(view.layoutParams as ConstraintLayout.LayoutParams).apply {
    width = 200
    height = 100
    view.layoutParams = this
}
```

`LayoutParams`的类型必须与**父容器**一致，否则运行时抛`ClassCastException`：

| 父容器 | LayoutParams 类型 |
|:--|:--|
| `ConstraintLayout` | `ConstraintLayout.LayoutParams` |
| `LinearLayout` | `LinearLayout.LayoutParams` |
| `RelativeLayout` | `RelativeLayout.LayoutParams` |
| `FrameLayout` | `FrameLayout.LayoutParams` |

### Dialog 尺寸

Dialog 展示后尺寸就固定了，所以要在`show()`之后、内容绘制之前调整：

```kotlin
dialog.show()

val params = dialog.window?.attributes ?: return
params.width = (resources.displayMetrics.widthPixels * 0.8).toInt()
params.height = WindowManager.LayoutParams.WRAP_CONTENT
dialog.window?.attributes = params
```

Dialog 默认有一圈内边距，去掉它：

```kotlin
dialog.window?.decorView?.setPadding(0, 0, 0, 0)
```

### Activity / Fragment 尺寸

同样是改窗口属性，只是窗口来自 Activity：

```kotlin
val params = window.attributes
params.width = (resources.displayMetrics.widthPixels * 0.9).toInt()
params.height = WindowManager.LayoutParams.WRAP_CONTENT
window.attributes = params
```

> 现代应用基本不做“半个屏幕的 Activity”，这类需求用`DialogFragment`或`BottomSheetDialogFragment`更合适。
