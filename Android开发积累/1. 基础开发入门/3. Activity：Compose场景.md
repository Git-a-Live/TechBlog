> 本篇只讨论**Compose 项目里 Activity 还剩下哪些职责，边界在哪里**。
> 版本基准（2026-11 核实）：activity-compose 1.13.0、navigation-compose 2.10.2、lifecycle-runtime-compose 2.11.0。

## Activity 的角色：从“页面”退成“容器”

Compose 没有取代Activity，而是把它降级成承载 Compose 的宿主：一个应用通常只保留一个Activity，页面切换交给 Composable 与导航库。

| 职责 | View 体系 | Compose 体系 |
|:--|:--|:--|
| 加载界面 | `setContentView(R.layout.xxx)` | `setContent { }` |
| 控件引用 | `findViewById` / ViewBinding | 状态直接声明在组合函数内，无需引用控件 |
| 页面切换 | 多Activity + Intent | 单Activity + Navigation Compose |
| 状态保存 | `onSaveInstanceState` | `rememberSaveable` / `SavedStateHandle` |
| 返回处理 | `OnBackPressedCallback` | `BackHandler` |

```kotlin
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        // 官方示例即放在 super.onCreate() 之前：它不依赖已创建的窗口状态
        enableEdgeToEdge()
        super.onCreate(savedInstanceState)
        setContent {
            AppTheme {
                AppNavHost()
            }
        }
    }
}
```

> `setContent`可以调用多次，第二次会复用已存在的`ComposeView`并**替换**其内容，不会产生两棵视图树（早期版本会直接抛异常，现行实现改为替换）。即便如此，规范做法仍然是在`onCreate()`里只调用一次。

## 边到边与 Insets

自Android 15（API 35）起，targetSdk ≥ 35 的应用在 Android 15 及以上设备上被强制进入**边到边**模式：系统栏透明，内容绘制到状态栏与导航栏之后。`enableEdgeToEdge()`负责在低版本上做同样的行为，保证各版本表现一致。

Compose 侧不需要手动计算 insets，交给`Scaffold`：

```kotlin
Scaffold { innerPadding ->
    LazyColumn(
        modifier = Modifier.fillMaxSize(),
        // 顶部避开状态栏，底部避开导航栏
        contentPadding = innerPadding
    ) {
        items(list) { ItemRow(it) }
    }
}
```

三个注意点：

1. `Scaffold`会按`contentWindowInsets`为内容预留系统栏空间，把它提供的`innerPadding`传给内容即可。
2. **不要**在`Scaffold`内部再叠加`Modifier.systemBarsPadding()`，那会得到双倍留白。
3. 需要精确控制某一块区域时用`Modifier.windowInsetsPadding(WindowInsets.statusBars)`或`WindowInsets.navigationBars.asPaddingValues()`，而不是全局加 padding。

## 返回处理

`BackHandler`是`OnBackPressedCallback`的Compose封装，注册与注销随组合生命周期自动完成：

```kotlin
BackHandler(enabled = isDialogVisible) {
    isDialogVisible = false
}
```

- `enabled = false`时不拦截，返回事件继续向外层或系统传递。
- 底层仍是`OnBackPressedDispatcher`，因此开启了预测性返回（`android:enableOnBackInvokedCallback="true"`）后同样生效，不需要另写一套API。
- 多个`BackHandler`嵌套时，**最内层**的那个优先处理。

## 状态保存

| API | 重组后 | 配置变更后 | 进程被杀后 | 适合存什么 |
|:--|:--:|:--:|:--:|:--|
| `remember` | 保留 | **丢失** | 丢失 | 临时UI状态（动画开关、焦点） |
| `rememberSaveable` | 保留 | **保留** | **保留** | 输入框内容、选中项、滚动位置 |
| `ViewModel` | 保留 | 保留 | 丢失 | 页面数据、请求结果 |
| `SavedStateHandle` | 保留 | 保留 | **保留** | 页面参数、需跨进程重建的关键值 |

```kotlin
// 旋转屏幕后内容仍在
var query by rememberSaveable { mutableStateOf("") }

class DetailViewModel(private val handle: SavedStateHandle) : ViewModel() {
    // 进程重建后依然能拿到
    val id: String = checkNotNull(handle["id"])
}
```

> `rememberSaveable`底层走`SavedStateRegistry`，最终写进Bundle，因此只能保存Bundle支持的类型。自定义对象要么实现`Parcelable`，要么提供`Saver`，不要塞大对象——它和`onSaveInstanceState`共享同一个Binder事务额度。

## 生命周期与状态收集

Compose 里最常见的错误是在`LaunchedEffect`或`lifecycleScope`里直接`collect`，界面退到后台后依然在收集。正确做法是让收集跟随生命周期：

```kotlin
// 推荐：内部等价于 repeatOnLifecycle(STARTED)
val uiState by viewModel.uiState.collectAsStateWithLifecycle()
```

需要显式控制时：

```kotlin
val lifecycleOwner = LocalLifecycleOwner.current
LaunchedEffect(lifecycleOwner) {
    lifecycleOwner.repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.uiState.collect { /* ... */ }
    }
}
```

两者的行为一致：界面进入STARTED开始收集，退到后台停止，回到前台重新收集。区别只是`collectAsStateWithLifecycle()`把结果转成了`State`，可以直接参与重组。

## 导航：把多Activity收敛成一个

Navigation Compose 2.8起支持基于Kotlin Serialization的**类型安全路由**，不再靠字符串拼接：

```kotlin
@Serializable data object Home
@Serializable data class Detail(val id: String)

NavHost(navController = navController, startDestination = Home) {
    composable<Home> {
        HomeScreen(onOpen = { id -> navController.navigate(Detail(id)) })
    }
    composable<Detail> { entry ->
        val route = entry.toRoute<Detail>()
        DetailScreen(route.id)
    }
}
```

对应的收益很直接：参数类型在编译期就能校验，拼错路由名这类问题从运行时崩溃变成编译错误；同时“返回栈”由`NavController`维护，不再需要`ActivitiesCollector`那类批量`finish()`的工具。

## 常见问题

1. **在`@Preview`里看不到真实行为**：预览没有Activity，`BackHandler`、`enableEdgeToEdge()`、`rememberSaveable`的真实恢复逻辑都不参与。
2. **Scaffold与`systemBarsPadding()`叠加**：双倍留白，内容被顶下来一截。
3. **用`remember`存输入内容**：旋转屏幕后清空，应改`rememberSaveable`。
4. **`collect`不感知生命周期**：退到后台继续消耗CPU，应改`collectAsStateWithLifecycle()`。
5. **`setContent`放在`super.onCreate()`之前**：会因缺少LifecycleOwner等所有者而崩溃，顺序必须是`super.onCreate()`在前。
