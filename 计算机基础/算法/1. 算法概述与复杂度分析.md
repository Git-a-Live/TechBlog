## 什么是算法

算法（Algorithm）是对特定问题求解步骤的一种描述，它是指令的**有限序列**，其中每一条指令表示一个或多个操作。算法与数据结构是程序的两大基石：算法决定"怎么做"，数据结构决定"如何组织数据"。

算法具有 5 个重要特征：

| 特征 | 含义 |
|:---|:---|
| **有穷性** | 对任何合法输入，算法总是在执行有穷步之后结束，且每一步都在有穷时间内完成 |
| **确定性** | 每条指令都有明确的含义，相同输入在任何条件下都产生相同输出 |
| **可行性** | 算法中描述的操作都能通过已实现的基本运算的有限次执行来实现 |
| **输入** | 一个算法有零个或多个输入，取自某个特定的对象集合 |
| **输出** | 一个算法至少有一个输出，这些输出与输入之间存在某种特定关系 |

设计算法通常有 4 个要求：

1. **正确性**：算法应满足问题的需求，输入输出符合规定格式。
2. **可读性**：可读性影响开发者的理解、调试与维护成本。
3. **健壮性**：对非法输入应有适当的处理能力，避免产生难以解释的结果。
4. **低复杂度**：低的时间与空间复杂度可提高效率、节省资源。

## 时间复杂度

### 大 O 表示法

时间复杂度衡量的是算法中**基本操作重复执行的次数**随问题规模 n 的增长趋势。它并不给出确切的执行时间，而是描述"随着 n 增大，运行时间以怎样的速度增长"。

其形式定义为：

$$T(n) = O(f(n))$$

表示随着问题规模 n 的增大，算法执行时间的增长率与 f(n) 的增长率相同。f(n) 是描述问题规模的函数。大 O 表示法关注的是**增长率的量级**，因此会忽略常数项和低阶项。

### 常见复杂度量级

按增长速度从慢到快排列：

| 记号 | 名称 | 典型示例 |
|:---|:---|:---|
| $O(1)$ | 常数阶 | 数组按下标访问、散列表查找（平均） |
| $O(\log n)$ | 对数阶 | 二分查找 |
| $O(n)$ | 线性阶 | 简单查找（顺序遍历）、一次循环 |
| $O(n \log n)$ | 线性对数阶 | 快速排序、归并排序、堆排序 |
| $O(n^2)$ | 平方阶 | 选择排序、插入排序、冒泡排序 |
| $O(n^3)$ | 立方阶 | 矩阵乘法（朴素）、Floyd-Warshall |
| $O(2^n)$ | 指数阶 | 求解 NP 完全问题的暴力法 |
| $O(n!)$ | 阶乘阶 | 旅行商问题的暴力法 |

> 随着 n 增长，不同量级的差距急剧放大。例如 n=100 时，$O(n^2)$ 约需 10000 步，而 $O(2^n)$ 需要约 $1.27 \times 10^{30}$ 步，远超可计算范围。这是设计算法时优先选择低数量级的根本原因。

### 计算复杂度的两条基本规律

1. **顺序执行**：若算法由 n 段顺序执行的代码组成，各自复杂度为 $T_1(n), \dots, T_n(n)$，则总复杂度取**最大者**：
   $$T(n) = \max(T_1(n), \dots, T_n(n)) = \max(O_1(f_1(n)), \dots, O_n(f_n(n)))$$

2. **嵌套执行**：若 n 段代码相互嵌套，则总复杂度为各段复杂度的**乘积**：
   $$T(n) = T_1(n) \times \dots \times T_n(n) = O(f_1(n) \times \dots \times f_n(n))$$

### 最坏、平均与最好情况

- **最坏情况**：算法在给定规模下运行时间的上界，是性能的保证。
- **平均情况**：对所有可能输入的平均运行时间，反映"典型"表现。
- **最好情况**：最有利输入下的运行时间。

> 不特别说明时，时间复杂度通常指**最坏情况**。最坏情况才是对性能的可靠承诺。

## 空间复杂度

空间复杂度描述算法运行所需的存储空间：

$$S(n) = O(f(n))$$

一个程序运行时，除了存储指令、常量、变量和输入数据外，还需要：对数据进行操作的工作单元，以及为实现计算所需信息的**额外空间**。若额外空间相对于输入规模是常数，则称该算法为**原地工作**（原地算法，如原地快排、堆排序）。

与时间复杂度一样，不特别说明时按最坏情况分析。

## 数学知识复习

以下基础知识是分析算法复杂度所必需的。

### 指数

$$X^A X^B = X^{A+B}, \quad \frac{X^A}{X^B} = X^{A-B}, \quad (X^A)^B = X^{AB}$$

$$X^N + X^N = 2X^N \neq X^{2N}, \quad 2^N + 2^N = 2^{N+1}$$

### 对数

对数是幂运算的逆运算：$X^A = B$ 当且仅当 $\log_X B = A$。对数运算满足：

$$\log_A B = \frac{\log_C B}{\log_C A} \quad (\text{换底公式})$$

$$\log AB = \log A + \log B, \quad \log \frac{A}{B} = \log A - \log B, \quad \log A^B = B \log A$$

$$2^{\log N} = N, \quad \log 1 = 0$$

> 在讨论复杂度时，$\log$ 通常指 $\log_2$（二进制对数），因为常数底数的差异在渐近意义下可忽略。

### 级数

- 等比级数（几何级数）：
  $$\sum_{i=0}^{N} 2^i = 2^{N+1} - 1$$
  $$\sum_{i=0}^{N} A^i = \frac{A^{N+1} - 1}{A - 1} \quad (A \neq 1)$$

- 等差级数：
  $$\sum_{i=1}^{N} i = \frac{N(N+1)}{2} \approx \frac{N^2}{2}$$

- 调和级数（用于散列等分析）：
  $$\sum_{i=1}^{N} \frac{1}{i} = \ln N + O(1)$$

### 模运算

若 $N$ 整除 $A - B$，则称 $A$ 与 $B$ 模 $N$ 同余，记作 $A \equiv B \pmod N$。模运算在散列（取模散列函数）和循环队列的索引回绕中广泛使用。

## 递归

递归是算法设计中最重要的技巧之一。**递归就是一个函数直接或间接地调用自身**。

### 递归的两个要件

1. **基线条件（Base Case）**：使递归停止的条件，函数不再调用自身。
2. **递归条件（Recursive Case）**：函数调用自身的条件。

以阶乘为例：`fact(n) = n * fact(n-1)` 是递归条件，`fact(1) = 1` 是基线条件。没有基线条件的递归会无限进行下去，最终导致栈溢出（StackOverflow）。

### 递归与调用栈

递归的工作原理依赖**调用栈（Call Stack）**。每次函数调用都会将当前的局部变量、参数和返回地址压入调用栈；函数返回时再弹出。递归深度过大时，调用栈可能溢出。

> 递归与循环通常可以互相转换。递归的代码往往更清晰，但可能带来额外的栈开销；尾递归可在编译器优化下转为迭代以消除栈开销。

### 递归 vs 迭代的权衡

| 维度 | 递归 | 迭代 |
|:---|:---|:---|
| 可读性 | 对分治、树遍历等结构天然清晰 | 对简单重复更直观 |
| 空间 | 需要调用栈空间 | 通常只需常数空间 |
| 风险 | 深度过大可能栈溢出 | 一般无此风险 |

### Kotlin 实现

```kotlin
// 阶乘（递归）
fun factorial(n: Int): Int = if (n <= 1) 1 else n * factorial(n - 1)

// 斐波那契（朴素递归，存在大量重复计算，指数级）
fun fib(n: Int): Int = if (n <= 1) n else fib(n - 1) + fib(n - 2)

// 尾递归：用 tailrec 修饰，编译器优化为循环，避免栈溢出
tailrec fun fibTail(n: Int, a: Int = 0, b: Int = 1): Int =
    if (n == 0) a else fibTail(n - 1, b, a + b)
```
