字符串（String）是文本处理的核心对象。字符串算法涵盖排序、查找、匹配、压缩等多个方面，是搜索引擎、编译器、生物信息学（基因序列）、自然语言处理的基础。

## 字符串排序

字符串排序的键是字符串本身，而非单个数字。两类主流方法：

### 低位优先（LSD，Least Significant Digit）

从**最右端**（最低位字符）开始，对**定长**字符串逐位进行**稳定**的基数排序（如计数排序）。

- 复杂度：$O(WN)$，W 为字符串长度，N 为字符串个数。
- 适用：**定长**字符串（如车牌号、身份证号）。

### 高位优先（MSD，Most Significant Digit）

从**最左端**（最高位字符）开始，按当前字符分桶后**递归**处理每个桶，处理**变长**字符串。

- 复杂度：$O(WN)$（一般情况）。
- 适用：变长字符串，是 `String.sort()` 之外的常用选择。

## 单词查找树（Trie）

### 定义

Trie（前缀树）是一种**共享前缀**的树形结构，用于高效存储和检索字符串集合。每个节点代表一个字符，从根到某节点的路径对应一个字符串前缀；若该节点被标记为"词尾"，则该前缀是一个完整的词。

### 性质与操作

- **插入**：沿字符串字符逐层创建/复用节点，最后一个字符标记词尾。
- **查找**：沿字符路径向下走，判断是否到达被标记的词尾节点。
- **前缀匹配**：天然支持"找出所有以某前缀开头的词"（自动补全的核心）。

### 应用

1. **自动补全 / 输入联想**。
2. **拼写检查**、**IP 路由最长前缀匹配**。
3. **词频统计**：在词尾节点记录计数。

> 与散列表对比：Trie 在**前缀相关**操作（最长公共前缀、前缀查询）上远优于散列表，但空间开销更大。

## 子字符串查找（模式匹配）

**问题**：在文本 T（长度 n）中查找模式 P（长度 m）出现的所有位置。

### 暴力匹配

逐个位置尝试匹配，最坏 $O(nm)$。简单但效率低。

### KMP 算法（Knuth-Morris-Pratt）

**核心思想**：利用模式串的**自身结构**，构造**部分匹配表（next 数组）**，匹配失败时**不回退文本指针**，而是根据已匹配的信息将模式串移动到合适位置。

- **next 数组**：记录"模式串每个前缀的**最长相等前后缀**长度"，即失配时模式串应回退到的位置。
- 复杂度：$O(n+m)$（线性），预处理 next 数组 $O(m)$。

> KMP 的意义在于避免暴力法"文本指针回退"造成的重复比较，是线性时间字符串匹配的经典成果。

### 其他匹配算法

- **Boyer-Moore**：从右向左比较，利用坏字符/好后缀规则跳过更多字符，实践中常比 KMP 更快。
- **Rabin-Karp**：用滚动散列快速比较子串。
- **Z 算法 / Manacher（最长回文子串）**等。

## 正则表达式

正则表达式（Regular Expression）用**模式字符串**描述一类字符串集合，用于匹配、检索与替换。

### 核心机制

正则表达式可转换为**非确定有限自动机（NFA）**或**确定有限自动机（DFA）**，用于在线性时间内判断文本是否匹配模式。

- 基本运算：**连接**（ab）、**或**（a|b）、**闭包/星号**（a*，零次或多次）。
- NFA 通过"状态集合 + ε 转移"实现匹配，可模拟正则的全部能力。

### 常用元字符

| 元字符 | 含义 |
|:---|:---|
| `.` | 匹配除换行外的任意单字符 |
| `*` `+` `?` | 前项出现 0/多次、1/多次、0 或 1 次 |
| `{n}` `{n,m}` | 恰好 n 次 / n 到 m 次 |
| `^` `$` | 匹配字符串开头 / 结尾 |
| `[abc]` `[a-z]` | 字符类 / 字符范围 |
| `\d` `\w` `\s` | 数字 / 单词字符 / 空白 |
| `()` | 分组，捕获子表达式 |
| `\|` | 或 |

> 正则的三种典型用途：**匹配**（整个字符串是否符合模式）、**检索**（找出所有匹配子串）、**替换**（用模式匹配并替换，可用 `$1` 反向引用分组）。

## 后缀数组与后缀树

后缀树与后缀数组是字符串处理的高级结构（其数据结构实现在「数据结构」笔记的"高级数据结构"篇中讲解）。从算法视角看，后缀树可在 $O(m)$ 内判定模式串是否出现，后缀数组以更小的空间代价配合 LCP（最长公共前缀）数组解决同类问题，广泛用于基因序列分析、文本索引、最长公共子串与最长重复子串。

## 数据压缩

### 霍夫曼编码（Huffman Coding）

**思想**（贪心）：根据字符出现**频率**分配**变长**编码——高频字符用短码、低频字符用长码。用**优先队列**反复合并两个最小频率的节点构建霍夫曼树。

- 前缀码性质：任何字符的编码都不是其他编码的前缀，保证解码无歧义。
- 应用：文件压缩（如 DEFLATE、JPEG、MP3 的一部分）。

### 其他压缩思想

- **游程编码（Run-Length Encoding）**：连续重复的字符用"字符+次数"表示。
- **LZW**：用动态字典替换重复出现的子串。
- **算术编码**：用概率区间编码整个消息，接近熵极限。

## Kotlin 实现

### Kotlin 内建字符串与正则方法

```kotlin
val s = "hello world"

// 子串查找（内建，底层为高效算法）
s.indexOf("world")           // 6，首次出现下标，未找到返回 -1
s.contains("hello")          // true
s.startsWith("he")           // true
s.endsWith("ld")             // true

// 前缀 / 后缀处理
s.removePrefix("hello")      // " world"
s.removeSuffix("world")      // "hello "

// 正则表达式
val regex = Regex("\\d+")
regex.containsMatchIn("abc123")                    // true
regex.findAll("a1b22c333").map { it.value }.toList() // ["1", "22", "333"]
"abc123".replace(Regex("\\d"), "#")                // "abc###"
```

### KMP（构建 next 数组 + 线性匹配）

```kotlin
fun buildNext(pattern: String): IntArray {
    val next = IntArray(pattern.length)
    var j = 0 // 当前已匹配的最长相等前后缀长度
    for (i in 1 until pattern.length) {
        while (j > 0 && pattern[i] != pattern[j]) j = next[j - 1]
        if (pattern[i] == pattern[j]) j++
        next[i] = j
    }
    return next
}

fun kmpSearch(text: String, pattern: String): List<Int> {
    if (pattern.isEmpty()) return emptyList()
    val next = buildNext(pattern)
    val result = mutableListOf<Int>()
    var j = 0
    for (i in text.indices) {
        while (j > 0 && text[i] != pattern[j]) j = next[j - 1]
        if (text[i] == pattern[j]) j++
        if (j == pattern.length) {
            result.add(i - j + 1) // 匹配起始位置
            j = next[j - 1]
        }
    }
    return result
}
```
