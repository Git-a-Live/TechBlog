# 表（List）

## 一、表的定位

表是最基本、最常用的数据结构，其模型为**一组元素排成有序的一列** $A_0, A_1, \dots, A_{N-1}$。程序中的学生名单、待办事项、日志记录、内存对象列表等，均为"一组有序元素"。

对该列元素的常见操作分为两类——**按位置访问**（"第 $i$ 个元素是谁"）与**插入删除**（"在第 $i$ 个之后插入/删除"）。两类需求存在天然矛盾，本章的核心即是研究**顺序存储与链式存储两种结构在这一矛盾上的权衡**。表之所以作为全书第一站，是因为它把"**存储结构决定操作效率**"这条主线阐述得最清晰，后续的栈、队列、树、图均在此主线上作加法。

## 二、表的抽象数据类型（List ADT）

表 $L$ 是形如 $A_0, A_1, \dots, A_{N-1}$ 的**有序**序列，$N$ 为表的大小（空表 $N=0$），下标从 0 开始：$A_{i-1}$ 是 $A_i$ 的前驱，$A_{i+1}$ 是其后继。

表 ADT 的核心操作：

| 操作 | 含义 |
| --- | --- |
| `isEmpty()` | 判断表是否为空 |
| `size()` | 返回元素个数 |
| `get(idx)` | 返回下标 `idx` 处的元素 |
| `set(idx, x)` | 将下标 `idx` 处元素替换为 `x` |
| `add(x)` | 在表尾追加 `x` |
| `add(idx, x)` | 在下标 `idx` 处插入 `x` |
| `remove(idx)` | 删除下标 `idx` 处的元素 |
| `contains(x)` | 判断是否包含 `x` |
| 遍历 | 按序访问所有元素 |

ADT 仅规定操作的语义，不规定存储方式。以下两种实现即体现了"同一 ADT、不同实现、不同权衡"。

## 三、顺序表（数组实现）

### 1. 连续存储与随机存取

顺序表用**一组地址连续的存储单元依次存放元素**。其核心优势是**随机存取**：已知首元素地址与下标，即可用算术直接算出目标元素地址，无需逐个查找。

设首元素地址为 $LOC(A_0)$，每个元素占 $l$ 个存储单元，则第 $i$ 个元素的地址：

$$LOC(A_i) = LOC(A_0) + i \times l$$

定位时间为常数 $O(1)$，与 $i$ 无关，故 `get(idx)`、`set(idx, x)` 均为 $O(1)$。

### 2. 插入与删除的代价

插入或删除需**移动后续所有元素**以保持连续性：在下标 `idx` 处插入，须将 $A_{idx}, \dots, A_{N-1}$ 整体后移一位；删除则整体前移一位。移动量取决于位置——表尾操作无需移动（$O(1)$），表头操作几乎移动所有元素（最坏 $O(N)$），平均移动约 $N/2$ 个元素（$O(N)$）。

### 3. 容量与动态扩容

数组长度固定，而表的大小可变。填满时需扩容：分配更大的新数组（通常**翻倍**），整体复制旧元素。

扩容虽需 $O(N)$ 复制，但**摊还到每次插入仍为 $O(1)$**。摊还分析：从容量 1 起插入 $N$ 个元素，扩容发生在第 1、2、4、8……次插入，总复制代价 $1 + 2 + 4 + \dots + N/2 \approx N$；将其摊到 $N$ 次插入上，平均每次仅多出 $O(1)$。

> 扩容必须按倍数增长（翻倍），而非每次固定增加 1。若每次加 1，则每插入一个元素都需整体复制，摊还代价退化为 $O(N)$。

## 四、链表（链式存储）

### 1. 任意存储与指针相连

链表用**一组任意（可不连续）的存储单元**，通过**指针**把元素串起来。它以放弃随机存取为代价，换取插入删除无需移动元素。

**单链表**每个结点包含两部分：`data`（数据域，存放元素）与 `next`（指针域，存放直接后继的地址，末结点的 `next` 为空）。

```
┌────────┬──────┐
│ data   │ next │──→ 下一个结点
└────────┴──────┘
```

### 2. 插入与删除

链表插入删除只需修改指针，无需移动元素。以"在结点 $a$ 之后插入新结点 $i$"为例：① 令 $i.next$ 指向 $a$ 原后继；② 令 $a.next$ 指向 $i$。删除 $a$ 的后继则令 $a.next$ 指向其后继的后继。

前提是"已定位到目标位置"：若已知指向 $a$ 的指针，插入删除为 $O(1)$；若要找到 $a$（如第 $i$ 个结点），须从头遍历，$O(N)$。这正是链表与顺序表的镜像对照——链表以随机访问变慢换取插入删除变快。

### 3. 头结点（哨兵结点）

链表的边界麻烦在于：插入或删除"第一个元素"时没有前驱可供修改指针，若每次都写 `if (是第一个元素) ... else ...` 分支，代码繁琐且易错。**头结点（哨兵结点）**在真正首元素之前固定放置一个不存数据的结点，使"插入到第一个位置"等同于"插入到哨兵之后"，与普通插入同构，统一了边界处理。

> 哨兵结点的价值在于消除特判，让所有插入删除走同一路径，是链表实现中最重要的工程技巧之一。

### 4. 插入示例

设链表 `A → B → C`（含哨兵），在 `A` 之后插入 `X`：

```
初始：  A → B → C
① 令 X.next 指向 B：   X → B
② 令 A.next 指向 X：   A → X → B → C
```

若颠倒顺序（先改 `A.next` 再设 `X.next`），则 `A` 指向 `X` 后原后继 `B` 的地址丢失，造成"断链"。**先接后链、再改前链**是链表操作的基本准则。

## 五、顺序表与链表的权衡

| 维度 | 顺序表（数组） | 链表 |
| --- | --- | --- |
| 随机访问 `get/set` | $O(1)$ | $O(N)$ |
| 表尾追加 | $O(1)$ 摊还 | $O(1)$ |
| 中间插入/删除 | $O(N)$（移动元素） | $O(1)$（已定位后） |
| 查找 `contains` | $O(N)$ | $O(N)$ |
| 存储 | 连续，仅存数据 | 每结点多一个指针开销 |

除时间复杂度外，还有两个实际因素：

1. **内存局部性（cache locality）**：顺序表元素连续存放，遍历时缓存命中率高，实际速度常优于"同样 $O(N)$ 但指针跳转"的链表。
2. **内存开销**：链表每结点额外存储指针，存储相同数据占用更多内存。

选型原则：频繁随机访问选顺序表；频繁中间增删且几乎不按位置访问选链表；不确定时默认顺序表（实现简单、遍历快、缓存友好），仅在明确出现"大量中间增删且无随机访问"需求时链表才占优。

## 六、双向链表

单链表的天然缺陷是**从一个结点无法直接找到其前驱**，删除当前结点须先遍历找到前驱。双向链表为每个结点增加一个指向前驱的指针，可双向遍历，删除"已知结点本身"仅需 $O(1)$（不必先找前驱）。代价是每结点多一个指针，插入删除需同时维护两个方向的指针。

双向链表常配头、尾两个哨兵结点，使首尾操作统一且 $O(1)$，是栈、双端队列等结构的高效底座。

## 七、小结

- 表是"有序元素序列"的抽象，有顺序表（连续存储）与链表（指针相连）两种实现。
- 顺序表胜在随机存取 $O(1)$，靠翻倍扩容维持尾部追加 $O(1)$ 摊还；链表胜在中间增删 $O(1)$，代价是随机访问需遍历。
- 二者是"访问 vs 增删"的经典权衡，体现了"存储结构决定操作效率"的全书主线。
- 哨兵结点（统一边界）与"先接后链"（避免断链）是链表实现的关键技巧；双向链表以多一个指针的代价换来 $O(1)$ 的前驱访问。
