# 栈和队列（Stack & Queue）

## 一、共同特征：受限线性表

栈与队列都是**操作受限的线性表**：栈只在一端操作，队列在两端分别操作。限制并非缺点，反而带来清晰、可预测的行为，使其成为程序设计中用途最广的两种结构。二者的差异在于"顺序"：

- **栈**遵循后进先出（LIFO），记录的是"最近"——适用于撤销、回溯、嵌套等需要回找最近状态的场景。
- **队列**遵循先进先出（FIFO），记录的是"先后"——适用于排队、逐层、公平等按到达顺序处理的场景。

## 二、栈（Stack）

### 1. 栈模型：后进先出（LIFO）

栈是**限定仅在表尾（栈顶）进行插入和删除**的线性表，最后放入的元素最先被取出。**栈顶（top）**是唯一可见、可操作的一端，**栈底（bottom）**是最早进入、最后被访问的一端。

栈 ADT 核心操作：

| 操作 | 含义 |
| --- | --- |
| `push(x)` | 入栈，把 `x` 压到栈顶 |
| `pop()` | 出栈，删除并返回栈顶元素 |
| `top()` / `peek()` | 查看栈顶元素但不删除 |
| `isEmpty()` | 判断栈是否为空 |

### 2. 栈的实现

**数组实现**：以数组末尾作栈顶，用下标 `topOfStack` 记录栈顶位置。`push` 为"下标加一后写入"，`pop` 为"读出后下标减一"，均为 $O(1)$ 且常数因子极小。

```java
E[] array;
int topOfStack = -1;          // 空栈

void push(E x) { array[++topOfStack] = x; }   // 先 +1 再写入
E pop()        { return array[topOfStack--]; } // 先读后 -1
E top()        { return array[topOfStack]; }
```

**链表实现**：以**表头**作栈顶（单链表即可），`push` 头部插入、`pop` 头部删除，均 $O(1)$。

> 链表栈的栈顶应置于表头而非表尾。单链表的删除须先找到前驱，若栈顶在表尾，`pop` 需遍历整条链，代价 $O(N)$；置于表头则删除仅改头指针，$O(1)$。该细节体现了"存储结构决定操作效率"。

通常数组实现更优：出入栈以极快的常数时间运行，且贴近硬件指令，是更流行的方案。

### 3. 栈的应用

#### 应用一：平衡符号检查

编译器需检查代码中的括号、花括号、方括号是否配对且不交叉。用栈可在线性时间内完成：遇左符号入栈；遇右符号与栈顶匹配则弹出，不匹配则报错；处理完毕栈为空即平衡。

例：检查 `[ ( ) ]`：

```
[   → 入栈        栈: [
(   → 入栈        栈: [ (
)   → 匹配栈顶 ( → 弹出   栈: [
]   → 匹配栈顶 [ → 弹出   栈: (空)
结束 → 栈空，平衡
```

而 `[ ( ] )` 中 `]` 与栈顶 `(` 不匹配，可立即发现错误。

#### 应用二：后缀表达式求值（逆波兰表达式）

中缀表达式 `a + b` 存在括号与优先级问题；**后缀表达式**将运算符置于操作数之后（如 `a b +`），无需括号与优先级即可机械求值：扫描到操作数入栈；扫描到运算符弹出两个操作数运算后压回结果。

例：求值 `6 5 2 3 + 8 * + 3 + *`：

```
6     → 入栈        栈: 6
5     → 入栈        栈: 6 5
2     → 入栈        栈: 6 5 2
3     → 入栈        栈: 6 5 2 3
+     → 弹 3、2，算 2+3=5 压回     栈: 6 5 5
8     → 入栈        栈: 6 5 5 8
*     → 弹 8、5，算 5*8=40 压回    栈: 6 5 40
+     → 弹 40、5，算 5+40=45 压回  栈: 6 45
3     → 入栈        栈: 6 45 3
+     → 弹 3、45，算 45+3=48 压回  栈: 6 48
*     → 弹 48、6，算 6*48=288 压回 栈: 288
```

最终栈中仅剩结果 `288`，全程 $O(N)$。

求值过程有三条必须遵守的约定：

1. **弹栈顺序**：先弹出的是右操作数，后弹出的是左操作数。`a b -` 的结果是 `a - b` 而非 `b - a`，减法与除法不满足交换律，顺序颠倒会得到错误结果。
2. **运算符元数**：二元运算符弹两个操作数，一元运算符（如取负）只弹一个。后缀式允许一元与二元运算符共存，前提是转换阶段已把二者区分为不同的运算符符号。
3. **合法性校验**：扫描结束时栈中应恰好剩余一个元素，且过程中任何一次弹栈都不得对空栈操作。后缀式无需括号，语法错误直接表现为对空栈弹栈，或扫描结束时残留多个元素，这是它相对中缀式的一项附加优势。

时间与空间均为 $O(N)$：每个 token 恰好入栈一次、出栈一次；栈的最大深度不超过操作数的个数，最坏情况（所有操作数先全部入栈，如 `1 2 3 4 + + +`）需要与操作数个数相等的槽位。

```kotlin
fun evalPostfix(tokens: List<String>): Double {
    val stack = ArrayDeque<Double>()
    for (t in tokens) {
        when (t) {
            "+", "-", "*", "/" -> {
                val right = stack.removeLast()   // 先弹出的是右操作数
                val left = stack.removeLast()
                stack.addLast(when (t) {
                    "+" -> left + right
                    "-" -> left - right
                    "*" -> left * right
                    else -> left / right
                })
            }
            else -> stack.addLast(t.toDouble())
        }
    }
    return stack.last()
}
```

#### 应用三：中缀表达式转后缀

计算器须先将中缀式 `a + b * c` 转为后缀式 `a b c * +`。算法为：操作数直接输出；运算符入栈，优先级高者先出；遇左括号入栈、遇右括号则弹出到左括号为止。栈在此处的作用是暂存尚未到输出时机的运算符。

上述规则在实际实现中需要补足三个细节：优先级与结合性的判定、括号在栈内的特殊地位、运算符扫描结束后的收尾。完整规则如下。

**优先级与结合性**：

| 运算符 | 优先级 | 结合性 | 说明 |
|:---|:---:|:---:|:---|
| `(` | — | — | 入栈后作为屏障，不与任何运算符比较；遇 `)` 时被弹出并丢弃 |
| `+` `-` | 1 | 左 | 同级从左向右结合 |
| `*` `/` | 2 | 左 | 优先于加减 |
| `^` | 3 | 右 | 幂运算，同级从右向左结合：`2^3^2 = 2^(3^2)` |
| 一元 `-` | 4 | 右 | 负号与减号同形，按上下文区分，见下文 |

**转换算法**：

1. 扫描到操作数，直接加入输出序列。
2. 扫描到左括号，入栈。
3. 扫描到右括号，弹出栈顶运算符并加入输出，直到遇见左括号；左括号弹出后丢弃，不进入输出。
4. 扫描到运算符 `op`，循环比较栈顶：当栈非空、栈顶不是左括号，且「栈顶优先级 > `op` 优先级」或「两者优先级相等且 `op` 为左结合」时，弹出栈顶加入输出；条件不满足则停止比较，`op` 入栈。
5. 扫描结束后，依次弹出栈内剩余运算符加入输出。

第 4 步的判定同时处理了优先级与结合性：左结合运算符在优先级相等时也要先弹出栈顶，因此 `a - b - c` 转为 `a b - c -`；右结合运算符在优先级相等时保留栈顶，因此 `a ^ b ^ c` 转为 `a b c ^ ^`。

**推演示例**：中缀式 `a + b * c - (d + e) / f`。

| 步骤 | 读入 | 动作 | 栈（底→顶） | 输出 |
|:---:|:---:|:---|:---|:---|
| 1 | `a` | 操作数，输出 | — | `a` |
| 2 | `+` | 栈空，入栈 | `+` | `a` |
| 3 | `b` | 操作数，输出 | `+` | `a b` |
| 4 | `*` | 栈顶 `+` 优先级 1 < 2，不弹，入栈 | `+ *` | `a b` |
| 5 | `c` | 操作数，输出 | `+ *` | `a b c` |
| 6 | `-` | 弹 `*`（2 > 1），弹 `+`（1 = 1 且左结合），栈空后入栈 | `-` | `a b c * +` |
| 7 | `(` | 左括号，入栈 | `- (` | `a b c * +` |
| 8 | `d` | 操作数，输出 | `- (` | `a b c * + d` |
| 9 | `+` | 栈顶为左括号，停止比较，入栈 | `- ( +` | `a b c * + d` |
| 10 | `e` | 操作数，输出 | `- ( +` | `a b c * + d e` |
| 11 | `)` | 弹 `+`，遇左括号停止并丢弃 | `-` | `a b c * + d e +` |
| 12 | `/` | 栈顶 `-` 优先级 1 < 2，不弹，入栈 | `- /` | `a b c * + d e +` |
| 13 | `f` | 操作数，输出 | `- /` | `a b c * + d e + f` |
| 14 | 结束 | 依次弹出 `/`、`-` | — | `a b c * + d e + f / -` |

结果为 `a b c * + d e + f / -`，其结构等价于 `(a + (b * c)) - ((d + e) / f)`。

**一元负号的歧义**：`-` 在 `3 - 2` 中是二元减法，在 `-2`、`5 * -x`、`(-a + b)` 中是一元取负。二者优先级不同（取负高于乘除），仅凭符号本身无法区分，必须依据**前一个 token 的类型**判定：表达式起始、左括号之后、其他运算符之后出现的 `-` 为一元取负；数字、标识符、右括号之后出现的 `-` 为二元减法。判定应在读入 token 时完成，并把一元取负转写为独立运算符（如 `neg`），分配独立优先级与右结合性，而不是在弹栈阶段补救。

**Kotlin 实现**（假定输入括号已配对，运算符限于 `+ - * /`）：

```kotlin
private val precedence = mapOf('+' to 1, '-' to 1, '*' to 2, '/' to 2)

fun infixToPostfix(expr: String): List<String> {
    val output = mutableListOf<String>()
    val stack = ArrayDeque<Char>()
    var i = 0
    while (i < expr.length) {
        val c = expr[i]
        when {
            c.isWhitespace() -> i++
            c.isDigit() -> {                      // 连同小数点一起读入完整操作数
                val start = i
                while (i < expr.length && (expr[i].isDigit() || expr[i] == '.')) i++
                output += expr.substring(start, i)
            }
            c == '(' -> { stack.addLast(c); i++ }
            c == ')' -> {
                while (stack.last() != '(') output += stack.removeLast().toString()
                stack.removeLast()                // 丢弃左括号
                i++
            }
            else -> {
                while (stack.isNotEmpty() && stack.last() != '(' &&
                       precedence.getValue(stack.last()) >= precedence.getValue(c)) {
                    output += stack.removeLast().toString()
                }
                stack.addLast(c)
                i++
            }
        }
    }
    while (stack.isNotEmpty()) output += stack.removeLast().toString()
    return output
}
```

`>=` 对应左结合：优先级相等时也弹出。若要支持右结合的 `^`，需将比较拆为「优先级更高即弹」与「优先级相等且当前运算符左结合才弹」两个条件。

#### 应用四：前缀表达式

**前缀表达式（波兰表达式）** 将运算符置于操作数之前，`a + b * c` 写作 `+ a * b c`。其求值规则与后缀式对偶：**从右向左**扫描，遇操作数入栈；遇运算符弹出两个操作数，此时**先弹出的是左操作数**，运算后压回结果。

例：求值 `- + a * b c / + d e f`（即 `(a + b * c) - (d + e) / f`），自右向左扫描：

```
f   → 入栈
e   → 入栈
d   → 入栈
+   → 弹 d、e，算 d+e 压回
/   → 弹 (d+e)、f，算 (d+e)/f 压回
c   → 入栈
b   → 入栈
*   → 弹 b、c，算 b*c 压回
a   → 入栈
+   → 弹 a、(b*c)，算 a+b*c 压回
-   → 弹 (a+b*c)、((d+e)/f)，相减得结果
```

前缀式与后缀式共用同一棵表达式树，运算符的位置已经隐含了树的结构，因此二者都不需要括号。前缀式在工程中的实际形态是 Lisp 系语言的 S 表达式与各类函数调用写法，运算符位于最前，参数依次排列。

#### 三种记法的对应关系：表达式树

三种记法并非彼此独立的编码，而是**同一棵表达式树的三种线性化结果**。表达式树以操作数为叶结点、运算符为内部结点，优先级高的运算符位于更深层，括号决定子树归属。

以 `a + b * c` 为例：

```
        +
       / \
      a   *
         / \
        b   c
```

- 前序遍历（根—左—右）：`+ a * b c`，即前缀式。
- 中序遍历（左—根—右）：`a + b * c`，即中缀式。
- 后序遍历（左—右—根）：`a b c * +`，即后缀式。

中缀式与树并非一一对应：`(a + b) * c` 的中序遍历结果同样是 `a + b * c`，但树结构不同（根为 `*`）。这正是中缀式必须依赖括号与优先级才能还原运算次序的原因，也是前缀式、后缀式无需括号的原因——运算符的位置已经编码了树的结构。

由此可得一条统一的认识：三种记法之间的转换，本质是同一棵树在三种遍历序之间的切换。教材以栈算法分别实现「中缀转后缀」「中缀转前缀」，是在不显式建树的约束下模拟先建树再遍历的过程；若已建树，三种记法只需三次遍历即可直接得到。

| 维度 | 前缀式（波兰式） | 中缀式 | 后缀式（逆波兰式） |
|:---|:---|:---|:---|
| 运算符位置 | 操作数之前 | 操作数之间 | 操作数之后 |
| 对应遍历 | 前序 | 中序 | 后序 |
| 求值扫描方向 | 右 → 左 | 需先转换 | 左 → 右 |
| 弹栈后操作数角色 | 先弹出者为左操作数 | — | 先弹出者为右操作数 |
| 括号 | 不需要 | 必需 | 不需要 |
| 单栈求值 | 可以 | 不可以 | 可以 |

#### 应用五：方法调用

每次函数调用，系统将**返回地址、局部变量、参数**压入**调用栈（call stack）**，返回时弹出。递归的本质即系统栈的运用——每次递归调用压入一层，返回时逐层弹出。递归过深会导致**栈溢出（Stack Overflow）**，因为栈容量有限，而无基准情形的递归会无限压栈。

## 三、队列（Queue）

### 1. 队列模型：先进先出（FIFO）

队列是**限定仅在一端（队尾 rear）插入、另一端（队头 front）删除**的线性表，遵循先进先出。

| 操作 | 含义 |
| --- | --- |
| `enqueue(x)` | 入队，在队尾插入 |
| `dequeue()` | 出队，删除并返回队头元素 |
| `front()` | 查看队头元素 |
| `isEmpty()` | 判断队列是否为空 |

### 2. 队列的数组实现：循环数组

朴素数组实现会遭遇**假溢出**：`enqueue` 在尾部追加、`dequeue` 从头部删除，删除后队头腾出的空间用不上，队尾下标却一路涨到数组末尾，前方虽有空间却无法插入。

**循环数组（circular array）**将数组视为首尾相接的环，下标移动用取模绕回：

- 维护 `front`（队头下标）与 `back`（队尾下一空位下标）；
- 入队：写入 `array[back]`，`back = (back + 1) % capacity`；
- 出队：取出 `array[front]`，`front = (front + 1) % capacity`；
- 元素个数：`size = (back - front + capacity) % capacity`。

需处理的细节：`front == back` 既可能是"队空"也可能是"队满"，无法仅凭下标区分。两种常见解法：**牺牲一个槽**（规定"`back` 的下一位是 `front`"为满，最多存 `capacity - 1` 个元素），或**额外维护 `size` 字段**（`size == 0` 为空、`size == capacity` 为满）。

所有操作均 $O(1)$。链表实现（双向链表）同样 $O(1)$，且无需考虑容量。

### 3. 队列的应用

1. 广度优先搜索（BFS）：逐层扩展，用队列记录待访问的下一层。
2. 作业调度 / 打印队列 / 消息队列：按到达顺序公平处理。
3. 缓冲区：生产-消费模型中生产者入队、消费者出队。
4. 树的层序遍历：用队列依次记录每一层结点。

## 四、栈与队列的对比

| 维度 | 栈 | 队列 |
| --- | --- | --- |
| 原则 | LIFO（后进先出） | FIFO（先进先出） |
| 操作端 | 仅栈顶一端 | 队尾入、队头出 |
| 典型实现 | 数组（栈顶在末尾） | 循环数组 / 链表 |
| 复杂度 | 全部 $O(1)$ | 全部 $O(1)$ |
| 对应思想 | 深度优先（递归、回溯） | 广度优先（逐层处理） |

## 五、小结

- 栈与队列是"受限线性表"，限制反而成就了清晰语义与恒定的 $O(1)$ 操作代价。
- 栈是深度优先思想的载体（递归调用、回溯、表达式求值），队列是广度优先思想的载体（逐层遍历、任务调度）。
- 二者较少以裸数组/链表的面目出现，而作为算法与系统的底层机制：调用栈、事件循环、缓冲队列、搜索队列。
- 两个关键实现细节：链表栈的栈顶应置于表头（避免 $O(N)$ 删除）；循环队列需处理"空 vs 满"的歧义。
- 三种表达式记法是同一棵表达式树的三种遍历序：前缀对应前序、中缀对应中序、后缀对应后序。中缀式须先转换再求值，前缀式与后缀式可直接单栈求值，转换算法的核心是优先级与结合性共同决定的弹栈条件。
