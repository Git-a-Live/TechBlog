# 散列（Hashing）

## 一、散列的引入

前面讨论的查找结构都依赖比较：BST、AVL 树通过"比大小"缩小范围，最好也不过 $O(\log N)$。散列表（hash table）走的是不同路径：**用键直接算出它应放置的位置**，理想情况下一次计算即定位，实现平均 $O(1)$ 的插入、删除、查找。

$O(1)$ 与 $O(\log N)$ 的差距在超大数据集上是数量级的。散列是"用空间换时间、用计算换比较"的典范，也是实现集合（Set）与映射（Map）的主流底层结构。

## 二、一般想法

给定键 `key`，用散列函数 $h(key)$ 算出它在表中的下标，直接存取：

```
key ──散列函数 h──▶ 下标 i ──▶ 表[i]
```

理想散列函数应满足两点：计算快（否则 $O(1)$ 无从谈起）、分布均匀（尽量让键分散到不同位置）。

**冲突（collision）**：两个不同键映射到同一位置，不可避免——键空间远大于表大小。散列的核心任务即两件事：设计好散列函数、优雅地处理冲突。

**装填因子（load factor）** $\lambda$ = 元素个数 / 表大小，是衡量表"拥挤程度"与性能的关键指标，$\lambda$ 越大冲突越多、性能越差。

## 三、散列函数

### 1. 除留余数法

$h(key) = key \bmod M$，即用键对表大小取模，是最常用、最直观的方法。

**$M$ 常取素数**，因为取模结果的分布与键的二进制模式相关：若 $M$ 取偶数或 2 的幂，键的低位规律会直接反映到散列值上，导致分布不均；取素数能打散这种规律性，使键更均匀地落入 $[0, M-1]$。

### 2. 对字符串键

字符串键需先折叠成整数再取模。经典做法是**霍纳法则（Horner's rule）**，将字符串视为"以 37 为基的多项式"：

```java
int hash(String key, int tableSize) {
    int hashVal = 0;
    for (int i = 0; i < key.length(); i++)
        hashVal = 37 * hashVal + key.charAt(i); // 37 常用作乘数
    hashVal %= tableSize;
    if (hashVal < 0) hashVal += tableSize;      // 处理负数
    return hashVal;
}
```

例：`"cat"` 的散列值为 `((0*37 + 'c')*37 + 'a')*37 + 't'`，即 `'c'*37² + 'a'*37 + 't'`。

### 3. 散列函数失效的后果

若 $h(key) = 0$（所有键都映射到位置 0），所有操作退化为 $O(N)$。散列性能的上限完全取决于散列函数的质量。

## 四、分离链接法（Separate Chaining）

### 1. 思想

冲突时将散列到同一位置的所有元素用一条**链表**串起来，表的每个槽是链表的头：

```
表： [0] → [1] → [2] → [3] → [4]
      |     |           |
      A     B           C
      |     |
      D     E           (冲突元素挂在同一链表)
```

插入为"算下标后插入对应链表"，查找/删除为"在对应链表里查找/删除"。

分离链接法允许装填因子 $\lambda > 1$——链表可无限长，表不需要有空位，这是它与开放定址法的根本区别。

### 2. 性能分析

若散列均匀，每个链表平均长度为 $\lambda$：不成功查找平均遍历 $\lambda$ 个结点，成功查找平均遍历约 $1 + \lambda/2$ 个结点。只要将 $\lambda$ 控制在小常数（如 $\lambda \le 1$），平均操作即 $O(1)$。

> 分离链接法的性能取决于装填因子而非元素总数，只要表大小与元素数保持同步增长即可维持 $O(1)$。

## 五、开放定址法（Open Addressing）

### 1. 思想

不借助链表，冲突时按某个探测序列在表内寻找下一个空槽，要求 $\lambda < 1$（表必须有空位）。探测序列一般形式为 $h_i(key) = \big(h(key) + f(i)\big) \bmod M$，$f(i)$ 决定第 $i$ 次探测的偏移量。

### 2. 线性探测法（Linear Probing）

$f(i) = i$，冲突后顺序探测下一槽。

例：表大小 10，$h(k)=k\bmod 10$，依次插入 `89, 18, 49, 58, 69`：

```
插入 89 → 89%10=9 → 放 [9]
插入 18 → 18%10=8 → 放 [8]
插入 49 → 49%10=9 → [9] 冲突 → 试 [0] → 放 [0]   （顺序探测）
插入 58 → 58%10=8 → [8][9][0] 冲突 → 放 [1]
插入 69 → 69%10=9 → [9][0][1][2] 冲突 → 放 [2]
```

冲突元素会挤成一串，即线性探测的致命缺陷——**一次聚集（primary clustering）**：连续被占用的槽形成聚集块，且越长越易变长（新元素落入块内任何位置都会顺着探测把块再拉长）；聚集一旦形成，插入查找都要沿长块一路探测，性能随 $\lambda$ 增长迅速恶化。

### 3. 平方探测法（Quadratic Probing）

$f(i) = i^2$，探测位置依次偏移 $0, 1, 4, 9, 16, \dots$，冲突后跳跃式探测，避免形成连续聚集块。

例：表大小 10，$h(k)=k\bmod 10$，插入 `89, 18, 49, 58, 69`：

```
插入 89 → 9 → 放 [9]
插入 18 → 8 → 放 [8]
插入 49 → 9 冲突 → 偏移 1 → [0] → 放 [0]
插入 58 → 8 冲突 → 偏移 1 → [9] 冲突 → 偏移 4 → [2] → 放 [2]
插入 69 → 9 冲突 → [0] 冲突 → [3]（9+4=13→3）→ 放 [3]
```

**关键定理**：若表大小 $M$ 是素数且表至少半空（$\lambda \le 0.5$），则平方探测一定能找到空槽。这是平方探测要求"素数表大小 + 装填因子 ≤ 0.5"的原因。

平方探测仍有轻微缺陷——**二次聚集（secondary clustering）**：散列到同一初始位置的元素会探测相同序列（都用 $f(i)=i^2$），但远不如一次聚集严重。

> 平方探测的删除必须懒惰：不能直接置空，否则会截断探测链（后续按同一序列探测的元素会误判"不存在"）。正确做法是标记为"已删除"，探测时跳过、插入时可复用。

### 4. 双散列（Double Hashing）

$f(i) = i \cdot h_2(key)$，用第二个散列函数决定步长。两个键只有两个散列函数都冲突时才走相同探测序列，分布比平方探测更均匀。常用 $h_2(key) = R - (key \bmod R)$（$R$ 为小于表大小的素数），保证步长非零且与表大小互素。双散列是开放定址法中分布最均匀的方案，代价是需两个散列函数。

### 5. 再散列（Rehashing）

当装填因子超过阈值（平方探测 $\lambda > 0.5$、分离链接 $\lambda > 1$）时，性能明显下降。再散列即换一张更大的表：建立约 2 倍大小的新表（通常取下一素数），用新散列函数重新插入所有元素，释放旧表。摊还代价 $O(1)$（与顺序表扩容同理），是维持"$\lambda$ 恒定 → $O(1)$"的关键机制。

## 六、标准库中的散列表

- `HashSet<E>`：基于散列的集合，`add`/`remove`/`contains` 平均 $O(1)$。
- `HashMap<K, V>`：基于散列的映射，`put`/`get`/`remove` 平均 $O(1)$。

使用要点：

1. `hashCode()` 与 `equals()` 契约：作为键的类必须保证相等的对象有相等的 `hashCode`（反之不必须），否则散列表会"找不到"本应存在的键。
2. 散列表无序，不能按键序遍历；需有序遍历时改用 `TreeMap`/`TreeSet`（红黑树）。

## 七、小结

| 冲突处理 | 平均查找 | 关键约束 / 缺陷 |
| --- | --- | --- |
| 分离链接 | $O(1+\lambda)$ | 链表开销，$\lambda$ 可大于 1 |
| 线性探测 | 随 $\lambda$ 恶化快 | 一次聚集 |
| 平方探测 | 好于线性 | 素数表 + $\lambda \le 0.5$；二次聚集 |
| 双散列 | 开放定址中最优 | 需两个散列函数 |

核心结论：散列表以平均 $O(1)$ 换取了"无序"，是"用计算取代比较、用空间换时间"的代表。性能的三大支柱为好散列函数（均匀）、合适的冲突处理（分离链接/开放定址）、再散列（保持 $\lambda$ 恒定）。选型上，只需快速查存且不关心顺序选 `HashMap`/`HashSet`，需按键有序遍历选 `TreeMap`/`TreeSet`。
