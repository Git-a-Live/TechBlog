# 不相交集类（Disjoint Set / Union-Find）

## 一、等价关系与动态等价性问题

集合 $S$ 上的关系 $R$ 是**等价关系（equivalence relation）**，当且仅当同时满足三条：

1. **自反性（reflexive）**：对任意 $a \in S$，$a R a$。
2. **对称性（symmetric）**：若 $a R b$，则 $b R a$。
3. **传递性（transitive）**：若 $a R b$ 且 $b R c$，则 $a R c$。

等价关系把集合 $S$ 划分成若干**等价类（equivalence class）**：类内元素两两等价、类间互不等价。典型例子：图的"连通"关系（连通分量即等价类）、整数"模 $N$ 同余"（把整数分成 $N$ 个等价类）。

**动态等价性问题**：给定一个集合，最初每个元素各自成一类，之后不断收到"$a$ 与 $b$ 等价"的声明，需随时回答"$a$ 与 $b$ 是否已在同一等价类"。不相交集（并查集）即为解决该问题的数据结构。

## 二、模型

不相交集维护一组**互不相交**的集合，支持两种操作：

| 操作 | 含义 |
| --- | --- |
| `find(x)` | 返回 $x$ 所在等价类的代表元（通常用该类的根表示） |
| `union(a, b)` | 若 $a$、$b$ 不同类，则合并它们所在的等价类 |

判断"$a$、$b$ 是否同类"只需比较 `find(a)` 与 `find(b)` 是否相等。Kruskal 算法、网络连通性、生成迷宫等问题均归结为该模型。

## 三、基本数据结构：森林表示

核心思想是用**树**表示等价类：每棵树对应一个等价类，树的根即该类的代表元，整个结构是一片森林。最简实现用数组 `s[i]` 存结点 $i$ 的父结点下标，根结点的 `s[root] = -1`：

```java
int find(int x) {
    if (s[x] < 0) return x;   // 负数说明是根
    return find(s[x]);
}

void union(int a, int b) {
    int rootA = find(a), rootB = find(b);
    if (rootA != rootB) s[rootB] = rootA;
}
```

朴素 `union` 不做任何选择，可能导致树退化为链：

```
union(1,2):  1 ← 2
union(1,3):  1 ← 2 ← 3
union(1,4):  1 ← 2 ← 3 ← 4   ← 越来越长
```

此时 `find(4)` 需一路爬到根，最坏 $O(N)$。

## 四、灵巧求并算法（Smart Union）

思路是合并时总让"小树挂到大树下"，避免树变得又细又长。两种策略：

- **按大小求并（union by size）**：结点多的树作根，`s[root]` 存负的结点数（$-size$）。
- **按高度求并（union by height）**：较矮的树挂到较高树下，`s[root]` 存负的高度（$-height$）。

```java
void union(int a, int b) {
    int rootA = find(a), rootB = find(b);
    if (rootA == rootB) return;
    if (s[rootB] < s[rootA]) {      // rootB 更大/更高（负数更小）
        s[rootA] = rootB;
    } else {
        if (s[rootA] == s[rootB]) s[rootA]--; // 高度相同时合并后高度 +1
        s[rootB] = rootA;
    }
}
```

按大小/高度求并后，**任意树的深度不超过 $\log N$**。直觉依据：一个结点每下沉一层（被挂到别的树下），其所在树的大小至少翻倍；从单结点起大小最多翻 $\log N$ 次即到 $N$，故深度 ≤ $\log N$，`find` 最坏 $O(\log N)$。

## 五、路径压缩（Path Compression）

在 `find(x)` 上溯过程中，把路径上每个结点直接指向根，把树"拍扁"：

```java
int find(int x) {
    if (s[x] < 0) return x;
    return s[x] = find(s[x]);   // 递归上溯，同时把父指针直接改到根
}
```

例：`find(5)` 在链 `1 → 2 → 3 → 4 → 5` 上执行后：

```
压缩前：  1 → 2 → 3 → 4 → 5
压缩后：  1 → 2
          ├→ 3
          ├→ 4
          └→ 5       （2、3、4、5 全部直接指向根 1）
```

路径压缩使这一次 `find` 变贵，但将树拍扁，使后续 `find` 更快，属于"用一次代价换取长期收益"的摊还思想。

## 六、按秩求并 + 路径压缩的最坏情形

两者结合后，连续 $M$ 次操作（含 $N$ 次 `find`）的总时间可证明为：

$$O\big(M\ \alpha(M, N)\big)$$

其中 $\alpha(M, N)$ 是阿克曼函数的反函数（inverse Ackermann function），增长极慢：对任何现实中可出现的 $N$，$\alpha(M, N) \le 4$。即并查集每次操作摊还近似常数时间，这是算法分析中难得的"几乎最优"结论，也说明"按秩求并 + 路径压缩"并非简单叠加，而是产生协同效应。（"秩 rank"是按大小/高度求并的统一抽象，是高度的上界。）

## 七、应用

1. Kruskal 最小生成树：边按权排序后，用 `find` 判断两端点是否已连通，未连通则 `union` 加入该边。
2. 图的连通性 / 连通分量：动态判断两点是否连通。
3. 生成迷宫：随机打掉不相连房间之间的墙（`union`），直到起点与终点连通。
4. 等价类维护：网络连通关系、字符串归类等问题。

## 八、小结

| 优化手段 | 效果 |
| --- | --- |
| 朴素森林 | `find` 最坏 $O(N)$ |
| 按大小/高度求并 | 树深 $\le \log N$，`find` $O(\log N)$ |
| 路径压缩 | 拍平路径，配合求并达 $O(\alpha)$ |

核心结论：并查集 = 森林表示 + 按秩求并 + 路径压缩，三项组合使每次操作摊还近似 $O(1)$（$O(\alpha(M,N))$）。它是"实现极简、分析极深"的典范数据结构——代码十余行，背后却是阿克曼函数级别的精巧分析。
