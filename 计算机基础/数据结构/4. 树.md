# 树（Tree）

## 一、树的引入

线性结构（顺序表、链表）的共同局限是**查找元素平均需 $O(N)$**——元素排成一列，查找往往需逐个比较。当数据量很大时，$O(N)$ 不可接受。树将元素组织为**层次结构**，使每次比较都能排除掉约一半候选，从而把查找从线性级降至对数级。

树是全书最重要的结构之一：它不仅是查找的载体，更是排序（堆）、图遍历（DFS）、优先队列、高级数据结构（红黑树等）的共同根基。理解树，即完成从"线性思维"到"分治思维"的关键跨越。

## 二、预备知识

### 1. 术语

树是 $N$（$N \ge 0$）个结点的有限集，**有且仅有一个根（root）**；除根外，其余结点可分为若干**互不相交**的集合，每个集合本身又是一棵树（根的**子树**）。含 $N$ 个结点的树恰有 $N-1$ 条边。

- 孩子（child）/ 父亲（parent）/ 兄弟（sibling）：父子间的相对关系。
- 叶结点（leaf）：没有孩子的结点。
- 路径（path）：结点序列 $n_1, n_2, \dots, n_k$，其中 $n_i$ 是 $n_{i+1}$ 的父亲；路径长为边数 $k-1$。
- 深度（depth）：根到该结点的路径长，根深度为 0。
- 高度（height）：该结点到最深叶结点的路径长，叶高度为 0；树的高度即根的高度。
- 祖先（ancestor）/ 后裔（descendant）：路径上的上下级关系。

### 2. 树的实现

树不能简单用数组表示，因为每个结点的子结点数目不确定。典型实现为**第一子结点/下一兄弟表示法（first child / next sibling）**：

```
┌───────────┬────────────┬─────────────┐
│ 数据元素   │ 第一孩子指针 │ 下一兄弟指针 │
└───────────┴────────────┴─────────────┘
```

每个结点含两个指针：一个指向第一个孩子，一个指向下一个兄弟。无论结点有多少个孩子，结点结构统一，且能表达任意度数的树。

### 3. 树的遍历

- 先序遍历（preorder）：先访问结点，再递归访问孩子，用于"先列目录名再列子目录"。
- 后序遍历（postorder）：先递归访问孩子，再访问结点，用于"先统计子目录再累加到父目录"。
- 层序遍历（level-order）：逐层从左到右，用队列实现。

## 三、二叉树（Binary Tree）

### 1. 定义与性质

二叉树每个结点至多有两个孩子，且左右孩子有序（不可互换）。

- 满二叉树：每层结点数都达到最大（第 $i$ 层 $2^{i}$ 个结点，$i$ 从 0 计）。
- 完全二叉树：除最后一层外每层填满，最后一层结点靠左排列，是数组表示的前提（堆的底层）。

二叉树性质（层数从 1 计）：

- 第 $i$ 层最多 $2^{i-1}$ 个结点。
- 高度为 $h$ 的二叉树最多 $2^h - 1$ 个结点。
- 叶子数 $n_0$ 与度为 2 的结点数 $n_2$ 满足 $n_0 = n_2 + 1$。
- 完全二叉树可用数组紧凑表示：根在位置 1，位置 $i$ 的左孩子在 $2i$、右孩子在 $2i+1$、父亲在 $\lfloor i/2 \rfloor$。这是堆（第 6 章）无需指针、用数组实现的原因。

### 2. 二叉树的遍历

先左后右的三种深度优先遍历：

| 遍历 | 顺序 | 用途 |
| --- | --- | --- |
| 先序 | 根 → 左 → 右 | 复制树、前缀表达式 |
| 中序 | 左 → 根 → 右 | BST 得到有序序列 |
| 后序 | 左 → 右 → 根 | 释放结点、后缀表达式 |

```java
void inorder(Node t) {
    if (t == null) return;
    inorder(t.left);
    visit(t);          // 中序：访问根在中间
    inorder(t.right);
}
```

三种遍历经过的结点完全相同，仅访问根的时机不同，复杂度均为 $O(N)$（每结点访问一次）。中序 + 先序（或中序 + 后序）可唯一确定一棵二叉树。

## 四、二叉查找树（Binary Search Tree，BST）

### 1. 定义

对树中每个结点 $N$：**左子树所有结点的值 < N 的值 < 右子树所有结点的值**。这一"序"性质使中序遍历一棵 BST 得到升序序列。查找时每次比较可排除约一半候选——比当前结点小往左、大往右，路径长度即树高；树接近平衡时树高 $O(\log N)$，查找即 $O(\log N)$。

### 2. 核心操作

**查找（contains）**：从根开始与目标比较，小则去左子树、大则去右子树、相等命中、走到 `null` 则不存在。

**找最小值/最大值**：最小值一路向左、最大值一路向右。

**插入（insert）**：沿查找路径走到 `null` 处挂新结点，插入永远发生在叶结点位置。

**删除（remove）** 分三种情形：

1. 叶结点：直接删除。
2. 只有一个孩子：用孩子顶替。
3. 有两个孩子：用其**右子树的最小结点**（或左子树最大结点）替换该结点的值，再递归删除那个最小结点，使删除递归落到"单子或叶"的简单情形。

```java
Node remove(E x, Node t) {
    if (t == null) return t;
    int cmp = x.compareTo(t.element);
    if (cmp < 0) t.left = remove(x, t.left);
    else if (cmp > 0) t.right = remove(x, t.right);
    else if (t.left != null && t.right != null) {   // 双子结点
        t.element = findMin(t.right).element;        // 用右子树最小者替换
        t.right = remove(t.element, t.right);        // 递归删掉它
    } else {
        t = (t.left != null) ? t.left : t.right;     // 单子或叶
    }
    return t;
}
```

### 3. 插入示例

依次插入 `6, 2, 8, 1, 4, 3`，观察树的生长：

```
插入 6        插入 2        插入 8
  6            6             6
              /             / \
             2             2   8

插入 1        插入 4        插入 3
    6             6              6
   / \           / \            / \
  2   8         2   8          2   8
 /             / \            / \
1             1   4          1   4
                                /
                               3
```

查找 `3`：`6 → 左(2) → 右(4) → 左(3)`，共 3 步（等于树高）。中序遍历得 `1, 2, 3, 4, 6, 8`，升序。

### 4. 性能分析

- 平均情形 $O(\log N)$：等可能插入序列下，结点平均深度约 $1.38 \log N$。
- 最坏情形 $O(N)$：插入序列有序（如 `1, 2, 3, 4, 5, ...`）时，每个新结点都插到最右侧，树退化为链，查找退化为线性。

```
1
 \
  2
   \
    3
     \
      4     ← 退化为链表
```

> BST 的核心矛盾在于性能完全取决于树形，而树形取决于插入顺序。为此需"自平衡"机制，即下一节的 AVL 树。

- **懒惰删除（lazy deletion）**：对含重复项的 BST，删除时仅将结点标记为"已删除"并减少计数，而非真正移走，以避免删除操作使树形恶化，适合"查找为主、删除较少"的场景。
- **内部路径长（internal path length）**：所有结点深度之和，是衡量查找总代价的指标。

## 五、AVL 树

### 1. 平衡条件

AVL 树是带平衡条件的 BST：任一结点的**左、右子树高度差不超过 1**（空子树高度记作 $-1$）。高度为 $h$ 的 AVL 树结点数至少按斐波那契式增长，故 $h \approx 1.44 \log N$，所有操作严格 $O(\log N)$。

### 2. 旋转（Rotation）

插入可能破坏平衡，通过旋转局部调整。旋转的本质是"改变局部根、保持中序不变"——旋转前后中序遍历结果完全一致，这是其安全的保证。

分四种失衡情形：

| 失衡情形（相对失衡结点） | 旋转方式 |
| --- | --- |
| 左子树的左子树插入（LL） | 右单旋 |
| 左子树的右子树插入（LR） | 先左旋左子，再右旋 |
| 右子树的左子树插入（RL） | 先右旋右子，再左旋 |
| 右子树的右子树插入（RR） | 左单旋 |

**单旋转（以 LL 为例）**：失衡结点 $k_2$ 的左孩子 $k_1$ 过深，将 $k_1$ 上提为根：

```
       k2                  k1
      /  \                /  \
     k1   Z    ──右旋→   X    k2
    /  \                      / \
   X    Y                    Y   Z
   ↑ 新插入导致过深
```

旋转后 $X < k_1 < Y < k_2 < Z$ 的中序关系不变，高度差被抹平。

**双旋转（以 LR 为例）**：新结点插在左孩子的右子树，单旋无法解决，需先对 $k_1$ 左旋，再对 $k_2$ 右旋：

```
       k2            k2            k3
      /  \          /  \          /  \
     k1   Z  左旋→  k3   Z  右旋→  k1   k2
    /  \          /  \           / \   / \
   X    k3       k1   Y         X  A  B  Z
       /  \     / \
      A    B   X   A
```

口诀："左-右"失衡先左后右、"右-左"失衡先右后左；外侧失衡单旋一次、内侧失衡旋两次。插入至多一次旋转即可恢复，$O(\log N)$；删除可能需沿路径多次旋转，$O(\log N)$。

```java
// 右单旋（LL 失衡）：k2 的左孩子 k1 上提为根
Node rotateWithLeftChild(Node k2) {
    Node k1 = k2.left;
    k2.left = k1.right;   // Y 改挂到 k2 左侧
    k1.right = k2;
    k2.height = max(height(k2.left), height(k2.right)) + 1;
    k1.height = max(height(k1.left), k2.height) + 1;
    return k1;
}
```

## 六、伸展树（Splay Tree）

伸展树是自调整的 BST，其思想为：每次访问某个结点，就把它旋转到根（展开，splay）。动机是**利用局部性**——实际应用中，被访问过的元素近期很可能再次被访问，将其提到根可加速后续访问。

- 无需维护任何平衡信息（无高度、颜色等字段），实现简单；
- 摊还分析下，连续 $M$ 次操作总时间 $O(M \log N)$（单次可能较慢，平均是好的）；
- 对"近期频繁访问某几个元素"的缓存式场景表现尤佳。

## 七、B 树

### 1. 多路树的动机

AVL 树在内存中性能良好，但数据量大到需放磁盘时问题改变：磁盘瓶颈是读写次数，一次 I/O 读到一个块（如 4KB），耗时远高于内存访问。二叉查找树每结点仅存一个键，树高（$10^9$ 键约 30 层），一次查找需 30 次 I/O。**B 树使每个结点"变胖"**——一个结点存多个键、有多个孩子，恰好塞满一个磁盘块，一次 I/O 读入大量键，树高骤降，查找的 I/O 次数随之减少。

### 2. 定义与操作

$M$ 阶 B 树：

- 根可有 $2 \sim M$ 个孩子；
- 其余内部结点有 $\lceil M/2 \rceil \sim M$ 个孩子；
- 所有叶结点在同一深度（严格平衡）。

一个结点存放有序关键字与指向子树的指针，关键字数比孩子数少 1。例如 $M=4$ 的结点可存 3 个键、4 个孩子：

```
[ 20 | 50 | 80 ]
  /   |   |   \
 <20  20-50 50-80  >80
```

- 查找：结点内先定位区间再下到相应子树，复杂度 $O(\log_M N)$（树高约 $\log_M N$，远小于二叉树的 $\log_2 N$）。
- 插入满结点时分裂成两个半满结点，键上提到父结点；父满则继续向上分裂。
- 删除引起下溢（少于 $\lceil M/2 \rceil -1$ 键）时借位或合并。
- 应用：文件系统（B-tree 族）、数据库索引（B+ 树是其变体，数据全放叶层并串成链表）。

## 八、标准库中的集合与映射

标准库以红黑树实现有序集合与映射（详见"高级数据结构"）：

- `TreeSet<E>`：有序集合，操作 $O(\log N)$。
- `TreeMap<K, V>`：有序映射，按键排序，操作 $O(\log N)$。

二者与哈希实现（`HashSet`/`HashMap`，无序、平均 $O(1)$）的区别在于是否有序：需按键遍历时选 Tree，只需快速查存时选 Hash。

## 九、小结

| 结构 | 查找/插入/删除 | 特点 |
| --- | --- | --- |
| 二叉查找树 | 平均 $O(\log N)$，最坏 $O(N)$ | 简单，但可能退化 |
| AVL 树 | 严格 $O(\log N)$ | 严格平衡，插入至多一次旋转 |
| 伸展树 | 摊还 $O(\log N)$ | 自调整，无需平衡信息 |
| B 树 | $O(\log_M N)$ | 多路，适合磁盘/数据库 |

核心思想：BST 提供有序查找，平衡机制（AVL 的旋转、伸展树的展开、B 树的多路分裂）保证树高对数级，将最坏情形从 $O(N)$ 压回 $O(\log N)$。这一"用平衡对抗退化"的思想贯穿后续的散列、堆与高级数据结构。
